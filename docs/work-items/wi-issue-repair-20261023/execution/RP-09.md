## Diagnosis and change

recovery catalog filtered v2. Consequently neither exposed v3 initial-design
recipes. The project-page detail also unconditionally dereferenced the v1
`input.reference`, so removing the filter alone would crash for v2/v3.

It preserves all supported v1/v2/v3 records and their fixed revision, searches
kind/instruction/reference/scope, and retains six-item pagination. Detail reads
each version's actual fields. V3 exposes parameters, page profiles, samples,
coverage gaps and tradeoffs without inventing a reference image. It explicitly
labels the recorded scope and basis as distinct from current deck-wide direction
or production permission. V1 modification remains unchanged; v2 modification
uses the existing screenshot recovery entry; v3 structural modification is
explicitly directed to the design planning entry rather than converted to v1.

Trial preview keeps the exact recipe ID and selected scope through the existing
core plan API. Feasibility recipes remain readable with trial controls disabled.
No recipe, confirmation, task, authorization or original artifact is rewritten
by browsing or reopening.
