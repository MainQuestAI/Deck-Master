版本：2026-10-23 / r2。状态：**方案待实施，产品修复未完成**。

本基准整合原修复方案的六点复核结论，以及第二轮前链路/Web UI 审计新增的 #181–183 与 5 条评论。覆盖 #132–183 中的 51 个 Issue（#147 是现有 PR），拆成 31 张任务卡：29 张承担 Issue 最终关闭责任，1 张跨轮诊断卡，1 张联合验收卡。

## 后续修复 PR 如何引用

每个 PR 标明“基准 PR + 本目录 + 使用的基准 commit + RP-xx”，列出完成的验收项和剩余项。正常修复从包含该基准的最新 main 分支创建；若基准尚未合并，先以本基准分支为 base 做堆叠 PR，合并基准后再 retarget 到 main。基准是范围和验收的锚点，不要求后续代码永远停在旧 main。

一张任务卡可分最小实现与完整验收两个 PR，但最终关闭责任只有一个 owner。多个卡可在同一小 PR 完成时应分别报告证据；不得顺带吞入无关变更。依赖表示完整验收前置，准备/静态分析可提前开展；没有依赖的任务可独立交付。本清单不自动启动实现、Agent、安装、模型调用或发布。

合并时不得使用“关闭全部 51 个 Issue”的关键字。只有满足任务卡验收、处理所有残项后，具体修复 PR 才可关闭其负责的 Issue。
