# 验收与兼容性

## 共同兼容矩阵（F6）

由 RP-15/#180、RP-17/#162/#165/#166、RP-19/#173 在各自 PR 内执行，RP-20/21 消费这些语义，RP-30 汇总同一集成版本。新增字段必须进入唯一活动合同及相应默认/版本处理，不能向 additionalProperties=false 对象临时塞字段。

|ID|固定用例|通过要求|
|---|---|---|
|C1 历史读取|不含新策略/资产语义的旧项目、旧候选、旧冻结输入；v1/v2/v3 规范混合|可读取原始事实，不原地改写，不暗中把旧字段解释为新策略或当前方向。新消费若需迁移，给出显式受支持路径。|
|C2 真正变化|改当前页内容、页级样式、实际消费资产字节、适用决定|相关候选/审查的 basis 变 stale；新生产冻结正确版本，旧结果不得假装当前。|
|C3 局部隔离|改无关页、未消费字段或历史记录|没有关系的页、候选和有效审查不因全局粗粒度 revision 而全失效；变化影响可说明。|
|C4 冻结方法|既有任务的旧 manifest、当前职责/phase/scope 变更|旧任务不可静默补方法或换 scope；正式过期/恢复后 reader 与新任务一致。|
|C5 异步与权限|取消、晚到结果、并发修改、未知调用、同 operation 重放|保留 CAS、执行身份、调用额度和真实结算；已提交可信结果可恢复，不能重复付费或绕过新操作权限。|
|C6 格式消费|Logo、普通图片、字体、PPTX 模板分别走登记/绑定/消费/成品路径|每格写明 supported/unsupported/pending 及证据；没有实际消费不标完成，正文抽取不当母版复用。|

## 三条联合流程

- **内容线**：合法零调用正文试作 → 当前稿保持 → 采用后正确失效 → 只重审失效单元 → 有效请求进入 packet → 受众表达审查 → 冻结 prompt 与实际图像核对。覆盖 RP-02/03/11–16。
- **设计线**：当前策略/逐页覆盖/资产固定 → 可读 v3 规范 → 代表原图表达审查 → 带已知错边的修复与复核 → 采用/扩页 → SVG/PPT 的保真和编辑范围分别核对。覆盖 RP-09/17–21。
- **操作线**：当前总览 → 可辨识目标 → 内容编辑/准备 → 跨轮恢复及真实接手 → 阶段完成与可读产物；并核对紧凑回执、重放、读取性能。覆盖 RP-04/06–08/10/22–29。

真实图像与原生会话只有实际发生才可记通过；可先用零外部调用合成用例验证事务和边界，但不得据此关闭需要真实消费的验收。当前授权仅制作修复基准，不启动上述流程。

## 性能口径

固定源码、安装、项目规模、材料长度、历史深度、并发及操作序列。记录响应字节、构造 CPU、wall time、JSON 读取、依赖构建、遍历、哈希、写入/fsync 或渲染计数中与问题相关的项。至少报告一次预热/冷读条件与重复采样方法，不用不同输入比较。#183 使用 1/13/30 个待办的固定材料；其他规模增长测试按对应任务选择 N/2N/4N。

减少重复工作后必须检查返回事实、错误行为和权限一致；不跨请求缓存资格通过。没有基线不预设任意百分比目标；单次 GET 不当 p95，调用次数不直接换算整机温升。
