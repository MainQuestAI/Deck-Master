## 2. 范围（2026-11-20 起本轮）

### 范围内
1. **受众与决策框架：** 生成前锁定读者、要读者做的决定、读者最关心的 1–3 点、讲述人身份与语气（例如资深战略顾问向 CEO 汇报）。之后每页都能回指这个框架。
2. **主线先于页面：** 先写 5–8 句金字塔式主线，按结论→理由→证据排列。主线保存并通过检查后才展开成页。只读页标题就能复述整条论证。
3. **判断句标题：** 判断页的标题必须是可以被反驳的判断句，正文只支撑这一句。说明页、查阅页、教学页沿用 `page-writing.md` 的豁免。
4. **论证链五环：** 每个关键主张都要有：
   - 主张；
   - 2–3 条理由，彼此不重叠、合起来能撑住主张；
   - 证据，必须能追溯到材料，否则标“待补”，不得编造；
   - 推理，说明证据为什么能推出结论；
   - 反驳与边界。
   五环在页面上的落位：主张写在标题，理由和证据写在正文，推理写在图表或注释，反驳与边界写在讲稿备注或附录。缺环且未标注的页，不得进入出图或 native 生成。
5. **证据具体，缺口醒目：** 优先用数字、案例、对比和原话，不用形容词充当证据。材料没提供的东西显式标为待补，并汇总成缺口清单，不能用空话填充。
6. **讲述人表达，去过度防御：** 讲述人身份与语气作为显式约束写进 Host 的写作指令，不依赖模型默认语气，Codex 默认偏谨慎。具体要求：
   - 结论先行，语气肯定；
   - 真正的不确定性只在相关处说一次，不在全稿重复；
   - 限定说明不能压过结论；
   - 主线上的风险最多 1–2 条，并且各带应对；
   - 用决策人的语言，不用工程腔（如“验证、门槛、阻塞、过闸”）。
   这项要求**不得**删掉真实的不确定性或必要条件，对应 `expression-review-humanizer.md` 中需要保护的事实。
7. **出稿前审稿门**，检查六项：
   - 主线是否连贯；
   - 证据能否推出结论；
   - 可预见的质疑是否已回答；
   - 去防御检查；
   - 读者可见页面上没有内部备注；
   - 最终页确实被看过。
   审稿要留下可查记录，`self_check` / `other_model` / `human` 分开记录。未审稿时，导出结果必须显式标出“未审”，不能静默放行。
8. **（可选，单列）** 同一页内 `cNvPr/@id` 唯一，见 AC-08。
9. 用合成夹具 CQ-F1/F2/F3 做 main 与候选版的前后对照，详见 AC-07。

## 4. 解锁顺序与角色

角色：
- PM（产品经理）：范围解释、夹具与量表维护，不写代码。
- Eng lead：CodeManger，负责协调和分派。
- 设计：架构师，负责实现方案、字段与门的设计。
- 开发：SWE。
- 代码评审：Reviewer。
- 最终完整核验：Codex。
- 视觉判定：只限 Los 或他指定的人，本轮不需要。

步骤：
1. **方案评审（并行）：** Reviewer 与 CodeManger 评审本切片，CodeManger 拉架构师参与。输出包括阻塞问题、架构师实现方案（字段、门、技能改动面、兼容策略）和估时。PM 只就范围问题修订；修订要另存带日期的补充文件，不改写本文件。
2. **开发：** CodeManger 分派 SWE 在独立分支开发，建议顺序 AC-01 → AC-02 → AC-03 → AC-04/05 → AC-06 → AC-08（可选）。SWE 只用 F1、F2 自测，可以开 PR，但不能合并。
3. **代码评审：** Reviewer 评审 PR。有阻塞项时退回 SWE，循环到 Reviewer 无阻塞为止。
4. **完整核验：** 在 Reviewer 无阻塞的候选头上，Codex 按 AC-01…08 逐条核验，AC-07 包括 6 次 Host 运行。AC-07 的盲评由 Reviewer 或另一位非 SWE、非 Codex 的人打分，CodeManger 负责匿名化 X / Y。Codex 汇总出核验报告。
5. **修复循环：** 报告里每条 FAIL 退回 SWE 修复，经 Reviewer 评审后，Codex 只复核受影响的 AC，同时重跑 AC-07 的回归部分。循环到 AC-01…07 全部 PASS（AC-08 为 PASS 或 DEFERRED）为止。如果出现以下情况之一，则停下交 Los：
   - 同一 AC 连续 3 轮仍 FAIL；
   - 需要动范围外的内容；
   - 某个 BLOCKED 必须靠 Los 才能解除，例如登录、额度或费用。
6. **交付：** CodeManger 交出候选头 SHA、PR 链接、Codex 核验报告、盲评 JSON、缺口清单样例和 6 份稿的 SHA，由 PM 汇总给 Los。合并与发版等 Los 另行点头。

独立性：
- 修复由 SWE 做，核验由 Codex 做。
- 如果 Los 指定 Codex 亲自修复，那么 Codex 修过的 AC 改由 Reviewer 核验，Codex 不能自核。
- 写夹具的 PM 不打盲评分。
