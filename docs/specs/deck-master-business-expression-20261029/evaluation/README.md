# D00 评测工作目录

本目录保存明确合成的评测输入、调用前冻结草案和人工填写的报告模板。执行状态只看上级 `execution-index.json`。输入分诊和工程测试不构成内容效果验收。

材料按最低档准备：`dev-01`、`dev-02` 用于开发，`holdout-01` 至 `holdout-03` 留待 D08。每包只有一个共享事实底座；首次提案与竞标通过 `tasks.json` 的不同作者任务区分，不使用 live/read 版本代替。合成材料是本次明确选择的实验输入，不是遇到真实材料失败后的 fixture fallback，也不能证明客户接受。

`manifest.json` 固定文件字节/hash、分组与合成标记。留出材料在选定时编写，当前编写者见过其内容；尚未进入任何生成、评分或方法调试。后续开发只向生成会话提供开发包，不读取留出正文，不依据留出表现改方法。该限制和初始暴露均须写入最终报告。

## 当前入口

在本工作树的 Python 3.12 开发环境运行：

```bash
.venv/bin/python docs/specs/deck-master-business-expression-20261029/evaluation/triage.py --out <新的本地证据目录>
```

脚本不调用模型。它使用当前 `read_source` 逐文件核验完整文本/hash/末尾约束，以真实 `service.create` 创建 4 个独立、零 Page 的 `content_only / plan_only` 开发项目，并保存首个 Task 的实际方法字节及 hash。现有 Task 不追加方法。留出包只校验字节/hash，不创建项目或展开方法；完整读取能力由同格式开发包验证。

生成项目和完整执行日志留在仓库外；仓库只记录去除本地路径的分诊摘要。不要提交 `.deckmaster`、模型会话、私有原件或生成运行。出现错误保留失败证据，不在同一目录覆盖重跑。

`freeze.json` 固定材料、任务、模型请求 ID、方法实验、门槛及模板。老板已明确同意 I0 使用现有订阅额度，最多 32 次模型请求，不新增 API 付费；D08 调用费用仍未授权。`protocol.md` 规定生成、盲评和失败保留方式；`report-template.md` 在调用前固定报告列。调用返回仍须记录实际可见模型元数据，不能把请求 ID 说成已证实后端快照。作者判断未就绪时，D00 保持未完成，D01 不开工。

本轮 D00/I0 小样采用策划范围：每份必须有完整 Narrative.v1 与 planned ContentPlan.v2 提案、可读主线/展开/取舍说明，不产生 Page、口播或视觉。第五维只记录计划的连续性，全文贯穿记为未验证；D08 按完整内容包评全部五维，不以策划分代替全文分。
