# D00 调用与评审协议

调用前固定本文件、材料 manifest、任务、实验补充指令、报告模板和具体执行条件的 SHA。未取得费用条件、可固定的模型身份或作者判断时，记录缺口，不用工程检查补齐。D00a 不调用生成、评审模型。

## 材料和比较

选择最低档：开发 2 包、留出 3 包，全部明确合成。理由是先用能覆盖需求、能力与限制的最小配对集合验证方向；此时没有模型输出或评分，未依据效果删样。材料路径/hash、两类任务及分组见 manifest/tasks。D08 启用留出前固定代码、方法、原始基线和模型；不得重选留出、降低门槛或删除失败。

I0 为 2 开发包 × 首提/竞标 × 基线/实验，共 8 份**完整策划输出**。每份完成 framing、argument 两阶段，后者带 planned Plan。每份必须保留两次模型原始返回、信封、Runtime 接纳/拒绝、完整 Narrative、Plan、来源与可读稿。模型返回后不得手写一份更好的结果代替；技术修正也保留原版及全部成本。完整稿及第五维全文贯穿尚未验证。

基线固定为开工时 origin/main `035845f228d1ba4cd7fc9b41cdedd8fd734043df` 的当前最佳合法内容流程。首阶段选择 M01；argument 首提选 M02/M04/M07/M08/M10，竞标选 M02/M03/M05/M07/M08/M10，并保留 Runtime 默认规则与真实依赖。选择见 tasks；允许在正式冻结前按实际任务修订并记录，冻结后只沿正式退役/重派路径改变。

两臂共用同材料、任务、方法选择、模型版本、推理设置、最多 6 页的计划、阶段调用数和结果合同。两臂均使用充分输入与合法选卡，不用“不给方法”的弱基线。实验只增加单列 `experiment.md` 指令；其额外字节与消耗单列。它不是注册方法卡，不暗改冻结 manifest，不向 narrative.v1 塞 v2 字段，不把实验说明当正式作者决定。原始方法字节/hash 与补充指令 hash 分开保存。

每份新建独立 Runtime 项目和全新生成会话，不能把另一臂的输出或留出材料放入上下文。同一份的 argument 可以读取本份已生成 framing；其他输出不可见。先完成所有基线，再做实验；不得根据配对结果选择重跑某一臂。失败占分母，只在已记录的技术原因及预算内重试，不补造成功。

生成通过真实 `task start` 声明实际协议/能力，再依现有信封 `task accept`。按真实接纳结果推进。策划提案不等于采用，采用需要具体版本的有效作者决定；不为评测绕过 closed request、review 或授权。D00a 创建的四个 pending 项目只证明入口，不冒充八份已生成输出。

## 五维与硬失败

锚点统一为 0 明显不成立或偏离，1 有方向但需实质重构，2 作者小改可用，3 业务具体、结构有解释力且可直接展开。

| 维度 | 评议必须定位的内容 |
| --- | --- |
| 策略适配 | 作者本次争取的判断、既有共识、开场与展开责任是否匹配；首提/竞标有实质差异 |
| 业务框架 | 名称背后有明确含义与关系，能够组织业务对象，不只是模块重排或口号 |
| 反向展开 | 主题可回到真实需求、能力、使用场景与限制，不凭空补能力 |
| 内容取舍 | 主线、支撑、下放、省略有任务依据，关键限定不被删掉 |
| 全文贯穿 | D08 核对正文、场景、讲稿、演示提纲的完整贯穿；I0 仅记录计划连续性，全文分留空 |

严重失败按 SPEC 全量保留：编造已实现能力或竞争事实、扭曲关键需求与约束、框架无法映射实际内容、两种任务只换措辞、突破作者范围、混入旧稿或其他候选。材料中的具体禁止项只是定位补充，不缩减失败定义。分数不抵消硬失败。

I0 的 go 条件：有可辨认的策略/业务组织改善，零新增关键事实错误，且至少一套结构经项目作者本人确认可展开。否则 adjust；条件未齐为 incomplete。不会因为平均分更高就跳过作者判断。I0 不应用 D08 的全文五维达标数量计算。

## 作者主审 + 三模型辅审

在评分前用系统随机源为每对生成 A/B 映射，映射留在评审不可见的本地目录。盲评包包含任务、同源材料、事实边界与两份可读完整稿，去除版本身份、方法名和可泄露身份的解释；原版仍保存。先固化作者初判，再启动辅审或把辅审反馈展示给作者。未有作者初判，不抢先以模型分数引导作者。

Claude、Codex、Kimi 分别使用冻结的具体模型 ID，在互不可见的全新会话中评分；不使用生成会话或共享历史。Kimi 不生成内容。生成模型参加辅审时披露可能偏好自身输出。别名、客户端版本、登录成功及自报身份都不足以证明调用到哪个模型；保留具体请求与工具能提供的实际响应元数据，无法确认时保持未验证。

保留作者初判、三模型原始评分、多数意见、作者终判和解盲时间。三模型一致而作者终判相反时记一句理由。最终统计依据作者终判，称为“作者主审 + 三模型辅审”，不是第三方评审。

## 费用和 D08

I0 费用提议为现有订阅额度内最多 32 次：16 次阶段生成、12 次配对辅审（4 对 × 3 模型）、4 次失败重试。一次 CLI/会话可能产生多个模型请求，预算以实际模型请求计；无法限制或观察时不以一次 CLI 当一次调用。到上限停止，未知请求先核验，不自动重发。新增 API 付费、购买额度未授权。

D08 冻结最低档的规模与质量门槛：3 包 × 2 任务 × 2 版本 × 2 次 = 24 输出/12 对；新版 12 份中严重失败 0，五维均≥2 至少 10，整体更好至少 8，首提与竞标各更好至少 4/6。失败和缺失保留在原分母，缺完整结果即未完成。D08 使用 content_full，保留完整逐页正文、约定口播与计划。具体模型调用数与费用在实际进入留出前估算和落实；本次未授权、未执行，不能暗用 I0 额度。该费用缺口不改变已经固定的规模、门槛和模板。

只有完整调用条件冻结后才开始 I0；作者 go 后才进入 D01/D02a。所有预备记录、模型意见、工程检查和作者结论分开保存。
