# D02 方法选择与成果审查接通

[套件入口](../README.md) · [唯一执行状态](../execution-index.json) · [总方案](../SPEC.md)

迭代：I1。前置工作单元：D02a、D02b（本卡为收口单元）。D02a 开发样本校准完成；D02b 工程接线已实现，真实内容验证待分配费用。[方法校准](../implementation/D02a-validation.md) · [接线证据](../implementation/D02b-validation.md)，状态以执行索引为准。

**目的：** 让方法成为实际内容加工动作，解决“有卡但调用和落稿不稳定”。

**实施：** 修订 M01、M02、M07、M08 及 selection、content-methods、narrative-patterns、method-review，其他卡保持独特职责。采用前述两种初始入口，新版默认包按能力或合同版本隔离；framing 不提前承担成熟框架生成。后续阶段在派发前以合法职责选卡。补 outline/preproduction dispatch、native review 及相应 API/CLI 的正式评审选卡传递。演示组织在 argument/plan 形成，讲稿根据已采用结构展开，不扩大 speech 卡范围或正文写权限。

**代码落点：** method_resources.py、resource_catalog.py、skills/deck-master/resource-catalog.json、content_production.py、service.py、outline_review.py、content_review.py、native_review.py、cli.py、collaboration_api.py、method_library_view.py、四 Skill 共用 references。

**验收：**

- **D02-AC01** 初始创建不出现“任务已冻结后再补卡”的循环。

- **D02-AC02** 新版最小包不改变旧任务、纯写稿或纯口播任务的默认职责；framing 提案不被当作已采用策略。

- **D02-AC03** 每个被选方法说明处理的具体问题，并能关联真实成果或明确未采用原因。

- **D02-AC04** Host 不要求普通作者先理解和勾选方法编号。

- **D02-AC05** 范围不匹配、未知资源、依赖缺失、字节漂移继续明确拒绝或正式重派。

- **D02-AC06** 前审拿到真实完整材料和本次需要的方法，不能只复述作者的自评。

- **D02-AC07** pending/recovery 审查复用不更换 manifest；确需改变时走正式退役重派。

- **D02-AC08** “已返回资源字节”不被当作“方法已有效应用”。

- **D02-AC09** 上下文减负通过实际字节和内容对照验证，不以删掉必要方法作为优化。

**依赖：** D02a 仅依赖 D00，可与 D01 并行；D02b 依赖 D01、D02a。D02 整卡待两单元完成后收口，不重复拥有 AC。

## 执行顺序与增量边界

D02a 校准 M01/M02/M07/M08 及 selection、content-methods、narrative-patterns、method-review 的方法文本，负责 AC08、AC09。沿 D00 的合法小样对象做方法应用与完整依赖字节/内容对照，无需等待 D01 新协议，也不先改运行时选卡默认。

D02b 在 D01 合同与 D02a 文本就绪后，接通新版创建起步包、后续阶段选卡、outline/preproduction/native review 到 freeze 的参数链，负责 AC01–AC07；复验实际接线后的打包字节与旧 manifest。默认全卡加载不算完成。

复用现有状态、不可变对象与作用域约束，不另建同义生产或审批链。
