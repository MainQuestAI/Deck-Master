# D04 前置质量审查与完整内容展开

[套件入口](../README.md) · [唯一执行状态](../execution-index.json) · [总方案](../SPEC.md)

迭代：I2。前置工作单元：D03。当前未实施；验收不得根据文档编制完成而勾选。

**目的：** 使好框架真正进入正文和讲述，不停在概览金句。

**实施：** 复用 outline review，在已采用且匹配的 Narrative 与 planned Plan 上审查；plan_only 已关闭时先走 D03 的有界后续请求与采用路径。在 argument 单位检查任务适配、主张、框架定义和业务映射，在 progression 单位检查取舍和顺序。通过后，在作者已经请求完整内容的范围内，沿已有 Plan、Page、Speech 链路写完整内容；完整前审再检查实际落稿。只做策划的请求不自动扩展为正文生产。首版不新增同义的 review kind 和审批状态机。

**代码落点：** outline_review.py、content_review.py、content_production.py、content_plan.py、design_requirements.py 及相关要求消费处、Page 映射与内容审查相关合同。

**验收：**

- **D04-AC01** 空口号、框架与能力脱节、首提/竞标策略混用，产生定位到实际内容的 finding。

- **D04-AC02** 新框架标准有版本要求，旧 argument 审查不能自动冒充通过新标准。

- **D04-AC03** 正文、案例和讲稿保持已采用主张与框架；不能只在标题使用框架词。

- **D04-AC04** 页职责、语义节点、可见 atom 和必要条件正确对应。

- **D04-AC05** 演示提纲说明展示哪个场景、关联什么能力、要说明什么；无实际能力时不声称可演示。

- **D04-AC06** outline 通过不替代完整稿或视觉审查。

- **D04-AC07** 独立审查不可用时保留可读待审结果，不制造通过。

**依赖：** D03；先完成框架审查，再做全文展开，最后复查真实成品。

## 执行顺序与增量边界

先把新评价标准绑定具体审查依据，再用空口号和框架脱节反例验证 finding；仅在完整内容授权范围内展开，逐页核对 atom/节点和整稿主线，最后独立回读。

复用现有状态、不可变对象与作用域约束，不另建同义生产或审批链。

## 具体交付

新标准下的大纲与全文审查 packet、定位 finding、修订前后完整正文/案例/讲稿及框架映射。
