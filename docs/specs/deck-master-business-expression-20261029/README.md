版本：规划 v0.2 · 2026-10-29（Asia/Shanghai）。文档修订基线：`03c06add760eb20a9e457c6f8bda0b2a8b8036b7`；运行代码核对基线仍为 `ce4ef8b204dd5033019364ce44979adac7f4243b`。

## 顺序与关口

| 迭代 | 工作单元 | 作者可检查的成果 | 关口 |
| --- | --- | --- | --- |
| I0 | D00a → 条件 X01 → D00（冻结 D08 评估设计） | 两包素材、两类任务的 8 份配对内容小样 | 策略/业务组织有可辨认改善，无新增关键事实错误；否则调整 |
| I1 | D01 ∥ D02a → D02b → D06a → D03 | 可读、可修正、可采用的策略与框架 | 不是只有 schema 或后台 JSON；零页面策划可正确采用和审查 |
| I2 | D04 → D05 → D06b | 完整正文/讲稿，以及策略变化后的真实重组 | 范围受控、版本一致、旧稿可读；内容-only 可完成 |
| I3 | D06 收口 → D07 → D08 | 固定版本作者包与留出对照报告 | 内容质量、兼容与作者流程共同满足冻结后的候选门槛 |

D00a 先做材料选择与输入分诊；X01 默认 inactive，仅在真实输入阻塞时启用，随后完成 D00。I1 中 D01 与 D02a 并行，D02b 等两者完成；D02 整卡随后收口。D06a 已包含真实修正/采用/恢复，D03 接入实际生成结果；D06b 只接策略重编。具体有向依赖与每项 AC 的唯一工作单元归属见 execution-index.json。按一个有界单元推进，每个单元须有可审查结果。D08 评测设计归 D00，最终效果验收归 D08。

评审采用“作者主审 + 三模型辅审”，作者终判为准；目标/最低两档在 D00 冻结。详见 [评审流程与候选门槛](SPEC.md#验收设计与候选门槛)。

## 可立即开始与仍需冻结的事项

下一张执行卡是 D00，从 D00a 输入分诊开始：复核 main 差异，准备授权材料与两个作者任务，记录原始能力/需求边界，冻结评估条件后做小样。评审由作者（项目作者本人）主审 + Claude/Codex/Kimi 三模型辅审，留出集最低 3 包；具体材料、模型版本与费用额度由 D00 冻结。按此流程完成的验收即本轮专业评审验收，合成材料单独标注，不能外推为客户接受或商业成功。

拟采用 Narrative.v2 和 `business-framing.v1`，保留 compose.v2、Plan/Page.v2；最终字段和名称在 D01 根据 D00 结果及所有消费处确定。严禁向 strict v1 偷塞字段。评测目标 12 包（开发 6/留出 6）、留出 48 份输出；最低 5 包（开发 2/留出 3）、留出 24 份输出。两档门槛见 SPEC，均未执行、未冻结实际档位及费用。

## 暂不进入本轮

新增排版风格、HTML 引擎、企业母版无损编辑、Office 原生图表、通用多分支平台、跨 Host 自动执行和自动操作外部 demo 不进入主卡。现有生成/渲染链发生内容或版本正确性回归时仍须修复。X01 只解输入阻塞，不引出原生图表工程。

## 每卡关闭方式

卡片保存 AC 定义，execution-index.json 保存状态和证据。每个 AC 有唯一所属卡及唯一验收工作单元；跨卡验证可以引用同一证据，但不能代替各自结论。关闭时填写实现提交、实际修改、检查命令与结果、完整内容样本、评议、未执行项和风险。工程通过、独立模型评价、业务作者认可分别记录；任何缺项不补造通过。

本次文档校验只证明套件结构与引用一致，不能关闭 D00 或 D08。推送文档不执行安装迁移、生成调用或 Release 发布。
