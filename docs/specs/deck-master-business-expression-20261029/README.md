# Deck Master 商业表达能力开发套件

版本：规划 v0.1 · 2026-10-29（Asia/Shanghai）。基线：`ce4ef8b204dd5033019364ce44979adac7f4243b`。

**目标：帮助讲述者根据具体商业任务，从真实需求和产品能力中提炼业务主张与可展开框架，并贯穿正文、场景、讲稿和策略改写。** 核心理念见 [产品说明](../../product-philosophy.md)。

本次交付是 README 与开发卡套件；功能尚未实施。产品方向按原讨论的最终纠正整理；具体协议命名、样本、预算和数值门槛作为待冻结设计。文档推送不表示产品发布或专业验收完成。

## 顺序与关口

| 迭代 | 工作单元 | 作者可检查的成果 | 关口 |
| --- | --- | --- | --- |

## 可立即开始与仍需冻结的事项

下一张执行卡是 D00：复核开工时 main 差异，准备授权材料与两个作者任务，记录原始能力/需求边界，冻结评估条件后做小样。当前未选定实际材料、模型和费用额度，也未安排专业评审；这些是 D00 的输入与冻结工作，不妨碍本次文档交付。缺真实材料可先准备明确合成案例，但不能宣称专业商业验收通过。

拟采用 Narrative.v2 和 `business-framing.v1`，保留 compose.v2、Plan/Page.v2；最终字段和名称在 D01 根据 D00 结果及所有消费处确定。严禁向 strict v1 偷塞字段。评测建议 12 包（6 开发/6 留出）、最终 48 份输出；数值门槛见 SPEC，均未执行、未冻结费用。

## 暂不进入本轮

新增排版风格、HTML 引擎、企业母版无损编辑、Office 原生图表、通用多分支平台、跨 Host 自动执行和自动操作外部 demo 不进入主卡。现有生成/渲染链发生内容或版本正确性回归时仍须修复。X01 只解输入阻塞，不引出原生图表工程。

## 每卡关闭方式

卡片保存 AC 定义，execution-index.json 保存状态和证据。每个 AC 有唯一所属卡；跨卡验证可以引用同一证据，但不能代替各自结论。关闭时填写实现提交、实际修改、检查命令与结果、完整内容样本、评议、未执行项和风险。工程通过、独立模型评价、业务作者认可分别记录；任何缺项不补造通过。

本次文档校验只证明套件结构与引用一致，不能关闭 D00 或 D08。推送文档不执行安装迁移、生成调用或 Release 发布。
