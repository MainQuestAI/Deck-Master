# UI 同步修订建议

保留 DESIGN.md 的五工作面、浅色中性表面、黑主按钮、无衬线及业务文案。内部 Ref、hash、operation_id 仅在依据详情出现。

| 修订 | 原 UI 最小变化 |
|---|---|
| R1 / §4 | 无决定且可记录时显示“记录方向决定”；记录成功后重新读取，满足 can_adopt 才显示“采用此方向”。有可复用决定不重复记录。策略拒绝就近解释；部分成功明确“决定已记录，方向尚未采用”，未知状态“待核实”。 |
| R2 / 方法准备 | 目录浏览与“当前不能派发”同时可见；所有状态均标只读准备。复制不接手，浏览器不自动调用 continue；不可给 frozen Task 补卡。 |
| R3 / §4 | plan_only 零 Page 仍展示 Narrative、对应固定 Plan 的职责/顺序；计划页明确尚未产出，Page 入口不伪造。不同方向各自显示真实关联 Plan；缺失按缺失显示。 |
| R4 / 比较 | 两份不同合法可读 Narrative 即可比较，允许当前+候选。固定两侧引用；历史比较保留阅读和差异，禁用决定/采用写动作。 |
| R5 / Review | 深链接、刷新、返回、排序/过滤后保持同一 Ref/revision/source_index；定位失败就近说明，绝不跳到第一条。页/范围交接仍以真实范围为准。 |
| R6 / 通用 | 不可读对象保留依据与错误；不填“无标题”、空节点、空 finding 或通过状态作为真实业务值。其他可读对象继续使用，错误对象不提供采用/以其作写依据。 |

方法脚本只能阅读，不执行。四公开 Skill 保留；读取、准备和复制不产生 Host 执行证据、专业认可、生产授权，不消耗调用、不提高 writer floor。
