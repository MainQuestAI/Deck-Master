## 开发子任务

这些是本卡负责人的内部步骤；跨卡提前交接以[阶段交接与验证](handoffs.md)为准，不逐项作为独立任务派发。

### T11.01 实现唯一审阅解释

- [ ] 实施：evaluate_current统一检查适用性/依赖/must_fix/needs_judgment；接收读取UI导出复用。
- 交付与核对：同一当前Review在各入口结果一致，空registry/空findings不自动满分。

### T11.02 连接真实检查对象

- [ ] 实施：读取实际PPT页面/备注/隐藏项/XML与当前页集合，共享解析但按检查目的判断。
- 交付与核对：正文、关系、内部指令泄漏有具体定位；页码/业务词不误判。

### T11.03 实现三类视觉差异复核

- [ ] 实施：正常还原、故意缺节点、合理抗锯齿差异分别实测；需要判断的指标保留问题。
- 交付与核对：严重缩水不能靠revision_required=false清空；accepted_variance有具体观察。

### T11.04 实现真返修闭环

- [ ] 实施：repair生成新产物；新Review用replaces/finding_id关联旧失败并实际复查。
- 交付与核对：review-fixed正负例真实接收；只改fixed、旧subject或过期观察均不关闭。

### T11.05 如实记录审阅身份与证据

- [ ] 实施：区分tool/Host/human、execution_ref和实际阅图；原图期待独立于输出登记。
- 交付与核对：同人两个名字不算独立；模型互相同意不等于专业人类验收。

### T11.06 补内容判断与失效检查

- [ ] 实施：分别复算计算、核对事实和审阅有条件建议；方法或产物变化只失效对应结论。
- 交付与核对：54/120可核算，无依据40%被识别；旧pass不盖当前fail。
