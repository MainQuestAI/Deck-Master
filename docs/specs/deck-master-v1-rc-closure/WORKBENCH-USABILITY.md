## 四路审查与实施

主 Agent 使用 Product Design audit 检查工作流，并按 design-qa 对照现有视觉；三路子 Agent 分别使用
design-review、impeccable、design-taste-frontend。最后一路明确该 Skill 不适用于多步骤工作台，
只采用保留式改进、密度和可访问性规则，产品约束仍以 DESIGN.md 为准。

共同问题是控件显露时机：移动端首屏几乎全部用于操作，桌面意见目的和作用范围比正文更突出。
本次先合并一批结构改动，再做一次确认和运行修补，不增加新风格方向。

| 项目 | 实施 | 验证与边界 |
|---|---|---|
| 单页作品优先 | 页选择移入分页组；桌面使用紧凑图层导航，手机使用带状态的图层选择器 | 390×844 的真实工程副本中，画布起点约832→487，底部约728；首屏看到完整作品；标题正文保留 |
| 页面操作 | 比较、参考和缩放通过具名入口；进入比较关闭菜单；Esc关闭菜单并恢复焦点 | 同页/层/版本、缩放路由、历史比较与Esc层级继续测试；修补了展开菜单的溢出及遮挡问题 |
| 意见区 | 正文和保存优先；范围、目的和标注工具收起，草稿附属动作独立入口 | 默认仍为阅读，整页意见需明确开启；展开设置不启动标注；新入口沿用只读/加载禁用守卫 |
| 候选 | 候选与试作放在作品之后；数量和固定版本提示保留 | 固定双方比较与候选入口仍可达，不改变trial、采用或输入时效 |
| 画廊 | 图层、搜索与筛选保留；阅读方式和列数收入阅读设置 | 选择方式/列数后设置保持展开；移动阅读投影、筛选和桌面偏好恢复仍测试 |

## 检查

新增 `test_workbench_usability_browser.py` 六项真实服务浏览器场景，覆盖三个视口、图层与固定版本、
菜单/Esc/焦点、区域模式、画廊阅读设置和只读入口。现有回归只补进入新披露区的步骤，
固定版本、恢复、草稿保存、冲突和比较断言继续保留；候选位置断言按明确的作品优先布局更新。
安装后回归入口同时加载新六项，并继续审核所有模块和静态资源来自非editable安装包。

主检查：Ruff、非浏览器1231项、真实渲染52项；相关交互40项、恢复27项与新增六项定向检查。
完整浏览器和最终CI、wheel/sdist重建及安装后检查结果在本轮外部证据与PR检查中记录。
独立子 Agent 的确认没有发现阻断可用性的P1/P2；它们没有冒称重跑主 Agent 的交互门禁。

证据目录 `workbench-usability/` 保存在仓库外，包括固定基线代理、同页同层截图、组合对照、
原生截图、测试日志、包摘要与安装来源。视觉对照方法和五类保真检查见根目录 `design-qa.md`。
曾发现不匹配缩放的原生基线截图，归入rejected，不用于通过结论。

本轮不增加模型调用、不重做真实整稿，不修改API、对象、schema、writer、请求摘要或安装激活机制。
版本仍为1.0.0.dev2，PR仍为Draft。工程收口不替代用户对最终UI和实际风格样例的确认。
