# 审阅发现连续性：本次 UI 实现与 #186 边界

本轮负责已有固定审阅记录进入 UI 后的范围交接，不将 #186 的外部专业报告闭环冒充已完成。

## 已实现的最小依赖

- 审阅页显示记录总发现数、当前定位数，以及逐项问题身份；明确通用通过不等于原发现关闭。
- 范围交接草稿仍绑定完整 `review_ref`（路径与 SHA）、阅读 revision、finding_id、source_index、page_ref、element_refs 和 repair_layer。
- 新草稿同时保留该记录全部 findings、subjects、targets 与 reviewer evidence ref。选中的一项仅列在 `selected_source_indices`；集合的初始复核状态为 `not_run`。其他项不会因本次进入编辑被移除或判为解决。
- 这些数据是个人交接记录，不是新的专业审查、不触发派发，也不取代核心逐 finding 的关闭规则。已存在的草稿保持原内容，不静默补写或改签。
- 核心继续要求同一固定审阅的显式替代、同一发现和相关当前产物。通用 pass、漏掉剩余 finding、另一份同名 finding 都不能形成关闭证据。

## 尚属 #186 的能力工作

| 所属 | 尚需完成 | 可观测验收 |
| --- | --- | --- |
| 外部专业报告 producer | 将真实 Host 审阅放入标准 external_review_report，完整保留报告身份、源产物 SHA、六项发现及其期待/实际/影响/责任/验收条件 | 两份各含 R01 的报告可明确区分；机械读取的 reviews=[] 不伪装成专业完成 |
| Master 返修入口 | 有合法绑定时沿用现有 review.bindings/import；无法绑定时保存项目外的固定返修验收集合 | 只读审阅不初始化或写入项目；修复只作用于已授权范围 |
| 定向复核与交付 | 每项对正确层级实际复查，分别返回 fixed/open/accepted_variance/not_run | 六项修复中 F1 仍开放时，通用前审通过不关闭 F1；视觉结论必须看最终实际产物 |

上述能力未在这个 UI 批次新增公共命令或重建审查状态机。它们归 #186，不能由本文、草稿元数据或 UI 截图关闭。PR 中需明确列为未解决依赖，不声称完成外部专业报告的端到端验收。
