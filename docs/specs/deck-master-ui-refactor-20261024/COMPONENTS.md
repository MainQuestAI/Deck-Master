# 组件与 Token 治理

## 1. 减少的是类型，不是可发现性

常驻执行控件只保留黑主按钮、白底有边界次按钮两类；危险是语义修饰，仅用于真正破坏性动作。IconButton是按钮的紧凑形式，不额外创造一套颜色。导航、分段切换、链接、状态各自有独立语义，不能都叫“文字按钮”。

| 元素 | 默认视觉与尺寸 | 何时使用 | 何时禁止 |
| --- | --- | --- | --- |
| Button primary | 黑底白字、36px、13/20、水平13px、圆角6 | 当前工作上下文下一主动作 | 每行/每卡各放一个；把无对象的“继续”当主动作 |
| Button secondary | 白底可辨边界、32px、13/20、水平11px | 次操作、明确工具动作 | 透明无轮廓的大字号字串 |
| IconButton | 32×32；18px图标；触控44×44 | 上下页、关闭、更多等熟悉命令 | 无名称；只靠悬停出现；陌生业务动作用图标猜 |
| Object link | 标题文字、持续下划线或明确链接样式 | 进入页面/来源/版本等对象 | 执行保存、删除、采用 |
| Nav item | 36px，选中背景与字重，稳定区域 | 工作面导航 | 冒充黑色业务主行动 |
| Tab / Segment | Tab下划线；Segment容器内单一选中 | 同对象局部视图 | 与阶段执行、对象状态混放 |
| Status | 12/18，文字+小标记；不具按钮外观 | 已保存、待核对、已返回等事实 | 只用颜色；所有状态都大胶囊；可点击却无语义 |
| Field | 持久标签、14/22、44px输入、错误近字段 | 真实编辑 | placeholder代标签；阅读时全量表单 |
| Row / Table | 最少64px，16px横向留白，状态/菜单列固定 | 有可比字段的对象集合 | 每行塞4–6个等重命令；用假grid破坏Tab |
| Drawer / Dialog | 440px短编辑，500px短对话，宽编辑约880px | 边界明确的任务 | 所有详情都模态；双图/长差异被挤窄 |
| Notice / Empty | 局部持久信息+一个恢复动作 | 等待、失败、未知、空与无结果 | 只给toast；失败清空原输入 |

上述尺寸是桌面视觉规则，触控尺寸由媒体特征与实际命中区域共同保证。命中框不能靠重叠外扩偷满足。默认菜单项至少32px，触控44px；常驻动作间12px、不同动作组24px，切换组内部可8px。控件不能继承正文1.65行高后随机变高。

## 2. 状态与组合必须一并定义

按钮：default / hover / active / focus-visible / disabled / busy。忙碌保持原位置和宽度，文案表达进行中；禁用保留原因，不能只降低透明度。焦点2px、偏移2px，不用仅颜色变化表达。错误恢复沿用同一按钮，而非新增“特殊红色大按钮”。

表单：empty / filled / focus / invalid / readonly / disabled / saving / conflict。只读可选中复制，禁用说明原因。错误关联字段，保存失败保留值与光标意图。

菜单：关闭/打开/边缘翻转/不可用项；主表行不裁切浮层。抽屉：初始、草稿、校验、保存中、未知、冲突、宽编辑；背景与焦点规则由模态性质决定。表格：零选/部分选/全选/筛选外选中/混合资格；筛选变化不清除有效选择。

组件例外需具体到用途并登记，不允许以页面名再复制一组按钮 CSS。每个组件一个样式所有者；工作面只拥有排列、宽度与响应式，不改组件基本字号/行高/边框语义。

## 3. Token 分层

r2 草案的99项 token与58旧变量映射作为迁移输入，数量不是完成指标。本方案不再为了“系统性”制造更多同义变量；先证明每项职责和所有引用。

| 层 | 负责什么 | 例子与约束 |
| --- | --- | --- |
| 基础值 | 有限色阶、间距尺度、字号/行高、圆角、时长 | 色值可追溯；不让业务组件直接任意挑基础色 |
| 语义角色 | 阅读面、工具面、文字层级、动作、状态、焦点 | `--dm-color-action`、`--dm-type-size-reading`；这是组件应消费的接口 |
| 组件配方 | variant、size、状态、内边距、图标/标签对齐 | Button/Field/Menu统一配方；不逐屏写“overview-button” |
| 场景布局 | 栏宽、阅读行宽、比较列、页画布比例 | 40rem阅读宽度共享；局部几何按场景管理，不全提升为公共token |

`--ui-*` 仅为参考样本的语义别名，产品采用 `--dm-*` 或实际工程统一命名后不得永久保留两套平行真值。JSON为规范数据，CSS为消费产物，组件规则引用同一语义值；工程阶段验证二者一致。

## 4. 核心视觉尺度

| 角色 | 数值 |
| --- | --- |
| 工作底 / 阅读面 / 工具面 | #F4F5F6 / #FFFFFF / #F7F8F9 |
| 主文 / 次文 / 辅文 | #1B1F24 / #505760 / #68717C |
| 主动作 / 常规边界 / 控件边界 | #191C20 / #E2E5E8 / #8B929B |
| 成功 / 待处理 / 错误 | #24694D / #8A5A1E / #AC352C，必须配文字 |
| 页面 / 区域标题 | 24/32/600；18/26/600 |
| 阅读 / UI正文 / 操作 / 辅文 | 16/28/400；14/22/400；13/20/500；12/18/400 |
| 间距 | 4、8、12、16、20、24、32、40、48；2/6用于微对齐 |
| 圆角 | 控件6、面板10、浮层12；不将全部对象胶囊化 |
| 图标 | 24单位viewBox、1.75线宽、常用18px渲染；同一族 |
| 动效 | 120/180/240ms；只表达反馈与层次；reduced-motion关闭非必要动效 |

系统字体沿现有本机无衬线回退，不加载在线字体。等宽仅用于身份/原始数据/必要命令；不把所有辅助信息设计成代码面板。

## 5. 迁移治理

第一批先冻结各工作面 computed style 与按钮分类；标记旧变量“沿用/映射/待查/可退役”，不能因一次搜索没引用就删。根 DESIGN 的44规则、截图断言、组件规范须在同一实施批次明确变更，不靠叠最后一层CSS掩盖冲突。

每次迁移一个组件或工作面，同时迁出其旧覆盖；只清理已证明被替代且引用清零的声明。不得删原稿、历史记录、用户资产和旧版本证据。新样式不能影响未迁移工作面；如需临时作用域，写清撤除批次，避免永久双主题。

本轮输入可下载：[Token JSON](design-tokens.proposed.json)、[Token CSS](design-tokens.proposed.css)。这些仍是草案，不声称已覆盖产品实际全部 computed style。
