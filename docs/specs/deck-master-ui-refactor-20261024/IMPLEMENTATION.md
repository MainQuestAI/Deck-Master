# 实施顺序与验收合同

## 1. 实施入口

此文档是拟实施方案，不是开工或发布记录。本轮只读产品代码；没有同步分支、应用补丁、改安装、运行客户生成或创建PR。产品改造须在用户确认进入实施后开始，保持已有 repair-only 基准的关闭责任。

启动时重新核对远端主线、活动安装模块/BUILD_ID、实际Web入口和资源指纹，并固定一份实施 SHA。当前已读本地是 `92e9f567`，现场远端是 `afcc23d1`；不能把二者的测试结果混用。PR184核验时未合并，其两条开放审查（补丁持久来源、恢复操作覆盖）需并入实施前置。新增 #186 需明确负责卡，不默认为现有某卡已包含。

## 3. 实施技术边界

继续使用现有原生 ES Modules。Studio复用v2业务模块，初始9张CSS加动态比较样式；先确定入口和级联所有权，不能只改某一个tokens.css或复制原型app.js。dom.js按钮适配器先保兼容，再按语义显式分类；未迁移页面有边界，迁移完成移除临时兼容。

不得更改不可变原图原则、候选资格、原operation重放、暂停门禁、晚回包保护、固定版本与导出门禁。任何真实缺口进入已有RP/B责任，视觉PR不夹带后端重写。历史/比较、输入/草稿、当前版本/所选版本必须继续分离。

回退以代码批次为单位，保持数据合同兼容。若新增个人视图状态，使用既有恢复机制和版本化读取；不能把关闭抽屉当删除草稿。移除旧样式前核对入口和引用，不能删除用户文件、生成稿或历史资产。

## 5. 五条完整任务与证据分层

冻结实现后，用同一合成项目连续完成：①创建并补材料；②阅读、调整顺序和正文；③选页制作并交接；④比较候选并采用/保留；⑤固定版本检查与导出。每条记录起点对象、动作、返回状态、产物与用户可见反馈。故障路径附加丢响应、基准冲突和取消晚回包。

| 证据层 | 通过意味着什么 | 不能替代 |
| --- | --- | --- |
| 文档与静态检查 | 范围、引用、组件规则和源文件可审查 | 浏览器运行/真实行为 |
| 隔离原型 | 示例布局和指定本地交互可用 | 产品合同、持久化、真实生成 |
| 同SHA工程测试 | 实际模块行为满足被测条件 | 最终安装/Host/用户认可 |
| 实际浏览器与合成项目 | 当前服务的页面和链路行为成立 | 真实外部制作工具与交付质量 |
| 冻结安装/真实工具/导出 | 对应产物与工具层验证成立 | 专业内容和设计批准 |
| 用户认可 | 本次产品体验与交付被接受 | 未来版本自动通过 |

每层记录 PASS/FAIL/BLOCKED/NOT_RUN。已知缺项必须可见；不得用其他SHA、其他安装、历史通过数填绿本次清单。已有回归文件与模块见ENGINEERING，不为纯数值替换增加复述实现的测试。
