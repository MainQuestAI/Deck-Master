本包修复了一个实际读取问题：1500 个候选和 1500 个冻结请求会挤出页面/任务共用的缓存，导致每次轮询重新读取完整记录。现在将简短身份/关联信息独立缓存，不保留请求正文；每次读取仍检查对象路径与文件签名，损坏或替换后缓存失效。附加回归在热读取后破坏冻结请求，确认 UI 仍报告不可读。复核又补齐冻结请求的 schema 类型检查：损坏关联若误放同任务/同项目/同页的候选头，也不能宣称请求已记录；第二个回归覆盖这项误判。前份候选的长跑因此中止，保留中间样本但不计为正式通过，最终从本候选重新完整计时。引用语法缓存只缓存短字符串，不缓存文件存在或完整性；HTTP JSON 改为紧凑编码。

验收脚本同步当前控件、折叠正文编辑、正常 Tab 顺序和旧入口拒绝结果；显式接受系统 Chromium 路径。全部业务断言及 250 ms / 2 s / 20 分钟门槛保留。summary 门超标现在返回失败退出码，避免原脚本只记录 `passed:false` 却退出 0。
