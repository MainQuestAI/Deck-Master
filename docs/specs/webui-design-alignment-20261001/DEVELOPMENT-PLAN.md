## 审查结论

方向可采用，但原方案尚不足以直接执行。批量操作、聚合待办、个人偏好和测试门禁需要先明确契约。视觉层继续沿用最新收讫设计；生产数据、版本与事务语义不以原型模拟行为替代。

| 级别 | 核对到的不足 | 计划修正 |
|---|---|---|
| 高 | overview 的 `needsWork` 包含提示词缺失、待核实等状态，不能代表允许生成；选页当前不消费 | 把“待处理筛选”和“某动作可执行对象”分开，逐动作判断；明确排除页及原因，不能静默缩减选择 |
| 高 | workbench `_assemble_actions` 会聚合多个事实；单一 destination 无法表达多个候选/跨页正文变更集 | 采用“单对象直达、多对象列表”的目标解析；先保留聚合事实关联，再实现 UI 跳转；固定 revision，不选第一项冒充全体 |
| 高 | summary action schema 与 ui_position schema 都是 additionalProperties=false | 新读能力显式协商；总览偏好独立 schema/存储，不直接塞进旧 position；旧核心降级只读或会话态 |
| 高 | 偏好方案未覆盖 B05 个人状态清理和多窗口并发 | 新偏好必须纳入清理范围/备份/冲突处理；业务选择与提交收据不进入普通偏好 |
| 高 | 新浏览器测试允许缺 Chromium 时 skip；现有 unit job 不保证安装浏览器，render job 只跑指定旧验收脚本 | 设显式浏览器门禁，安装浏览器并执行新测试；验收任务中缺工具必须失败或明确 unavailable，不能用 skip 当通过 |
| 中 | 把真实 Host、最终安装、长期压力全部放在末尾，会晚发现环境与协议问题 | 开工即确认工具/材料与可复现基线；功能冻结后在同一候选包进行最终验收；外部条件不阻塞独立 UI 工作 |
| 中 | 只对总览做了十视口核对，无法代表七个工作面响应式和异常恢复都通过 | 增加全工作面桌面/窄屏检查与高风险状态矩阵；保留完整十视口总览门 |

核对源：`workbench.py::_assemble_actions`、`overview.js::{actionRoute,matrixPanel}`、`trial-actions.js::openCandidate`、`candidate-desk.js`、`ui_journal.py::{save_position,CLEAR_INPUT_KEYS}`、`workbench-summary.v1.schema.json`、`ui-position.v1.schema.json`、`.github/workflows/rebuild.yml`。以上是源码与方案审查，不是新一轮完整视觉或安全审计。

## 开发范围与顺序

一次一个活动任务包。每包提交核心/HTTP/浏览器适用证据，经评审后进入下一包。不重新实现已有 changes、candidates、style recipe、BusinessOperations 收据恢复或图像池。

| 包 | 目标 | 前置 | 主要交付 |
|---|---|---|---|
| U00 | 建立可复现验证基线 | PR83 当前代码 | 测试运行环境、浏览器必跑门、准确未通过项、PR83 合并前核验 |
| U01 | 待办直达正确对象 | U00 | 动作目标解析契约、固定版本目标列表、候选/任务/页面精确导航 |
| U02 | 总览批量操作闭环 | U01 | 动作级选页、批量计划/确认/交接、风格目标传递 |
| U03 | 总览阅读偏好恢复 | U02 | 独立个人偏好 schema、读写与清理、跨页/刷新恢复 |
| U04 | 风格与内容工作面设计收敛 | U02、U03 | 风格渐进布局、目标缩略图/搜索、材料影响摘要与产品文案 |
| U05 | 七工作面集成与异常验收 | U01–U04 | 浏览器交互矩阵、响应式/键盘、版本/收据/历史/恢复链路 |
| U06 | 最终候选安装与真实制作验收 | U05；材料/环境就绪 | 同包安装摘要、三用途导出、压力/回退、真实 Host 与 30 页证据 |

U06 的材料、真实制作工具及长跑环境准备从 U00 开始跟踪。材料缺失时照常推进 U01–U05，但 U06 的真实层保持未完成。实际 HOME 迁移与真人观察保留为用户执行项。PR83 合并前可在其分支做准备，后续功能 PR 以其最终合并 SHA 为基线，避免依赖漂移。

## U00：验证基线与入口收尾

- 明确支持的 Node 版本/命令：解决实验参数兼容问题，执行实际模块测试，不能直接删除参数或跳过用例。
- 在验证环境补齐 rsvg-convert/soffice/pdftoppm 与所需字体；缺失要定位到对应层，不把环境故障统称代码失败。
- CI 显式安装 Chromium 并运行 `test_ui_design_browser.py` 与安装包 UI 验收；本地可跳过，发布门不能跳过。
- 核对 PR83 的根入口、新版资源、旧地址 404、CLI 旧选项拒绝及暖构建无旧 UI 残留。

验收：U00-1 Python 3.11/3.12 单元结果可复现；U00-2 渲染组单独有结论；U00-3 浏览器组确实执行、缺浏览器不能绿灯；U00-4 记录基线 SHA、命令、工具版本、退出码和已知失败，不使用“56 个定向通过”代替全量结论。

## U01：待办目标解析与导航

接口设计先落 `INTERFACES.md`，再落 schema、服务和前端。建议新增 `action_targets.v1` 读能力及固定版本解析端点，例如 `GET /api/actions/<action_id>/targets?revision=…&limit=…&offset=…`，路径在实现评审时冻结。

- 保留现有 summary 的轻量聚合及 action_id，不把所有成员对象塞进轮询 summary；解析端点复用同一快照中的事实关联，不解析 hash 猜类型。
- 响应明确 `project_id/revision_id/action_id/total/targets`，目标按 kind 区分 task、page_layer、candidate、content_changeset、content_reconciliation、review；业务 ID 与页面 ID 分开。
- 单目标直接打开；多目标进入固定版本列表，显示各自页/层/状态。整稿变更集进入变更集比较，不硬塞到没有 page_id 的单页路由。
- 路由继续保留 project/revision/page/layer/task/candidate；需要新增变更集路由时同步校验器。旧核心没有 capability 时提供明确通用入口，不能冒称精确直达。

验收：U01-1 聚合待办不漏成员、不重复；U01-2 单任务/单候选/跨页变更集分别正确落地；U01-3 同标题页、跨项目链接、对象缺失/损坏/旧 action 均有明确反馈；U01-4 历史链接保持固定版本且不写业务；U01-5 300 页样本 summary 不因目标解析膨胀为全历史读取。

## U02：批量计划、确认与交接

第一版范围限定为：原图试作、SVG 重建/修复、把所选页带入风格校准。正文结构变更及 PPT 装配保留既有专用路径，不混成一个“全部生成”按钮。

- `needsWork` 只做筛选。选择具体动作后按 effective_actions、项目格式、只读/历史、必需输入及未知执行/收据状态确定可操作页。
- 当所选页不能全部执行时显示排除清单；用户必须明确调整范围后重新预览。不能自动挑第一层、自动忽略页面或静默改动调用上限。
- UI 收集目标页/层/阶段与短要求，复用 changes plan/commit。确认页展示服务端返回的范围、固定基准、引用、调用上限和下游失效项。
- 提交统一走 BusinessOperations；保持同一 operation_id 的结果核实和重放。复制交接不改变 running 状态，不自动调用模型。
- 风格校准只传固定参考及目标选择；到达风格面后仍需确认参考、单页试作、采用后扩展。

验收：U02-1 混合可操作/受限页有完整解释；U02-2 提交计划目标与最终确认范围一致；U02-3 筛选/输入/版本变化使旧计划失效；U02-4 重复点击、丢响应、未知收据不产生重复任务；U02-5 取消/迟到结果不覆盖当前稿；U02-6 刷新不自动恢复待执行选择或触发生成。

## U03：个人阅读偏好

新增独立 `ui_overview.v1` 个人记录及 capability，不扩展严格的 `ui_position.v1`。记录项目身份、阅读版本、搜索、筛选、排序；采用与现有 GalleryMemory 相同的版本冲突/CAS 约定。存储限制大小和版本数量，避免每次轮询产生无限历史。

- 恢复优先级：显式有效 URL → 当前项目/固定版本已保存偏好 → 默认值。新版阅读基准不自动继承旧版业务选择。
- 不保存勾选页、执行计划或 operation_id；这些继续由既有业务草稿/收据协议管理。
- B05 清理计划、备份与提交必须覆盖新偏好；只读示例和本机存储失效遵守既有个人状态边界。

验收：U03-1 刷新/跨工作面返回可恢复；U03-2 跨项目/跨版本不串数据；U03-3 损坏数据、并发修改、写失败可恢复且保留当前输入；U03-4 清理后不由延迟保存写回旧偏好；U03-5 全程 Document revision、任务及调用账本不变。

## U04：风格与内容工作面

- 风格面保留“参考与目标→确认与单页试作→采用后扩展”三阶段，当前阶段展开，已完成阶段显示摘要；输入失效关系沿用现有 serial/plan 机制。
- 参考与目标增加缩略图、页码、搜索和明确计数，复用 imageView/图像池；保留缺图、失败与重试状态。不得把未选中的保留维度擅自更改。
- 内容面用“制作工具影响判断”替代 Host；摘要与大纲分层，原始依据折叠。登记、读取、影响判断、协调四态由真实来源决定。

验收：U04-1 30 页选择在窄屏仍可操作；U04-2 改参考/目标/要求后旧计划不可提交；U04-3 清空要求后刷新仍为空，不被默认文案覆盖；U04-4 离开工作面释放图片与请求，迟到响应不覆盖新状态；U04-5 来源缺失不显示已解析/已协调，关键错误有内容保留说明和下一步。

## U05：整合验收

覆盖项目入口、总览、内容、画廊、单页、风格、任务交付七个工作面。桌面 1280×800、1440×900，窄屏 390×844 全覆盖；总览保留十视口几何门。检查真实 DOM/点击结果与截图，不以字符串锚定替代运行回归。

验收：U05-1 所有关键操作键盘可达、焦点可见/返回正确；U05-2 没有整页溢出，局部表格可滚动；U05-3 断连/损坏对象/旧核心/只读示例/固定历史明确呈现；U05-4 未知保存、冲突、候选保持/采用、取消迟到链路无重复写；U05-5 正文变更集与图像候选分型正确、当前版本不被浏览行为改变；U05-6 给出逐工作面设计差异单，标明保留的生产适配与未验项。

## U06：最终候选与真实证据

冻结同一 SHA，构建 wheel/sdist 并记录摘要，在隔离目录安装后验证 UI 与核心。先完成工程层，再区分真实层与用户执行项。

验收：U06-1 wheel/sdist 重建、品牌与模块完整、无旧 UI 残留；U06-2 安装环境完成 review/delivery/engineering 导出及历史固定下载，delivery 缺门时正确拒绝；U06-3 300×5×3 样本按既有 W12 长跑门槛复测，不降低门槛或以短跑替代；U06-4 隔离前缀完整版本回退，避免旧核心写入不兼容的新格式；U06-5 获准真实 30 页项目完成两轮修改，关联请求/调用/候选/采用/质量记录；U06-6 HOME 迁移、macOS 目录选择与真人 30 秒观察分别取得证据才关闭。

## PR 拆分与完成标准

- PR83：当前设计对齐与旧 UI 移除；本计划作为后续开发入口。
- PR-U00：工具链/测试执行门禁；不夹带功能。
- PR-U01：聚合动作目标解析及前端导航（契约与消费者同包）。
- PR-U02：批量操作闭环。
- PR-U03：偏好与清理集成。
- PR-U04：风格/内容界面细化。
- PR-U05：集成缺陷修复与浏览器验收证据。
- PR-U06：最终候选验证与必要修复；缺外部条件时只提交工程层证据，真实层继续 open。

每包以对应 AC 为退出条件，提交适用的核心/HTTP/浏览器测试和 SHA 绑定证据，评审无高优先级阻塞项后合入。测试修复不得通过删除断言、扩大 skip 或模拟生产成功达成。计划不承诺本机/材料条件尚未具备的完成日期；实施估算在 U00 核对环境、U01 冻结契约后更新。
