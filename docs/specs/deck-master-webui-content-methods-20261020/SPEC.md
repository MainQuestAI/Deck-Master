# 开发 Spec：PR127 后续 Web UI

版本 v1.0｜2026-10-20｜状态：READY_FOR_BASELINE_RECHECK / IMPLEMENTATION_NOT_STARTED。

## 1. 产品目标

PR127 把方法、案例和校准资源接入实际生产链。本轮把这些能力的依据和产物接入已有 Web UI，让用户完成三个动作：

1. 了解一项任务用了什么依据、为何受阻、应该如何接续。
2. 在逐页制作前读懂核心回答、理由、条件与替代，作出有对象、有版本的方向决定。
3. 从具体正文或审阅问题回到证据和允许的修改范围，比较并采用后续结果。

本轮不以新增模块数量或方法使用次数衡量成效。没有实测前不承诺质量提升比例。

## 2. 确定范围

| 原报告功能 | 本轮交付 | 开发卡 |
|---|---|---|
| UI-01 方法依据与恢复 | 任务详情中的冻结资源、当前可用性、具体缺口及既有恢复入口 | WU01、WU02 |
| UI-02 论证主线与比较 | 当前/待选论证阅读、两份真实方向比较、复用决定与采用事务 | WU01、WU03 |
| UI-03 正文—论点—证据 | 单页对象到论点、条件与来源的固定版本联动 | WU01、WU04 |
| UI-04 审阅定位与局改 | finding 阅读、实际定位、明确范围的修改草稿和原流程交接 | WU01、WU05 |
| UI-05 用途与表达 | 中性用途文案、可选要求示例；保留现有阅读方式与约定产物 | WU06 |
| UI-06 方法选择与案例 | 注册目录的只读浏览、合法依赖预览、为制作工具准备选择要求 | WU07 |
| UI-07 内容到设计 | 从既有 content_requirements 展示本页职责、必须保留的条件与关系 | WU04、WU06 |

**高级选择的明确边界：**本轮网页可准备方法选择、预览示例并复制制作要求；实际派发仍交给制作工具调用 PR127 的有界接口。页面不向已冻结任务补卡，不增加浏览器自动派发、取消重发或脚本执行按钮。此选择是个人准备稿，直到实际任务 manifest 回读一致才可称“已用于本任务”。

该边界使 UI-06 可交付且保持与现有“复制不启动执行”一致。未来若要网页带参派发，需要另行设计精确基准检查与断线恢复；它不属于本轮完成条件。

## 3. 迭代组织

### 增量 A：读懂内容与修订依据

WU01–WU05：有界读模型、任务依据、论证阅读/采用、正文证据、审阅交接。先解决用户必须打开 JSON 才能理解制作结果的问题。

增量 A 收口必须能演示：经营诊断的论证阅读、方案选择的方向比较、教学稿的具体审阅定位；成功、无记录、依据变化、对象不可读与写冲突均可解释。

### 增量 B：准备要求与设计交接

WU06–WU07：用途文案、设计语义说明、方法/案例准备。使用增量 A 的固定版本和只读组件，不建设另一套资源工作台。

### 集成收口

WU08：从最终源码构建独立安装，运行浏览器主路径、范围回归、历史读取与跨版本恢复，记录实际 Host 验证和人类体验反馈的独立状态。

两段均属于本轮范围，不能在只完成 A 时宣称整轮完成。每段可用独立 PR；不预占 RC6 或正式产品版本号。

## 4. 保留与非目标

- 保留项目入口、五工作面、单页链、现有稿件与不可变历史、候选/授权/额度/决定分离。
- 不重做渲染引擎、SVG→PPT、上传、导出或口播稿入口；这些能力只回归相关路径。
- 不新增十个方法菜单、自由论证图编辑器、方法评分、证据业务库、审批台或第二个正式内容计划。
- 不把案例资产登记成客户来源；不自动将客户输出回流到公开库。
- 不要求每个观点都有完整映射：缺少记录时仍能读正文，并明确未记录。
- 本轮无需修改 Narrative/Page/Review 的持久 schema 即可表达主要功能。若实施发现确实不足，先提出精确差距及兼容补充，不向已有严格 schema 私塞字段。

## 5. 设计和工程原则

沿用 [DESIGN](../../../DESIGN.md) 与 [产品 UI 语言](../../design/webui-opendesign-20261001/product-ui-language.md)。浅色、黑色主按钮、无衬线、业务对象优先；原始 ID/hash/JSON 仅放对应对象详情。

同一阅读对象始终绑定 project identity、revision、Ref；“读取当前”解析到明确版本后再请求其子对象。自动轮询不得把正在比较或阅读的内容换成新版本。

所有读投影复用 Store、snapshot、资源 resolver 与已有语义校验。GET/预览不创建任务、消耗额度、执行脚本或提升 writer floor。写动作由现有事务执行，浏览器不直接写对象。

方向决定和采用是两个已有持久动作。一个交互可以编排两步，但必须正确展示部分完成、复用原操作 ID 和核实原回执。不得通过新“确认”字段隐藏中间状态。

## 6. 完成条件

- 50 项 AC 各有唯一开发卡负责，执行记录可以是 PASS/FAIL/BLOCKED/NOT_RUN；只有有证据的项目才置 PASS。
- 全部本轮工程 AC 通过，最终安装包包含所需静态文件，源码与安装运行同一行为。
- 实际 Host 案例覆盖与专业内容质量分别报告，不能拿模拟数据或 RC5 文字探针代替 Runtime 写入验收。
- 人类认可未发生时保留 NOT_RUN。工程可完成并提交体验验收，不宣称用户已接受。
- 合并、发布和真实 HOME 激活不由本 Spec 自动授权；本轮文档制作也不启动实施。
