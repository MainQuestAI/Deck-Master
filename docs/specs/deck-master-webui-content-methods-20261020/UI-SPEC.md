# 页面级开发规格

本文件描述目标行为；不是当前 UI 已支持的声明。接口与操作边界见 [API-SPEC](API-SPEC.md)。

## 1. 页面清单

| 页面/区域 | 改动 | 默认展示 | 主要动作 | 原有功能保留 |
|---|---|---|---|---|
| 项目新建 | 用途文案及可选示例 | 名称、用途、受众、约定产物、阅读方式 | 创建项目 | 完整稿导入、保存位置、恢复 |
| 内容与来源 | 新增“论证主线”子区 | 当前主线/可读待选方案；无主线时说明 | 阅读、比较、采用方向、返回大纲 | 材料、页序、章节/页面职责 |
| 内容与来源/方法准备 | 渐进展开高级区 | 关闭；用户主动展开才加载 | 选方法、预览示例、复制要求 | 不改变当前任务 |
| 单页/逐页稿 | 正文对象到依据联动 | 原正文；有映射对象显示可达入口 | 查看依据、返回审阅问题 | 阅读、编辑、标注、口播 |
| 单页/来源抽屉 | 论点、条件、来源组合 | 被选对象的真实记录 | 看材料、看主线 | 固定来源版本 |
| 单页/预备提示词 | 内容到设计的只读摘要 | 现有提示词；语义说明折叠 | 看必须保留项、提出内容修改 | 实际提示词与原图等独立 |
| 任务与交付/任务详情 | 方法依据区 | 摘要；异常自动展开一次 | 核实原任务、复制接续要求 | 调用、取消、结果、交接 |
| 任务与交付/质量记录 | 可定位 finding 列表 | 状态、审阅范围、具体问题 | 定位、准备局改 | 原审阅身份、完整依据、交付判断 |

不新增第六个顶级工作面；任务方法是任务详情，不做全局“方法执行看板”。研究原文不进入主导航。

## 2. 通用状态、版本与导航

| 状态 | 用户表达 | 行为 |
|---|---|---|
| loading | 正在读取这版记录 | 保留旧内容并标识读取中，禁用针对新对象的动作 |
| ready | 展示事实 | 不自动提升检查状态 |
| absent / not_recorded | 这版未记录… | 继续读已有稿件；不自动生成缺项 |
| partial | 部分记录暂不可读 | 完好部分可读，错误贴近损坏项 |
| unreadable | 这份记录暂不可读 | 重试同一引用/返回；不替换成当前版本 |
| historical | 正在阅读历史版本 | 只读；固定内容不漂移 |
| basis_changed | 当前内容与这份记录的依据不同 | 保留原文；核对当前再规划 |
| capability_missing | 当前核心暂不支持此项 | 保留原有阅读能力；禁用对应新动作 |
| conflict / unknown_operation | 版本已变化 / 提交结果待核实 | 保留原 payload、UUID、选择与文本 |

不可读分支只展示已验证 Ref 与 issue，不编造标题、成熟度、Review 内容或空问题清单；按照 API 的判别 union 消费 null。

固定历史不是“错误”；旧资源在当前安装缺失也不等于旧任务从未执行。

路由新增参数均为本轮拟增项：

- 内容子区 `content_area=materials|plan|argument|methods`。
- 主线选择 `proposal=<sha256>`，对照 `compare_proposal=<sha256>`；仅 `surface=content&content_area=argument` 合法。
- 原子定位 `atom=<atom-id>`；仅单页 content/source 层，或质量记录跳转到该层。按真实 atom 合同校验，长度上限 256。
- finding 定位 `finding=<finding-id>&review_sha256=<sha256>&finding_index=<source_index>`；必须连同 revision 和既有 review_id，仅在质量记录路由合法。服务端解析合法完整 Review Ref，核对原数组索引与 ID；缺失、越界或不匹配显示定位错误，不默认首项。不接受路径，不新造持久 finding ID。
- 所有新对象链接必须有 `revision`；查询 SHA 只定位服务端已证明可达的 Ref，不接受路径。

沿用原有 project identity 和 action/candidate/review/task 互斥校验；新参数不能绕过原规则。跨页保留返回上下文，刷新可恢复同一对象。无效参数显示局部错误，不静默选第一条。

## 3. 任务方法依据（UI-01）

在 `run-desk.js` 任务详情中，放在“制作要求与执行身份”之后、“结果与实际调用”之前。

正常摘要：“本任务固定了 N 项方法与参考资源”。N 来自冻结 manifest；历史无 manifest 时不套当前默认值计数。

展开后列：名称、用途类型、本次可用性。名称优先取经过同 release/hash 核对的元信息；无法核对时显示冻结 ID，并注明“名称未记录”。不在主层直接显示本地绝对路径。

异常摘要：“本任务的 N 项依据需要核实”。展开显示缺失/字节变化等真实原因。资源版本和 hash 放“技术依据”内。

两个事实分开展示：

1. **任务派发时固定的依据**：来自所选 revision 的 Task。
2. **当前安装能否提供这些字节**：带实际检查时间，是现在的可用性观察，不写成历史当时的状态。

“核实原任务”只读。接续按钮只有核心已有动作允许时出现；未知调用先核实/结算，不提供自动重试。用户仅展开详情不触发 continue。

## 4. 论证主线（UI-02）

### 阅读

内容区子导航使用“材料与要求 / 页面大纲 / 论证主线”；方法准备是次级展开入口。

主线区依序呈现：

1. 交流任务：受众问题、希望形成的理解/判断/行动、阅读方式。
2. 核心回答：central_node 指向的原句；framing 无核心回答时如实显示阶段。
3. 关键理由与条件：节点原文及关系，不用模型再总结一份。authority 翻译为“材料事实/推断/计算/建议/目标/假设/操作说明”。
4. 未决问题：question、impact、resolution；允许“接受限制”，不能被 UI 擅自改成 resolved。
5. 业务替代：description、benefit、cost。明确标题“可行替代与取舍”，不冒充待选叙事稿。
6. 对应计划职责与页面：读取固定 Plan Ref 的 input.page_roles；已绑定才跳转真实 Page，planned 职责没有 Page 时显示“尚未产出页面”，page_ref=null；无真实计划关联显示未记录。

没有 Page 的 plan_only 仍能阅读 Narrative 和 planned Plan。当前 Plan 复用固定 revision 的 /api/content-plan；候选 Plan 从 API 的 plans 投影按 narrative_ref 精确关联。比较两方向时分别展示其真实 Plan，缺失/不可读不借用另一方的计划，不创建第二计划。导入稿没有 Narrative 时显示“这份导入稿未记录论证主线”，仍可读页面大纲、正文和来源。

### 比较

选择器分组“当前采用 / 本请求待选 / 历史记录”。同一比较最多两份；固定左右 Ref 和 revision，左基准右待选。桌面并列，窄屏先基准后待选。

比较展示交流任务、核心回答、关键理由、条件、未决项及页面职责。用真实节点/字段差异；不得把不同 ID 的节点强行按位置认作同一观点。非同一请求来源的历史稿可阅读，但不标成同一批候选。

两份不同、可读、合法且在各自固定 snapshot 可达的 Narrative Ref 即可比较，支持 current+candidate；同 Ref、非法/不可读/不可达对象不可比较，不自动生成第二份。历史比较只读，不提供决定或采用写动作。

### 采用

仅 argument、非历史、来源合法且 can_adopt=true 时展示“采用此方向”。缺覆盖决定时 can_adopt=false，但 needs_decision=true 且 can_record_direction_decision=true 时显示“记录方向决定”，避免按钮依赖尚未创建的决定。已有有效决定复用，不重复记录；策略拒绝分别展示决定/采用的 reason_codes。framing 可读但不可采用为方向。

确认区显示所选核心回答、精确范围、会受影响的既有 Plan/结果、原稿保留方式。使用同一次明确指令记录方向决定；第一步成功后以返回 revision/decision_ref 重新读取采用准入，再执行独立 proposal adoption。决定成功不承诺采用成功，不新增方法批准。

已有有效决定覆盖同一 proposal 和范围时复用。第一步成功、第二步失败显示“方向决定已记录，采用尚未完成”，提供核实/继续原采用，不能显示成功或重复记录仍有效的决定。用户显式重新评估时，若旧决定已失效且没有有效替代，归档旧回执、解锁理由并在核心允许时提供记录新决定按钮；此动作不自动提交。有效替代 D2 则直接供下一次明确采用使用，原待核实请求保持。

保持旧比较稿不跳走，成功后提供“读取采用后的版本”。采用不自动调用 continue，不授予生图额度。

## 5. 正文与依据（UI-03）

正文默认保持原排版。已具备稳定 atom 身份的段落、条目、表格单元等增加键盘可达的“查看此处依据”；不把整段正文变成无法选字的链接。无映射仍可选字和标注。

来源抽屉分为“原句 / 论点与条件 / 来源材料”，展示 visible_links → Narrative 节点 → qualifications/edges/source_links。直接来源和经论点关联的来源分开标明，不暗示每个来源都支持所有句子。

来源全文复用 sourceReader；source_version 和 locator 保持原值。无法解析 locator 时显示原定位文本和材料入口，不伪造精确高亮。

项目 Narrative 已变化而 Page 仍绑定旧 narrative_ref 时，先显示 Page 真实绑定的旧论证并提示差异，不跳去新主线。损坏一条 source 不影响其余正文。

## 6. 审阅定位与局改（UI-04）

质量记录沿用现有 `views.js` 入口，显示实际 review.status、审阅者身份和覆盖范围。v1/v2 均完整保留 must_fix / needs_judgment / advisory、open / fixed / accepted_variance / not_applicable；仅 v1 合同未要求的 v2 扩展字段显示未记录。v1 同样要求 finding_id、impact、resolution，缺失不得伪装合法旧记录。

刷新、后退、排序与过滤保持 revision+Review Ref+finding_id+原 source_index；相同 ID 的另一 Review 不替换当前对象。

每条 finding 显示：问题原文、影响级别、实际记录、期望、已记录的证据、解决状态。`expected` 标为“期望”，不能伪称独立的改写建议。不能用模型临时补“为什么”或“建议”冒充原审阅者。

“定位正文”使用实际 page_id/element_refs。缺 page_id 的整稿问题可回主线/整稿阅读；缺 element 显示页面级定位；过期定位不在新版猜测对应句。

“准备局部修改”仅准备现有内容操作草稿，预填选中页、问题与期望；在现有计划预览中确认真实范围。只读审阅 request 下禁用写提交，提示先明确新的修改请求。speech/design/source 问题不得一律转成正文 rewrite：

- page_copy 且 scope 允许：进入原 rewrite/候选流程。
- speech/design：进入既有对应范围的制作要求；不能改正文。
- 输入事实错误：进入材料/输入修改入口。
- 无法确定修改层：只复制问题和引用，不自动猜测任务。

生成或采用修稿不自动把 finding 标 fixed。只有既有 Review 记录/接续机制明确提供的 resolution 才展示为已解决。

## 7. 用途与设计交接（UI-05、UI-07）

新建及内容区统一“用途 / 受众”，提示“这份内容要帮助受众理解什么、判断什么、选择什么，或学会做什么？”

可选示例按钮为“经营诊断 / 方案比较 / 教学讲解 / 工程评审 / 研究说明”。点击前若 brief 非空，追加可编辑提示片段，不覆盖用户文字；不写新的业务类型枚举，不改变 content_intent。表达偏好直接体现在用户可见的 brief 文本中，不隐藏结构化 JSON。

阅读方式、口播和约定产物沿用现有字段，按既定规则处理 mixed/未指定，不能擅自填成已确认。

预备提示词区增加“本页内容交接”折叠：

- page_role 中的受众问题、预期理解、页间衔接。
- required_qualifications。
- structure_refs 可解析的节点/原子关系。
- visual_intent、layout_hint、content_profile 与 density_rationale。

来源是同版本既有 content_requirements 或既有纯计算 resolver；不额外生成设计建议。字段缺失按缺失处理。正文变化须回 Content，UI 不把“太挤”变成自动删字或拆页。

## 8. 方法与案例准备（UI-06）

入口：“内容与来源 → 准备方法与参考”，默认收起。提供业务动作名称、用途、适用职责、资源类型与依赖；可搜索名称/ID，不增加方法评分或推荐概率。

上下文必须来自服务端：当前 request 的下一内容阶段，或用户明确指定的独立只读角色/阶段。若当前有冻结待办，显著提示“已有任务的依据已固定”；本轮不为该任务添加资源。

没有下一阶段、等待决定或已有冻结待办时，目录可读仍正常浏览；同时展示“当前不能派发”及具体原因。browse_status 与 dispatch_status 分开呈现；没有真实阶段时不声称选择已通过范围校验，不允许复制尚未评估的选择。所有预览均为 preparation_only，new_content_task_possible 不是派发许可。

本轮支持**新内容阶段**的准备及独立只读方法浏览，不把蓝图/修复/编译的所有自动继续分支抽象成通用派发预览引擎。非适用阶段仍可查看已经固定的任务资源。

用户选择后点“核对所选资源”，只读返回显式选择、默认项和依赖项；三者分别展示，顺序服从现有 resolver。校验失败保留选择并定位问题。

案例预览顺序 input → after → walkthrough，before 按需展开。显示“教学示例，不能作为本项目事实”；不提供导入客户来源的快捷按钮。script 只显示代码/用途，不执行。

“复制给制作工具的要求”包含用户选择、核对时的版本/阶段/范围、具体未满足项及现有 CLI/API 合法用法。明确“复制尚未应用；制作工具需重新核对当前状态后派发”。禁止生成携带任意 shell 路径的命令模板；复用核心交接格式。

个人准备稿只含项目身份、revision、选择 ID 和目录指纹，使用已有草稿机制。复制前携带 expected_basis 重新核对；资源字节或上下文变化后需重新预览，复制按钮禁用；不能把旧预览标成最新。实际使用是否成功以新 Task 的冻结 manifest 为准。

## 9. 视觉与可访问性验收

主视口 1280×800、1440×900；390×844 检查窄屏。保持正文阅读区，不用大量卡片把文本割碎。比较表局部横向滚动，页面整体不得横向溢出。

折叠区使用原生 details 或具备 aria-expanded 的按钮；弹窗和抽屉有明确标题、键盘关闭、焦点约束和关闭后焦点返回。状态使用文字与图标共同表达，支持 reduced motion。

长稿和较多资源按区块按需加载。首次任务列表不加载全库正文；方法预览一次一份，离开后取消未完成读取。所有文本/Markdown 作为不可信展示材料处理，禁止原始 HTML/script 执行。

范围交接的单次点击必须等待已在途保存及其后最新输入的保存回执；blur 与 click 共同等待 P1 后新发 P2 时，不得因 saving 状态提前返回。unknown/conflict 保留草稿并阻断导航，不自动重放。
