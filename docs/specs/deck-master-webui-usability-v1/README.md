## 实施契约

首次写入提交时间或截图状态通过正常事务提升 `workbench-quality.v1`；读旧项目不迁移。引用不可变，原图不可覆盖；新配方 v2 与现有 v1 并存。截图分析使用独立 `style_analyze` Host 任务、`visual_reference` 能力和零生图额度，结果仅保存视觉规范；Builder 使用用户确认的配方及目标正文。

图片上传为受 token 保护的二进制 POST，单图 64 MiB / 3200 万像素，PNG/JPEG/WebP。原件与派生预览分开。每个分析冻结 1–5 图及要求。多图冲突须由用户解决。v2 试作仍走现有 changes/candidates/generation，不自动采用，不引入自动执行器。

历史提交时间与项目创建时间分开，旧记录时间缺失不推算。历史分页以固定 head 为锚，相关变化按真实页对象及产物引用计算；不把接手/调用结算当页面修改。

## 工作台使用入口

“风格校准”中可以选择项目内已有页面作为参考，也可以选择“外部截图”。外部截图流程为：上传 1–5 张图，选一页试作目标，写短要求，交给 Deck Master Agent 分析；结果返回后核对参考图、七项规范与拆解图，确认借用维度和字体，再预览并提交单页试作。多张图有冲突时先明确选参考并重新分析，不直接混合。

Agent 返回候选后在单页画布旁比较当前稿与候选，使用适应窗口、100%、放大、同步平移或全屏查看局部。SVG 与实际 PPT 分开显示；实际 PPT 尚未生成、失败或缺工具时显示对应状态。明确采用样例后，才向选中的其它页面扩展；参考里的文案、数字和品牌图形不会成为目标正文。

离开工作台前检查个人草稿实际保存状态。换端口或新会话时明确恢复项目草稿；历史项目也可从“恢复项目中的截图分析与规范”选择已保存结果。恢复不会自动重派任务或采用候选。查看两次修改时进入相关历史，选定两个版本并固定比较；旧记录没有可靠提交时间时显示“时间未记录”。

完整验证见 [验收表](ACCEPTANCE.md)、[真实制作](REAL-BUSINESS-VALIDATION.md)、[独立复审](CORE-REVIEW.md) 和 [安装包复验](PACKAGE-VALIDATION.md)。用户对新版 UI / 风格样例的视觉认可独立记录，工程通过不替代它。
