## CR-01｜P2：离开风格页后，迟到的截图目录响应重新锁住图片

位置：`src/deck_master/resources/static/v2/visual-style.js:134`，固定提交 `ece47b3` 的 `loadReferences().then(...)`。

`loadReferences()` 内部在组件已销毁时返回，但正常返回会兑现外层 Promise。外层继续调用 `showTarget()`，在组件清理函数已经释放图片之后重新申请目标图片。新租约对应的 DOM 已脱离页面，此后没有清理入口；图片一直处于 pinned 状态，无法通过图片池正常淘汰。

独立复现使用真实源码 Web 服务和真实 Chromium，进入已选目标页的外部截图工作区，截住 `/api/styles/references` 的真实 HTTP 响应，切到任务记录后再释放原响应。没有修改客户工程，也没有模型调用或用 mock 图像替代请求。页面上已没有风格工作区或画布，但修前图片池从零占用变为一个未释放的缩略图租约。

| 相同延迟／离开顺序 | 响应释放前 pinned | 响应释放后 pinned | 响应释放后 thumbnails | 后续网络／解码峰值 |
| --- | ---: | ---: | ---: | ---: |
| 固定提交，修前 | 0 | **1** | **1** | 1／1 |
| `.then` 入口增加销毁判断，修后 | 0 | **0** | **0** | 0／0 |

影响：在目录慢响应与切换工作区重合时遗留图片锁；重复访问不同目标或版本可能积累不可淘汰缓存，损害长时间使用和图片池容量。单次探针证实租约泄漏，不声称已经实际填满全部 60 个缩略图槽。

修复为 `.then` 第一条执行 `if (disposed) return`，阻止销毁后创建目标图、其它页预览及后续规范读取。修前、修后使用同一个探针，日志分别为 `leak-probe.log`、`leak-probe-fixed.log`，结构化快照为 `leak-before.json`、`leak-after.json`，复现脚本为 `delayed-response-probe.py`；均保存在仓库外的核心复审证据目录。

## CR-02｜P2：跨端口恢复个人草稿后，截图分析与确认方案无法继续

位置：`src/deck_master/resources/static/v2/visual-style.js:9–13`。截图选取、试作目标、要求、分析任务 ID、确认的 recipe ID 和修改后的规则只读取／写入 origin 内的 localStorage；没有写入个人项目草稿，也没有监听草稿恢复后重新接入这组状态。`style-calibration.js:249` 的既有风格选择入口仅列 v1，不能作为截图 v2 配方的恢复入口。

## 核实的核心行为

| 路径 | 独立核对内容与结论 |
| --- | --- |
| 截图导入 | 二进制长度、真实解码、PNG/JPEG/WebP 格式、单帧、3200 万像素限制均在发布引用前校验；原始字节保留，EXIF 旋转仅产生派生 PNG。截图引用与业务页面资产分离。锁内先回执恢复再检查基线；更换相同操作 ID 的字节摘要不能复用原回执 |
| 分析任务 | 请求固定项目、截图引用、要求及字体登记；领取需 `visual_reference`。分析任务没有页面范围，外部图像调用入口明确拒绝 `style_analyze`。提交路径先校验任务状态、输入身份与迟到状态，再进入分析接收；结果不能夹带页面、图片生成、审阅或调用事件 |
| 分析结果 | 七项规则、参考区域边界、冲突来源均受活动 schema 和核心额外检查约束。拆解 SVG 仅使用显式几何、规范色值和转义后的文字。分析完成只发布规范与任务结果；Page、原图、SVG 和整稿输出不由该分支改写 |
| 规范确认与消费 | 规范必须属于当前项目已完成分析；冲突不能通过直接过滤图片后继续沿用混合规则，要求重新分析明确参考。确认重算提议并固定配方。实际生成请求使用用户确认／编辑后的规则及所选维度；目标原图在引用序列首位，参考业务文字、数字及品牌图形不进入目标正文 |
| 候选／目标新鲜度 | v2 风格任务固定目标原图引用；领取、生成和采用校验该引用。检查在内容身份快捷通过之前执行。历史候选可从固定任务恢复旧基准，不能借当前状态重写基准；自己采用后的结果只在对应采用记录及目标引用匹配时保持有效。首样例必须单页，跨页扩展依赖仍有效且已采用的对应样例 |
| Web 二进制与事务 | 二进制专用入口复用同源 Origin、Host 和 token 判断，校验在读请求体前执行；拒绝 Transfer-Encoding、缺失／重复或超限长度，原 JSON 上限未扩大。前端保留操作 ID、基线与字节摘要，检查回执身份；服务通过已提交祖先链恢复回执，不以缓存索引作为唯一已提交事实 |
| 历史 | 列表锚定固定 head，游标包含 head 与祖先位置；分页不会把新提交混入已固定的比较。相关页面／图层变化与依据变化分别投影，保留全部记录入口。提交时间来自实际事务字段；旧记录缺失时不采用文件时间或项目创建时间推算 |
| 版本与安装资源 | `workbench-quality.v1` 位于图标能力之后；图标写入判断接受更高已知版本，旧写入器不应把新字段当作兼容旧项目。旧项目读取不添加新字段，正常 v3 写入产生真实提交时间并升级边界。CLI、活动 schema、打包方法资源和唯一公共 Skill 接入同一截图流程 |
