# 真实业务副本连续修改与实际 PPT 验证

2026-10-04，本轮 Codex Host 对已有 30 页工程的独立副本执行修改。原验收稿未修改。原件、客户内容、调用记录和导出文件全部保存在仓库外；本报告只记录可追溯摘要和验收边界。

## 实际执行

1. 将已有第一页原图作为外部 PNG 参考登记，实际读取截图，返回七项视觉规则、参考区域与字体不确定说明。分析没有生图调用；核心生成拆解 SVG。该截图沿独立参考资产入口处理，未加入正文材料或页面资产。
2. 确认仅借用配色和文字层级的工程测试规范，显式指定第 2、3 页范围。实际执行第 2 页单页试作、比较、采用，再以该样例向明确选中的第 3 页扩展。候选都是本轮实际 Host 返回结果。
3. 根据新原图重新制作原生 SVG，保留全部标题、正文与业务标签。实际渲染后发现图标交叉、断行和文本超出分组的问题，通过正式审阅发现项与 repair 任务修复并关闭。
4. 第二轮修改第 2 页一处同义措辞，再生成 SVG，重新审阅。其余 29 页 Page 摘要保持原验收稿内容，第 2、3 页之外的原图与 SVG 保持原件。
5. 实际编译整稿，LibreOffice 渲染，PPT XML 回读和六维 Host 自审，按正常接口导出审阅、内部工程和正式交付三个用途。

## 调用与失败记录

本轮实际使用四次 imagegen 调用，两个合格图像候选最终采用。最初仅参考截图的试作偏离目标构图，候选保留而未采用；随后 Builder 明确传入目标原图及参考图。另一次调用虽实际发生，但工具参数的记录格式无法证明冻结参考匹配，核心以 `generation_evidence_incomplete` 拒绝接收。取消该任务后，以正常新任务和可校验参数重做。

首次整稿回读失败是 Host 在 SVG 中使用了不完整 atom 绑定，核心正确拒绝绿色检查。通过正式 repair 将绑定恢复为标准完整标识，文字与几何不变；重新编译后检查通过。调用消费、失败、取消、修复与操作回执均保留，没有删除失败或将其计为成功。
