## 1. 决策摘要

**本轮主要损失发生在材料变成论证和完整页面内容的阶段。** 原材料中的比较对象、判定条件、异常处理和管理含义，被概括成短段落；通用商务设计进一步把短段落放大为图标卡片；审阅证明了不少“内容被保留”的事实，却没有有效拒绝“正确但浅”的稿件。

建议在现有内容协作 v1.2 上做定向补强：把完整分析页和正反审阅样例放入实际运行方法，将内容结构和密度要求传入冻结设计请求，再验证蓝图、SVG、PPTX 是否保留关系、层级与可编辑信息。备注交付同步补齐。

这次迭代的目标是：**从原材料起步即可得到业务具体、论证成立、各页有信息增量的首份完整稿；设计和制作把这些内容可靠地交付出来，用户无需替系统重建主线。** 不以字数、页数、卡片数、脚注数或工程测试数量定义成功。

建议实施顺序：

1. **T03：完整分析写作与“正确但浅”审阅校准一起改。** 在进入大量视觉制作前先验证首稿。
2. **T07：验证候选安装确实派发新方法。** 隔离候选环境，不将仓库文档更新当成用户已用到。
3. **T05：打通内容结构到设计输入，用真实代表页验证蓝图与成品。** T03/T04 必须在共同候选上联合通过，才启用相应生产路径。
4. **T06：备注写入、页映射及依赖失效。** 可与 T05 并行开展。
5. **T08：受控对照、Owner 审阅、讲述／阅读验证与最终文件检查。** 以适用 AC 及具体缺陷关闭情况决定发布。

不新增第二套 Runtime、内容数据库、审批状态机或 LLM Provider；不重写 SVG→PPT 编译器；不在这份报告中修改既有 PPT、产品代码、安装和长期规则。

### 5.1 权威内容与投影

| 对象 | 唯一责任 | 不承担 |
|---|---|---|
| 原始 Source | 原文、原值、位置与版本 | 自动证明作者推论 |
| Narrative | 论证关系、依据、条件与推理边界 | 复制全部可见正文 |
| ContentPlan v2 | 页职责、Narrative 映射、时长／篇幅、content_profile、density_rationale | 另一份正文或另一套批准状态 |
| Page | 完整客户可见内容、实际结构和 speaker_notes | 把图像文字当事实源 |
| 有效设计上下文／recipe | 当前布局、视觉层级、结构承载方式 | 暗改事实、结论或必要限定 |
| 冻结 request | 本次实际发给生产工具的版本化输入 | 调用时临时补入未记录的新要求 |
| SVG／PPTX／render | 按既定内容与设计交付、可回读的表达 | 为方便制作重写主张或删关系 |

### 5.2 密度接口已定案

准确接口以 [CONTRACTS §11.4.1](CONTRACTS.md#1141-内容密度到生产请求的最小接口约定2026-10-13-修订) 为准，不再留待实现时各自解释：

| 冲突 | 布局不能覆盖事实、限定、职责、比较归属及业务关系；过期映射/版本冲突拒绝冻结，指出受影响对象 |
| 失效 | 只消费该页内容/语义、对应 Plan 字段、recipe 和适用决定；无关 Plan 页变化不重做全稿 |
| 兼容 | 无完整 Plan 的确认稿沿 fidelity：缺失字段为 null，保留原稿/设计；不补造 Narrative 或批准记录 |

“文字未变”不是纯设计变更的充分条件。箭头从人工确认后提交改为模型直接提交、交换表格主体归属，都回内容责任与审查；同一关系仅移动左右布局才是设计修改。仅备注更新则重编译交付，不重生未变视觉。

本节指定待实现内部派生载荷，不改变现有运行时 schema。本轮只修规范；后续实施必须验证现有 design_context 容器和语义校验兼容性，若需升版先按 T02 路径修订，不隐式拼接新字段。

## 7. 三类代表页：修复应产生什么内容

以下是本轮回归用的**方案表达草案**，用于说明可审查成果，不是已完成的 PPT，不宣称 F-Test 已实现全部动作。P04 的材料关系来自已读取的命题规则；P05 的分工及 P13 的指标属于建议设计，实施时核对能力边界。

### 7.1 P04：跨材料核对矩阵

建议标题：**65 项规则围绕同一笔费用，交叉核对合同、付款、活动执行与申报。** 分类数量仅作范围提示。

| 核对问题 | 对照材料 | 要检验的关系 | 财务接手内容 |
|---|---|---|---|
| 钱是否付给正确主体 | 合同乙方、银行收款方与账号 | 主体和账户能否对应 | 不一致原值、原件位置及需确认事项 |
| 申报是否覆盖实际活动 | 合同期间、申报期间、逐日照片 | 时间范围与逐日影像覆盖 | 冲突日期或缺日，需补充的依据 |
| 申报产品是否与现场一致 | 申报产品线、现场品牌、用酒记录 | 品牌与产品线能否互相印证 | 明确冲突与证据不足分别呈现 |
| 实际用酒是否有依据 | 用酒明细、开瓶／空瓶影像、扫码记录 | 宣传物料不能独立证明实际用酒 | 已观察内容、未能确认部分与下一动作 |

读者应能回答“比什么、为何比较、异常之后怎么办”。若最终只剩四个大图标和类别词，即使每个字都保留也不通过。

### 7.2 P05：从技术名称到工作交接

建议标题：**读取与解释、确定性核对、财务处置分别承担不同责任。**

| 环节 | 输入 | 处理及边界 | 下一环节收到什么 |
|---|---|---|---|
| 材料读取 | 合同、回单、申报单、现场图片 | 提取字段候选和图像观察；不把识别等同于验真 | 原值、原件位置、缺失项 |
| 确定性核对 | 可比较字段与正式规则 | 按明确条件计算／比对；缺输入保留未判定 | 结论、对应输入和触发条件 |
| 语义辅助 | 影像、执行说明及业务要求 | 解释可见内容；不足以确认的保留待核验 | 观察、冲突与补充材料建议 |
| 财务处置 | 异常、缺失、原件依据 | 按现有责任确认、补正或退回 | 处置结论与后续动作 |

采用泳道或紧凑交接表均可。核心验收是责任、条件、输入输出和方向正确，不能把“模型／规则／人工”三个标签当完成。

### 7.3 P13：从 KPI 名称到可执行测量

建议标题：**试点同时检验核对可靠性、材料完整性和实际复核负担。** 无测量结果时只给测量设计，不制造收益数字。

| 指标 | 建议口径 | 采集与比较 | 管理用途／限制 |
|---|---|---|---|
| 关键字段可核对率 | 可形成有效原值与来源关系的必需字段数／该样本适用的必需字段数 | 固定字段与缺失规则，保留未知，不剔除难例美化比例 | 判断材料／提取缺口；不等同于整笔审核正确率 |
| 规则判定可靠性 | 按通过、不通过、待人工分别对照独立财务复核；单列错误放行、错误拦截 | 同一批样本、同一规则版本，保留争议及裁决 | 判断哪些规则能使用；不能将待人工算成确定结论 |
| 单笔复核负担 | 完成同类复核所需人工时间及补件往返，分别记录 | 可比样本与任务，记录材料复杂度；避免重复阅读造成学习偏差 | 验证流程变化；未测量前不承诺节省比例 |
| 问题处置闭环 | 按业务约定期限已处置的问题数／该期限应处置的问题数 | 固定责任、时间窗口和未结案状态 | 衡量执行闭环；不归因成模型准确率 |

这些口径须由任务 Owner 校准，不作为既有客户制度。页面过载时先去重复、聚焦主要决策或合理拆页，不删单位、条件和分母来“提高密度”。

失败定位与回退：

- Page 已浅：回 T03，停止用视觉润色掩盖内容缺口。
- Page 完整、request 漏要求：回 T05 投影；不重写原材料分析。
- request 完整、blueprint 丢结构：定向调整设计并在范围内重试。
- blueprint 合格、SVG／PPTX 降级：保留原图，修对应重建或编译缺陷。
- 文件完整但正文难懂：检查解释、布局、关系和必要限定并修订；不要求外部听众反馈才发现问题。
- 安装不匹配：先处理候选安装／路由，不将旧方法运行结果用来否定新方法。

候选安装按现有 candidate→隔离临时 registry smoke→验证→授权范围内激活路径推进。正式激活和发布是后续实施行为，本报告没有执行；既有项目与历史原件不原地改写。恢复旧内容也不恢复已撤回授权。

### 9.1 三类质量结论不能互相替代

普通交付依据当前稿与实际文件是否满足任务收口，已发生的首稿错误与修订如实保留。若另行主张方法效果或恢复，再区分原始稿、首次交付稿和新方法重新运行的结果；不把人工精修的旧稿改名为新首稿，也不把这类实验变成每次交付的前提。
