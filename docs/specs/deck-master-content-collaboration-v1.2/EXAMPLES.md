# 合成样例、流程轨迹与评价锚点

本文件是可复制的产品原型与测试输入说明。所有组织、设备、数据、SOP 和用户对话均为合成；没有运行真实项目、生成样页或验证受众效果。文本候选不是 golden truth：T00 必须依据源材料和评价锚点复核，不能让实现逐字模仿示例当作通过。

标识 Q1–Q4 是材料包；P1–P6 是案例内页面名，落盘时使用稳定 page_id；N/E 是论证/证据节点。示例中的 `proposal-v1` 等是可读代称，实际 Ref/hash 必须由真实对象字节产生，不能把代称或全零摘要写入正式对象。

## 1. 四个固定材料包

### Q1：新接单员培训

T00 可按以下三个文本块原样建立合成来源；行号 locator 必须对应实际保存内容，不能事后编造。

**S1-sample.txt**

```text
合成抽样：100 条售后请求，其中 38 条首次记录缺少设备版本。
本材料没有记录补问轮次、处理时长、解决率或其他字段的完整情况。
这组抽样只用于教学，不代表任何真实团队的业务统计。
```

**S2-training-sop.txt**

```text
本合成SOP用于培训新接单员，不作为真实业务操作规定。
首轮记录包括设备型号、设备版本、已观察的问题、已尝试动作及结果、可取得的附件。
设备版本无法取得时填写“未知”并说明具体原因，禁止推测、伪造或留空不解释。
紧急程度依据既有紧急条件判断；版本是否已知不单独决定紧急程度。
符合紧急条件时立即按现有紧急路径流转，带上已知信息，不为补齐版本而延误。
普通请求版本未知时，记录未知原因，按普通路径流转；未知不自动变成紧急或专家升级。
目标是下一位接手者知道已知、未知及下一步，不代表当前已解决故障。
```

**S3-old-draft.txt**

```text
历史草案，未经验证：采集前移能带来38%的效率提升。
历史草案，未经验证：所有请求都应先补齐版本，再进入任何处理路径。
```

S3 是错误参考而非当前要求。新方案应明确舍弃两句错误表述，保留舍弃理由；不能因它来自用户材料便覆盖 S1/S2 的证据边界。

**确定后的合成任务**：面向新接单员，8 分钟、6 页现场培训；目标是会记录并正确流转；本示例显式要求口播逐字稿，故使用 verbatim。另建同源分支检验“未要求逐字稿时 live 默认 cues”与“read_alone 默认 none”。

### Q2：限定试点决策

**S1-facts.txt**

```text
合成抽样120条售后请求，54条首次提交缺少设备型号或版本。
当前人员访谈称设备条件缺失可能带来接单后的补问，但没有统计补问轮次、处理时长或其相对其他成本的占比。
未测量任何新方案实施后的时间、成本、解决率或收益。
```

**S2-scope.txt**

```text
本合成一期范围只读，不允许AI自动提交、修改或关闭正式工单。
可读取经许可的手册、历史工单，并展示来源引用；人员在现有系统完成正式提交。
一线有时无法取得版本；试点必须允许注明未知及原因，不能靠强制填写制造虚假完整性。
```

**S3-capabilities.txt**

```text
合成已知能力：许可资料接入、引用问答、门户只读嵌入。
不含已验证的设备诊断能力、自动写入接口、成本节省证据或生产可靠性结论。
```

合成任务：向售后运营与 IT 负责人提出 10 分钟立项讨论，是否开展 4 周小范围试点。页数上限 8，口播默认 cues。两个产品组、具体资料和成功阈值只能作为待选择试点范围，不能冒称已获业务批准。

**正确论证候选**：54/120 表明首次提交存在设备条件缺失；访谈提出“可能引起补问”的机制假设。推荐先验证字段可得性与补问是否下降，并评估带引用资料是否适用，保留人工正式提交。现有证据不足以宣布唯一瓶颈、时间收益或全面自动化立项。

**必须拒绝的反例**：“54/120，所以节省45%成本”；“检索一定尚未开始”；“唯一成规模的重复成本”；把“只读”画成写回箭头；版本未知就阻止紧急处理。

### Q3：独立阅读的研究说明

**S1-study.txt**

```text
合成研究A：12位有经验的值班人员，用同一组标准案例评估两种信息呈现方式；8人更容易在表格中找到版本限制。
合成研究B：另一组20位新接单员阅读不同案例的卡片；14人正确复述处理步骤。
两项研究的受众、案例和任务不同，不能比较成表格或卡片整体更有效。
未测量正式业务处理时间、长期记忆或故障解决率。
```

**S2-confirmed-copy.txt**

```text
合成确认稿；用于独立阅读，不要求口播或销售行动号召。以下六页均为完整上屏内容。

P1 标题：两项研究各自支持什么？
正文：研究A观察有经验人员定位版本限制，研究B观察新接单员复述步骤。
正文：本稿分别呈现两项发现，再解释为什么不能直接比较表格和卡片的整体优劣。
限定：所有样本与结果为合成，不代表真实业务成效。

P2 标题：研究A：8位参与者更容易用表格找到版本限制
表格：参与者=12位有经验的值班人员；任务=同一组标准案例中评估两种呈现方式；观察=8人更容易在表格中找到版本限制。
正文：该观察可提示此受众、此任务中的表达适用性。
限定：没有测量故障解决率、正式处理时长或长期记忆；不能将8/12解释为一般业务成功率。
来源：S1-study.txt第1、4行。

P3 标题：研究B：14位新接单员正确复述了步骤
表格：参与者=另一组20位新接单员；材料=不同案例的卡片；观察=14人正确复述处理步骤。
正文：该观察描述这组受众对步骤的复述结果。
限定：没有给出同一受众使用表格的对照，不能推出卡片优于表格；也未测业务处理效果。
来源：S1-study.txt第2–4行。

P4 标题：两个结果不能放在同一胜负榜上
表格列：比较项、研究A、研究B。
表格行：受众、有经验值班人员、新接单员；样本量、12人、20人；案例、A的标准案例、与A不同的案例；任务、定位版本限制、复述处理步骤；观察、8人报告表格更易定位、14人正确复述。
结论：受众、案例和测量任务同时不同，8/12与14/20不构成表达方式优劣的直接比较。
来源：S1-study.txt第1–3行。

P5 标题：保留两项发现，同时保留各自的适用范围
正文：研究A可作为“版本限制如何呈现”的后续设计线索；研究B可作为“新员工如何理解步骤”的后续设计线索。
正文：线索可用于提出设计假设；不应改写为所有人、所有任务都适用的结论。
限定：当前不能宣布哪种方式整体更有效，不能宣布节省时间或提高解决率。
来源：S1-study.txt第1–4行。

P6 标题：下一次比较应控制哪些差异？
正文：若要比较呈现方式，先固定目标受众、相同案例与相同测量任务，再改变呈现方式。
正文：分别记录定位正确性、理解是否符合任务，以及错误发生在哪些信息上；指标选择仍需按研究问题确定。
限定：这是后续研究设计建议，尚未执行，不是本次已经验证的业务收益。
页脚：合成研究说明｜两研究不可直接比较整体优劣。
```

任务分支：①研究报告转 6 页阅读稿，主线未定时应提出研究问题与证据边界；②用户明确“沿用上述确认稿，只做排版”，只查忠实性与密度；③高密度证据表无法在指定页数内完整显示，必须展示删留/附录/篇幅方案。

**正确页职责**：研究问题→A 的方法与结果→B 的方法与结果→不可比原因→可支持的判断→后续验证设计。不要套痛点/解决方案/购买 CTA；不把 8/12 与 14/20 并排画成竞赛胜负。

### Q4：已有技术 Deck 与控制状态

Q4 的业务文字可由 Q2 派生，建立两个独立 checkpoint：

- **Q4-A**：6 个固定 Page，有来源和完整正确逐页稿，无任何 blueprint；P5 明确“人员确认后在现有系统正式提交”。用于无内容 blocker 的“只试 P5”和初始设计正例。
- **Q4-B**：由相同 6 页衍生的历史已交付项目，故意植入下述旧稿错误；历史交付不代表语义已验收。用于局部修改、历史交付、备注、更换来源、暂停/撤回、晚到和恢复。单元层可使用清楚标 synthetic 的对象；工程验收必须另造真实 SVG/PPT/回读产物，不能用占位文件替代。

仅 Q4-B 的 P5 故意含错误句“助手自动提交正式工单”；其 P1/P6 含依赖该能力的推荐。用户只要求修改 P5 时，这些跨页矛盾用于检查影响报告和范围约束；不得静默一起改，也不得假称剩余全稿已一致。Q4-A 不包含这些错误，不能用带 blocking 内容的稿件测试“应允许首次样页”的正例。

另建控制变体：无 ContentPlan 的旧项目、`existing_decisions=["已确认"]` 的旧项目、1 次调用额度、in-flight/unknown call、host_self professional_use/pass、PPT-only not_evaluated、当前文件的人类审阅证据。各变体记录实际构造方式，不混淆 fixture 与正式入口。

## 2. 四条必跑流程

### 2.1 模糊材料启动：Q1 / V01

**输入**：“用这个目录做套 PPT。”仅提供 Q1 三份材料。

**系统先完成**：读源、区分事实/SOP/错误草案、提出任务分歧；生成可读理解稿，不先写完整 Page 或调用图像。

**用户看到的第一张卡片**：

> 我读到两条可用依据：抽样中存在版本缺失；SOP 允许记录未知并按紧急程度流转。历史草案的“38%效率提升”和“全部先补齐版本”都与现有依据不一致。推荐把这次做成新接单员培训；若是向主管报告问题，主线应改为现状与验证计划。请确定受众与使用方式：是新接单员现场培训，还是主管独立阅读？另外，本次要内容方案还是完成整套？

这是有产物的针对性访谈。问题可以合并为一轮，不以问够三题/几轮为结束条件。可继续核对材料和备选主线；不能自主把推荐标为用户选择。

**合成用户答复**：“给新接单员，8分钟，6页。先让我看主线，再给最密的一页样稿，确认后再做全套。需要逐字稿。”

系统记录任务、verbatim 要求及分阶段范围；“确认后做全套”是有条件的未来流程要求，不是现在可开始整套。产出本文件第3节的 Narrative、页面职责、时间方案和设计可行性。

**第二张卡片**展示实际中心任务、证据边界、6页职责、需保留的未知分支、候选取舍和时间预算。用户看到的选择是“按此培训路径”“改成主管说明”“修改其中某项”，而非只对一个目录点通过。

**合成用户答复**：“主线按这个，样页先只做P5。”

方向决定绑定当前方案；新论证按默认前置独立内容审查处理。输出完整稿与审查发现；发现无依据收益或未知分支缺失时返 Content，不能带着 blocking finding 开始生图。满足条件后只给 P5 样页授权，固定 page_id、内容版本、recipe、1 个候选、1 次外部调用。

完成样页后返回实际预览、正文差异/限制、覆盖范围。只有后续明确“这版密度和结构可以，按此做余下5页”的指令，才产生余下页的执行范围；若用户只说“颜色可以”，只记录 palette 决定。

### 2.2 已有确认稿：Q3 / V03

**输入**：“这是确认过的6页阅读稿和模板，按原内容完成整套，不需要讲稿。”

系统读取并固定字节/来源；记录本次明确指令与范围。稿件映射标 imported/derived，不能假造作者早已批准了系统刚生成的 Narrative。模板的已有适用性可以作为设计依据。

自动继续：忠实性核验、每页完整性、模板与最密表格的适配检查、范围内制作与工程回读。不得重复询问受众、是否现场讲解，或强制生成逐字稿。

真实停顿只来自新冲突：例如 P4 的表格在模板中不可读。展示同一页的完整表格与两个可行选项：保留6页并将辅助说明移至已许可附录；或者放宽页数。用户未允许新增附录/页数时，不能自己选择突破约束。

若核验发现确认稿把不可比研究作了优劣结论，必须给出冲突和修订建议。确认稿是可复用决定，不能豁免事实/忠实性检查。

### 2.3 只试样页：Q4-A / V07

**输入**：“只做第五页的样页，先别做全套。”

运行时应解析“第五页”为当前版本的稳定 page_id，范围包括必要设计分析、P5 样页和比较。缺旧 blueprint 时走本增量初始设计入口，不能先为六页生成旧图再调用 style calibration。

**样页完成卡**至少展示：固定正文、实际图像、阅读顺序、密度处理、明确未覆盖的页型、实际消耗、当前停止边界。选择包括采用、保留候选、指出修改、拒绝；无任何选择默认扩套。

选择“只喜欢配色”只满足配色维度；选择“采用P5”只改变 P5 当前候选，仍没有整套范围。若另一个旧 full_deck 请求存在，新的只试样页请求不自动允许其后台推进；必须有显式后台委派。

**已明确请求两页的变体**：“P4流程与P5密集页各试一页。”允许在两页/两候选/两次调用范围内完成两张，不能因为实现沿用“首张trial只能一页”就强迫中间多确认。两张独立候选不需要伪造第一张已获用户采用。

**拒绝与返修**：“两张都不要，保留原稿。”记录拒绝版本与原因，保留旧稿和历史费用。自动继续可整理明确改进方向；不得原样重做同样候选或开始全套。

### 2.4 局部修改与范围外冲突：Q4-B / V09

**输入**：“P5的自动提交改为人工确认后在现有系统提交，其他页先别动。”

系统先形成 change plan，展示 P5 的完整改前/改后、受影响的备注和视觉关系；检查相关主张发现 P1/P6 仍有自动提交承诺。

允许自动修改已授权的 P5；不改 P1/P6。返回明确 findings：“P1/P6 与新范围矛盾，当前全稿不能宣布一致。建议将其同步修改；如只保留本次局部修改，可交回局部审阅稿，整稿交付资格仍阻塞。”

用户若说“所有自动提交的承诺都一起修”，此明确语义范围可以覆盖 P1/P5/P6；无需逐页再次确认。Host 给出影响集合并绑定新授权，修改可见正文、口播和视觉关系，重新审对应主张与整稿输出。没有受影响的来源与 palette 决定保持有效。

**撤回变体**：P5 任务已 reserve、尚未 begin 时用户说“别做了”；暂停当前请求，begin 被拒绝。若调用已在飞，仍登记成本，结果隔离保留且不能采用。恢复旧内容不恢复被撤回授权。

**续作变体**：“继续刚才的P5修改。”只在原范围内重新判定；如果原行为是暂停，可恢复请求。如果授权已撤回，必须建立明确范围的新授权，不能复活旧 grant。

## 3. Q1 的完整内容原型

### 3.1 Brief 与语义论证

| 输入维度 | 本案例确定值 |
| --- | --- |
| 受众与已有认知 | 新接单员，知道收到问题后要记录，尚不能稳定区分未知信息与紧急流转 |
| 交流任务 | 培训后能填写可接手的首轮记录，并选择正确流转路径 |
| 核心判断 N1 | 可接手意味着接手人知道已知、未知与下一步；不等于所有字段有值或故障已解决 |
| 证据 E1 | S1第1行：38/100首次记录缺版本；支持教学关注点，不支持收益与因果 |
| 规范 E2 | S2第2–7行：记录项、未知原因、紧急/普通路径与交接目标 |
| 推进 | 目标 → 为什么关注 → 记录方法 → 两轴例外 → 具体改写 → 新情境应用 |
| 必须保留的限定 | 合成数据、没有收益测量；未知不能伪造；紧急流转不等齐版本 |
| 不要求的叙事 | 采购建议、痛点放大、ROI、销售 CTA |

**简短论证全文**：本次培训要解决的是首轮记录能否被下一位人员直接接手。合成抽样显示，100条记录里有38条缺少版本；这足以把版本记录作为教学重点，却不能说明任何效率提升。方法依据来自合成SOP：记录五类信息，无法取得的版本如实标为未知并解释原因。信息可得性决定怎样填写，紧急程度决定怎样流转；二者不能混成一条“补齐再处理”的规则。训练是否有效，需要用新情境检查学员能否同时写对字段和选择路径。

N1 由交流目标和 S2 的交接定义支持；E1 是问题背景，不是推导 SOP 的依据。内容计划引用这些节点，不复制另一份可独立变动的中心判断。

### 3.2 页职责、时间与密度预算

| 页 | 唯一沟通职责 | 目标讲述预算（秒） | 互动/停顿预算（秒） | 表达关系 / 风险 |
| --- | --- | ---: | ---: | --- |
| P1 | 建立“可接手”的学习目标 | 30 | 5 | 简明目标；不做装饰封面 |
| P2 | 正确解释38/100与证据边界 | 45 | 5 | 部分与整体；防收益暗示 |
| P3 | 知道首轮要记录哪些事实 | 85 | 10 | 5项映射表；避免像问卷一样填空 |
| P4 | 区分紧急程度与版本可得性 | 85 | 15 | 两轴条件；误流转是高风险 |
| P5 | 识别并写出可接手记录 | 70 | 20 | 错误/改后对照；最密页，首选样页 |
| P6 | 在新情境应用规则 | 65 | 45 | 先作答后展示答案；不能把照抄当理解 |
| 合计 | 6个不同职责 | 380 | 100 | 480秒=8分钟 |

这张表是人工设置的上限预算，**不是已测讲述时间**。本页口播片段也不是经过计时的终稿。T00 先核算预算与内容；T08 实际试讲，在8分钟内完成必要解释和练习，超时必须改写、移出次要内容或重新协商，不能仅增加/减少页数或加快语速。

密度默认按真实画布检查，字号以现有 design_context 和最终渲染为准。若 P3/P5 同屏不可读，设计应提出拆页、短化重复解释或分步呈现；不能删“未知原因”或“紧急不等待版本”来满足页数。

### 3.3 完整逐页上屏稿与讲述内容

以下标题、正文、表格、图示文字、脚注均属客户可见内容；布局说明仅供制作。每页页脚固定为“合成教学案例｜非真实业务统计与正式SOP”。

#### P1｜这次培训：提交一张可接手的工单

**上屏正文**

- 记录已知设备条件和已观察的现象。
- 信息无法取得时，写明未知项与原因，不猜测、不留空不解释。
- 依据紧急程度选择流转路径；紧急情况不因补齐版本而延误。

**完成标准**：下一位接手者知道“已知什么、未知什么、下一步做什么”。本次不要求接单时已经解决故障。

**制作说明**：标题下三条学习目标，底部一条完成标准；不要把整页做成无实质内容的封面。三条目标对应后续P3/P4/P5，阅读顺序自上而下。

**口播逐字稿候选**：“今天只练一个动作：把收到的问题写成下一位同事可以接手的记录。可接手不等于你已经解决故障，也不等于每个字段都有答案。接手人需要知道我们已经确认什么、还有什么不知道，以及下一步按哪条路径处理。后面先看记录方法，再练两种容易混淆的情况。”

#### P2｜这次合成抽样中，38单缺少设备版本记录

**上屏表格**

| 首次版本记录情况 | 请求数 |
| --- | ---: |
| 被记录为缺少设备版本 | 38 |
| 未被列入上述缺失组 | 62 |
| 合计 | 100 |

**可以支持**：版本记录值得作为本次教学关注点。

**不能推出**：解决率、节省时间或效率提升；也不能据此认定其余62条的所有信息都完整。

**来源**：S1-sample.txt 第1–3行，合成抽样。

**制作说明**：使用明确分母的条形或两行表格，两个分组文字完整。不能做“提升38%”增长曲线，也不能用绿色完成标记把62条展示为全部正确。

**口播逐字稿候选**：“先看这里的38。它表示在100条合成记录中，有38条首次没有设备版本。它不是解决率，更不是节省了38%的时间。另一组62条也只能说明没有被列入这个版本缺失组，不能据此说其他字段都完整。这个数字的作用，是提示我们练习怎样处理记录中的缺口；具体怎么填和怎么流转，要依据下一页开始的SOP。”

#### P3｜首轮记录五类信息，让接手人不必从零了解情况

**上屏表格**

| 记录项 | 应写的事实 |
| --- | --- |
| 设备型号 | 可核对的型号；铭牌型号不等于软件版本 |
| 设备版本 | 取得的实际版本；无法取得写“未知”及具体原因 |
| 已观察的问题 | 发生了什么、看到什么；不要把猜测写成故障诊断 |
| 已尝试动作及结果 | 做过什么，之后有什么变化或没有变化 |
| 附件 | 已取得的照片/记录；必要附件未取得时明确说明 |

**提醒**：目的是让信息可接手，不是猜出所有字段。

**来源**：S2-training-sop.txt 第2–3、7行。

**制作说明**：双列表，左列固定标签、右列具体写法。型号和版本分开；不能用“设备信息”一个大标签掩盖两者。五行解释超过可读密度时先简化重复话语，仍须保留未知写法与事实/猜测区别。

**口播逐字稿候选**：“第一轮记录有五类。型号和版本要分开：看到铭牌上的型号，不等于已经知道软件版本。问题描述先写实际观察，例如开机后屏幕无显示，暂时不要把原因猜成主板损坏。做过重启，就写重启一次、现象未变。附件也一样，已经取得什么就记录什么，没有取得的必要信息要说明。暂时不知道并不可怕，不知道却让别人以为已经确认，才会影响下一步。”

#### P4｜紧急程度决定路径，版本可得性决定填写方式

**上屏规则**

| 紧急程度 / 版本情况 | 版本怎样写 | 下一步 |
| --- | --- | --- |
| 符合既有紧急条件；版本已知 | 写实际版本 | 立即按既有紧急路径流转 |
| 符合既有紧急条件；版本未知 | 写未知及原因，附已有信息 | 立即按紧急路径流转，不等版本补齐 |
| 普通请求；版本已知 | 写实际版本 | 按普通路径流转 |
| 普通请求；版本未知 | 写未知及原因 | 按普通路径流转；未知不自动升级 |

**关键规则**：版本是否已知，不单独决定是否紧急。

**来源**：S2-training-sop.txt 第3–6行。

**制作说明**：表格或先紧急分流、再说明填法的图示都可。不能绘制“版本未知→紧急升级”箭头；不能把“紧急且已知”的情况省略，使听众误以为紧急总与缺信息绑定。

**口播逐字稿候选**：“这里要分开两个判断。第一，是否符合既有紧急条件；第二，版本目前是否拿得到。前一个决定走哪条路径，后一个决定字段怎么写。紧急请求即使版本未知，也要带着现有信息立即流转，不能为了填完表等待。普通请求如果版本未知，如实写原因后仍按普通路径走，不自动升级。你不需要在这页重新发明紧急标准，而是正确应用已规定的标准。”

#### P5｜从“信息不足”改为“可接手”：未知也可以被准确记录

**改前记录**：“设备坏了，尽快处理。”

**改后记录**

| 字段 | 示例内容 |
| --- | --- |
| 流转类别 | 普通请求；已按既有条件判断 |
| 型号 | A-200，来自设备铭牌 |
| 版本 | 未知：屏幕无法读取，其他查询途径尚未核实 |
| 观察 | 开机后屏幕无显示 |
| 已尝试动作 | 重启1次，现象未变 |
| 附件 | 已取得铭牌和屏幕照片 |
| 下一步 | 按普通路径交接；接手人继续核实可用版本查询途径 |

**本页结论**：未知有原因、已知有依据、下一步明确。该记录不代表故障已经解决。

**来源**：依据S2构造的合成填写例；设备名和现象均为虚构。

**制作说明**：小面积显示改前一句，主要面积显示改后表格。突出“版本未知及原因”和“下一步”，不要为了大字号把原因裁掉。这是本案例最密页，应优先试样；它不能单独证明P4的两轴图式已经过视觉校准。

**口播逐字稿候选**：“原来的记录说设备坏了，却没有给接手人可用的事实。改后并没有假装版本已经知道，而是写清楚为什么不知道。型号来自铭牌，屏幕现象和重启结果是观察，照片也有记录。注意最后一行：这次按普通路径交接，接手人继续核实版本的取得途径。它仍然不是故障诊断结论，但下一位人员已经知道从哪里接着做。”

#### P6｜两道情境题：分别判断填写方式和下一动作

**情境A**：普通请求，型号、现象和尝试动作已知；版本无法读取。版本字段怎样写？下一步走哪条路径？

**情境B**：请求已符合既有紧急条件，版本V2.4已知。应先完成普通流程还是立即按紧急路径流转？版本怎样记录？

**作答要求**：每题同时说出“怎样填写”和“如何流转”，并说明依据。

**制作说明**：现场版先显示题目，作答后再显示/讲出答案。初次作答不能先把答案放在旁边；若做阅读稿，答案可在下一块/下一页清楚标为解析，不能将看过答案的复述当独立验证。

**口播与讲师答案**：“现在试两种情况。先别只说一个动作，每题请同时回答字段怎么写、路径怎么选。A是普通请求，版本无法取得，因此写未知和具体原因，仍走普通路径。B已符合紧急条件，版本也已知，因此写V2.4，并立即按紧急路径流转，不先走一遍普通流程。区别来自紧急程度，不来自版本是否缺失。最后请用自己的话说：可接手的记录，需要让下一位人员知道哪三件事？”

答案只属于该页讲师 notes 或明确的作答后解析，不能偷偷混入初始试题画面。P6 的训练题也不能拿来充当 T08 的陌生情境迁移测试。

### 3.4 真实返修演示

**发现**：草案P4曾写“版本未知→升级处理”。

**定位与影响**：冲突于S2第4、6行，会让普通未知请求错误升级，属于 blocking semantic finding；影响P4正文/图式、P5下一步、P6答案和对应口播。

**处理**：Content 改为紧急程度与版本可得性两轴；Design 调整P4图示，Review逐一复核四种组合。无需重新询问已确认受众或重选palette；若用户只许可P4，先提交其修正并列出其他受影响对象，不越界改写。

**关闭证据**：源文件locator、改后全部4种组合、P5/P6一致性检查和新版本复审记录；“已修复”一句话、图画得更漂亮或字段齐全不能关闭该 finding。

## 4. 页数/时间/密度冲突的可执行处理

### 4.1 Q1 改成5分钟但仍要求六页

Content/Design 先提供实际差异，不直接把6页缩成4页：

| 方案 | 保留内容 | 实际代价 | 权限判断 |
| --- | --- | --- | --- |
| 保持8分钟6页 | 完整方法、四组合、改写、双题练习 | 超出新时间要求 | 需要用户接受延长 |
| 5分钟6页概要+课后练习 | 保留核心规则与未知/紧急边界；现场只做一题，另一题课后 | 不再满足原现场双题学习验证 | 需要接受目标/练习范围变化 |
| 5分钟面向已有经验者 | 简化基础字段解释，重点四组合 | 改变原“新接单员”受众假设 | 不能自主选择 |

三个方案均不得默默删掉“未知原因”或“紧急不等版本”。如果用户明确授权 Content 自行调整练习方式而不得改受众，系统可选择第二种，记录取舍并更新对应计划与审阅，随后不再为同一已委派取舍重复确认。

### 4.2 Q3 阅读稿的高密度表格

同一论证可能需要更多上屏解释。Design 先指出不可删除的样本/方法/不可比限定，给出拆页、正文压缩重复解释或附录的真实文案版本。阅读稿不能把这些解释全藏进 speaker_notes，然后宣称内容没丢。

### 4.3 新页型出现

已接受P5表格样式后新增架构或复杂流程页，Runtime 按设计覆盖清单给出未覆盖项。可以追加该页型的有限样页；不失效已有 palette，不默认全稿再试一次，也不借“总体风格已确认”跳过实质新风险。

## 6. 与 V01–V12 的对应
