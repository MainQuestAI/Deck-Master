# 04 执行、并行与集成计划

## 1. 开发前的必要核验

以下是执行步骤，当前未执行新功能开发。负责实施的 Codex 应先核验：

1. 工作树与远端 head：记录准确 SHA、分支、工作树变更和基线差异；保留用户未提交文件。若 main 已前进，做与六卡相关的差异分析，不重启全仓审查。
2. 当前 AGENTS 与本轮 Spec：原行为约束继续有效，过时的固定环境断言不当作已安装事实。
3. Python/Node、开发依赖、实际 renderer/browser/字体与 Host 的可用性；使用现有 doctor/版本命令，不凭路径推测。
4. 准备独立分支或 worktree、临时项目和隔离安装 prefix；技能修改最终随代码 git 提交，不只留本机文件。
5. 将台账模板复制为该候选的唯一执行台账，填写 base/head、Owner、环境。所有新 AC 初始 NOT_RUN，旧 CI 只记录为 inherited evidence。
6. 固定 [03 的 I01–I08](03-ARCHITECTURE-AND-COMPATIBILITY.md#2-跨卡接口冻结表)，尤其是 legacy adapter、no-op revision、writer floor 和 v2 协商。

本包不要求先做一次无差别全矩阵测试才能开工。先核对已有基线 CI 与本地环境，首个变更优先跑相应聚焦回归。

## 2. 批次与依赖

| 任务切片 | 前置输入 | 可并行项 | 交接要求 |
|---|---|---|---|
| N1 核心恢复 | 固定 SHA、现有 receipt fixture | N2、N3 | I01/I02/I03 实现与正反例；N4可禁用 |
| N2 安装事务 | 当前 install/verify 与单/四 Skill 布局 | N1、N3 | 隔离 prefix 的阶段故障、恢复与外部所有权证据 |
| N3 结构与方法 | 当前 Task/Review/方法合同 | N1、N2 | I05/I06、方法矩阵、新旧 Task 与旧writer对照 |
| N4A 读取去重 | N3 I05/I06 已固定 | N4B、N6 | full 等价先过，再加 delta/manifest；v1兼容 |
| N4B 历史索引 | N1 I01 已固定 | N4A、N6 | 无索引 canonical对照，冷/热/增量和故障回退 |
| N5A 活动文档 | 本包目标与既有活动入口 | 从 B0 起可准备 | 活动/历史分工草案；不提前写新功能已实现 |
| N6A 效果准备 | 可用中性材料、可访问既有稿或当前正常路径 | B1各项 | 首份完整稿或本轮修改前稿、实际缺陷与拟改进点，保留真实身份 |
| N6B 改进应用 | N3方法依据可追踪；所用N4入口稳定 | N4后半与N5 | 方法/布局变更、受影响内容重做、约定范围内适用产物检查 |
| N5B / 集成 | N1–N4可集成；N6具体改进已入候选 | 原Owner支持复查 | 版本一次更新、wheel方法一致性、最终影响回归和报告 |

N4A/B 可分别提交和测试，但 N4 只有一个最终 Owner。N6 方法正文改动后需生成新 dispatch；不要因改变 hash 回填或“修正”旧任务的历史清单。

## 3. 文件所有权

同一文件容易被多卡触及，应按下表协调，避免多个 Agent 同时写同一区域。只读分析可并行。

| 文件/区域 | 主写 Owner | 协作约定 |
|---|---|---|
| operations.py / Store receipt 查询 | N1，随后 N4B | N1先固定解码与wrapper，N4B只优化resolver内部 |
| snapshots.py | N1，随后 N4B | 固定head与安全读取先落地；缓存复用后接 |
| service.py 的 inputs_update | N1 | N3/N4不改此业务核心，只使用公共接口 |
| service.py 的 task_summary / pending投影 | N3，随后 N4A | 方法来源先收敛，再引入资源收集器 |
| method_resources.py | N3，随后 N4A | 选择/manifest/basis由N3；传输投影由N4A |
| models.py / Task与Document相关schema | N3 | writer和验证政策统一提交，N1复用既有receipt合同 |
| install.py / 安装CLI段 | N2 | N5只消费最终命令和恢复流程 |
| CLI/HTTP参数段 | 各卡所属段；集成Owner合并 | 每项登记新增参数、错误码与旧响应快照，禁止无关改写 |
| 四 Skill的入口正文 | N3与N5 | N3修职责/必读；N5修活动路由和安装/恢复入口 |
| skills/deck-master/references/专业方法 | N6；N1/N2/N3贡献定向变更 | 一个提交序列形成最终字节，禁止复制到四个目录分别维护 |
| README/AGENTS/CLAUDE/ROADMAP/CONTRIBUTING/版本 | N5 | 先目标草案，合入代码后更新真实状态；候选bump一次 |
| AC判据/台账 | 原AC Owner / 集成Owner | 判据单处维护；状态只在候选台账 |

代码抽取不在其他 Owner 未完成的分支上顺手做。确需跨区域变化时先同步接口和影响，再由该区域 Owner 接受提交。

## 4. 推荐提交粒度

无需机械规定一个任务只能一个 PR。可以沿可验证责任拆分：

1. N1 resolver/新原子普通输入提交；N1旧入口错误与特定eligibility读边界。
2. N2持久事务与恢复，包含故障测试和安装说明。
3. N3内容政策/Task manifest/Review派发与兼容。
4. N4A v2 full与协商，再补delta/manifest；N4B查询去重和索引。
5. N6证据指向的方法或布局改进及正常任务复查。
6. N5入口与版本集成、完整必要回归记录。

每个提交说明具体问题、行为变化与验证。遵守仓库 DCO。用户身份缺失时不冒用身份签署；可先完成工作树和测试，按现有仓库流程处理身份配置。本文不要求额外“先批准计划”流程。

## 5. 受影响验证与集成

### 局部阶段

各 Owner 先运行任务卡所列聚焦测试；N1/N2/N3需要新的正反例，N4需要内容等价和真实读取计数，N6需要完整稿与约定范围内适用产物检查。可使用合成 fixture 验证恢复、并发、结构和读取成本，但明确标记 SYNTHETIC_ENGINEERING。

### 联合阶段

至少覆盖以下跨卡链条：

| 联合链 | 重点 |
|---|---|
| N1 + N4B | 索引开/关/丢失/损坏不改变原操作恢复、冲突、未知态；普通与content两族摘要不混 |
| N3 + N4A | 精确manifest/order/hash不变；v1/v2完整解引用后业务上下文等价；旧Task不被补新方法 |
| N2 + N3 + N5 | 新安装包四Skill/方法hash一致；安装回滚不降低项目writer floor |
| N3 + N6 | 新方法改进真正被新Task派发和应用；旧首稿、修改稿和方法复跑可区分 |
| N4A + N6 | 去重不删来源/正文/原图；完整材料理解与实际页面检查仍成立 |
| N1 + SDK/HTTP | artifact/control固定，状态与错误保留，响应差异为显式适配而非事实差异 |

### 最终门禁

沿现有 .github/workflows/rebuild.yml 执行必要候选门禁；不能以本机缺工具将 required browser 改成 skip。对应工具缺失时记录 BLOCKED，并继续不依赖该能力的工作。

准确命令、分组与证据规则见 [05-ACCEPTANCE.md](05-ACCEPTANCE.md)。最终实现或方法字节变化后只补受影响回归与必要对照，不无界重复已经充分的验证。

## 6. 变更失败与回退

- 源码实现问题：在隔离分支修复或回退相应提交，不重置用户工作区。
- N1：回执或CAS失败保持旧current；current已提交但索引失败返回真实成功与缓存告警，避免业务重做。
- N2：按journal和实际所有权恢复；外部路径冲突保留并报告。不能以删除用户目录作为“自动修复”。
- N3：rc4-content.v1项目不能降floor供旧writer写回。使用隔离副本验证升级，生产数据问题优先向前修复。
- N4：保留v1路径和关闭派生索引的canonical查询方式；关闭优化不能使业务失效。
- N6：保留真实首份完整稿/修改前稿与未修finding，方法修改造成新退化时回退该方法变更或继续定向修复；不覆盖证据伪装首稿成功。
- N5：历史文档移动需可追溯映射和链接修复；不重写Git历史或清掉客户产物。

发布tag、推送公开Release或激活用户实际HOME只在当时已获授权且条件具备时执行。本包要求先完成候选和可审阅证据；缺少发布权限不阻止授权范围内的实现与验收。

## 7. 交接包内容

最终开发交接至少包含：

- 精确候选 SHA/tree、包版本、构建包和安装资源身份。
- 六卡 AC 的唯一台账及证据路径，实际命令和环境。
- 新旧协议、操作族、writer floor、旧Task和安装事务的兼容说明。
- N6真实首份完整稿/修改前稿、具体改进、当前稿/适用产物及观察结论。
- 已知限制、未执行项和受影响的后续动作；不把历史report结论复制成新候选PASS。
- README/Agent入口中可顺序执行的正常流程、恢复方式和当前事实。

代码候选、实际安装、外部发布各写各自状态。后续接手者不需要从多个历史PR和报告中猜“现在该执行哪一版”。
