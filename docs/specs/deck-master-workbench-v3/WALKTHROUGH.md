# 三条主路径与补充状态走查

从 [本地原型](http://127.0.0.1:8766/) 开始；服务未启动时见 [启动方式](README.md#当前交付状态)。建议桌面浏览器 1440 × 900，至少 1280 × 800。

这是合成演示，不会执行真实生成或创建真实项目。所有“模拟 Host”按钮仅推进样本。交接文本带演示标识，**不应交给 Host 处理真实项目**。原型保存草稿、任务和采用选择到本浏览器；需要从初始状态重走时，使用侧栏“重置演示进度”。

## 路径一：看完整稿，再把第 7 页的好风格用到第 8 页

目标：回答“整稿哪里不一致、为什么、我要怎么改、现在轮到谁”。

1. 打开 [制作总览](http://127.0.0.1:8766/#overview)，点 **“看 24 页原图 →”**。这份样本有 24 页：20 页已有原图，最后 4 页保持缺项空位。切换“连续”可顺着阅读，不必逐个打开文件。
2. 在 [整稿画廊](http://127.0.0.1:8766/#gallery) 查看第 7、8、9 页。第 7 页是参考样本，第 8、9 页故意采用不同色板和圆角语言。筛选“风格待校准”可以集中定位这两页。
3. 打开 [第 8 页原图](http://127.0.0.1:8766/#page/8/image)。右侧“执行提示词”展示合成的当次快照；从“色板”“字体与信息密度”找到与原图对应的要求，再切“逐页稿”“来源”查看本页要表达什么。这里演示真实绑定的设计方式，**不是一条真实模型调用记录**。另可打开 [第 19 页](http://127.0.0.1:8766/#page/19/image)，检查缺少历史提示词时如何明确显示“未记录”。
4. 点“去风格校准 →”，或直接进入 [风格校准](http://127.0.0.1:8766/#style)。默认固定第 7 页为参考，第 8、9 页为目标。写一句要求，例如“沿用第 7 页的颜色和线条，保留第 8 页的标题、数字与结构”。无需先读精细设置；需要时再展开查看维度和提示词差异。
5. 看右侧影响说明，点 **“先试第 8 页 →”**。它保存一条请求并进入交接面板；当前原图没有改变。记下目标为第 8 页、基准为 R18、当前状态为待交接。参考页版本、选定维度、自由要求和本次执行范围随请求固定。
6. 点 **“复制交接文本”**。成功后应显示“已复制，尚未开始”。浏览器拒绝剪贴板时会打开手动复制文本框，不会谎报自动复制成功。文本应带第 7 页参考版本、实际只处理第 8 页、选定维度与保留内容要求。到 [制作总览](http://127.0.0.1:8766/#overview) 后，可从待办返回同一请求；刷新也应保留。
7. 在明确标出的“原型演示控制”中依次点 **“模拟 Host 接手”**、**“模拟候选返回”**。候选返回后，左侧当前采用和右侧候选同时存在。核对标题、事实和结构，再判断视觉是否接近参考。
8. 候选不满意时点 **“保留当前”**：当前图不变，本次待决定项结束，候选记录保留。再点 **“调整要求再试”**，编辑要求后点“保存第 8 页的新请求 →”；它会建立新的请求身份，旧要求与候选不被覆盖。再次用模拟接手、返回进入比较。满意时点 **“采用这个候选 · 仅第 8 页”**：当前原图与提示词显示 v3，SVG / PPT 仍是 v2 并提示待更新。请求比较的左侧仍保留原 v2 基准；采用不等于整稿质量通过。
9. 点 **“将余下 1 页加入待交接”**，检查 [运行与交付](http://127.0.0.1:8766/#runs) 中第 9 页的新请求。它复用已确认的固定参考与维度，但执行范围只包含第 9 页，不会在采用第 8 页时自动启动。返回第 8 页已采用请求，继续按钮变为 **“查看第 9 页请求”**；再次点击应打开原请求，不重复安排。需要新试作时，进入该请求明确点“调整要求再试”。

走完应能解释三个动作的区别：保存要求、让 Host 接手、采用返回结果。当前原型的参考与目标固定为第 7 / 8、9 页；任意选页和真实模型生成归正式开发。

## 路径二：从 PPT 结果返回正确的修复阶段

目标：看到成品问题时，先分清是原图、SVG 重建，还是最终 PPT 的问题。

1. 打开 [第 12 页 PPT 预览](http://127.0.0.1:8766/#page/12/ppt)。初始样本中，“诊断”与“处理”之间的箭头反向。确认页号、层和版本，再点 **“固定双层比较”**。若此前已修复此页，可重置演示进度后重走。
2. 右侧“对照”先选 **SVG**：该层也有同一反向箭头；再选 **原图**：原图箭头向右，顺序为准备 → 诊断 → 处理 → 客户确认。两侧固定在比较时的 R18 产物版本。由此可见这个合成缺陷始于 SVG 重建，应保留原图，只修 SVG。
3. 点“退出双层比较”，进入 [第 12 页 SVG](http://127.0.0.1:8766/#page/12/svg)，打开 **“标注与意见”**。可直接写整页意见，也可切“框选模式（可选）”框住反向箭头；Esc 取消框选。输入“中间箭头应从诊断指向处理，保留原图和文字”，点 **“保存意见”**。此时尚未创建任务。
4. 点 **“仅重建 SVG”**，核对保留原图与执行提示词的影响说明，再点 **“加入待交接”**。这会把当前 SVG 层已保存的意见及选区带入**同一条 SVG 请求**。本路径无需再点“加入修改”；后者是直接提交该层意见的另一个入口。
5. 在 [运行与交付](http://127.0.0.1:8766/#runs) 检查“第 12 页仅重建 SVG”的目标层与意见，按需复制演示交接文本，再依次点原型控制的 **“模拟接手”**、**“模拟返回候选”**、**“查看候选并比较”**。
6. 比较框左侧是固定的 **SVG v2**，仍有反向箭头；右侧是 **SVG v3 候选**，箭头已向右。点 **“采用这个样本候选”**，再进入第 12 页的三个产物标签：SVG 为已采用 v3；原图和实际提示词仍是 v2；PPT 保持旧版 v2，提示“上游 SVG 已变化，待更新”。可刷新再次核对。

这条路径演示了可见的合成缺陷、定位、定层请求、候选比较及采用后的影响。真实 SVG 重建、检查、整稿重新装配与 PPT 恢复仍须由 W07 / W12 实证。

正式工作流的分支是：逐页稿事实错则改内容；内容对但提示词漏要求则改请求；原图本身不符合要求则重新试图；原图正确而 SVG 出错则只重建 SVG。UI 应帮助用户做这个判断，不能默认所有问题都重生成原图。

## 路径三：从新建，到离开回来，再选择交付文件

目标：陌生用户知道入口在哪，回来后能找到工作，导出时知道拿到的是什么。

1. 打开 [全部项目](http://127.0.0.1:8766/#projects)，点 **“新建项目”**。先留空提交，观察项目名称和方案目标的必填提示；可用“取消”返回，不创建记录。
2. 再次打开表单，填名称、这份方案要促成的决定，以及可选材料说明，点 **“保存模拟项目”**。进入独立的制作前准备页，明确没有逐页稿、原图、SVG 或 PPT，不会拿已有 24 页稿冒充新项目结果。
3. 点 **“保存首轮制作请求（模拟）”**，再复制首轮交接文本。关闭窗口、刷新后，项目入口仍有新建的样本条目；打开准备页可继续。此处只写浏览器记录，保存位置是概念示意，没有创建目录或读取文件。
4. 返回既有 24 页样本，打开 [第 8 页](http://127.0.0.1:8766/#page/8/image)，在“提示词草稿”或“标注与意见”中输入内容并保存，刷新检查保留。再到 [运行与交付](http://127.0.0.1:8766/#runs) 找回路径一产生的任务。待交接时能复制或取消；模拟接手后可演示返回或失败。
5. 观察失败和取消仍留下任务记录。保存结果未知、冲突和超时核实的交互可继续走下面的独立状态样板；**它们没有真实时钟或服务端故障注入**，不得通过模拟按钮宣告生产恢复能力已通过。
6. 在“固定版本导出”选择 **R18 当前版本**或 **R16 历史快照**，点“预览审阅包清单”或“预览工程包清单”，确认弹窗显示选定版本。审阅用于阅读稿件与预览；工程包保留继续制作和恢复所需材料。
7. 查看“交付文件”的未就绪说明，点 **“定位缺项页面 →”**，进入缺少 PPT 预览的页面列表。缺 PPT 的位置保持空位，不用原图填充。当前只预览设计清单，**不下载真实 PPT、ZIP 或审阅文件**。

## 补充走查：六个独立状态样板

主原型侧栏点 **“异常与整稿操作样板”**，或直接打开下列入口。它们与 24 页主原型使用不同的本地存储，任意一个样本可点“重置当前样本”重新开始，不改变其他场景。

1. **[只有正文](http://127.0.0.1:8766/states.html#text)**：编辑第 3 页标题与正文 → “保存正文（样本）” → 刷新 → “比较 R16 与当前保存稿”。应看到新保存版与固定 R16，页面明确无原图 / SVG / PPT。该样板只演示一页正文编辑，整稿找页仍在主原型。
2. **[保存结果未知](http://127.0.0.1:8766/states.html#unknown)**：继续修改右侧后写草稿 → 选择标为演示控制的核实结果 → “核实原保存结果（模拟）”。若已提交，可“以新基准建立后写草稿”；若未提交，才出现“重放原请求（相同 ID / 内容）”。检查左侧原请求始终不变、后写内容不被覆盖。真实产品查询服务事实，用户不能指定结果。
3. **[内容冲突](http://127.0.0.1:8766/states.html#conflict)**：看固定的本机 R16 草稿与服务端 R18 内容 → “基于 R18 建立新草稿” → 自行编辑并刷新。原来两份内容仍可看、可复制，新草稿不自动提交；明确一个区域与两个区域的冲突由谁决定。
4. **[批量部分返回](http://127.0.0.1:8766/states.html#batch)**：第 7 页“比较第 7 页候选” → “只采用第 7 页候选”或保留旧结果；第 9 页修改要求 → “只为第 9 页保存新请求”。第 8 页依次“核实第 8 页状态（模拟）” → “取消旧任务…” → 确认取消 → “生成新交接（模拟）”。核对只处理指定页、旧取消记录保留。比较框明确使用文字占位，并非真实图像；起点已是一批部分完成结果，不演示从多意见开始的一次批量提交。
5. **[整稿调整](http://127.0.0.1:8766/states.html#structure)**：用 Tab 聚焦上移 / 下移按钮，Enter 改顺序，确认 page_id 不变；移除一页前看确认影响。选两页并选择“合并两页” → “保存重组请求…” → “保存 Host 请求（模拟）” → “模拟 Host 返回候选” → “查看候选并确认采用…” → “采用结构候选（样本）”。查看新页来源与旧意见历史；重置后选一页，改为“拆分一页”重复。此样板没有跨页改写正文的编辑流程。
6. **[历史与恢复](http://127.0.0.1:8766/states.html#history)**：依次“查看 R16” → “比较 R16 与 R18” → “恢复 R16 的内容…” → 阅读确认信息 → “确认创建 R19（模拟）”。查看不改当前 R18，确认后才出现 R19；A7 完成事实、A8 取消与晚到拒绝记录保留。可取消确认返回继续查看。

这 6 个样板在 Chromium 1280 × 800、1440 × 900 各通过 47 项检查，14 张截图保存在 validation 目录；见 [states-smoke-result.json](prototype/validation/states-smoke-result.json)。此处引用已运行的测试证据，不把合成结果提升为真实服务验收。

## 走查后的判断

| 可以据此判断 | 还需要正式开发验证 |
|---|---|
| 页面组织、文案、主次动作是否清楚 | CLI / HTTP 与核心服务是否实现相同规则 |
| 24 页同层观看是否比逐文件查阅更易理解 | 真实 20–30 页产物的加载、缓存和浏览性能 |
| 找依据、先试、交接、比较采用的操作是否连贯 | request / attempt / output 的真实绑定与不可变性 |
| 本地草稿与模拟请求在刷新后是否保留 | 多项目隔离、冲突、未知保存、取消和晚到保护 |
| 正文保存、双稿冲突、核实 / 取消、重组和恢复的下一步是否清楚 | 同一流程接入真实核心后的事务、调用事实与恢复正确性 |
| 固定版本与三类文件用途是否可理解 | 真实导出内容、质量门槛、安装包和恢复能力 |
