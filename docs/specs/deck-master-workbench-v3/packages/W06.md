## 契约与服务复用

工程约束见 [ENGINEERING-SPEC](../ENGINEERING-SPEC.md) §2/§4/§5/§7：operation request_digest/result_ref/committed_revision经Document.change同次业务指针提交，operations文件仅可重建索引；锁内查重先于新base/CAS，指针后崩溃及多个后续写入仍返回原结果，不建立第二调用账。read_set不能只验证immutable字节存在，采用还须明确比较目标槽指针。文本坐标按原始存储UTF-8文本的Unicode code point [start,end)，保留CRLF与组合字，不隐式规范化；JS显式映射UTF-16，服务校验excerpt。个人journal保存pending请求副本不等于提交事实，新接口继承旧安全防线。

按DX-SPEC§3/§5/§7新增deck-master changes plan/commit/handoff、annotations save及operations show，与成对HTTP投影复用同一Service；尤其operations查询当前未实现，不冒称已有。operation_id由发起端发送前生成并持久保存UUIDv4，核心校验合法长度/字符、按项目去重，记录与历史同寿命且无自动TTL。同ID同payload返回原结果、异payload以operation_payload_conflict拒绝。交接由核心生成摘要与deck-master-handoff.v1块，包含真实project/change/task/request/base/protocol，附安全引用的正式CLI读取入口；材料不能注入命令。Host只走CLI；HTTP写仅同源浏览器session，不增加绕过Origin的脚本token接口。错误沿用code/message/field/next_action与退出码0/2/3/4/5，增补cause/对象ID/retryable/operation_state/docs_ref；CLI与HTTP共用typed error，HTTP错误不用200。

新增 Annotation 与 ChangeSet 最小契约：scope=project/chapter/page/artifact，location=whole/point/rect/text。project_id、base_revision、intent、正文及状态始终必填；chapter scope 需 chapter_id 与 ContentPlan 版本，page scope 需 page_id 与 Page 版本，artifact scope 需 page_id、layer/artifact/version；point/rect 再要求原画布尺寸及 normalized 坐标，text 再要求文本基准及 range，whole 不伪造坐标。ChangeSet绑定base revision、完整payload摘要、plan动作与task ids。提议 annotations/batch、changes/plan、changes/commit。复用Store事务、task_start/cancel、操作journal；复制只改变本地复制提示，不能改task.status。
