## 执行边界

- 一次执行一张卡；同卡跨核心/前端时拆两个串行PR：共享核心/schema/CLI/Host能力先main，前端同步后接入。
- 使用活动 `src/deck_master/resources/contracts/`，复用不可变Store、核心Task与现有命令；不建立第二套执行器或状态真相。
- AC只由所在卡负责最终验收。下游可复用证据，不重复计算为多个卡的完成；每条记录commit、环境、层级及证据路径。
- 自动化证明契约/行为，浏览器证明交互，真实Host证明执行往返，真实阅图证明修改效果；四者分别记录。
- 旧B卡中的取消、超时、固定版本、导出、打包保护继续适用；旧“稿件/修改”信息架构不再限制新方案。
- 这里只交付开发包，不改变默认入口、不发布、不迁移真实HOME或生产项目。

## 跨包恒定验收

交互规范统一见 [UI-SPEC](../UI-SPEC.md)。默认切换需M2真实证据、最终安装候选和可演练回退，仍按已有发布授权；M1只读与合成原型不能触发切换。SVG/PPT能力声明、工程检查、专业/桌面编辑实证分开；本期不新增OCR或图像文字叠加层。

任何包都不能破坏页面身份、固定版本、来源可信度、幂等提交、取消后晚到保护、当前/历史分离或既有质量门禁。新模型缺记录时诚实降级，不补假历史；试作不写当前指针，采用才传播失效。无Web仍可通过Host/CLI生产，打开UI不成为强制逐页审批。

每张卡交付时至少带：变更清单、schema/兼容说明（若有）、验证命令与结果、必要浏览器/Host证据、失败案例、回退说明、独立复核结论。真实Host无法进行属于未验证，不可用mock测试代签。
