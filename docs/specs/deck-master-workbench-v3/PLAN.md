## Implementation plan
# Deck Master 生成工作台 v3：产品、交互与实施方案

版本：1.0 / 2026-09-26。状态：AutoPlan 与四轮修订评审完成，可交付设计评审与开发拆包；整体结构与功能已获用户认可；前端调整保留，生产发布尚未执行。
本轮交付是可评审设计、原型和开发包；不是正式功能已实现。代码核查基线 d1c7c46，旧 B 线方案是历史输入而非本方案的边界。

## 1. 重新定义产品

Web UI 是 Deck Master 的“生成工作台”：让人从整稿尺度看制作进展，从一页的结果追溯生成依据，再在准确的层级调整、试作、比较和继续生产。它与 Codex/CLI 操作同一个项目，同一套服务和记录，不建立第二个执行器或状态真相。

独立入口意味着用户可以自己打开、找回项目、理解现状并提出操作，不依赖聊天里找链接；不意味着脱离本地核心和 Host 独立执行模型。工作台可在没有聊天窗口打开时阅读和保存草稿；执行生成仍需要可用 Host，界面必须如实表示。

原来“稿件 / 修改”的审批导向不再是信息架构约束。审阅成为制作链上的一个任务；材料、大纲、逐页稿、生成请求、图、SVG、PPT 是连续的工作对象。默认不展示任意节点连线画布，也不要求用户理解编排引擎。

### 1.1 打开时机、用途与收益

| 时机 | 打开后的问题 | 用户操作 | 不打开时 |
|---|---|---|---|
| 开始一个项目 | 这份方案给谁看、以什么材料为依据 | 新建/打开项目，选入材料，填用途和页数目标，交给 Host 组织内容 | Codex 仍可通过 create/inputs 开始 |
| 材料整合/大纲形成 | 讲什么、证据够不够、章节顺序对不对 | 看来源映射，调整章节与页目标，标出缺事实处 | 由 Host 按要求继续，但同样保存过程产物 |
| 第一批原图出现 | 整稿阅读节奏与风格是否成立 | 连续阅图、联系表、多页并排，选基准页 | 继续生成不强制开网页；会错过低成本早期视觉校准 |
| 第7页好、第8页偏 | 是内容、提示词、风格、还是SVG重建偏差 | 固定两页，比较提示词与原图，提取指定风格，先试1页 | 可用CLI/Host做同样操作，但需要手动定位对象与引用 |
| SVG/PPT形成 | 转换是否还原原图、文字可编辑吗 | 同页原图/SVG/PPT预览对照，定位到变差的阶段 | 核心检查照常运行；无可视化不免除检查 |
| 中断后回来 | 哪些已完成、哪个版本、下一步是谁 | 恢复位置，查看待办、运行事实和失败原因 | continue仍可以续作 |
| 对外使用 | 当前可拿哪一版、缺什么 | 固定版本下载审阅/交付/工程包 | 核心export仍可使用同一规则 |

用与不用不改变事实记录、产物完整性、质量门槛和基本执行能力。使用 UI 的增加值是跨页整体观看、跨层定位、精确选区、可控的局部试作与可见的影响范围。不能把“打开网页”做成强制审批或每页点击一次的生产阻塞。

### 1.2 第一用户与可验证价值

第一用户是通过 Host 生成20–30页方案的负责人，需要控制内容、视觉一致性与可编辑交付。首个验收样本为24页合成方案，含不同版式、2页风格偏离、缺图页和一次失效的旧PPT。
必须验证三件事：30秒内定位整稿中未制作/偏离的页；从一张图最多3次明确点击找到对应逐页稿与当次执行提示词；保留第8页内容，用第7页指定风格先试1页、比较采用，再继续指定余页。
这些是待实测目标，不是已测效率提升。不得宣称提示词相同就保证画面一致。

## 2. 主对象与全链路关系

```text
项目任务事实 ─┬─ 选入材料版本/摘录 ─→ 内容整合与证据映射 ─→ 章节大纲
             └─ 风格规范版本                                  │
                                                            ↓
稳定页面身份 ─────────────────────────────────────────────→ 逐页稿版本
                                                            │
风格参考/用户调整/生成参数 ─→ 冻结的生成请求（含提示词） ←───────┘
                                      │
                                      ↓
                           当次调用与原图候选
                                      │ 采用到当前页面
                                      ↓
                              SVG重建版本
                                      ↓
                    单页SVG预览/检查 → 整稿PPT快照及逐页预览 → 固定版本导出
```

这不是一个每次全走完的线性向导。材料可影响多页，风格可被多页引用，整稿PPT依赖有序页面集合；各页可以处于不同阶段，历史产物可继续看。UI 主轴是“页面 × 产物层”，任务是侧面执行记录。

### 2.1 四类必须分开的状态

1. 产物存在性/适用性：未生成、当前可用、依据已变化、历史、来源未知。
2. 执行：待交接、已接手、处理中、返回、失败、已取消、已失效。只有事实可驱动。
3. 候选采用：试作候选、当前采用、历史。试作返回不等于自动换稿。
4. 人的关注：草稿、待决定、未查看、已查看。个人已查看不等于专业质量通过。

“原图存在、SVG未生成、PPT仍旧版”可以同时成立。不能用一个绿色完成点掩盖差异。已有自动流水线照旧产生当前结果；仅用户发起的试作进入候选分支，不强制把所有生产变为人工逐页采用。

### 2.2 提示词必须有可信来源

区分：系统模板版本、根据逐页稿拼出的预备提示词、用户编辑的草稿、实际提交文本与附件、调用结果。展示“当次实际提交”需要 Host 调用前后记录支持，不能用最新逐页稿重新拼出一个提示词冒充历史。
冻结请求只保存调用前已知输入：逐页稿版本、内容依据版本、设计上下文版本、模板版本、确切提示词、参考图与角色、拟用模型/参数（未知则未知）、阶段。每次尝试另建Attempt事实，绑定request_id并记录接手、实际提交回执、供应商调用ID、实际参数、返回/失败、用量与输出对象；追加结果不修改已冻结请求。一请求可有多次尝试，供应商未返回的种子/账单保持未知；只冻结未发送的请求不得标submitted。
提示词面板按事实显示“已冻结未观察提交 / Host申报 / 工具已观察 / 供应商回执”，同时说明观察主体与request hash；回执不含正文时不得推断正文一致。多来源一致时优先展示覆盖该字段的直接证据，冲突时并列原记录，不静默合并。工程包保留观察来源。历史未记录实际提示词时显示“未记录”，仍可看预备稿；用户可以据此新建候选，但不得显示为原图的已验证生成依据。由图反推提示词问题是人工/AI建议，必须标“推测”，不改写历史事实。

### 2.3 过程产物不再可有可无

新项目 compose 必须产出简明内容整合、章节大纲及页与材料的映射。允许大纲来自用户导入；事实不够时给缺口，不编造引用。新Host协议必须在外部生成前冻结实际请求，返回后关联图片；只保存原始文本/引用，不保存秘密凭证。
旧项目逐步兼容：已有明确引用读出来；可以推导的仅标“推导关联”；无法找到的留“未记录”。不得扫描用户目录猜测文件关系，也不自动原地迁移旧格式。

## 3. 信息架构与页面设计

画面、首屏落点、主次动作、候选/交接/冲突与全功能状态的规范见 [UI-SPEC.md](UI-SPEC.md)，属于本方案必需规格。原型演示范围与正式验收分开记录。

独立启动页：最近项目、打开已有项目、新建项目。每个项目展示名称、最后活动、当前可看产物、待办；不做全局生成率仪表盘。单项目服务继续隔离；项目入口负责注册路径和启动/复用已有服务，不将浏览器文件名当本机目录。

项目内五个主功能区：

| 功能区 | 目的 | 默认画面 | 主动作 |
|---|---|---|---|
| 制作总览 | 知道整稿在哪、哪里需要人处理 | 顶部项目事实+待办，正文为页×阶段矩阵 | 定位具体缺口/继续上次位置 |
| 内容与来源 | 整理材料和论证，形成可制作的页 | 左章节树、中逐页稿、右按需来源 | 保存内容调整/提交Host改写 |
| 整稿画廊 | 一次看20–30页同层产物 | 原图联系表；可切连续/并排、SVG/PPT预览 | 选页比较、标注、设风格参考 |
| 风格校准 | 有控制地把好的视觉扩到指定页 | 固定参考图+目标页+一句要求；精细设置折叠 | 先试1页，再比较采用 |
| 运行与交付 | 交接执行、恢复、查看质量和文件 | 按操作组的运行列表+当前文件 | 复制交接/看返回/下载固定版 |

单页工作台是跨上述功能区复用的详细页，不另设第六个主模块。上方固定页面标题、所在章节、前/后页与版本；链路标签为来源/逐页稿/提示词/原图/SVG/PPT。中间大画布，右栏按需显示选中对象的来路、意见和动作。任何地方点击页，都保留page_id、层、版本和返回位置。

### 3.1 制作总览：页面×阶段矩阵

行=章节和页，列=逐页稿、提示词、原图、SVG、PPT预览。材料/大纲在上方摘要和来源工作区；整稿PPT不是每页一个假文件，矩阵单元格说明所属整稿或单页检查预览。
单元格默认仅显示文字状态/图标及小缩略图（存在时），点击直接进入该层；时间、证据与失效详情按需展开。主标签优先显示不可读/依据变化/缺失/可看，候选待选为独立角标，未查看仅为次要提示，不能混成一个完成状态。状态不依赖颜色。列可收起；30页用自然纵向滚动、固定表头和页面列，不用无限画布找方向。
待办只有需用户动作：选择缺失事实、待交接、候选待选择、冲突、未看结果。正在运行只显示进度；不要把每个内部任务都变成用户todo。无待办仍有“打开整稿画廊”和继续阅读。

### 3.2 整稿画廊：首先解决一张张开图

进入默认选择“原图”，清楚标记这是视觉稿而非PPT。支持2/3/4列、章节分组、缩略图密度、完整一页连续阅读和2–4页并排；提供筛选未生成/依据变化/有意见/风格参考/已标记偏离。
一键切同层SVG预览/PPT预览；缺产物显示该页状态与可执行入口，不能用原图填充PPT列。可选“当前最佳可看”混合模式，但每页必须显示真实产物类型，不能成为默认对比基准。选中页跨过滤保留并显示“其中N页在当前筛选外”。键盘方向切页，Enter聚焦，Escape回到原位置。
连续模式滚动时只有当前页+临近页加载大图，缩略图使用本地缓存，按内容hash缓存、切版本不串图。并排默认同尺寸不裁剪，同步缩放可关。原图与PPT像素差异只能提示差异，不能自动判断语义质量。

### 3.3 内容与来源

展示任务目的、受众、材料选入/已读取/已用到页的不同事实；正文内引用定位至材料版本及页码/段落。无法精确定位时显示材料级关联，不伪造行号。
大纲按章节和页面目标组织；重排保持身份，新增/移除保留历史；合并拆分是Host内容任务，返回来源关系。正文可直接编辑，复杂改写交给Host。用户可以从图上的错误回到逐页稿修改，但UI要展示下游影响，不假定所有问题应改prompt。

### 3.4 风格校准

1. 从画廊或单页直接选第7页为固定参考原图、第8/9页为目标，打开同一个风格校准工作面；主导航只是可重访入口，不要求先找模块。
2. 默认写一句要求，持续显示“保留目标页标题、事实与数字”，点击“先试1页”。历史实际prompt未知也可按参考图片试作，不能声称复用了未记录文本。
3. “精细设置”默认折叠：色板、字体层级、密度、线条、构图、参考角色、模型参数和prompt差异。旧prompt无法可靠拆分时原样展示或人工选片段，不自动乱拆；约束冲突/事实替换风险时展开并明确处理。
4. 确认第8页的短影响计划：产生原图候选，当前图/SVG/PPT继续可看；实际调用次数上限可见，未知费用不估。保存后打开持久交接面板，复制仅表示复制，真实接手后才处理中。
5. 候选返回后固定“当前采用/候选”双栏，参考图作为辅助，持续显示基准和所选请求/尝试；只采用当前候选，保留当前或再试为次动作。
6. 采用后只使目标页SVG及整稿PPT待更新；未改页保持。再把已确认风格方案用于显式指定的余页，执行前重新检查基准。全局规则变化不偷改历史请求。

用户可只调某页，不建立风格方案；风格方案是可追溯可复用的选择集，不新增庞大设计系统管理产品。视觉不稳定也可能由模型/参数/参考图造成，UI同时展示这些差异而非保证prompt合并能解决。

### 3.5 标注与编辑能力

必须有标注，它是“针对一个确定产物版本提出变更”，不是另造一套自由设计编辑器。
支持整稿/章节/页意见；图/PPT预览的点与矩形框；正文文本范围；提示词段落/文本范围；SVG命中有稳定内部ID时元素定位，否则退回画面区域。首版不做任意钢笔/涂抹修图。
每条意见都有project_id、scope、base_revision、意图、正文和状态。scope=project只要求项目；chapter要求固定章节ID/ContentPlan版本；page要求page_id/Page版本；artifact要求page_id、layer、artifact_id/版本。定位是whole|point|rect|text之一；只有point/rect要求画布尺寸及归一化坐标，text要求文本对象版本与范围/引用摘录，不能给整稿意见伪造画布。历史意见只在原目标展示，可明确新建到新基准的意见，原记录保留。同页多个选区保留，执行时可合并要求；不能丢区域合成一段文字。缩放、letterbox留白、浏览器滚动必须统一转换到原始画布坐标；区域不自动迁移到新版。提供无鼠标替代：整页意见和键盘定位。
意图选择用结果语言：“内容不对”“画面风格不合”“结构还原有误”“文字排版问题”；系统建议修改层并展示原因，用户可改。SVG源码为高级只读/下载入口；直接拖形状、在浏览器编辑PPT、外部PPT自动回写不在本期。

## 4. 用户动线

### A：从零到完整制作
启动页→新建项目，填用途/材料→交接Host→内容整合/大纲返回→按需改论证→逐页稿/提示词→第一批原图→整稿画廊检视节奏→通过的继续SVG/PPT检查→整稿PPT及交付。保留既有自动continue策略，不用网页审阅替代专业门控；需要生成全部原图再转SVG的批量优先策略列为后续可选策略，不在本次静默改编排。

### B：20–30页整体观看与纠偏
打开项目→看整稿原图→选偏离页8/9→按第7页参考修正→写一句要求→短影响预览→先试第8页→持久交接→真实接手→固定前后比较→采用→9页复用→只重建受影响SVG与PPT→回画廊确认一致。采用不代表专业审阅通过，须继续原有检查。

### C：从结果反查问题
PPT预览第12页看见箭头方向不对→并排原图/SVG/PPT→原图正确、SVG错误→框选SVG并提出结构修复→仅重建SVG，原图和提示词不变→单页预览/复核→重新装配整稿。如果原图已错，再看实际prompt与逐页稿：逐页稿事实错误改内容；内容对但prompt漏约束改请求；都对但图不合要求则重新试作原图。

### D：中断、返回、导出
重开工作台恢复项目/页/层/缩放/草稿→看任务实际状态→保存未知用原operation_id核实/重放→冲突保留双方→超30分钟提供取消后重新交接→晚到结果拒绝覆盖→固定版本查看/导出。历史阅读不写入，恢复生成新版本，不回滚外部调用事实。

## 5. UI效果与交互规范

定位为桌面专业制作工具，保留严肃工具感。新原型选冷墨#0B0E12、实面#11151B/#161B22、细线#232A33、琥珀铜#E09043动作、2–4px圆角；Satoshi/Geist/IBM Plex Mono优先，缺字体的原型明确标系统回退，正式包必须含授权字体与license。旧OpenDesign蓝色探索保留为历史稿，本轮不是改它的颜色。
1440×900：顶部56px项目定位，左导航184–208px；工作区填满余下宽度；右上下文320–380px仅需时展开。1280×800可折叠左栏，不缩小正文；没有固定三栏审批台、全屏欢迎页、装饰性指标卡。
正文16px、UI14px、元信息12px且保持对比；主阅读画面高优先级，摘要和工具条合并到有限两行。每个局部任务一个主按钮；保存/试作/采用/交接语义分明。
全局导航有当前位置；历史/候选有持续标识。可用产物未加载时用匹配骨架；缺失展示原因+下一动作；失效显示来源和影响；失败在对象旁保留输入和恢复动作。
键盘完成开项目、筛页、阅读、选参考/目标、输入意见、保存、复制、查看候选；可见焦点、语义表格/对话框、关闭返回原焦点。对比4.5:1，触控主按钮44px，减少动画尊重系统设置。仅承诺>=1280桌面；较窄显示可阅读/待办并建议桌面进行多页校准，不假装支持完整手机编辑。

下文“试作不变当前/当前稿保持”均指trial提交与返回的副作用；auto可独立更新current，固定比较不漂移，采用前重新核对计划。正文/整稿操作及历史恢复的具体画面见UI-SPEC§10–11。

## 6. 核心服务与接口设计（提案，不是已存在路由）

沿用 Python 核心与本地HTTP、原生JavaScript ES Modules。先对已有Service/CLI做能力复用，新Web投影集中在view/web而不是前端推状态。新增域对象按最小必要字段扩展现有不可变对象存储。

| 能力 | 主数据/提议接口 | 规则 |
|---|---|---|
| 项目入口 | registry + 打开/新建项目服务 | 仅用户注册目录；旧格式只读提示，不能原地迁移 |
| 链路读取 | GET /api/workbench?revision=；GET /api/pages/{id}/lineage | 摘要/按页读取，明确现有、推导、未知关系 |
| 生成请求 | GenerationRequest版本 + task输入/调用记录 | prepared/submitted明确；submitted不可变，Host回执事实 |
| 内容结构 | ContentPlan + SourceLink + Page稳定身份 | 主线compose扩展，旧项目缺失兼容 |
| 变更计划 | POST /api/changes/plan | 只读影响预览，精确页/层/父版本，操作数量上限 |
| 执行提交 | POST /api/changes/commit | 基准复核+事务+operation_id；不直接调用模型 |
| 候选 | Candidate + POST /api/candidates/{id}/adopt | 单页采用原子；批量采用先全量预检、一次事务全部采用或零采用。冲突逐项列明，用户另选可用子集后新operation_id重新计划，禁止默默部分采用 |
| 标注 | POST /api/annotations/batch | 保存意见不执行；组合ChangeSet交接后执行 |
| 风格校准 | StyleRecipe版本 + proposal与prompt diff | 引用固定参考版本，目标内容不可隐式替换 |
| 运行读模 | summary/full任务投影、handoff | copy不迁移task；取消/晚到保护沿用核心 |
| 版本与导出 | 现有history/view扩展指定版本与engineering | 可对外审阅包与工程包分离，delivery继续强校验；SVG/PPT层展示真实可编辑性检查和未知项，不从一张截图推断文字可编辑 |

### 6.1 最小新对象

ContentPlan：章节、页目标、来源关联；不替代Page正文真相。
GenerationRequest：请求的冻结文本与引用；一条请求可有多次调用尝试，输出由attempt绑定。
ArtifactEdge：typed(parent,child,role)，可由已有引用投影不必全部另存；明确per_page/whole_deck与可置信性。
ChangeSet：用户意图、作用域、基准、计划动作、标注与执行任务集合；重用Task执行状态不另开调度器。
Candidate：产物与请求/调用/基准关联、选用事实；并行候选不写当前指针。
StyleRecipe：用户选定风格字段及参考版本，建议文本与确认后的文本分开。
以上命名为提案，落地时优先扩展现有契约而非重复存储同一字段。

### 6.2 局部修改与失效传播

| 改动 | 直接改变 | 下游动作/有效性 |
|---|---|---|
| 仅标注/草稿 | 草稿与意见 | 不让当前任何产物失效，不执行 |
| 逐页稿事实 | 指定Page版本 | 提示词/原图适用性待判；需重做时显式生图，SVG/PPT旧版可看 |
| 风格/提示词试作 | 新GenerationRequest/候选 | 当前版本不变；只试选中页 |
| 采用新原图 | 指定页当前原图 | 该页SVG与PPT预览不再适用；整稿需重新装配；其它页保留 |
| 仅SVG结构修复 | 新SVG | 原图/请求不变；整稿装配及对应PPT预览重跑 |
| 重排/删页 | 有序页面集合 | 既有未改页产物保留；整稿PPT失效；删页未完任务作废 |
| 材料/受众变更 | content_basis/inputs | Host明确判断影响页；不凭字数/时间自动宣告无影响 |

计划必须体现现有门控。UI可请求某阶段，核心拒绝不满足依赖的执行并列出前置；不能通过新接口跳过逐页原图对照、专业复核和整稿检查。

### 6.3 一致性、性能与安全

读当前快照+summary探测变化，活动3秒、闲置15秒、隐藏暂停、focus刷新、失败退避最大30秒；单请求在途。任务有分页，30页矩阵摘要一次加载，详细prompt按需，原图懒加载，不轮询触发continue。
每次写入带project/base_revision/目标对象基准/operation_id；同ID相同内容返回同结果，异内容拒绝。preview plan绑定基准与完整payload摘要；执行前失效则重新规划，不能默默扩大页范围。候选晚到只记事实不能覆盖当前，取消事实与调用用量保留。
本机服务仅loopback，沿现有全部请求Host校验、Origin、X-Deck-Token会话写能力与请求体大小限制；注册目录之外不可读，下载路径白名单；文本转义，SVG隔离渲染/净化避免脚本；不把绝对路径、提示词私密材料和模型密钥放入审阅导出。工程包需明确包含内部材料，默认不携带认证信息。

## 8. 验收与不做范围

产品验收：初次/再次/无产物/部分完成/历史/冲突六种进入状态可理解；24–30页原图不再逐文件打开；同页跨层定位；跨页参考保留目标内容；标注对齐；候选采用后影响正确；没有Host时可看/存，不能显示自动执行。
契约测试：prepared/submitted区别、旧缺字段、引用版本、重复提交、事务失败、并行结果倒序、取消后晚到、删除页/重排身份、失效只传播相关层、工程/审阅敏感数据隔离。
浏览器：1280×800/1440×900，键盘、焦点、滚动/缩放后区域、草稿隔离、离线资源、固定比较、下载版本。真实Host：从页面prompt冻结到图片输出绑定一次完整证据，两轮视觉修改、一次跨页风格扩散、一次只改SVG。自动审阅和人工肉眼确认分别记录。
性能目标统一按ENGINEERING-SPEC§6（全部待实测）：300页×5候选×3Attempt，warm summary p95≤250ms，30页窗口首屏可操作≤2s，最多6图请求/2解码、60缩略图/4大图缓存、20分钟稳定段heap增长≤20%。summary与首屏是不同测量；最终安装复验同一manifest，点击本地反馈<100ms另记，不以100页观测代替固定门槛。
不做：云多人账号平台、通用节点编排器、自由画布PPT编辑、外部PPT自动回写、独立模型代理、任意插件市场。高级诊断可以有节点关系只读视图，不能挤占主要阅读路径。
默认入口切换/对外推荐必须具备M2真实证据和W12安装验收，发布仍需既有发布授权；本轮不自动迁移真实HOME或用户项目。新方案完成也不证明旧Web已被替代。
