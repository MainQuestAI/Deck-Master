# Deck Master 生成工作台 V3 · 交互原型

直接用浏览器打开 `index.html`，或在此目录运行 `python3 -m http.server 8766` 后打开 `http://127.0.0.1:8766/`。没有外部网络资源、框架、构建步骤或生产服务依赖。

这是独立设计原型。24 页内容、所有原图/SVG/PPT 预览、提示词、来源和 Host 进度均为**合成演示数据**。它不会运行模型、调用 Deck Master CLI、改变真实项目或导出真实文件。页面图件使用内联 SVG 绘制，作为三种不同产物层的展示样本，不能据此声称三种真实产物已生成。

## 可走通的路径

1. `#projects` → 打开项目 → 制作总览，查看整份方案的逐页制作矩阵。
2. 总览 → 整稿画廊 → 切换原图/SVG/PPT 层、网格/连续、筛选、搜索 → 点一页进入完整生成链。
3. 第 8 页 → 原图与实际执行提示词并看 → 双层固定比较 → 提示词草稿保存（不执行）→ 检查影响后加入待交接。
4. 单页 → 标注与意见 → 阅读/框选模式（Esc 可取消框选）→ 整页意见或可选选区 → 保存意见（不建任务）→ 加入修改（创建待交接请求）→ 复制文本（复制不等于接手）→ 原型控制模拟接手/返回 → 比较候选并采用。
5. 风格校准 → 第 7 页作为参考，8/9 页作为目标 → 一句话要求，保留目标事实 → 先试第 8 页；风格维度、参数说明和提示词差异在可展开的“精细设置”内。试做后保存请求/目标层/基准版本，复制显示“已复制，尚未开始”，总览待办可重新进入固定请求 → 明确标记的原型控制模拟接手/返回 → 比较采用 → 余下第 9 页加入待交接。
6. 第 12 页 SVG 是明确标注的箭头方向偏差合成样本：在 SVG 保存意见，再点“仅重建 SVG”会把该层已保存意见及选区带入同一条请求。模拟返回后并排比较 SVG v2/v3；采用只更新 SVG，原图与实际提示词保持，PPT 旧版待更新。“加入修改”也可直接创建该层请求，不必重复执行两种入口。
7. 内容与来源 → 章节关联页、材料记录 → 请求材料影响判断，保留“已上传”和“已读取”的差别。
8. 运行与交付 → 选择固定版本 → 审阅文件/工程包清单 → 交付缺项跳回缺少 PPT 的页面。

`←` / `→` 在单页工作台切换页；输入时不会触发。所有操作使用原生按钮，可键盘聚焦。任务、意见及提示词草稿存于 `localStorage`；侧栏有显式重置入口。第 19 页故意缺失历史执行提示词，不会从图像反推。第 21–24 页无原图；第 17–24 页无 SVG；第 13–24 页无 PPT 预览；空位不会用原图冒充其他层。

## 设计与限制

- 冷墨色界面、琥珀铜动作色、实面细线、克制圆角。核心是整稿生产索引与稳定页面身份，不是固定三栏审批台。
- CSS 字体声明优先 `Satoshi / Geist / IBM Plex Mono`。本原型没有附带字体二进制，未安装时回退为系统中文字体；不会请求 CDN。字体随包许可与离线装载需要在正式前端包验收。
- 默认设计宽度 1280×800、1440×900，窄屏有折叠布局。完整生产桌面交互仍需浏览器验收。
- “新建项目”具备项目名称/目标必填验证、材料说明、保存位置概念、取消与本地模拟记录；创建后进入独立无产物准备页，再保存首轮模拟制作请求。不会把已有 24 页样本伪装成新项目结果。本机目录授权、真实项目发现、上传文件和生产接口未接入。
- 标注坐标按实际演示画面归一化，并按页、层、基准版本保存和恢复；不会把一个层的选区迁移到另一层。当前只有矩形标注，不含自由笔画，正式版本还需产物哈希和实际尺寸契约。
- 风格参考与目标固定为第 7 / 8、9 页；示范维度可选，未实现任意页批量选择。
- 候选的图形变化是确定性的样本切换，不是模型生成；采用与质量通过分开显示。请求保存目标层、固定基准、输入与候选身份；取消后的模拟返回不可采用。真实取消/超时/晚到结果、冲突、多执行顺序仍需正式契约与测试验证。
- 已执行 `node --check app.js`，以及 `python3 validation/smoke.py`：独立 Chromium 1280×800 下检查缺项显示、模拟接手门控、风格候选采用、页面局部下游失效、意见和选区草稿刷新恢复、旧提示词未知、7 个工作面无横向溢出。结果见 `validation/smoke-result.json`，运行时错误为空。1440 首轮截图也在 validation 目录。主任务另行执行完整设计审阅；本次通过只证明合成原型的指定交互。

## 设计评审修订验证

`validation/revision-smoke.py` 覆盖默认简化、精细设置折叠、交接复制后的真实反馈、离开/刷新后恢复固定请求、当前/候选双栏、仅采用第 8 页、Esc 退出框选、保存意见不创建任务、加入修改创建任务、新建项目空值校验/取消/独立无产物准备页。结果在 `revision-smoke-result.json`；修订后的 1440×900 截图文件名以 `revised-` 开头。均只证明合成原型的交互，不是生产 UI 验收。


## 第一轮 Review 修复后的能力与验证

- 普通修改请求按目标层比较和采用；P12 的 SVG 箭头从反向改为向右。原图与提示词保持 v2，SVG 更新为 v3，仅 PPT 保持旧版并提示待更新。没有把 SVG 返回误作原图采用。
- 风格候选支持采用、保留当前、调整要求再试。再试进入可编辑要求，保存新请求；旧请求、失败/取消状态和候选记录不覆盖。失败或取消后明确显示原图保留和下一步。
- 风格参考 P7 原图版本、计划目标 P8/P9、每次实际执行范围、目标层、维度、自由要求、保留事实、请求与基准在保存时固定。离开、刷新、复制和 P9 延续均读取该快照；这些是原型数据，不是生产协议。
- 当前产物的标题、图下版本和执行提示词身份一致；固定比较保留进入比较时的快照，采用后的请求比较仍能看到旧基准与已采用候选。
- P9 已有请求时显示“查看第 9 页请求”，重复进入沿用同一条；只有明确选择重新试作才保存下一条请求。

已运行 `node --check app.js`。`validation/smoke.py`、`validation/revision-smoke.py` 和新增 `validation/round1-fixes.py` 均在 Chromium 1280×800、1440×900 下通过，运行时错误为空。前两个脚本可用 `PROTOTYPE_VIEWPORT=1280x800` 或 `1440x900` 选择视口；专项脚本自动检查两种视口。

专项结果见 [round1-fixes-result.json](validation/round1-fixes-result.json)。`round1-before-*.png` 保留修复前页面；`round1-after-*.png` 覆盖 P12 缺陷/候选/采用、风格选择、固定交接、失败、取消、P8 版本和 P9 复用请求。已目视检查 SVG 双栏比较、风格三种决策和失败状态截图。此次结果只证明上述合成原型交互；不代表真实 Host、模型、CLI、产物生成或生产验收通过。


## 第二轮 Review 修复后的操作范围

材料补充框保留真实输入草稿，空值就地提示；保存后的请求、刷新恢复和交接文本使用同一份输入。缺图页可直接“安排本页原图”；缺图筛选可为 P21–24 保存四条同批单页请求，各自返回、比较和采用。首次生成与重新生成的文案分开，首次采用后该页原图可查看并能刷新恢复。

局部选项重绘后保持控件焦点，工作区导航聚焦新标题；对话框有标题语义，关闭/取消后回到触发控件。矩阵只有一个 Tab 入口，方向键移动，Enter 打开页/层，Esc 返回原入口；状态按钮包含页号、标题、产物层与状态。标注提供 x/y/宽/高百分比输入，键盘选区同样绑定产物版本。单页左右翻页仍避开输入框。P19 提示词层只保留一份历史缺口说明，右侧用于草稿或意见。

风格比较占满工作区，请求事实放在下方；固定基准、候选和参考图均可单独放大。画廊提供 2/3/4 列；请求更多列后若每幅不足 280px，自动按 2 列显示并说明原因。总览陈述可看产物与待办事实，恢复请求入口为次级动作；矩阵含小缩略图。任务状态保留明确文字，并分别使用处理中、已采用、失败、待处理及中性色。

`python3 validation/round2-fixes.py` 自动验证两种桌面尺寸的 R2 行为，并重跑 `smoke.py`、`revision-smoke.py` 和 `round1-fixes.py`。结果见 [round2-fixes-result.json](validation/round2-fixes-result.json)，修复后截图以 `round2-after-` 开头；修复前证据复用 `../reviews/round2-native-evidence/` 的冻结截图。本轮验证不包含真实 VoiceOver 朗读或完整 WCAG 认证。

章节折叠、任意页风格参考、真实 Host/模型、保存未知或冲突注入仍未在主原型实现。侧栏“异常与整稿操作样板”链接到独立设计样本；它不改变当前项目，也不代表真实执行状态。
