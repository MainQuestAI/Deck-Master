## R3-04 · P2 · 新建项目与首次 compose 任务的关系未收敛

位置：`UI-SPEC.md:33`、`packages/W03.md:21,37`；源码核查 `src/deck_master/service.py:175–183`（cad56e0）。

UI-SPEC 要求“创建项目只建项目；有材料后单独整理内容并生成大纲”，W03 又约定仅复用现有 create。现有 create 在没有 draft 时会立即创建 compose task 并返回待 Host 状态，它没有执行模型，但已经产生任务。规格没有说明后续“整理内容”应使用该任务还是再建一项；空材料项目可能显示可交接的旧任务，或材料补齐后产生重复任务。

最小修订：明确一个方案即可，优先复用已有行为：create 可以登记唯一待交接 compose，创建成功不调用模型；无材料/信息不足时 UI 不宣称可生成，后续补材料使用 inputs 协调及原有任务失效规则；“整理内容”读取最新 eligible compose 并交接，不无条件再创建任务。W03-AC01 增加“创建→补材料→交接”的任务 ID/数量与状态断言。若产品确实要求创建时零 task，必须把延后开 compose 的最小共享核心扩展明确归 W03，并保留旧 CLI create 默认行为，不能把它当现有服务能力。
