# 开发卡（C01–C09）

主卡唯一负责关闭；协作卡可以实施子项，但不能分散关闭责任。每张卡的验收必须逐条留证。

## C01 · 连续写意见和恢复后继续工作

**目标：** 保存 A 后仍能保存不同的 B；旧输入有去处，真实依据变化仍受保护。
**模块：** `resources/static/v2/drafts.js`、`annotations.js`、`page-workbench.js`、`project.js`、`ui_journal` 契约。
**修改：** 自动恢复只接受精确 revision 的草稿；旧稿进入恢复列表；新增「对当前版本写新意见」创建新
`draft_id` 与新 basis 并保留原稿；初次与恢复后挂载共用同一适配；历史、旧依据、请求进行中、响应未知、
冲突各有可见原因与下一动作。
**验收：** 保存 A→返回当前→写 B→保存→刷新，两条独立正式记录正确；真实产物变更拒绝旧局部范围而保留
文字；恢复不改变默认布局；晚 ACK 不覆盖新输入；未知响应沿原 operation 核实，无新请求自动重派。

## C02 · 分开正文用途，消除重复保存

**目标：** 用户不需要推理两个保存按钮的区别，私人文字不隐式发表。
**模块：** `drafts.js`、`annotations.js`、`page-workbench.js`、`business-operations.js`。
**修改：** 意见正文与私人笔记分开编辑与恢复；自动保留替代主面板的显式个人保存按钮；旧混合草稿首次
使用时选择用途并创建独立新稿（原记录保留）；保存成功标记正文/范围/依据签名，未变化时显示已保存并
阻止重复提交；修改已保存内容的后续输入表达为新意见。
**验收：** 实际 annotation、instruction、交接载荷中均无私人正文；连点与成功后再误点只新增一条；
同文不同合法范围仍可新写；恢复文件、跨会话与换端口恢复兼容；未确认丢响应不认定失败。
不得以服务端全局正文去重实现。

## C03 · 对齐意见范围、列表与历史读取

**目标：** 用户能直接辨别这条意见说哪页、哪层、哪个底稿。
**模块：** `annotations.js`、`annotation_service.py`、`web.py`、annotation 合同与 HTTP 测试。
**修改：** page/artifact/project/chapter 的可见标签与 payload 一致；单页默认展示本页整页意见与当前图层
意见并分组，其它图层/整稿/章节显示数量按需查看；卡片显示摘要、对象、范围、底稿版本与真实状态；
历史 API 接出现有固定 revision 读取能力，并定义合法过滤、无效参数与错误状态。
**关键边界：** 「意见存入哪个快照」与「意见针对哪个底稿」是两件事，不得按 base_revision 等于当前
revision 粗暴过滤；旧 artifact/whole 记录不改写成 page。
**验收：** 两页、三层、三个版本混合四种 scope；本页新意见保存后能找到，异页局部意见不混入；整稿认可
不变成本页修改要求；旧快照不静默显示未来讨论；局部坐标与固定引用匹配，选入计划前提示不适用原因。

## C04 · 明确修改要求和候选生效方式

**目标：** 选已有意见就能形成可理解的修改计划；结果如何生效在提交前说清楚。
**模块：** `annotations.js`、`changes.py`、`tasks.py`、候选/交接组件及 change/result 合同。
**修改：** 选意见后进入独立「修改要求」区域，填入所选意见原文为可编辑要求，私人草稿不再参与；空值/
不适用意见在预览前中文拦截；跨页层或矛盾意见逐目标确认或拆分；预览列明修改与保留内容、下游影响、
调用上限与「返回候选后采用」；要求或基准变化使旧预览失效。
**按 D01：** 普通修改默认 `mode=trial`；正文层映射协议 `intent=content` 而用户意图语义独立保留；
不支持组合明确禁用并说明，不静默回退 auto；旧 auto 任务保持原含义并清楚标示。
**验收：** 已有意见+空个人草稿可以预览；空要求发送前被拦截；私人正文不进入计划；跨页不自动扩任务；
fixture 验证返回后作品引用不变、明确采用才替换、取消及迟到结果保护。真实 Host 证明放 C09。

## C05 · 单页工作区与技术详情重排

**目标：** 三视口可以看作品、写意见、完成保存，长内容不破坏主动作。
**模块：** `page-workbench.js`、`workbench.css`、`navigation-usability.css`、`request-view.js`、`images.js`。
**修改：** 四态布局（阅读/写意见/看意见/比较）；压缩顶部链路，作品占剩余高度，保存行贴近输入；
提示词、JSON、hash、命令移入技术阅读路径并保留原文、选段、固定版本与返回；依真实产物标注实际 PPT、
SVG 或缺失原因；窄屏采用作品/编辑工作面切换。
**U13 关闭主责：** 维护跨工作面禁用动作清单（历史只读、旧依据、阅读模式、未选择、空输入、请求进行中、
响应未知、冲突、缺工具），逐项核对可见原因与下一动作；批次 2 可关闭布局子项，总体关闭待批次 3 收齐
任务/交付证据后交 C09 复核。
**验收：** 两桌面首屏 fit 完整作品，编辑时输入与保存同时可见；390 首屏作品与主入口可读、按钮不逐字
竖排；30 条意见与长原文不推走作品；滚轮作用可预测；切页/层、关闭再开保留正确输入与焦点；技术详情
完整可查且返回不丢上下文；主要禁用按钮都能解释为什么及怎么继续，错误不裸露内部英文代码作为唯一反馈。

## C06 · 候选与历史比较形成连续动线

**目标：** 新结果看得见，比较占主空间，退出回到原位置。
**模块：** `trial-actions.js`、`candidate-desk.js`、`page-workbench.js`、`project.js`、比较组件与 `comparison-canvas.css`。
**修改：** 近场显示候选数与待比较数，「新试作」分离；中央与单页入口统一固定 revision；当前跨版结果
只经显式导航进入；候选/历史共用同一空间与焦点规则，保留同页同层、固定双方；实际 PPT 的可读/未生成/
失败/缺工具分别呈现；采用先展示影响，沿用显式采用与保留决定。
**Esc：** 按最上层处理（关闭对话框/退出全屏/结束比较），不让同一次事件继续触发画廊导航；普通单页
既有返回行为保留。报告一重复复现、报告二 headless 未复现，须用 headed 浏览器与原焦点路径复核，
不直接宣称所有浏览器同一故障。
**验收：** 近场直接找到既有候选；候选返回前历史两入口均无未来候选、返回后当前可见；任选两次具体历史
修改比较，后台新结果不改变双方；全屏 Tab 到可滚动区域按 Esc 留在比较；结束比较焦点回入口，页/层/缩放/
输入保留；旧候选过期仍拒绝采用。

## C07 · 任务入口、待办与长列表

**目标：** 点击任务后立即知道要处理什么，不先读运行流水。
**模块：** `project.js`、`routes.js`、`run-desk.js`、`overview.js`、`candidate-desk.js`、`action-targets.js`。
**修改：** 普通工作面切换清除无关 layer/subtarget 并落到任务标题；只有明确交付链接定位交付；保留返回
阅读位置的语义；首屏以真实待接手、需核实、待采用、待检查及交付摘要组织；全部流水进入次级入口并沿用
分页；范围显示整稿页数或选中页数，用第 N 页+标题+图层替代孤立内部 ID，候选分组补图层。
**依赖：** 拆两个子项——路由修复在批次 1；待办整合在批次 3 消费 C04/C06/C08 的行动目标并收尾。
**验收：** 从总览、内容、画廊、单页 PPT、风格进入任务都到正确首屏；定向导出仍直达交付；136 条记录
不淹没待办；复制不冒充接手；0 待办、失败、未知、处理中、候选返回均有准确状态与入口；Tab 与返回位置正确。

## C08 · 采用后更新、检查与导出恢复

**目标：** 正式导出拒绝时知道缺什么、先处理什么，并能回到导出。
**模块：** `delivery-desk.js`、`exports.py` 事实投影、`action-targets.js`、任务/阶段读模型。
**修改：** 按产物未记录、依据变化、检查未评估、检查未通过、输入待协调、规则限制或无法自动分类分类
显示影响范围并保留全部原始缺项详情；先呈现可处理项及匹配入口；只使用真实支持的 action/target，没有
Web 执行能力时给「交给制作工具处理」；缺工具说明具体工具与恢复入口；采用后旧包仍属旧版本。
**验收：** 复用审计采用前后快照（先成功导出、采用已有 SVG 后正式拒绝）；能辨认 SVG 预览、PPT 预览、
整稿 PPT 的更新与独立质量评估项；处理回执到达后显式选择新版本重新核验；断网按原 `export_id`、用途与
固定版本核实重试，不换版本。另用标注清楚的夹具覆盖 `page_limit_violation` 与未知 reason：两者都保持
阻塞，不落入成功态或虚构修复按钮。

## C09 · 九流程回归、安装包和真实验收

**目标：** 交付可复核的完成证据，区别工程可用、真实执行与用户认可。
**模块：** 优先扩展现有 `test_navigation_usability_browser.py`、`test_deep_quality_browser.py`、
`test_comparison_canvas_browser.py` 及 annotation/change/journal/HTTP 测试。不新增仅为测试服务的生产 hook。
**验收产物：** 九流程矩阵逐项结果、精确 head/build、三视口截图与操作回执、缺陷关闭映射、当前安装包
checklist 复验、明确未执行项。测试通过不替代用户可用性确认。
**本轮范围：** 只交付工程与浏览器两层；真实 Host、独立 30 页副本、真实 HOME 安装与用户视觉认可
明确列为未完成。
