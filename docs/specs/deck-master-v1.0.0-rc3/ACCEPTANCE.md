# RC3 验收与交接规范

目标版本 V1.0.0-RC3。本文件定义执行卡出口和汇总方式，专业 AC/CQ 的唯一具体判据仍为[内容协作 v1.2 ACCEPTANCE](../deck-master-content-collaboration-v1.2/ACCEPTANCE.md)。37 项原 AC、13 条 CQ 全部保留，原能力 Owner 不变。任务描述、映射与历史报告不形成第二套通过状态。

## 1. 阶段出口

| 执行卡 | 可观察出口 | 不能代替的后续证据 |
|---|---|---|
| RC3-00 | 六项修复的连续路径与必要正例、准确联合 tree/最终回归/CI/必要审查、基线与接口接收 | 后续专业内容、设计、notes、真实安装与用户效果 |
| RC3-01 | 实际方法产出完整稿；浅稿可定位并实质修复；锚点重新校准；固定正文可交设计 | 后续完整稿与实际文件检查 |
| RC3-02 | 真实 PPTX notes 逐页完整，重排/仅备注修改/原注保留与依赖有效 | 内容主线、真实使用认可或最终安装一致性 |
| RC3-03 | 实际投影/样页/关系/编辑/页级失效正负例成立；范围调用符合授权 | 未覆盖的整稿风险与全入口集成 |
| RC3-04 前置 | 隔离安装消费正确方法与例子，必要独立审查能力真实可用 | 完整 H01–H03、四 Skill 全路径、正式安装和最终集成 |
| RC3-04 完整 | 当前候选三入口/四 Skill/导入迁移/只读/恢复一致；版本与安装可核对 | 本次任务、实际成品和最终候选索引 |
| RC3-05 | 全部适用 AC/CQ 的准确版本证据、真实使用/文件检查、RC3 候选结论 | 正式 1.0.0、未获授权的合并/发布/激活 |

工程交接出口与最终 AC 关闭分开。前序卡可交付可用输入让后序继续，后续真实验收再回填前序 AC；不能要求专业证据全部完成才允许集成，也不能因工程交接完成提前关闭专业层。

## 2. 唯一证据台账

从 [evidence-ledger.template.json](evidence-ledger.template.json) 复制生成某个候选的执行台账。原能力 Owner 对 AC 签结论；RC3 执行卡提供唯一汇总位置，其他卡只贡献证据。台账至少含：
- AC/CQ、能力 Owner、执行卡、准确候选 SHA/tree 与输入/输出 hash。
- 入口、环境、Host/模型/工具/实际安装与方法身份。
- Given/When/Then 的实际结果、证据层、来源、失败与关闭/复测、旧证据复用依据。
- 原始稿、首次 Owner 稿、当前返修与方法复跑分别定位，用户输入变化单列。
- 状态 PASS / FAIL / BLOCKED / NOT_RUN；确实不适用时 NOT_APPLICABLE，必须有场景依据。

台账是开发验收文档，不新增 Runtime 状态、合同 schema 或批准事实。37 AC/13 CQ 模板初始 NOT_RUN 只表示当前 RC3 候选尚未验，不撤销历史版本结果。历史结果必须标版本和证明层。

## 3. 失败与证据复用

只引用原 ACCEPTANCE §1.2 / §1.2.1 的 F0–F3、原 §1.1 的 L0–L6。RF01–RF06 是上游问题编号，P1/P2 是代码审查优先级。不得按编号相似自行换算严重度。

原始首稿与首次 Owner 完整稿失败不可被最终精修覆盖。F0/F1 阻止该候选通过，影响约定用途的 F2 必须修复；F3 按有效范围处理。失败不要求停止全部研发，但当前候选相应结论保持失败/阻塞。

旧 schema/门禁等未变行为证据可按准确依赖复用；新增页例/浅稿/投影/关系/notes/实际方法/最终安装及真实效果必须补本轮证据。最终候选变化先分析影响，再重跑受影响用例和必要对照，不能全部沿用也不无界重跑。

## 4. 当前交付检查与候选收口

按用户在 2026-10-18 的明确纠正，不再要求十二真实 Host 会话、两个 Owner 试用、每项三名听众、真人试讲计时或完成 E1/E2/E3 实验才能结项。普通内容与成品检查由制作/审阅 Agent 完成；用户正常审稿意见如有则处理，不要求其额外组织参与者。

当前检查限于：任务与来源是否被完整理解，论证与逐页内容是否具体，表格/箭头/单位/限定是否正确，实际渲染是否清楚，文件是否可编辑与正常导出，适用 notes 是否完整，相关入口与安装版本是否一致。用户明确提出时长时检查合理估算，不要求实测证明。

仍保留当前版本的实际检查与失败记录，不把取消要求写成已执行或通过。历史 AC/CQ 结果保留其版本；仅因听众/固定实验缺席而阻塞的旧结论不再代表当前门槛。需按修订后的具体条目重新核对，不直接批量改成 PASS。

人工 professional policy 仅在本次明确适用时需要真实身份和文件记录；不把它扩成所有 PPT 的默认人工审批。规划、工程候选、发布与安装激活仍按各自实际完成事实说明。
