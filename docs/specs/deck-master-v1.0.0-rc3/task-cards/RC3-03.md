# RC3-03｜密度设计与关系保真

**目标**：无需旧蓝图即可试作真实代表页；内容结构和密度进入实际请求，最终页面保留正确关系与可编辑信息。

**责任**：设计与制作实施线，原 T05 Owner；T02 对必需兼容调整负责。汇总 AC-D01–D03、CQ-03～CQ-05，I04/I05。

## 输入与进入条件

RC3-00 的共同基线与范围/预算接口。无调用设计准备可提前；真实样页需 RC3-01 固定且合格的完整 Page、页职责和限定，以及该范围有效的前审/授权。不要求整套 T03 的用户验收先关闭。

## 实施工作

1. 按 CONTRACTS §11.4.1 实现 content_requirements.v1 派生、basis 与完整 prompt 投影，Page/Plan/recipe 权威分清，fidelity 缺字段诚实为空，不倒推补造 Narrative。
2. 初始 style proposal 绑定真实代表 Page，无旧 blueprint 时走合法路径，不伪造原图。允许零调用版式可行性，真正生产冻结固定全文。
3. 代表页覆盖矩阵/机制/数据/架构等当前风险；数量由未覆盖风险决定。一页请求只试一页，候选不自动采用，采用/接受维度/扩范围分别有实际依据。
4. 逐层检查 Page→冻结 prompt→蓝图→SVG→PPTX→渲染，保留单元格归属、箭头方向、单位、限定、阅读顺序和主要信息编辑性。
5. 比较“文本完全相同但交换归属/反转箭头”的负例，与“同关系仅移动布局”的正例；前者为内容语义变化，后者不误判。无关 Plan 页修改只保留真正页级失效。
6. 定位损失在哪层再定向修复；不靠缩字、统一图标卡或无数据装饰性数量图兜底。合理示意与教学步骤可保留。
7. 固定正文执行 E2，逐层损失执行 E3，原始图片/产物和失败保留，不借设计比较补写正文。

## 输出

密度投影与实际请求、无旧图初始样页、覆盖/候选与维度决定、语义/几何成对失效记录、原图/成品对照、回读/渲染/编辑证据、E2/E3 所需固定产物。

## 工程交接与最终验收

交接出口：代表内容进入冻结请求且关系可用，范围/额度无扩大，产物可进入 RC3-04。最终 D01–D03/CQ 关闭必须覆盖实际设计与成品，字符回读全保留不足以证明关系与视觉正确。

## 验证与失败条件

只加“高密度”标签、概括漏传、混版本、recipe 覆盖内容语义、错箭头/归属仍文字覆盖 pass、无关页重做全稿、私自删关键内容或放大样页范围均失败。

## 并行与主要落点

主要落点：design resolver、production.project_prompt、request freeze/dependency slices、styles/visual_styles、changes/candidates 与制作审阅方法。与 RC3-02 可并行，公共 compiler/输出依赖改动统一合流。若实际 UI 修改须先读 DESIGN.md，并沿用现行 OpenDesign 设计。
