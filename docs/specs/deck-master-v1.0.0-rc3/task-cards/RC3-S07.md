## 问题和边界

六页 imported_mapping 原稿、null Narrative、P5 Request 下，真实接受的 Page-only
repair 会更新 P5 Page Ref，却保留旧 Plan link。Plan 投影成为 basis_changed，
中央 content phase 因 imported manuscript mapping stale 而 blocked。同条件的
现有 direct edit 已保持 links current。

generic `tasks.accept_result` 在原实际 Page/layer scope gate 和 trial 分流之后，
用完整的结果 Page 集合调用既有 `refresh_v2_plan_links`。只有已有 bound 或
imported_mapping v2 Plan、没有结果显式新 Plan、且实际 Page Ref 集合改变时才维护。
派生 Plan Ref 与真实 Page/Task result_refs、operation receipt 在原 CAS 中一起提交。
原 helper 对完整 membership/order、旧 mapping 当前性和 Page 身份的拒绝仍生效；
不会把 Page 写权限扩大为 editorial Plan 权限，也不会修复无关旧映射。

Plan input、roles、budgets、notes、Page order、Narrative、sources、非目标 Page 和
原 basis 保留；诚实递增 version，记录 previous_ref 和实际 task_id。旧 Plan 仍可读。
无变化 Page 不制造 Plan 版本，v1/无 Plan/planned 不转换。现有 compose/reconstruction/
repair 输出与 visual 失效规则、call facts、幂等和 late-result/CAS 路径保留。
`editing.edit_page` 路径未改，仍维护 links 并 supersede 受影响的 pending repair。
