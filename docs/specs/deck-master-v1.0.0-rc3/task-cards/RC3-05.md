# RC3-05｜稿件、成品与 RC3 候选收口

**目标**：核对当前任务、原材料、完整稿和实际 PPT，关闭具体内容/文件问题，交付可用的 RC3 候选。用户无需组织听众反馈或参加额外实验。

**责任**：原 T08 Owner 汇总 U01–U05、CQ-08～CQ-10/CQ-12，其他原能力 Owner 提供对应结果。

## 输入与进入条件

使用 RC3-04 已集成候选、已有完整稿件与来源、对应 PPTX/SVG/渲染及备注。已有材料够用就复用，不强制重建旧实验、凑会话或招募参与者。

## 实施工作

1. 对照任务和原材料检查事实、结论、范围、逐页职责和信息增量，修复空泛、重复、缺解释和无依据推论。
2. 对照实际页面检查密度、表格归属、箭头方向、单位、限定与阅读顺序，确认内容没有在制作中丢失或被误导表达。
3. 检查实际 PPTX 可读、主要信息可编辑、导出/恢复可用，按用户所选方式回读 notes 或独立讲稿；不以 XML 存在代替内容正确。
4. 用户明确给出时长或页数时做合理篇幅适配并标明估算；没有要求就不增加硬时长。不安排默认真人试讲或收集听众反馈。
5. 如已有用户审稿意见，按具体意见修订；没有额外用户参与不构成阻塞。内部对照只在定位问题时按需要使用。
6. 将当前候选、包/方法/安装身份、适用 AC/CQ 和具体检查结果归入同一索引；取消要求与历史结果分别说明，未检查项目不伪写 PASS。

## 输出

任务—来源—稿件—实际文件对应、内容/渲染/回读与编辑检查、具体问题及修订、当前候选与适用 AC/CQ 汇总。不要求听众名单、反馈问卷、试讲录像或固定轮数对照。

## 工程交接与最终验收

按修订后的 U01–U05/CQ 条目核对本次所需交付，内容、文件和相关工程问题关闭即可收口。只有本次明确要求的人类 professional policy 才需要其对应记录；不为所有 PPT 增设人工实验门槛。

## 验证与失败条件

虚构事实、主线偏离、正确但浅、必要限定丢失、关系错位、不可读/丢 notes、版本混用或未检查却标通过均失败。旧失败按原版本保留，不要求为了证明效果而重新招募用户或恢复旧实验。

## 并行与主要落点

在实际候选和产物上按风险检查，发现问题后定向修复/复核。更新候选与证据索引，不改写历史原件，不自动发布、激活或迁移真实项目。
