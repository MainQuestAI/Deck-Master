# RC3-05｜真实验收与 RC3 候选

**目标**：证明本轮在真实流程与约定用途下可用，汇总 V1.0.0-RC3 候选与证据，不让测试数量或最终精修稿代替首次效果。

**责任**：整体验收责任，原 T08 Owner；其他能力 Owner 对自己 AC 的结论负责。汇总 U01–U05、CQ-08～CQ-10/CQ-12，I07。

## 输入与进入条件

协议、合成材料、答案隔离与记录模板可在规划时准备。E1 在 RC3-01 与 RC3-04 前置能力可用时执行；E2/E3 随 RC3-03 产物执行；最终关闭需 RC3-04 完整集成与最终候选身份。

## 实施工作

1. 遵循原 ACCEPTANCE §4/§4.1，冻结 E1-A（补强前共同候选）、B（相同基础的本轮内容补强）、C（固定 CyberPPT 清理噪声版）。同材料、用途、预算，保留各组原生产物，只读转换不帮某组补写。若 RC3-04 前置切片改变共同运行基础，开跑前重核 A/B 的准确代码、安装、方法与允许差异，保留 RC3-00 原接收身份；不得沿用旧安装标签宣称纯方法效果。
2. 保留原始完整稿、至多一次同口径独立审阅与一次自主返修后的首次 Owner 稿，以及 Owner 后修改/方法复跑。额外循环单列；见过的例题不声称陌生迁移，答案对 Writer 隔离。
3. 固定正文做 E2，逐层定位制作损失做 E3；同一合格证据可复用，必须注明所支持问题与最终候选依赖。
4. 完成原定十二真实 Host 会话、两个代表性 Owner 试用（现场与独立阅读）、各至少三位未参与写作的目标类似受众。模型扮演用户不补人类证据。
5. 完整试讲计时、关键限定与必要练习不临时跳过；阅读稿无需作者补主线。失败按原固定任务归因，新增材料/目标变化单列。
6. 检查最终 PPTX/SVG/渲染/正文/关系/notes/编辑性/隐私及依赖；真实 professional policy 要求的人类证据独立核对。
7. 汇总所有 37 AC/13 CQ 的版本化结论，记录旧证据复用依据、缺口、失败关闭与复测；首次 Owner 系统误解 F1 保持原轮次失败，即使当前稿修好。
8. 形成 RC3 候选身份、准确最终 SHA/tree、包/安装/方法/合同 hash、实际 CI/环境、全部证据及限制。检查目标版本一致性；本卡不把正式 1.0.0 或自动激活混入。

## 输出

完整运行与输入 manifest、E1/E2/E3 对照、Owner/听众/试讲记录、最终文件检查、唯一验收台账、RC3 候选 manifest 和明确候选结论。

## 工程交接与最终验收

工程候选可评审与 RC3 全部适用验收通过分别写明。缺实际使用/文件/人类证据时，只报告相应未运行或阻塞层；可继续修复与出审阅稿，不能宣布完整 RC3 验收已通过。发布条件以原 AC-U05 为准。

## 验证与失败条件

挑最好一次、答案污染、同题当迁移、平均分抵消 F0/F1、把首稿失败改 pass、用手工修稿代替方法复跑、缺听众以模型代答、只看 XML/截图存在或总分即放行均失败。

## 并行与主要落点

证据与协议准备不阻断开发。最终运行使用固定候选；后续修改只重跑受影响用例与必要对照，明确复用依据。报告写合成或获许可脱敏材料，不提交客户原料、runs、token/cache；保留原始失败和不可变原件。
