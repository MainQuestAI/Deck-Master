# RC3-02｜口播备注交付闭环

**目标**：让适用的 Page notes 可靠进入实际 PPTX，修改、重排和恢复后的文件仍与页面对应。

**责任**：文件交付实施线，原 T06 Owner。汇总 AC-N01–N04、CQ-06，I06。

## 输入与进入条件

RC3-00 已接收的 Page/notes、speech policy、稳定 page_id 与输出依赖合同；固定合成三页、中文/数字/限定/换行及用户原备注。可直接与 RC3-01 并行，不等待 T05 全部完成。

## 实施工作

1. compiler API/native manifest 传入稳定 page_id 与对应 notes，按 cues/verbatim/none 和用户选择写真实 PPTX 备注；完整口播文档从有序 Page notes 投影。
2. notes 不混入可见正文、制作 prompt 或图像。read_alone/none 不强制新写，也不删除需保留的原备注。
3. 编译与输出 digest 覆盖 notes，备注变化使旧 PPTX/文件级复核失效；未变的 SVG/预览可复用，不新增无必要生图。
4. 页重排按 page_id 配对；拆合/删除依据内容线的新映射，未知配对明确阻塞或请求处理，不能猜索引。
5. 从实际 PPTX 回读逐页完整内容并核对关系，再在可用的兼容阅读器检查备注可用性；指定桌面环境仅在本次明确要求时适用；不只验证 notes XML 存在。
6. 输出依赖与 RC3-03/04 集成使用同一编译路线，保留现有 geometry/正文权威和原件。

## 输出

实际带备注 PPTX、编译 manifest、逐页回读与 hash、重排/拆合/删除证据、仅备注修改前后依赖/零图像调用、保留原注的正反对照及阅读器检查记录。

## 工程交接与最终验收

交接出口：真实文件内容与 Page notes 对齐、没有串页和失效遗漏；供 RC3-04 安装集成。最终 N01–N04/CQ-06 按原验收提供 L6 与适用用途证据，不能冒称未运行过的指定桌面验证；未指定某桌面环境时不因缺该环境阻塞其他已验证交付。

## 验证与失败条件

要求备注的页空写/丢失/截断，按旧页序串位，notes 修改交付旧文件，none 删除原注，关键限定只藏备注，备注变动导致无关整稿重生图均失败。可见正文与备注各自检查，不能总字数相等即通过。

## 并行与主要落点

主要落点：pipeline、compiler/api、native 编译脚本、输出依赖/readback 与导出。与内容方法独立；若 RC3-03 也需修编译损失，由同一交付责任顺序合流，复用原生 SVG 路线。
