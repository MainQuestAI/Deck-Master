# RC3-01｜内容质量与审阅补强

**目标**：从材料形成具体、完整、逐页有增量的正文，识别并修复“正确但浅”的稿件，使设计拿到合格内容。

**责任**：内容实施线；T00 负责评价校准，T03 负责内容 AC，T07 提供方法消费与审查能力。汇总 B02/B03、M01–M05；CQ-01/CQ-02/CQ-11，I01/I02。

## 输入与进入条件

RC3-00 固定基线、Q1–Q4、完整 R2 方案、CyberPPT 固定五份参考、当前方法。方法编写可在基线接收后推进；实际首稿/独立前审评价前，RC3-04 前置切片必须提供可用的真实加载与审查路径。

## 实施工作

1. 材料分析写清用途、权威、已知/未知、冲突和可接受推理；按培训、决策、研究用途选论证方法，不统一套销售故事。
2. 将矩阵、案例拆解、流程交接、指标口径四类完整正反页例放入活动方法；单元格、条件、异常、责任及含义具体，不要求每稿四类齐全。
3. 论证/Plan/Page 正文写出实质全文，保持主张到来源、页/atom 和 notes 映射；检查逐页独特贡献与前后推进，篇幅预算与已授权范围相符。
4. 为浅稿审阅增加六组成对校准，包含合理稀疏与不确定性正对照；审查者取得任务、相关材料和全稿，定位缺陷并实际改稿。
5. 依原唯一 F0–F3 重校准十二锚点；两位评价者独立初判后裁决，历史等级记录保持原版本，影响用途的 F2 也须修复。
6. 通过 RC3-04 的候选安装验证实际方法/例子消费，保留实际稿件、具体审阅与返修。仅在开展方法效果比较时固定比较版本与预算，不把该实验作为普通交付前提，也不让人工精修旧稿冒充新方法的原始效果。
7. 保留 speech policy、双用途版本、实际论据边界、已确认稿 fidelity。客户可见正文清除制作说明与无效内部索引，内部追溯依据仍完整。

## 输出

活动方法与四类完整页例、六组成对浅稿例、锚点独立评价与裁决、实际工作单/方法 hash、完整首稿和实质返修 diff、固定可交设计的 Page 全文与预算/映射。如开展内部方法对照，由 RC3-05 如实记录；不是默认完成前提。

## 工程交接与最终验收

交接出口：从实际候选入口产出范围内完整稿，必要事实/关系/限定可见，前审能定位主要浅稿并实质修复，正文可冻结供 RC3-03；与 RC3-02 并行不等待整套设计。

最终 B/M 关闭仍按原 AC 及新增 CQ：正式协议可复用未变 L1 证据，实际内容、审查与成品检查按任务需要提供；不要求额外真人试用/听众/计时，不因交接完成自动 pass。RC3-05 的后续证据回填原 Owner。

## 验证与失败条件

正文只列类别、空表、泛化单元格、制作说明上屏、把分析交给设计、丢必要限定、只补 observation 或证据 ID、同作者冒充独立、错误主线在首稿失败后被覆盖为通过均失败。保留不确定性、封面和合适的稀疏页，不以字数定义密度。

## 并行与主要落点

可与 RC3-02 并行，RC3-03 可先做零调用可行性。主要落点：content_production/content_review/content_plan、活动 content-methods/source-reading/content-examples、T00 锚点与评价记录。不另建内容真相源；method_resources/打包归 RC3-04 协调。
