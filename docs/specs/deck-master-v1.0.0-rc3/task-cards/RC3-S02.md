## 实施与验收

1. 真实 create → inputs_update → claim → compose.v2 input_revision 接受合法
   Narrative + planned Plan，或 PlanInput v2；保存拟议六页职责与空 page_links，
   Document.pages/output 不凭计划创建，记录真实 input basis。
2. 例外限于实际尚无 Page 的显式计划或已有 planned 依赖；已有 Pages 的 bound
   页序/完整当前 Page refs/角色关系保持严格。删除全部当前 Pages 不得把旧 bound
   计划静默当作新计划。后续实际 page_copy 派发/采用生成真实 bound links；不引入第二真源。
3. project/Narrative、scope、CAS/input digest、节点、qualification/source版本及
   locator、完整 Page mapping 校验保持；错误在计划或内容写入前拒绝。已有 late-Task
   结算/receipt事实不因 CAS 拒绝被抹掉，不把 bookkeeping 与内容采用混淆。
4. 对 required_qualifications 只添加公开 schema description：值须为同一
   Narrative 中 role=qualification 的真实 node_id，不是限定句子或 label；不改原
   validate_plan_input_v2、五方法或业务例子，不替作者提供节点答案。
5. planned 采用不意味着 bound、可制作或 professional PASS。当前独立内容 gate、
   制作授权及文件验收仍执行。真实旧 Q1 Plan 另有 qualification 字段错误，修结构
   缺口不表示该原稿能通过后续语义校验；不把额外诊断回送旧作者冒作同预算反馈。
