## 真实问题与最小修复

未采用的 framing proposal 后，source-only update 打开 within_scope input_revision。
原代码会直接采用此处返回的合法 maturity=argument Narrative；在 decisions=[]、
authorizations=[] 时也会改变 Document.narrative 并开放 page_copy，绕过普通 argument
proposal → covering direction decision → adopt_proposal 的方向采用边界。

在 input_revision 所有现有层/内容语义验证之后、实际采用的第一项写入之前，若当前
Narrative 不存在或尚非 argument，而结果要采用 argument，整份结果显式原子拒绝。
本卡选择保守拒绝：即使已有某条 decision，也不新造 input_revision 方向采用协议。
错误指向普通 argument proposal 和明确方向采用；不自动生成业务决策或内容。

真实 framing reconciliation、已采用 argument 的后续修订、proposal_only/candidate_only
保留行为、trial 非采用路径和普通 proposal/decision/adopt 的已有规则保持。
拒绝不完成 Task、不清 reconciliation、不移动当前指针，也不产生采用 receipt。
调用方原先已存的 proposal、旧 framing、Task、输入修订历史及错误均保留。
