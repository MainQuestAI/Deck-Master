# RC3-04｜入口、方法、安装与恢复

**目标**：让实际安装的 CLI/Studio/Host 与四 Skill 使用同一方法、合同、状态与权限；承接早期协议卡尚未交付的真实入口。

**责任**：集成与安装实施线，原 T07 Owner；原 T01/T02/T04 Owner 仍关闭各自 AC。汇总 P01–P03、C01–C04、R01–R07、H01–H03，CQ-07/CQ-13，I03/I08。

## 输入与进入条件

本卡分两个切片，仍是一张卡：
- **前置切片**只依赖 RC3-00，提供 RC3-01 的实际方法加载与所需独立审查能力，不等待 RC3-01 完成。
- **完整切片**依赖 RC3-01/02/03 的工程交接与固定产物，进行三入口/四 Skill/迁移与最终安装收口。

## 实施工作

1. 前置切片打通隔离候选打包、方法资源/例子 hash、实际 Host 工作单与消费；记录源码、包、安装三层身份，不以旧日常安装验证新方法。必要通道修复能共用时在 E1-A/B 保持相同；若只在 B 提供必要消费修复，逐项登记允许差异，结论只解释本轮补强组合。
2. 提供真实可核对的独立执行/来源回执能力；能力不存在返回真实 needs_reviewer/缺口，不能把 Skill 换名或同 Host 改 ID 当独立。人类 professional policy 仍按原约定。
3. 完整切片统一 create/continue/request/error/next_action 在 CLI/Studio/Host 的语义；按当前合同一次覆盖正式写入入口，不能默认 writer 切换后留绕过窗口。
4. 交付旧移交：确认稿 imported mapping + fidelity 审查 +统一 import 路由；§12 collaboration CLI/HTTP、项目外严格只读报告与源目录 hash 不变；用户可见 needs_reviewer/范围卡。
5. 统一迁移 describe/apply、最低 writer、旧任务晚到、restore、当前暂停/撤回/费用、历史交付控制；直接入口和完整流程同样受约束。
6. 实现 deck-master/deck-content/deck-design/deck-review 四职责方法与安装；点名、自然路由、Master 连续调用、恢复后调用四路径真实可用。共享合同/方法只维护一处。
7. 沿用现行 OpenDesign，展示真实稿/样页/差异、决定影响与恢复路径；实际浏览器覆盖普通、缺口、拒绝、过期、并发、窄屏/键盘。ID/hash 在必要详情。
8. 在候选打包阶段将版本统一为目标 RC3 的项目约定表示，并核对源码/包元数据/方法/合同/安装 manifest 一致；本次规划不预先改 pyproject。
9. 建立隔离候选安装、临时 registry smoke、升级/回退/续作证据。旧规则冲突按本轮已裁决语义更新入口文档；不改用户第三方 Skill/配置或原客户项目。

## 输出

前置切片：方法消费 manifest、真实工作单/加载记录、审查/来源能力与限制，供 RC3-01 使用。

完整切片：三入口同输入同状态、四 Skill 四路径记录、确认稿/只读报告/迁移恢复证据、最终候选版本/包/安装 hash、真实浏览器与安装测试、遗留关闭或明确缺口。

## 工程交接与最终验收

前置切片就绪只允许内容验效开展，不关闭本卡。完整出口：T01–T06 能力在同一候选安装形成可使用链路，三入口及恢复一致，供 RC3-05 验收。原 P/C/R/H 按精确版本证据分别关闭；既有未变 L1 可复用，当前安装/新增入口/真实通道不能沿用旧证据。

## 验证与失败条件

源码存在但包内缺失、工作单未消费、前端私存批准、确认稿强制重建主线、只读审查写源项目、恢复复活权限/费用、客户流程暴露内部命令、默认写入口能绕 gate、薄壳 Skill 总进全套、用 CLI 自报身份当受信人类均失败。

## 并行与主要落点

主要落点：cli/launcher/registry、service 适配、static Studio、install/build、method_resources、四 Skill 及 task index/recovery 文档。共享 service/gate/binding 由集成责任协调。前置与完整切片依赖分开登记，不形成循环等待；正式安装激活和发布按当时实际授权执行。
