**基线**：RC3-05 `3ec9917adcef7ede927338bd6f1ffb8fedf06f92`。
独立 `impl/rc3-s03`；不更改 RC3-05 的固定工具、候选安装、正式注册、原稿或运行项目。

## 真实触发与原范围

原 Q3 initial 指令的“阅读稿”被准备层映射为 API 不接受的 `read`。
原 A0 公开 create 在实际 schema 的 `live/read_alone/mixed` 枚举处失败，
留下四个不可变 Source/Extract 孤儿对象但尚无 Document/Task。
原 SDK1、失败、指令、材料与 no-template checkpoint 保留；B 未调用。
原 supplementary.reconcile 需要 public operation_id，此次 create 内部 ID 未返回，
不得捏造 ID、删除孤儿或手改 pending 来绕过恢复。

本卡补齐原 RC3-04 的恢复工程出口和 RC3-05/AC-U01 对 Q3 的完整失败/调用记录，
服务于原 AC-M04 整稿制作、CQ-12 的版本化证据复用/新增层区分；不增加专业质量配额或
人类门槛，不关闭内容、文件、盲评或真实 Owner 验收。`read`→`read_alone` 仅为
明确的非语义 API 映射，不能修改原注册文件来重写首次失败。

## 最小实施和验收

1. 新 companion `tools/rc3_campaign/precommit_recovery.py` 精确 pin 原 scoped/d0
   工具；原公开 Runtime、方法、schema、其它工具、共享预算和实际失败均不变。
2. Root 实际前瞻 amendment 绑定新工具 SHA、原注册/run、原失败/key、同一 project、
   原 managed installation。工具实际验证 own Python/module/manifest/完整包；
   不接受任意 caller JSON 作为 not-found 事实或使用 B 模块补 A0 能力。
3. 原 journal/resource/Runtime 同锁内，实际 own `inputs_show` 的 not-found 与
   严格 source-only 元数据前后及最终探测共同证明无 Document/Task/operation。
   已提交、未知、额外对象/receipt、别名、身份漂移或 TOCTOU 一律保留 pending。
4. 无 public ID 时不伪造 ID；只经正常 d0 `sdk_reconciliation` 结原 intent，
   原 SDK1/孤儿/错误保留，实际诊断查询收费同原池，不自动 retry/reset/new sample。
   后续正确枚举 create 必须另次明确公共调用；正式 Q3 不在本卡工程测试中操作。
5. 有意义正反工程覆盖真实 A0 create 失败/无-ID 旧恢复拒绝/真实公共 not-found/
   正常 reconciliation/同项目另次显式 create，以及 wrong Runtime/有 current/
   receipt/未知 Task 对象/材料变化/探测竞态/预算耗尽拒绝。合成 seams 明确披露。
