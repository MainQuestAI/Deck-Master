最终资源的一轮浏览器回归曾有 211 项通过、1 项受控延迟测试失败：两个风格来源读取相同目录 URL，测试只释放第一条请求，偶尔把项目配方恢复请求留在等待中。现已让用户选择阶段后释放所有相关目录请求，并增加所选配方实际保存回执校验；原恢复值和阶段断言均保留，未修改产品源码、增加固定等待或提高断言超时。失败 XML 单独保存在 `browser-before-delay-harness-fix.xml`，不计入最终通过记录。

后续一轮 211 项通过、1 项跨端口恢复断言失败，定位为旧 `open_visual_phase` 辅助函数在真实点击前读展开状态：被动定位发生在读取与点击之间时，两次点击会最终关闭目标阶段。辅助函数现先执行真实 summary 点击，按点击后的状态决定是否再展开，并增加最终 `open` 断言。原配方、截图选中、正文和草稿恢复断言不变；相关四项正式入口定向验证通过。失败 XML 保存在 `browser-before-phase-helper-fix.xml`；最终全量再次绑定同一产品 BUILD_ID，而不是将两个失败轮的通过项拼接收口。

1. **功能与数据行为：** 以冻结源码的全量门禁与隔离安装结果为准。九组修复都有明确处置和生产者—消费者验证；合成 Host 不升级为真实生成。

3. **完整任务体验：** 自动化工程走查覆盖现有五条任务及恢复反例；专业使用判断和用户连续操作认可未执行。远端 required CI、真实 Host／实际交付、HOME 激活分别列项，不与本机通过合并。

推送后在最终 Git HEAD 核对 required CI，包含 wheel、离线安装 UI 和安装后恢复。需要真实闭环时复用隔离副本完成一页，不重做整套 30 页、不自动采用客户候选。两项设计缺口未经用户体验验收前，不发布“系统性 WebUI 整改完成”声明。
