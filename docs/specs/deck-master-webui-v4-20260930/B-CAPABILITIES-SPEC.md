# 新B线：功能补齐Spec

旧W01–W11大部分工程实现已进入main，本轮沿用其读模型、请求/Attempt、项目启动、画廊、标注、批量修改、候选、风格、内容输入、恢复和导出。B线重点修补当前设计所需的少量真实缺口，并关闭剩余验收。

## 必须开发的增量

1. **B01 可行动读模型**：attention目前恒未记录、缺prompt概况；有候选时summary输出违反活动schema。提供有证据来源的待办及下一动作，不生成推测的风格结论。
2. **B02 入口与能力适配**：`view --open`显式选择新UI；server支持与项目实际可用动作分开，保护旧格式/只读/历史和协议能力。
3. **B03 正文与内容变更集候选**：现trial只支持原图/SVG，content_update回传接受即改当前稿，尚无回传后的人工采用步骤。增加不可变Page/结构及材料影响变更集候选、Host内容结果协议、比较读取与显式采用；复用局部内容更新，不旁路写当前Page。
4. **B04 保留当前的决定**：现按钮只返回。保存可追溯决定、重开与冲突保护，使任务/候选待办在重启后可信。
5. **B05 个人数据清理**：缩小原型reset范围，精确预览、备份、确认和并发保护；业务事实禁止清除。
6. **B06 风格及真实闭环**：现W08已观察未选构图漂移。明确保持项，补正向多页效果与30页真实项目全流程。核心约束与真实验证分切片，不用模拟替代效果。
7. **B07 最终安装与验收**：旧W12记录中安装摘要可追回但压力失败；在最终整合SHA重建并复验导出、压力、资源、回退和全部AC。

## 写入不变量

复用Store不可变对象与原子Document、既有operation账、Task cancel/late-result保护。trial可记录管理revision，但不变当前内容槽。采用以generation basis和当前目标指针的真实条件作校验，管理revision变化不等于内容冲突。异页结果乱序不互相废弃，同operation网络重放不产生新模型调用；取消后晚到仍拒绝。

正文候选采用按页更新并失效受影响图件，未改页保留；旧成果继续从历史可读。重排/移除影响整稿有序PPT依赖；历史恢复新增revision、不回滚调用事实。新字段若需要最低reader/writer能力，显式登记并在旧客户端前拒绝；不静默改造旧项目。

后端/CLI/活动schema/Skill/包构建归B；HTTP只做同源薄适配，Host写仍用CLI。新接口签名与迁移见 [INTERFACES](INTERFACES.md)，每卡带兼容和失败用例。当前系统无需新增云服务、数据库或第二个模型执行器。
