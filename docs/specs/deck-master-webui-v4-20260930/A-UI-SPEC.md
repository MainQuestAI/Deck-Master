# 新A线：Web UI实现Spec

目标是把已批准的OpenDesign设计运行在现有Deck Master主流程。原型可点击不算交付；每个按钮必须有真实服务行为、准确禁用原因或明确示例身份。

## 工作面与动线

| 入口/面 | 用户首先看到什么 | 主动作与完成反馈 |
|---|---|---|
| 项目 | 本机项目、可读性、搜索、新建/打开/示例 | 打开现有项目，或新建后补材料并复制整理要求 |
| 制作总览 | 当前版本、最需处理事项、余项、逐页制作矩阵 | 点一项待办到对应页/层/任务；完成后数量与事实对应 |
| 内容与来源 | 输入版本、整合/大纲、页目标、材料关联 | 改内容、更新输入或调整结构；先看影响再提交 |
| 整稿画廊 | 20–30页的完整页面节奏、当前层及缺项/旧版 | 连续阅读、跨页并排、进入问题页；不逐文件开图 |
| 单页 | 当前页+层+版本、完整产物、其前后来源 | 阅读/编辑/标注，保存意见或建立请求；不同动作分别反馈 |
| 风格校准 | 固定参考、目标、期望与已选维度 | 试一页→固定比较→采用/保留→再扩选，不自动全稿重做 |
| 任务与交付 | 待提交/执行/返回任务及需要用户决定项 | 复制制作要求、比较候选、恢复或下载固定版本 |

首次打开空项目引导到输入；有内容未生成图时可先读稿、准备prompt；在制作中默认回上次位置并提示新的真实状态；历史链接固定版本且只读。用户不用Web仍可经CLI继续，不要求全稿逐页批准。

## 状态及输入保护

事实状态与视觉状态分开：网络失败不能把任务写成failed；复制成功不设running；Host完成结果可能还在待采用/待制作/待检查。轮询遵循既有节奏，读取失败保留上次成功内容并显示更新时间。业务operation身份在发送前持久化；保存未知先查原ID，不自动另建调用。

正文、意见、prompt草稿和选区以项目、稳定page_id、层、基准引用隔离；后台数据变化不替换本地输入。冲突并列保留双方。读、改、框选互斥，Escape退回阅读，文本和百分比输入提供无鼠标替代。比较固定双方真实引用，采用计划失效后只能重新预览。

## 实施分包

按 [A01–A08任务卡](task-cards/README.md) 执行；A01可立即从共同基线开始。A02接B02工程切片，A03接B01，A05接B03内容变更集切片，A06接B03/B04/B06保持项合同，A07接B04/B05。等待接口时可开发视觉与只读部分，但不能以mock关闭验收。

主代码范围 `src/deck_master/resources/static/v2/`。保留旧入口与既有模块服务绑定，采用原生ES Modules；不引入前端框架/构建工具，不整段替换成OpenDesign演示app.js。生产数据来自现有HTTP API，Python/source/shared schema由B负责。
