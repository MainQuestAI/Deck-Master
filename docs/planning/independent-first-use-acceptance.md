# 独立首用验收执行协议

状态：`prepared / not_run`。本文和[记录模板](templates/independent-first-use-record.md)用于准备执行，不代表已有参与者或首用通过。建议规模为 **3 名未参与开发者，每人独立完成 1 份 10 页方案**；实际人员、日期和样本规模待安排。该规模用于发现首用问题，不足以证明普遍成功率，也不代替真实客户效果配对。

本协议补充[真实 UAT 规程](../specs/sc1.1-native-deck-core/acceptance/UAT_PROTOCOL.md)。它检验陌生使用者能否从公开入口完成工作，沿用已有工程、视觉和最终文件批准要求，不降低任何阈值。

## 参与方式与独立性

“真实独立首用”必须由未参与本产品设计、开发、当前修复及验收脚本编写的人实际操作。记录其相关工具经验和此前接触程度。参加者可以使用正式安装的 Deck Master Skill、宿主 Agent、公开文档及产品提示；Agent 是产品使用方式的一部分，不能由维护者在后台代为决定下一步。

每份记录只能选择一种执行类型：

| 类型 | 含义 | 能否计入独立首用结果 |
| --- | --- | --- |
| `human_first_use` | 合格参加者自己发起、理解结果并操作，使用标准宿主 Agent | 能；仍须逐项证据与判定 |
| `agent_rehearsal` | Agent 独自走流程，或由维护者用 Agent 排练 | 不能；仅检查材料、工具与步骤可执行性 |
| `maintainer_assisted` | 维护者给专门命令、定制提示词、诊断、改文件或代操作 | 不能记为无协助完成；保留原首用失败及修复后结果 |

观察者不提示入口、命令或排障方法。按事先准备的事实回答卡回应业务问题属于正常材料补充，记录问题与回答来源；引导如何提问、选择路由、恢复或修复属于维护者介入。公开文档自助查询和标准产品提示也须记录，便于识别路径过长的问题。

## 执行前准备

由组织者先冻结以下内容，再开始计时：

- 发布候选源码 SHA、发布树/安装包及安装清单哈希、公开文档版本。使用可分发安装产物；产品运行不依赖开发 checkout、旧 PPT Master 或维护者的私有配置。记录 OS、Python、宿主 Agent/模型、工具权限、LibreOffice、字体等实际版本。
- 每人独立的新工作目录、运行和已授权材料。材料只提供业务目标、原始资料和约束，不提供逐页稿、预制 Narrative/Package、现成 SVG、PPTX 或可导入的通过报告。
- 合成或明确授权的业务材料；资料后部包含关键约束。至少设置一项可公开研究的缺口和一项不能公开推断的客户事实。准备来源明确的事实回答卡；未给出答案时，正确行为是保留待确认或缩小主张。
- 模型、工具和每类动作预算沿用发布候选支持的正式配置。参与者遇到上限时保留失败记录并报告，不另建运行或换 action ID 规避。预算变更须单独记录已有授权及理由。
- 保存日志和录像的许可、脱敏规则、证据本地位置。仓库只提交匿名摘要、哈希及问题索引，不提交参与者身份、凭证或未经授权材料。

建议三份主任务中至少一份明确选择 `direct_svg`，其他任务使用默认 `image_blueprint`；实际分配在执行前填写，不能执行失败后改分组。两种路线都必须有真实人首用记录，才算覆盖完成。ImageGen 不可用时如选择 `direct_svg`，必须由参加者明确表达并记录选择；不能静默切换并把默认路线记为通过。

## 给参加者的任务卡

> 根据提供的业务原材料，完成一份面向项目决策者的 10 页方案，说明业务问题、解决机制、关键关系和推进条件。请使用安装后的产品与公开使用说明；事实不足时应确认或明确保留缺口。完成后识别当前可编辑 PPTX、其预览和待批准状态。过程中会安排一次正常暂停续跑、一次中断恢复和一次指定页修改。文件只有在你实际看过并明确批准后才能算获批；你可以不批准。

选择 `direct_svg` 的任务卡额外加入：“本次明确使用 direct_svg 制作，不使用 ImageGen。”任务卡不提供底层修复命令或逐页结构答案。

## 执行步骤与观察项

每项先保留首次尝试，不用成功重跑覆盖失败记录。除明确标记为整组覆盖的路线项外，每位参加者均需执行。

| 编号 | 场景与动作 | 观察及通过依据 |
| --- | --- | --- |
| FU-01 | 从分发入口安装并开始新任务 | 自己找到安装、开始入口和当前状态；缺依赖时提示具体可行，运行不借用隐藏开发环境 |
| FU-02 | 只交原材料、目标和边界，要求 10 页 | 无需交逐页稿即可形成完整方案；资料后部约束被实际读取并保留；保存首次完整稿 |
| FU-03 | 遇到公开研究缺口及客户未知事实 | 公开结论可追溯；客户事实不被猜成真值；业务补充问题有必要且可回答，原问题和回答均留痕 |
| FU-04 | 明确选择并核对 authoring mode（整组须覆盖两种） | 默认路线有真实 ImageGen 收据；direct_svg 有参加者明确选择和持久化路由证据，不依赖 ImageGen；续跑不偷偷换路线 |
| FU-05 | 完成一个阶段后结束会话，再开启会话续跑 | 从公开入口识别同一运行、当前状态及下一步；不用重述已保存决定或从头生成 |
| FU-06 | 在已记录的可恢复操作中安排一次中断后恢复 | 记录准确中断点、方式及授权；不损坏旧修订/文件，不重复计已提交结果，不丢预算记录；若无法继续，提示能让参加者判断下一步 |
| FU-07 | 根据指定页需求做一次局部修改 | 只处理受影响页，保留无关页输入哈希和业务决定；新成品与原成品可区分，旧批准不能转移到新文件 |
| FU-08 | 找到当前 10 页 PPTX、预览与审查结果 | 实际打开当前文件并逐页核对；能说明它对应哪个修订，哪里还有阻断，以及哪个文件可以交给谁复核 |
| FU-09 | 检查最终文件批准和导出 | 未批准时明确显示待批准并阻断正式导出；若本人实际批准，记录身份声明、时间及准确文件哈希，再验证导出；不批准时结果保留 pending，不代填成功 |

FU-06 由组织者事前选定产品支持的中断方式与阶段，避免随机破坏文件。观察者可按预定步骤触发中断，但恢复操作由参加者完成；触发中断和提供恢复提示分开记录。

FU-07 的指定页需求应来自任务目标，例如改一页中文表述或配色，不预先教参加者内部文件路径。多页关系变更属于另一个影响范围场景，可单列扩展，不能与单页修改混算。

## 记录和判定

使用[模板](templates/independent-first-use-record.md)为每人建立记录，并为整个批次保存汇总。执行状态只有 `not_run / blocked / failed / passed`；批准单独记录 `pending / granted / declined`。`blocked` 说明缺少什么外部条件；`failed` 说明已运行但行为不符合要求，不能把产品缺陷写成未执行。

记录至少包括：首次找到入口的时间、参与者主动操作时间、工具等待时间、首次完整稿时间、业务澄清次数、重复提问次数、失败/重试数、维护者介入次数与具体内容、修改页范围、最终文件哈希和参与者的原话反馈。耗时按实际事件记录，不填估计值；小样本按人数和逐例结果报告，不给伪精确成功率。

单个首用案例可标 `passed`，必须有完整 10 页、FU-01 至 FU-09 的适用证据、无尚未关闭的 P0/P1、没有维护者技术介入，且文件批准分支已由真人实际作出决定并验证对应行为。若参加者选择不批准，可通过“正确保留 pending/declined 并阻断导出”这一行为检查，但该文件仍未批准、不可当作成功客户交付。修复后的重跑引用原失败和新 SHA；接触过问题答案的人不再作为同版本独立新手样本。

整组“独立首用验收通过”还要求：事前确认的样本全部执行、两种路线均有真实人证据、必需场景无缺项、阻断问题已关闭并有可归属候选的复验。Agent 排练、维护者协助记录和历史 SHA 结果单列。没有真实参加者时保持 `not_run`；工程测试或 Agent 排练不能代填真人结果。本协议完成也不改变客户效果 `outcome_pending` 的结论。
