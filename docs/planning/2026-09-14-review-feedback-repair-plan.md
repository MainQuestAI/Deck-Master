## 4. 修复工作包

### R1｜输入与引用真实可用（P1，先做）

改动入口：[整稿导入](../../scripts/runtime/orchestration.py)、[页面包](../../scripts/production/page_package.py)、[证据判断](../../scripts/narrative/judgment_builder.py)。

- 共用最小来源解析函数：以明确 source_id 精确匹配为主；已有兼容引用仅允许规范化路径、完整 hash 或唯一名称精确匹配。重复名称必须用 ID 或路径消歧，不使用双向子串、任意数字或引用正文来确认来源身份。
- 区分“引用能定位到来源”和“来源能支撑论断”。不根据风险标记缺失、引用数量或 ID 存在推断语义充分；设计建议继续按机制、条件与理由编辑。
- 有明确 citation 时，来源清单缺失、损坏、为空或引用无法定位，要在活动文件写入前给出具体来源错误。无 citation 的设计建议不要求虚构来源；材料已提供但未登记时先通过现有材料入口登记，不要求用户重复录入。
- 正文完整性检查只计算实际可见内容，不计算 `type` 等元数据。正文页要求真实内容；封面、章节页按其实际职责允许短稿，不新增统一最低字数、最低页数或正文块数量门槛。
- 保留 Page Package v1 的 `ready_for_build`。导入成功只表示输入可继续制作，不表示专业审阅或客户批准完成。

验收：空来源、不存在来源、相似 ID、相同文件名不同来源全部正确处理；合法 ID/路径引用通过；无历史效果数据的设计建议仍可生产。正常 CLI 导入后正文、引用和页面顺序完整进入现有高密度加载器。空正文反例失败，合法封面和短稿通过。

### R2｜修改传播与可恢复导入（P1，接 R1）

改动入口：现有 import-plan 写入、PagePackageIndex、高密度内容/构建指纹、run 状态解析及产物新鲜度判断。

- 将来源溯源指纹与内容变化判断分开：不信任作者重复提交的 source_fingerprint 作为唯一变化依据。沿用现有 package/customer payload hash，按实际被制作器消费的正文、图示/visual_spec、资产与证据绑定识别变化；忽略纯审计时间戳变化。
- 保持稳定 beat/page ID。活动页面集合和顺序由当前叙事决定；被移除页面退出活动目录但保留历史。旧 legacy 包或无法映射的包不能偷偷混入新整稿，也不能直接销毁，应先归档或明确报告冲突。
- 正文、图示和证据变化只重做受影响页面；纯重排保留不受影响的页面图形，但更新整份文件的装配顺序和文件级检查。跨页共同事实变更时，既有审阅返修负责列出并修订相关页面，不以“ID 没变”判定无影响。
- 新内容生效后，旧 build/render/quality 产物只可作为历史，不能依据文件存在继续充当当前结果。状态判断须把当前包与当前产物绑定起来。
- 每次导入使用唯一备份目录。现有导入内增加持久化的写入中标记，先备份、校验和准备完整写入集合，再替换活动文件；全部成功后才标记完成。下游写入失败必须报失败并恢复，不能返回 imported + prune_failed。
- 恢复失败保留原错误与备份位置，不吞掉异常。发生进程中断时，next-step 明确指出待恢复状态；同一 import-plan 重试先恢复上一完整状态，再应用新输入，不让用户手工修 JSON。无需通用 action 服务或新治理平台。

验收：A/B/C → C/A、增加 D、稳定 ID 改标题、纯重排、引用更新、图示方向/状态更新、沿用旧来源指纹均反映到当前产物。第二/后续文件失败、下游失败、同秒多次导入、进程中断后重试覆盖恢复；只能观察到完整旧状态、完整新状态或明确待恢复状态，不能将混合状态当成功。

### R3｜无库生产与完整稿续跑（P1，接 R1/R2）

改动入口：CLI 的 library 参数与 autoplan/sourcing、run 状态解析、实际所选 builder 的能力检查、对应 playbook。

- 新建流程增加并默认采用明确的 `library-mode=none`，记录在 run 中；none 不发起检索、不读取旧缓存 selection，也不等待候选页。显式 auto/real 保留既有检索意图及真实失败；直接 search-library 本身仍是明确使用库的操作。
- 旧 run 未记录模式时保留既有恢复语义，不因默认值变化重写用户已选页面。指定历史 PPT 作为资料读取不要求安装 PPT Library。
- auto 的可用性判断使用现有实际配置解析，不只看 PATH 中是否有同名命令。fixture 仅供显式开发/演示，不作为 production 的降级结果。
- 整稿继续执行按 builder profile 检查真实依赖。高密度路线使用自己的能力检查，不被无关 PPT Master 绑定阻断；真实必需的图像/Agent/渲染能力缺失仍须准确报告。
- 完整稿从导入、构建、渲染、审阅到后续修改保持同一路径，产物已经生成后不再落回 sourcing/generation 的旧前置环节。首轮不扩展标准构建的 package-only 支持。

验收：无库未安装/未配置/无缓存、系统安装了库但选择 none、旧 selection 存在但选择 none，均不搜索且进入真实制作。显式 real 不可用时准确失败。已有成品改稿后 next-step 指向受影响构建/审阅，正常完成后不要求重新选页。
