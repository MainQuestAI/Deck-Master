# Deck Master 产品 UI 语言规范

## 适用范围

主工作台使用正式产品文案。状态规范页是独立的交互参考，不进入产品导航。数据保存范围是本机工作区：读取、保存、候选、恢复与导出经本机核心完成；生成（原图、SVG、PPT 与整稿）由制作工具在接手交接后执行，工作台负责冻结请求与核实结果；无云端同步，跨设备以文件为主。文案调整不改变这一能力边界。

## 信息层级

- 页面标题：直接命名工作对象，如「项目」「制作总览」「整稿画廊」「任务与交付」。
- 页面说明：说明当前可完成的工作，最多两句，不介绍系统实现。
- 状态：表达已发生的事实，不把复制、保存、提交、处理和完成混为一谈。
- 按钮：使用「动词 + 对象」，如「创建项目」「保存草稿」「采用候选」「取消任务」。
- 辅助说明：只保留影响用户判断的后果、限制与下一步。

## 统一术语

| 使用 | 不使用 | 含义 |
| --- | --- | --- |
| 项目 | 原型项目、模拟新建 | 用户管理的一份方案 |
| 示例项目 | 合成演示项目 | 预置内容，不是真实客户资料 |
| 制作工具 | Host | 执行生成工作的外部工具 |
| 任务 | 模拟请求、样本任务 | 已保存的工作要求 |
| 候选 | 样本候选 | 尚待用户确认的结果 |
| 当前版本 | current、currentVersionId | 正在使用的版本 |
| 制作要求 | 交接文本 | 提交给制作工具的内容 |
| 本机工作区 | 离线设计原型 | 数据保存范围 |

Codex 仅在确实需要用户前往该工具执行时出现。SVG、PPT、版本号等对产物判断有用的技术名称保留。

## 状态与操作

| 事实 | 状态文案 | 下一步 |
| --- | --- | --- |
| 要求已保存，尚未发送 | 待提交 | 复制制作要求 |
| 仅复制了文本 | 已复制，尚未开始 | 在制作工具中发送 |
| 已取得执行记录 | 处理中 | 查看任务或取消 |
| 结果返回但未采用 | 待确认 | 比较候选 |
| 用户采用结果 | 已采用 · 待检查 | 检查相关页面 |
| 执行失败 | 失败 | 调整要求后重试 |
| 请求已取消 | 已取消 | 查看记录 |
| 上游内容已更新 | 旧版 · 待更新 | 更新相关产物 |

现有示例执行记录必须标明示例，不可用「处理中」暗示真实服务已连接。

## 能力与错误说明

连接信息集中在「连接状态」；涉及文件上传、导出或跨设备保存时，在操作处保留必要限制。错误消息依次说明发生了什么、内容是否保留、可采取的动作。例如：「保存失败，输入仍保留。请重试或复制内容。」

破坏性动作说明删除范围和能否撤销。清除本机数据必须二次确认。采用候选必须保持版本比较与影响说明。

## 界面边界

主界面不出现模拟接手、模拟返回、模拟失败等测试控件。不自动推进任务，也不伪造生成成功。状态规范页可保留明确标注的模拟操作，用于检查异常分支。

## 视觉与图标

沿用 OpenAI token、无衬线产品字体、黑色主按钮与浅灰表面。图标沿用共享的 24 单位 SVG、1.75 线宽和圆角端点。状态必须同时有文字，不依靠颜色传递事实。

## 文案验收

检查导航、标题、按钮、输入提示、状态、空态、弹窗、反馈和复制文本。用户界面不出现内部开发标识；必要技术详情单独呈现。不得通过删除「示例」「未连接」等必要事实来伪装生产能力。

## 收尾规范

主工作台删除演示过程标注和无效控件；待执行请求统一使用“待提交”。示例项目、示例产物及未连接服务仍明确显示。清单与缺项数量以当前状态计算，不使用固定数量或承诺真实导出。状态规范页和设计系统页为独立参考，不作为正式产品导航。

## 统一词汇表（F14，2026-10-07 定稿）

方案 §9 要求把下列词固定下来，界面主层只用右列的写法；括号内是被替换的说法。

| 词 | 主层写法 | 说明 |
|---|---|---|
| 页 | 第 N 页 · 页面标题 | 不写内部 `page_id`（`p01`）作为名称 |
| 层 | 逐页稿 / 原图 / SVG / PPT / 预备提示词 / 实际提示词 | 与 `layers` 一致；不写 `original_image` 这类键名 |
| 规范 | 风格规范 · 已确认版本 Vn | 「规范」指已确认的视觉要求；未确认的阶段叫「本次方案」 |
| 候选 | 候选 · 待比较 / 已采用 | 候选取回后先比较再采用；不写「生成成功」 |
| 版本 | R 短码（8 位）或 当前版本 | 版本短码只用于版本；规范/计划/决定各自用 `shortRef`，不共用 R 前缀 |
| 修改组 | 修改组 · N 项已返回 | 不写 `change_id` 全码 |
| 复制 | 复制给 Agent 的要求 | 复制不启动任何执行 |
| 接手 | 待接手 / 已记录处理中 | 用于任务被制作工具取走的状态 |
| 返回 | 返回候选 / 返回上次工作面 | 与「采用」分开：返回不等于采用 |
| 采用 | 采用此候选 | 采用会更新下游产物，必须有影响说明 |
| 检查 | 工程检查 / 检查依据 | 工程检查不等于认可；「通过」只用于明确写出的检查项 |
| 交付 | 正式交付包 / 审阅包 / 内部工程包 | 用途名固定；「导出」只出现在文件名与下载动作里 |
| 未知 | 待核实 / 尚未确认 | 未知调用、未知提交一律「待核实」，不写成「失败」也不写成「安全重试」 |

## 主层与详情分层（F14，2026-10-07 定稿）

1. **主层只写业务语言**：不展开任何折叠时，界面文本不出现内部标识与证据——32 位以上十六进制码、`.deckmaster/objects/...` 路径、`operation_id` / `plan_id` / `sha256` 等字段名、原始 JSON。
2. **内部依据按需详情**：证据放进对应对象的 `details`（「固定引用与完整影响」「执行记录」「两份完整快照」），需要时展开核对；详情里保留真实字段名，不美化。
3. **异常就近展开**：错误贴在出错的动作旁（字段级或该操作的输出区）；需要用户比较或选择恢复对象的维护项在该异常发生时自动展开一次，之后以用户开关为准。
4. **维护设施分层**：私人笔记、草稿操作与「恢复、下载与版本详情」属于本机维护，收在同一条维护区；正常写作区只保留撰写、保存与已保存结果的选入。
5. **启动器/外壳同样适用**：创建与登记的恢复动作说清已发生的事实（「登记并打开这个位置」），不引导重复创建。

## PR103 联合修复的呈现规则

- 材料新增、任务要求调整和已有材料调整共用「内容与来源」内的宽编辑区。标题明确对象，差异、输入变化说明和确认在同一区域；关闭保留草稿并回到入口。桌面并排核对，窄屏在同一容器返回编辑。
- 输入确认只说明「输入进入待协调」。未获得并采用制作工具判断前，不声称已确定影响页或已经对齐内容。
- 项目与截图风格的阅读阶段独立于业务完成状态；用户点击阶段摘要或使用键盘选择后，被动恢复不改阶段。两种配方保持原来的五维／七维合同。
- 三处候选列表使用同一按页分组的卡片：页号、标题、产物类型、真实返回时间、状态，以及固定候选图片或实际正文摘要。整稿正文变更集单独分组；图片缺失不借用当前稿替代。
- 候选状态分别表达「当前采用」「曾采用」「待决定」「已保留当前」「依据已变化」。短码仅辅助追溯；打开比较后对象继续固定，不自动采用。
- 同一意见草稿的提交事实随项目草稿恢复。正文、范围、位置、意图或固定依据未变时提示已保存；「写新意见」开启新身份，不做全局同文去重。
