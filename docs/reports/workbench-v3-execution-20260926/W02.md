# W02：恢复切片

基线 main：`ea4b5b8fa1e4e4e3444b6cd8861f83f5fcc61468`。分支：`codex/workbench-w02`。
这是独立 Review F03 要求的包内第一步，已通过 PR #42 合入 main `de629349…`。W02 整卡未验收；后续协议及真实 Host 证据见 [W02-PROTOCOL](W02-PROTOCOL.md)。下文是恢复切片完成时的范围记录。

## 可用行为

task accept 的 Page、Artifact、Review 引用与 completed Task、原请求 digest、稳定结果一起提交。
指针已成功切换，但进程在返回或写 operations 缓存前退出时，使用同一任务、操作、依赖摘要及结果重试，可以取回原采用版本和结果。
即使其后又有新提交，重试也不会回拨当前指针或再写一个业务版本。
同 ID 换结果或依赖摘要仍拒绝；从未提交的孤立快照不算成功操作。

## 存储与兼容

复用 Document.change 的可选 `operation_receipt`，不新增调用账、数据库或持久化对象类型。
`request_digest` 覆盖 task_id、operation_id、produced_against 及解析后的完整 envelope，使用核心 canonical JSON；派生 journal 的既有 `result_digest` 仍只覆盖 envelope，两者用途不同。
稳定 response 的 revision 必须与承载它的 Document 相同，后续 revision 不可携带旧 receipt 冒充新提交。

成功重放返回 `status=already_applied`，`revision_id` 为原采用版本，`current_revision_id` 单列现在的指针，`operation_result` 保存原核心结果。
历史响应不再把新版本误称为本次提交版本，也不把历史 pending tasks 发成新待办。
丢失或损坏的 operations 文件可从已提交祖先重建；缓存 I/O 失败返回明确的 `receipt_cache_unavailable` 警告，不把已提交状态报告成未提交。

旧 Document 没有 receipt 仍按原 schema 可选兼容读取；旧 completed Task 同时缺 digest 和 journal 时拒绝猜测重放。
本次没有原地迁移旧对象。恢复支持覆盖普通结果及 input_revision/content_update；取消和晚到用量结算仍沿原通道，不计作 W06 全故障矩阵。
旧核心不认识新可选字段时不保证能够读写新 revision；W02 后续协议切片须完成明确的版本/能力与 writer 边界，不能宣称整包兼容矩阵已通过。
