## 用户可用结果

整稿摘要按真实页序显示内容、原图、SVG、SVG 预览及 PPT 预览；缺产物保留缺失状态。
每页链路可读保存过的 prepared/submitted 提示词、任务引用及有序 PPT 依赖。
历史读取固定到指定的已提交版本。后续当前稿变化不会让历史页或其提示词串到新稿。
坏对象只影响对应层，损坏的质量证据不会让旧工作台显示可交付。

## 实现与兼容

- 新增 `workbench.py`、两个只读投影 schema；没有新增持久化对象格式。
- CLI `view --summary`、`--revision`、`--page-id --lineage` 与 HTTP 共用投影。
  原 `view --json` 仍返回服务状态；读取选项与 `--open` 互斥。
- `/api/view`、`/api/view/summary`（别名 `/api/workbench`）、单页、单页 lineage、tasks、reviews 都尊重 revision。
  ID、路径、symlink、项目归属和从 current 可达的 parent 链共同约束读取；缺版本不回落。
- 元数据缓存按项目、对象 path/hash、inode/size/mtime/ctime，命中缓存仍校验路径。
  summary 不展开正文或提示词；大图/PPT 字节由文件接口校验 hash。
- prepared 直接读已冻结对象。没有可信绑定时保持 unknown；旧 submitted 仅是 host_reported。
  丢图片与丢元数据分开，仍可读的提示词不丢失。
- 文档中的 schema 副本分别随 rebuild/v3 规格镜像，活动真相仍在包资源内。
  边界扫描区分外部 `/autoplan` 技能记录与退役的裸 CLI 子命令。

原型、用户设计快照和历史评审按输入归档；它们没有接入生产路由。原始 CSV/测试日志/外部评审输入保留原字节与行尾，不为消除 diff 空白提示改写证据。
