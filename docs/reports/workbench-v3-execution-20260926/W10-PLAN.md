# W10 完整运行台与恢复执行边界

基线 `d42dda62c53bfeaf177c077f8e46074c8c23bdba`（W01 压力 PR #55 已合入），分支 `codex/workbench-w10-core`。先共享核心/CLI/schema 合入 main，再接前端。W07 真实 auto/trial 交错与第二页不变的缺口已在本卡验证期间补齐，见 W07-UI 的 2026-09-30 补证；用户验收仍单列。

核心复用现有 Task、ChangeSet、Candidate、GenerationRequest/Attempt、operations 和 Store；新增分页读取和按任务详情投影，不新增调用账或执行器。保留旧 `/api/tasks` 与 CLI status 的既有字段；新分页和详情共享固定 revision、typed error、离线恢复入口。

真实首次接手时间保存在 Task 中，由 `task_start` 写入，后续冻结请求/调用结算/重复读取不得伪造或移动。旧任务未记录时明确 unknown。新字段需写入边界保护，现有更高写入边界不能被采用候选、输入更新或组装降级。

运行事实：组内原请求、页、任务、结果/候选、调用额度和未知状态；正常 running 不列为人的待办。30 分钟只提示核实，不能自动 continue、重试、重新分配调用额度或取消。

前端复用既有草稿/业务操作恢复，补运行分页、局部错误、结果阅览/选择与用户待办。轮询活动 3 秒、闲置 15 秒、隐藏暂停、focus 立即刷新、最长 30 秒退避及单请求在途。核心合入后才修改这些界面。

验证保留原始 CLI/HTTP 输入输出、故障注入与真实 Host 记录的区别。W01 的 300×5×3 manifest 复用于 W04 首屏与 W10 20 分钟浏览；内存口径严格按第 6–10 分钟与第 16–20 分钟中位数，不在末段单独 GC。
