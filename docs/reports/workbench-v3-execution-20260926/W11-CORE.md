# W11 固定版本导出与历史恢复：共享核心

基于 W09 前端 PR #62 合并 `314df380b2b8df9d7540132f99a190c1d0b2f047`。本切片先接核心、合同、CLI 和同源 HTTP；浏览器导出界面及用户验收未完成。

`export --revision` 在开始时冻结可达快照。review 可在没有 PPT 时导出可读正文、已有图稿和缺项；不再复制原材料、完整提示词或工程对象。engineering 显式包含内部原件、引用闭包和该快照的祖先历史，可在临时目录恢复，排除运行认证、锁、服务状态、缓存与个人草稿。delivery 使用所选快照的检查、输入对齐、PPT 依据及专业政策，拒绝时返回同一版本的页/层缺项（exit 3 / HTTP 409）。

PNG/JPEG 元数据、SVG 注释/metadata 和 PPT 属性/备注/非可见形状描述在副本上清理。测试验证像素、正文和正常链接保留，原件 hash 不变；JPEG 扫描段后的注释和 XML 命名空间也检查。ICC 色彩解释保留，但私密值、未归一化 EXIF 方向、外部 SVG 资源、嵌入文件/宏及未知二进制内容会拒绝公开导出，避免悄悄改变可见内容。此检查不能替代对可见客户内容的人工判断。

每个导出有冻结 ID、用途、版本与 manifest。HTTP 不接受输出目录；GET 仅下载该项目 ID 的白名单文件，校验 manifest/hash。失败不会留下可下载半包，断线可重取同 ID。`handoff-check` 从当前原件重算确定性清理 hash，区分原件和清理副本，不相信调用者自报清单。

`history plan-restore/commit-restore` 提供影响预览和原子操作回执。确认创建新 revision；保留当前任务事实、调用、取消、政策和 user_stop。冲突不写入，回执缓存失败仍从已提交祖先恢复。旧 restore 复用同一恢复变换。
