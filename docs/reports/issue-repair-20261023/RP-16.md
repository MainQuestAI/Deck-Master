## Diagnosis and implementation

The existing packet carried the complete Page but did not explicitly make
audience register a page_copy check with per-Page identity, impact guidance and
counterexamples. The final privacy scanner addresses explicit markers, not
full semantic review; extending its keyword list would misclassify legitimate
sources, assumptions, timecodes and teaching examples.

New packet `page_copy_checklist` is a derived review input, not a new manuscript,
automatic finding generator or a second review flow. It anchors each checklist
entry to the exact manuscript Page ref, carries audience/task context, asks the
reviewer to inspect all visible fields, and distinguishes actual disclosure,
misleading production instructions, uncertain authorization and minor friction.
It explicitly preserves legitimate source/condition/timecode language. Native
review already reads the full packet; existing method readers freeze the updated
review method with contextual positive/negative examples. Findings use existing
page_copy with content/privacy kinds and existing impact/resolution fields;
no schema enum, authority, reader permission or persistence floor is relaxed.

The implementation does not claim to mechanically detect all semantic errors.
A real reviewer must actually read and judge the Page. A synthetic owned review
fixture supplies explicit judgments solely to exercise acceptance and gates.
