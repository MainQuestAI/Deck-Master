## Implementation

- `icons.confirm` and `candidates.decide` verify complete request digests and
  committed recovery inside the Store lock before applying new-operation gates.
- Explicit `pipeline.produce` performs exact recovery first, then both
  `stage.assemble` and `compile.ppt` gates under the same lock. `stages.assemble`
  delegates to this shared guarded implementation. Implicit production retains
  its compile gate. The second recovery/CAS check before output publication remains.
- `tasks.call_begin` verifies task, allowance, execution and frozen request before
  recovering an in-flight Attempt. `begin_attempt(replay_only=True)` cannot create
  a replacement Attempt if committed linkage is missing. Attempt schema and
  project/task identities are validated. New calls retain the eligibility gate;
  unknown/settled calls, stale inputs and terminal tasks retain rejection behavior.
- Recovery may refresh the disposable operations index through the existing
  recovery implementation. It does not create product artifacts, compile, render,
  read back PPT, allocate allowances or invoke models.
