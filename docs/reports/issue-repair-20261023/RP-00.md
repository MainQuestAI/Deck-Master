## Deferred-control follow-up from independent review

2026-10-22: independently reported hypothesis reproduced before repair.
`SummaryPoll.refresh()` awaited the async consumer then unconditionally restored
its old interval; `Project` could also publish old control/summary UI after that
await. A deferred control read, followed by `useSnapshot(completed)` and release,
failed deterministically with `3000 !== 15000` on the original RP-00 code.

The poll now provides a generation/visibility/lifecycle predicate to its consumer
and rechecks it after the await. Hiding retires the generation even if the tab is
shown again before completion. Project checks that predicate plus its navigation
generation before publishing control, summary, pending count, sync text or event.
This is read cancellation/fencing only; no permissions or snapshot meaning change.

PASS: `node examples/workbench/w10_poll_lifecycle.mjs`. The regression drives the
actual Project consumer with deferred control and route snapshot, stop, and
hide→show interruptions. It asserts no old info/latest/button/banner/sync/event
publication, preserves the newer polling interval, and proves the next visible
refresh succeeds. Existing timer/single-flight tests also pass. This is a Node
fault-injection test, not a new browser or customer acceptance claim.
