# RP-01 — Stage-specific reviewer discovery

Baseline: PR #184, `55adc97c5bb5f16ae7fcff7c33c43969fae9ce97`.
Implementation starts from integrated source `ae79d4c6`. Issue: #137.

## Diagnosis and behavior

The baseline `capabilities` projects only the currently registered receipt
providers. The native content runner installs its private provider only during
its owned execution, so an empty registry reports `needs_reviewer` without
revealing that runner. A content channel also says nothing about image or
conversion review support.

`review channels [--check-native] [--project <dir>]` now reports content,
original-image expression, SVG conversion and final-delivery channels separately.
`capabilities.review_channels` exposes the same default discovery. The existing
receipt flags and `review_channel_status` retain their semantics, explicitly
labeled as registered-receipt status.

Default discovery only locates the native executable. The optional check runs
`codex login status` with a timeout; it never starts an app-server, thread or
model turn, prints account output, installs credentials or changes providers.
It distinguishes missing tool, failed probe, missing native login, unverified
client and ready local prerequisites. Ready prerequisites are not a verified
session or completed review.

Independent Host/human receipt configuration and provider health are separate
from supported stage and actual executor evidence. The original-image Task
entry remains unsupported pending RP-20; native content review never claims
visual or human professional coverage. Existing project-native failed/running
executions are reported separately without altering their state.
