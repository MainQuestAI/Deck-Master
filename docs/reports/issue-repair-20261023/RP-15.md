## 实现与诊断

原来三个 Plan 字段仅约束类型/枚举，`design_requirements` 将原值完整送入制作 prompt，却没有字段级上屏语义。现在唯一活动合同和 Design 方法明确分类、密度解释、资格节点 ID 的含义和缺省边界。

新增可选、严格常量字段 `content_requirements.text_visibility=customer_visible_only.v1`。新解析器必定生成此标识，实际 `project_prompt` 据此写入消费规则：仅 `customer_visible` 供上屏，其他要求是非上屏设计上下文；保留合法来源/前提/限定，条件缺失返回内容阶段，不关键词过滤、不自动生成免责声明。原始设计依据仍可检视，不篡改 Page 或 Plan。

旧冻结输入缺此标识时保持原投影、哈希和读取，不注入新策略；fidelity/部分导入没有真实角色时继续返回 null profile/rationale 和空列表。既有 Plan 写入口仍校验实际 Narrative qualification 节点，任意新项目节点可用，空列表合法，未知 ID/错误角色/句子作为 ID 均拒绝。
