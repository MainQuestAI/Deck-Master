# RP-11 — Recover committed native review evidence

Baseline PR #184: `55adc97c5bb5f16ae7fcff7c33c43969fae9ce97`.
Issue #138. Built on RP-00 empty-findings fix and RP-01 discovery.

## Diagnosis and change

Previously the native runner persisted raw evidence objects during execution,
but failed Tasks did not retain a discoverable, bound acceptance checkpoint.
Retrying native review could start another execution; the judgment adapter also
required exactly one row per unit, preventing distinct historical owners of the
same unit from being rechecked together.

The owned runner now commits an observation checkpoint before parsing, then a
ready checkpoint after authenticating the envelope. Both are immutable objects
referenced by that exact Task. `review recover --project DIR --task-id ID` accepts
only that committed ready checkpoint, using the original event, envelope,
executor, operation, frozen basis, method release, validity interval and call
consumption. It never accepts an external JSON path, scans loose objects, renews
proof or invokes a model. Completed operations return `already_applied`.
`review native` advertises `recovery_available` for failed ready checkpoints.

Repeated unit rows must name distinct actual prior owners. Existing finding
closure and replacement validation remains authoritative; empty findings do not
erase a prior nonempty finding set.

## Acceptance and evidence

- AC1 PASS (synthetic): two complete sets of historical clean owners are replaced
  separately by the native adapter, preserving each review ID; an explicit
  finding-level test closes two owners independently and proves partial closure
  cannot close the other owner. Existing receiver tests reject empty-finding
  replacements of nonempty histories.
- AC2 PASS for tested faults (synthetic): invalid output preserves observation;
  receipt persistence failure returns `needs_evidence`; acceptance failure after
  proof commit recovers once; response timeout after actual acceptance commit
  returns already-applied without another execution. Original execution time
  and call allowances remain equal. Arbitrary filesystem/crash fault coverage
  is not claimed.
- AC3 PASS (synthetic): cross-project, wrong executor, altered envelope, stale
  manuscript, cancellation and expired original proof reject. No arbitrary JSON
  recovery API exists; missing authenticated evidence cannot be self-signed.
