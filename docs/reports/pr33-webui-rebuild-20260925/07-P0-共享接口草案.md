## 1. 结论摘要

1. PR33 的**运行时底座够用**：修订链、幂等 journal、任务状态机、新鲜度判定、审阅适用性、交付闸门都已存在。Web 缺的主要是**投影和入口**，不是新引擎。
2. 真正阻塞 U03–U05（选区修改 → Host 执行 → 回看结果）的只有 5 件事：区域结构化（缺口 G1）、Web 写入幂等（F1）、任务全生命周期投影（缺口 G2/G12）、任务结果回写（缺口 G7）、变化感知（缺口 G3）。这就是 S2-1 最小集合（§6.1）。
3. 两处 04 描述需要修正：
   - 缺口 G4：service 层已支持多页任务（`service.py:720-721`），只是 Web 写死单页。
   - 缺口 G5：没有专门的重排/移除入口，但 `import-draft` + `page_order` 已能做整稿重排/移除，代价是清空全部产物；合并/拆分完全没有。
4. 新增缺口 G7–G15、事实 F5–F6（§3.3）。其中缺口 G7（`result_refs` 从不回写）是 U04 对账的隐藏阻塞点，04 未列出。
5. 需要老板在决策点 G0 拍板的增量共 6 项（§9），其中"交接主路径"和"region 是否进 task schema"会直接改变 S2-1 的范围。

## 4. 增量方案

约定：所有新增字段均为**可选**，缺省时行为与当前 HEAD 一致；view 格式保持 `deck_view.v1`，只增字段不改含义。

### I-1 区域结构化（缺口 G1）
- **字段**：`POST /api/feedback` 请求体新增 `region`；Task 新增可选 `region`（需改 `task.v1.schema.json`，因 `:305` 为 additionalProperties:false）。坐标用页面画布归一化比例 0–1。
- **示例**：
```json
{"page_id":"p03","instruction":"把这张图换成流程图","base_revision":"r_0a1b",
 "region":{"x":0.12,"y":0.30,"w":0.40,"h":0.25,"unit":"canvas_ratio","element_refs":["atom_7"]}}
```
- **兼容性**：旧前端不传 region 时行为不变；老 document 中的 task 无 region 字段仍通过校验。`service.task_summary` 需把 region 带进交接包（`service.py:326-340` 附近）。
- **归属**：共享接口（web.py、schema）+ A 路（service.py 透传）。决策点 G0 确认"是否进 task schema"。
- **场景**：U04。

### I-2 Web 写入幂等（F1）
- **字段**：`/api/feedback`、`/api/restore`、`/api/export` 请求体接受 `operation_id`；`open_host_task` 允许调用方传入（替代 `service.py:731-734` 内部生成）；重复提交返回原 task。
- **示例**：
```json
{"operation_id":"op_7f3c...","page_id":"p03","instruction":"...","base_revision":"r_0a1b"}
→ 200 {"status":"awaiting_host","task_id":"t_19","operation_id":"op_7f3c...","replayed":true}
```
- **兼容性**：不传时仍内部生成；复用已有 OperationJournal（`tasks.py:81-107,263-283`）。
- **归属**：共享接口 + A 路。
- **场景**：U04（网络重试不重复开任务）、U05。

### I-3 任务全生命周期投影（缺口 G2、G12）
- **字段**：view 新增 `tasks[]`（保留 `pending_tasks` 不变），每项：task_id / kind / status / instruction / scope_pages / region / operation_id / dispatch_revision / result_revision / updated_at / invalidated_reason。可选 `?tasks=recent&limit=` 控制数量。
- **示例**：
```json
"tasks":[{"task_id":"t_19","kind":"repair","status":"completed","scope_pages":["p03"],
  "region":{"x":0.12,"y":0.30,"w":0.40,"h":0.25,"unit":"canvas_ratio"},
  "operation_id":"op_7f3c...","dispatch_revision":"r_0a1b","result_revision":"r_0a1c",
  "updated_at":"2026-09-25T10:02:11Z","invalidated_reason":null}]
```
- **兼容性**：纯新增字段；`/api/tasks`（`web.py:183-196`）同步补字段。
- **归属**：共享接口（view.py、web.py）。
- **场景**：U04、U05。

### I-3b 结果回写（缺口 G7，I-3 的前置）
- **字段**：accept 成功时把 `result_revision`、`result_refs` 写回 task 本身（当前 `tasks.py:609` 固定 `[]`，`tasks.py:940` 仅返回）。
- **示例**：`{"task_id":"t_19","status":"completed","result_revision":"r_0a1c","result_refs":[{"page_id":"p03","slot":"svg","digest":"sha256:..."}]}`
- **兼容性**：旧 task 无该字段视为未知；需同步 schema。
- **归属**：A 路（tasks.py）。
- **场景**：U04。

### I-4 变化感知（缺口 G3）
- **字段**：新增 `GET /api/summary` 返回 `{"revision_id","tasks_digest","view_status","updated_at"}`；或 `/api/view` 返回 `ETag`，支持 `If-None-Match` → 304。前端 2–5 秒轮询 summary。
- **示例**：`GET /api/summary → {"revision_id":"r_0a1c","tasks_digest":"9e1f","view_status":"ready"}`
- **兼容性**：新增路由，不影响现有 GET。SSE 不进 P0（stdlib http.server 单线程风险）。
- **归属**：共享接口。刷新机制待决策点 G0。
- **场景**：U04（Host 外部完成后页面自动更新）。

### I-5 批量修改请求（缺口 G4）
- **路由**：`POST /api/feedback/batch`，body `{"operation_id","base_revision","items":[{page_id, instruction, region?}...]}`；建议实现为"一个事务内开多个 task"，共用 batch operation_id 派生子 id。
- **示例**：
```json
{"operation_id":"op_b1","base_revision":"r_0a1b","items":[
  {"page_id":"p03","instruction":"换流程图","region":{"x":0.1,"y":0.3,"w":0.4,"h":0.2,"unit":"canvas_ratio"}},
  {"page_id":"p05","instruction":"标题改短"}]}
→ {"status":"awaiting_host","task_ids":["t_20","t_21"],"operation_id":"op_b1"}
```
- **兼容性**：新增路由；单条 `/api/feedback` 保留。
- **归属**：共享接口 + A 路（service 需提供批量事务入口）。语义（多 task 还是单 task 多页）待决策点 G0。
- **场景**：U05。
