## 目标

证明新工作台在**正常安装（wheel）**下完整可用：静态资源全部随包分发、完全离线、Skill 与程序版本一致（U15）。

## 已知事实（拆卡时核实，`c93f5a2`；2026-09-25 用测试 wheel 复核）

- **子目录打包已确认可用**：`MANIFEST.in` 的 `recursive-include src/deck_master/resources *.json *.css *.js *.html *.md` 配合 `include-package-data = true`，会把 `static/v2/` 下各级子目录里的这些类型文件打进 wheel（已用 `static/v2/index.html`、`static/v2/js/app.js` 实测）。
- **剩余风险：扩展名白名单**。同一次实测中 `static/v2/icon.svg`、`static/v2/font.woff2` **没有**进入 wheel。新前端如果使用 svg/png/woff/woff2/ico 等资源，必须同步扩展 `MANIFEST.in` 与 package-data（共享文件，走 S 类 PR），并用步骤 2 的测试兜底。
- `tests/rebuild/test_install.py` 已有：`test_wheel_carries_schema_static_and_methods`、`test_isolated_install_runs_full_local_flow`、`test_isolated_full_chain_and_local_edit`、`test_wheel_and_sdist_exclude_customer_material_and_secrets`。
- 版本号：真实发布清单用 `deck_master.__version__`（`1.0.0.dev2`，已有测试）；`skills/manifest.json` 的 `package_version: 0.9.14a4` 是重构前遗留字段，代码中无读取方，不影响运行。修正与一致性测试由 S 类 PR `codex/shared-skill-sync` 处理，本卡只复核其已合入。
- **Skill 双副本漂移（S 类 PR 前置处理）**：`src/deck_master/resources/skill/references/content-methods.md`（被 git 跟踪）含提交 `2cf9884` 的“原始要求 / 方案建议”区分规则，而构建钩子以 `skills/deck-master/` 为源覆盖该目录，后者缺这段，导致**正常安装丢失该修复**。现有 `test_install` 只比对 `SKILL.md`，没有覆盖 references。由 `codex/shared-skill-sync` 修复并补测试；本卡步骤 4 复核 wheel 中全部 Skill 文件与 `skills/deck-master/` 一致。

## 可改范围 / 禁止

- **可改**：`pyproject.toml` 的 package-data（`pyproject.toml` 属于共享文件时，按 S 类规则单独 PR 到 `main`，并在本卡中登记）；`tests/rebuild/test_install.py`（**只增加**用例）；必要的 `skills/manifest.json` 版本字段（需说明依据）。
- **禁止**：修改业务代码；为了通过测试删除或放宽已有的安装测试；发布到任何包索引；打 tag。

## 实施步骤
