## 目标

证明新工作台在**正常安装（wheel）**下完整可用：静态资源全部随包分发、完全离线、Skill 与程序版本一致（U15）。

## 已知事实（拆卡时核实，`c93f5a2`）

- `pyproject.toml` 使用 `include-package-data = true`，package-data 为 `"resources/static/*"`——**单层通配**。新前端放在 `static/v2/` 子目录时，这条规则很可能不会打包子目录，必须实测，按需改为 `resources/static/**/*` 或逐级列出。
- `tests/rebuild/test_install.py` 已有：`test_wheel_carries_schema_static_and_methods`、`test_isolated_install_runs_full_local_flow`、`test_isolated_full_chain_and_local_edit`、`test_wheel_and_sdist_exclude_customer_material_and_secrets`。
- 版本号：`pyproject.toml` 与 `src/deck_master/__init__.py` 为 `1.0.0.dev2`；`skills/manifest.json` 中 `package_version` 为 `0.9.14a4`。**两者不一致**，需要确认这是预期的（例如 manifest 记录的是兼容下限）还是遗漏，并在本卡中给出结论。

## 可改范围 / 禁止

- **可改**：`pyproject.toml` 的 package-data（`pyproject.toml` 属于共享文件时，按 S 类规则单独 PR 到 `main`，并在本卡中登记）；`tests/rebuild/test_install.py`（**只增加**用例）；必要的 `skills/manifest.json` 版本字段（需说明依据）。
- **禁止**：修改业务代码；为了通过测试删除或放宽已有的安装测试；发布到任何包索引；打 tag。

## 实施步骤

- [ ] 1. 构建 wheel 和 sdist，列出其中的 `resources/static/` 文件，与源码目录逐一对比。
- [ ] 2. 增加测试：wheel 中包含 `static/v2/` 的每个文件（按源码目录生成期望清单，不写死）；安装后 `/v2/` 的每个资源都返回 200。
- [ ] 3. 离线检查：`rg` 检查 `static/v2/` 中没有 `http://`、`https://` 的外部引用（本机 127.0.0.1 除外）；Playwright 在拦截全部外部请求的情况下完整走一遍主路径。
- [ ] 4. Skill 同版本：确认 Skill 中关于新工作台的指引（如交接方式）与本版本行为一致；给出版本不一致问题的结论，需要修改的一并完成。
- [ ] 5. 确认 `test_wheel_and_sdist_exclude_customer_material_and_secrets` 仍通过，并且新增的 prototype/、assets/ 截图等文档资产没有进入 wheel。
- [ ] 6. 在隔离的虚拟环境中安装 wheel，执行 `deck-master view --project <夹具> --open`，确认打开的是新界面（如果新界面仍在 `/v2/`，则确认该入口可用），并记录截图。
