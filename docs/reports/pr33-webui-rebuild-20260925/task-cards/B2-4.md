## 目标

在**正常浏览器 + 真实 Codex Desktop** 中完成 U04“框选箭头往返修改”，并按 G0 确定的交接方式完成。证明新工作台的主路径真实可用，不是在测试夹具中模拟出来的。

## 前置条件

- 使用 `codex/webui-rebuild` 最新源码，以可编辑方式安装或在仓库内运行，记录 SHA。
- 使用示例项目或测试项目（**不得使用客户项目**），其中至少一页有一个明确的箭头或图形元素，方便判断“改对了没有”。
- 已确定一条可验证的修改意见，例如“把这个箭头改为指向右侧的‘结果’方框”。

## 实施步骤

- [ ] 1. 启动新工作台，记录项目路径、源码 SHA 和初始 revision。
- [ ] 2. 在浏览器中框选箭头，写意见，提交。记录 task_id，保存请求体（去除 token）。
- [ ] 3. 按 G0 的方式交接到 Codex（自动 / 拉取 / 粘贴交接指令），记录用户实际操作了几步。
- [ ] 4. 确认 Codex 执行了 `task start`：`deck-master task status --json` 中状态为 `running`，并有执行方记录。截图浏览器此时的状态。
- [ ] 5. Codex 完成修改并 `task accept`，记录结果 revision。
- [ ] 6. 浏览器中：状态自动变为已完成 → 打开对比 → 截图。**人工判断箭头是否改对。**
- [ ] 7. 刷新页面、切页再切回：请求、结果和对比都还在；上一轮未提交的草稿也还在。
- [ ] 8. 从结果再发起一轮小修改，走完第二轮往返（验证“再改”）。
- [ ] 9. 写 `09-P2-真实往返记录.md`：环境、每一步的时间与截图、task_id、修改前后的 revision、Codex 接手证据（命令输出片段）、用户操作步数、发现的问题（附严重度）、结论建议。截图放 `assets/b2-4/`。

## 失败去向

- 交接失败 → 回到 G0 重新评估交接路径（B0-2 的补充实验）。
