## 目标

把运行时的内部状态（任务状态、revision、page_hash、审阅状态、产物新旧）翻译成用户看得懂的状态，并定义每个用户动作的即时反馈、最终结果和失败表现。这张表是 B1-2 原型和 P2–P4 前端实现的唯一交互依据。

## 背景与输入

- G0 决策（04 §6）：交接主路径是自动、拉取，还是手动批量。
- 07 接口草案（增量字段与路由）；05 基线（旧 UI 的问题）。
- 03 方案 §6（全部操作）、§7.2（手动退路）、§7.3（刷新策略）、§8（状态与异常）。
- 内部任务状态：`TASK_STATUSES`（queued、awaiting_host、running、completed、failed、cancelled、superseded）。

## 可改范围 / 禁止

- **可改**：只写 08 文档。
- **禁止**：发明运行时不存在的状态（例如“已送达”只在 G0 选择了自动模式、且有真实回执时才存在）；出现前端自行判断的“ready”状态。

## 实施步骤

- [x] 1. **动作表**：逐一列出 03 §6.1–6.6 的每个用户动作（至少包括：打开、找页、切视图、改正文、保存、撤销草稿、框选、写意见、保存修改请求、批量交接/发送、取消、比较、再改、重排、移除、合并、拆分、跨页改写、补材料、改受众、查看历史、比较历史、恢复、导出审阅、导出交付、导出工程）。每行包括：`动作 | 前置条件 | 调用接口（现有或 07 增量编号） | 立即反馈（≤300ms 内看到什么） | 最终结果 | 失败时显示 | 所属阶段(P2/P3/P4)`。
- [x] 2. **状态映射表**：`内部事实组合 → 用户文案 → 视觉标记 → 可做的下一步`。至少覆盖 03 §8 表中的九种情况，加上：冲突（409）、页面已移除、结果晚到、服务断开、保存结果未知、审阅停滞（A6）。
- [x] 3. **同页多状态**：说明同一页上“正文已保存 / 旧成品可看 / 新制作待接手”如何同时呈现（03 §8 首段），给出一页上多个标记并存时的优先级规则。
- [x] 4. **异常处理表**：03 §8 的六条异常要求，每条写出触发条件、界面表现、恢复步骤和保留的数据。
