## 目标

在新工作台中实现两种修改输入：**直接改正文**（U03）和**框选区域 + 写意见**（U04 的前半段），提交时使用 S2-1 的结构化字段，本地草稿不串页、不丢失。

## 可改范围 / 禁止

- **可改**：`resources/static/v2/`；`tests/rebuild/test_workbench_v2_*.py`。
- **禁止**：改后端；把区域拼进 `instruction` 文本（必须使用 `region` 字段）；在前端自行合并冲突。

## 实施步骤

- [ ] 1. **改正文**：按正文结构（标题、段落、条目、表格、脚注）编辑。调用 `POST /api/edit`，带 `base_revision`、`page_hash` 和前端生成的 `operation_id`（UUID，一次保存操作固定一个，重试时复用）。保存成功后显示“正文已保存，成品待更新”，旧画面保留并标“旧”（03 §6.1）。
- [ ] 2. **本地草稿**：按 `page_id` 保存在 `localStorage`（键包含项目身份和 page_id），记录基准 revision。切页、刷新后恢复；保存成功后清除；遇到 409 时保留草稿（冲突的完整界面在 B4-1，本卡只需保证草稿不丢，并提示“内容已被其他修改更新”）。
- [ ] 3. **框选**：在实际显示的画面（svg_preview 或 ppt_preview）上拖拽框选。坐标按图像自然尺寸归一化到 0–1，并记录所看的 slot 与 artifact sha256。缩放或窗口尺寸变化后，框的位置仍对应图像上的同一区域。
- [ ] 4. **提交修改请求**：意见 + region → `POST /api/feedback`（带 `operation_id`、`base_revision`、`page_hash`）。按 G0 结论显示“保存修改请求”或“保存并发送”；成功后显示 08 中对应的状态文案，**不显示“处理中”**（只有 Host 接手后才能显示，03 §6.2）。
- [ ] 5. **多条待交接**：同一页或多页可以先保存多条请求；如果 S2-1 实现了批量接口，提供“一次交接 N 条”的入口（U05 的前半段）。
- [ ] 6. **画面已变化**：页面画面的 sha 已经不同于框选时的 sha 时，旧框不再叠加到新图上，改为标注“针对旧画面”（03 §6.2 末段）。
- [ ] 7. 测试（Playwright）：
  - 改字 → 保存 → 刷新 → 内容正确；
  - A 页输入不保存 → 切到 B 页 → 切回 A 页，草稿还在，B 页没有 A 页的内容（U03 不串页）；
  - 框选后，抓取提交的请求体：`region` 字段存在，坐标在 [0,1] 内，`instruction` 中不含坐标 JSON；
  - 在 1280 和 1440 两种宽度下对同一区域框选，得到的归一化坐标误差 ≤0.01；
  - 双击保存只产生一个 revision（依赖 operation_id）。

## 验收标准

| AC | 标准 | 对应 |
| --- | --- | --- |
| AC1 | 完整测试全绿 | — |
| AC2 | 改字后刷新或切页，已保存正文准确；本地输入不串页；旧画面标“旧” | U03 |
| AC3 | feedback 请求体带结构化 region；`instruction` 是纯文字意见 | U04 |
| AC4 | 不同窗口宽度下，框选的归一化坐标一致（误差 ≤0.01） | U04、U14 |
| AC5 | 提交后没有显示“处理中”，文案与 08 一致 | U04 |
| AC6 | 双击保存或提交不产生重复 revision 或 task | U09 |
| AC7 | 画面变化后，旧框不会套在新图上 | U04 |

## 验收方法

1. 亲自运行测试，并用 Playwright 在夹具项目上复现 AC2–AC7。
2. 在 DevTools / Playwright 中抓取 `/api/feedback` 请求体，存档到验收记录。
3. 用 `deck-master task status --json` 读取刚提交的 task，确认 region 已持久化。
