## 目标

把“新界面成为默认”准备成**一次可回退的开关操作**，并写清旧界面的退役步骤与回退方案，供老板做 G5 决策。

## 可改范围 / 禁止

- **可改**：`resources/static/`（切换入口，例如把新界面挂到 `/`、旧界面移到 `/legacy/`，**或者**通过配置 / 环境变量切换——二选一，写明理由）；如需改静态路由，属于 `web.py` 共享改动，按 S 类规则走 `main`；文档。
- **禁止**：删除旧界面代码（退役在切换稳定之后另开卡）；打 tag；部署到 launchd 服务（`com.mainquest.deck-master.preview`）；推送 `main`。这些都需要 T25 发布授权。

## 实施步骤

- [ ] 1. 实现切换开关：默认值仍为旧界面（在 G5 之前不改变用户行为）；开关打开后 `/` 指向新界面；保留旧界面的访问入口。
- [ ] 2. 测试：两种开关状态下，入口都正确；两种状态下 `test_install.py` 都通过；旧界面的测试不受影响。
- [ ] 3. 写 `11-P5-默认切换与退役方案.md`：
  - 切换步骤（具体到命令）与验证点（`curl -sf http://127.0.0.1:5050/api/runs`、打开页面确认）；
  - 回退步骤与所需时间；
  - 旧界面的退役条件（例如切换后稳定使用 N 次、没有阻断问题）和退役时要删除的文件清单；
  - Skill / 文档需要同步修改的地方；
  - 与 A 路的合并顺序（B 路整体 rebase 到最新 `main` → PR → fast-forward `main` → tag），以及合并前的检查（`python3 -m pytest -q tests`）；
  - 风险与未验证项。
- [ ] 4. 汇总 B5-2 的结论，给出 G5 建议（切换 / 带条件切换 / 暂不切换）。
