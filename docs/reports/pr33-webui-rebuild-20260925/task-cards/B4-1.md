## 目标

让所有异常都有可理解的提示和可执行的下一步，并且**用户的输入不丢失**，覆盖 03 §8 与 U09–U11。

## 场景清单（每条都要有测试）

| 场景 | 期望行为 | 对应 |
| --- | --- | --- |
| 双击保存 / 提交 | 同一 `operation_id`，只产生一次写入；按钮在请求期间禁用 | U09 |
| 请求超时 | 显示“结果未确认”，提供重试；重试复用原 `operation_id`，服务端返回 already_applied 时显示为成功 | U09 |
| 服务端 5xx | 保留输入，提示可重试 | U09 |
| 并发冲突 409（另一个标签页或 Codex 已改动同一页） | 保留本地草稿；显示“稿件已被更新”；提供：查看最新 / 把我的修改应用到最新（重新提交）/ 放弃我的修改。**不做自动合并** | U10 |
| 取消进行中的任务 | 调用 `/api/cancel`，状态变为已取消；已开始的 Codex 工作如何处理，按 08 的文案说明 | U11 |
| 任务失败 | 显示原因摘要（不暴露内部栈信息）和下一步（重试 / 修改意见后重提） | U11 |
| 服务断开 / 电脑休眠后重连 | 显示连接状态；恢复后自动重新拉取 view；期间的本地草稿不丢 | U11 |
| 迟到结果（任务已取消或已被取代后才完成） | 按 view 中的真实状态显示，不把迟到结果当成当前结果应用 | U11 |
| 会话 token 失效（服务重启） | 重新获取 session；失败时提示重新打开工作台 | U11 |

## 可改范围 / 禁止

- **可改**：`resources/static/v2/`；前端测试。
- **禁止**：前端自动合并冲突；吞掉错误只显示“失败”；为了通过测试放宽服务端校验。
- 如需修改服务端（例如 `/api/feedback` 缺少幂等），只能开 S 类 PR 到 `main`，并在本卡中登记。

## 实施步骤

- [ ] 1. 实现统一的请求层：`operation_id` 生成与复用、超时、有上限的重试、错误分类（网络 / 409 / 4xx / 5xx）。
- [ ] 2. 按场景清单实现 UI 与文案（与 08 一致）。
- [ ] 3. 测试：使用 Playwright 的 `route` 注入超时、5xx、断网；409 用两个浏览器上下文或 CLI `edit` 制造真实冲突；迟到结果用夹具在 cancel 之后执行 accept（如果服务端允许）或用路由模拟。
- [ ] 4. 每个场景截图（1280），放 `assets/b4-1/`。

## 验收标准

| AC | 标准 | 对应 |
| --- | --- | --- |
| AC1 | 完整测试全绿；场景清单中每条都有自动化测试 | U09–U11 |
| AC2 | 任何异常下，已输入但未保存的内容不丢失（刷新后仍在） | U09–U11 |

| AC5 | 文案中不出现内部术语或栈信息 | — |

## 验收方法

亲自运行测试；手工复现 409（两个标签页）和断网重连；核对 revision / task 的数量。
