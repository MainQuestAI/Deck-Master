## 目标

搭建新工作台的骨架：整稿概览 + 页面导航 + 单页阅读区，数据全部来自真实 `/api/view`。旧界面在默认切换前保持可用。

## 设计决策（本卡负责落定，写进 PR 描述）

- **新旧并存方式**：推荐新界面放在 `/v2/`（`resources/static/v2/`），旧界面保留在 `/`。这需要 `web.py` 增加静态路由，而 `web.py` 属于共享文件，因此：要么在 S2-1 中顺带加入 `/v2/*` 静态路由，要么单开一个很小的 S 类 PR 到 `main`。**B2-1 不直接改 `web.py`。** 路由没有合入之前，可在本地用测试夹具注入 `static_dir` 进行开发。
- **技术栈**：默认原生 JS + ES Module，不引入构建步骤。如果要引入框架或构建工具，必须先证明它能满足 U15（离线、随 wheel 打包、`test_install.py` 通过），并在 PR 中说明取舍，由验收人确认。

## 可改范围 / 禁止

- **可改**：`src/deck_master/resources/static/v2/`（新建）；`tests/rebuild/` 下新增 `test_workbench_v2_*.py`（Playwright 浏览器测试或基于 `http.server` 的集成测试）。
- **禁止**：修改旧的 `resources/static/index.html|app.js|style.css`；修改 `web.py`、`view.py`；使用外部 CDN；任何写死的样本数据（测试夹具除外）。

## 实施步骤

- [ ] 1. 按 B1-2 原型的信息架构实现布局：顶部（项目名、当前版本的短标识、整体状态）、左侧整稿概览（缩略图 + 标题 + 页面状态标记）、主区（单页阅读）。
- [ ] 2. **缩略图规则**（03 §5.4）：有 `ppt_preview` 用 PPT 预览，否则用 `svg_preview`；两者都没有时显示正文摘要卡片，**不显示虚构缩略图**（U01）。预览与当前正文不对应时（正文比成品新），加“旧”标记。依据来自 view 中的真实字段；现有 view 无法判断时，把缺口登记到 07，并先显示“无法确认是否最新”，不猜测。
- [ ] 3. 页面导航：点击、方向键上下切页；URL hash 记录当前页（`#page=<page_id>`），刷新后回到原页（U02）。
- [ ] 4. 状态标记只用 08 中定义的用户文案。
- [ ] 5. 错误状态：`/api/view` 失败或服务断开时，保留最后一次成功的内容，并显示“连接中断，显示的是 <时间> 的内容”。
- [ ] 6. 测试：至少覆盖——带预览的项目和仅有正文的项目都能渲染；仅有正文时 DOM 中没有 `<img>` 缩略图；方向键切页；刷新后回到 hash 指定的页；view 请求失败时有提示。
- [ ] 7. 截图：1280×800 和 1440×900 下的概览与单页，各两张，放 `docs/reports/pr33-webui-rebuild-20260925/assets/b2-1/`。

## 验收方法

1. 范围检查：`git diff --stat` 只允许 `static/v2/`、新增测试和 assets。
2. 用两个夹具项目（有预览 / 仅正文）亲自打开新界面，逐条核对 AC2–AC4。
3. Playwright 拦截外部请求并运行一遍。
