## 目标

在接入真实接口之前，验证“看整稿 → 改一页 → 等待 → 比较 → 再改”这条主路径，以及整稿操作的交互模型，能不能在不看说明的情况下被理解。原型是讨论和决策用的，不是产品代码。

## 背景与输入

- 08 动作与状态表（唯一交互依据）；03 方案 §5（信息架构）、§10（视觉原则）；05 基线（旧 UI 问题，不要重犯）。
- 真实规模：≥12 页，标题长度参考 `examples/` 中真实示例的标题。

## 可改范围 / 禁止

- **可改**：只写 `docs/reports/pr33-webui-rebuild-20260925/prototype/` 和 `assets/b1-2/`。
- **禁止**：修改或替换 `resources/static/`；引用外部 CDN（原型必须离线打开，不联网也能用）；引入需要构建的前端框架（原型用原生 HTML/CSS/JS，打开 `index.html` 就能运行）；使用客户材料。
- **样本标记**：每个样本数据状态在画面上带可见的“样本”角标；README 写明所有数据都是样本。

## 实施步骤

- [ ] 1. **画面清单**，每个画面都要能通过原型内的操作到达（不是只能靠静态切换）：
  1. 整稿概览（≥12 页，缩略图 + 标题 + 页面状态标记）；
  2. 单页阅读与改正文；
  3. 框选区域 + 写意见；
  4. 待交接修改汇总（批量）；
  5. 等待接手（按 G0：手动模式下显示“复制交接内容”）；
  6. 处理中（旧成品仍可看）；
  7. 结果对比（同页前后）+ 在新版上再改；
  8. 冲突（保留本地草稿 + 显示服务端新内容）；
  9. 失败（保留旧结果 + 恢复方式）；
  10. 部分完成（批量中部分页有结果）；
  11. 仅有正文（U01：没有任何预览，不显示假缩略图）；
  12. 整稿操作：重排（含键盘操作）、移除、选中多页发起合并/拆分；
  13. 历史查看与恢复确认；
  14. 导出（审阅 / 交付 / 工程三种，交付不满足条件时说明原因）。
- [ ] 2. **状态切换器**：原型角落放一个“样本场景”切换面板（明确标为原型工具），可以一键进入上面 14 个画面，方便走查。
- [ ] 3. **尺寸**：1280×800 和 1440×900 下都不出现横向滚动、文字截断造成信息丢失、按钮重叠。
- [ ] 4. **键盘**：页面列表支持方向键切页；重排支持键盘移动；焦点可见。
- [ ] 5. **截图**：14 个画面 × 2 种尺寸，放 `assets/b1-2/`。
- [ ] 6. **缺口登记**：原型中凡是需要、但 07 草案和现有接口都没有的数据或行为，逐条登记（写进 prototype/README.md 的“接口缺口”一节，并同步补到 07）。
- [ ] 7. **走查脚本**：README 中写一段 5 分钟走查任务（例如：“把第 7 页的箭头改为从渠道指向平台，等结果回来后比较，再把标题改短”），供老板试走。

## 验收方法

1. 用 Playwright 在断网条件下（拦截所有非 `file://` 请求）打开原型，确认 0 个外部请求。
2. 按 08 逐个动作点一遍，记录偏差。
3. 在 1280×800 下截图，与执行者的截图比对。
4. 组织老板试走：只给走查任务文字，不讲解；记录老板卡住的位置。卡住超过 1 次的位置列为必须修改项。
