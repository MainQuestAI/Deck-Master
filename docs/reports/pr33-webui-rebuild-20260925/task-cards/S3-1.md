## 目标

补上 G5：提供页面**重排、移除、合并、拆分**的 service 函数和 CLI 入口，保证页面身份、来源关系和版本记录正确。这是 U06、U07 的前提，Web 只是调用方。

## 设计要求（先写设计说明，经验收人确认后再实现）

在 PR 或 `docs/` 中写一页设计说明，至少回答：

1. **页面身份**：重排后 `page_id` 保持不变；移除的页面是否保留在历史中；合并后新页的 id 如何生成，与原页是什么关系；拆分后各子页的 id 与来源。
2. **来源关系**：每页记录 `derived_from`（或同等字段），合并 / 拆分后可以追溯。
3. **与已有产物的关系**：合并 / 拆分后的页面，其 blueprint / svg / pptx 是否作废、需要重新制作；是否通过 open_host_task 生成 reconstruct 任务交给 Host；已有审阅结论如何处理（沿用 / 作废）。
4. **版本与并发**：每个操作生成一个新 revision；接收 `base_revision` 和 `operation_id`，冲突返回 409（沿用 editing.py 的 ConflictError 模式）。
5. **进行中的任务**：涉及页面有 `awaiting_host`/`running` 任务时，是拒绝还是把这些任务标记为 superseded。
6. **撤销**：通过 `history restore` 恢复到操作前的 revision 是否足够。

## 可改范围 / 禁止

- **可改**：`service.py` / `editing.py`（新增函数）、`cli.py`（新增子命令，如 `pages reorder|remove|merge|split`）、必要的 `store.py` 辅助函数、schema（只加可选字段）、`tests/rebuild/` 中新增测试。
- **禁止**：改变现有 edit / restore / export / 审阅的既有行为；修改 `resources/static/`；在本卡中加 Web 路由（属于 S3-2）。

## 实施步骤

- [ ] 1. 写设计说明，提交验收人确认。
- [ ] 2. 先写测试，至少包括：
  - 重排：顺序变化，page_id 不变，正文和产物不变，生成新 revision；
  - 移除：页面从当前版本消失，历史版本中仍可读取；恢复到操作前 revision 后页面回来；
  - 合并两页：新页正文包含两页内容（按设计规则），`derived_from` 指向两页，原页从当前版本移除；
  - 拆分一页：子页 `derived_from` 指向原页；
  - `base_revision` 过期时返回冲突；`operation_id` 重放时返回 already_applied；
  - 涉及的页面有进行中任务时，按设计说明处理；
  - `export` 在操作后仍然正确（页码目录 `NN-<page_id>` 顺序正确）。
- [ ] 3. 实现 service 与 CLI。CLI 支持 `--json` 输出。
- [ ] 4. 更新 `docs/agent-task-index.md` 或相关 Skill 文档，让 Host 知道这些命令（如属 A 路的 Skill 维护范围）。
- [ ] 5. 跑完整测试，开 PR。
