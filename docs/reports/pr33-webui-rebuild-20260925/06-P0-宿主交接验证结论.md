- 任务卡：`task-cards/B0-2.md`；对照：`03-Deck-Master方案工作台重构方案-v1.0.md` §7.1 / §7.2 / §7.3、§12.2 U 场景
- 源码基线：`c46e08c`（分支 `codex/webui-b0-2`），运行时 `.venv/bin/deck-master`（Python 3.12）
- 证据目录：`assets/b0-2/`（X-Deck-Token 已打码，Codex thread id 已打码）
- 测试项目：`/tmp/dm-b0-2/proj`（真实 Codex 往返），`/tmp/dm-b0-2/proj2`（失败路径与批量，宿主由验证 Agent 代行，非 Codex 实测）

## 1. 结论（先结论）

1. **推荐首版主路径：c 手动批量交接。** Web 生成交接文本，用户粘贴到已有 Codex 会话，Host 用 CLI 执行 `continue → task start → task accept`，结果自动回写 revision。已用真实 Codex（`codex exec` 0.156.1）跑通一次完整往返：task `758bdbb62e76`，revision `e5b0176… → a20b7113…`。
2. **退路：a Skill 拉取。** 用户在 Codex 会话里说“继续”，Host 执行 `continue`，领取全部 awaiting_host 任务。CLI 机制可用，但 Skill 没有“每轮先查 Web 反馈”的指令，Codex 不会自己发现（H3）。
3. **b 外部触发：当前判定为不可全自动。** 证据如下：
   - deep link 只预填输入框，没有自动发送；
   - AppleScript 没有发送提示的命令；
   - app-server daemon 没有运行；
   - 没有 MCP 入站入口，也没有快捷指令或 AppIntents；
   - `codex queue` 需要 thread UUID，而 Web 不知道这个 id。
4. 限制一：同页多条意见逐条回写时，第 2 条起会冲突（stale），必须合并成一个任务或支持 rebase（H2）。
5. 限制二：running 任务没有租约和超时，宿主断线后会一直停在 running，只能在 UI 取消（H4）。
6. 限制三：同一条意见在完成后再次提交，会新建任务并重复执行（H6）。
7. 限制四：本机正常安装不完整：Skill 链接悬空，`deck-master` 不在 PATH（H7）。
8. 本次“Codex 实测”用的是 Codex CLI（`codex exec`），**不是 Codex Desktop**。Desktop 实测列为“待老板配合”（见 §8）。

**手动路径对 §7.2 三条可用标准的回答：**

| §7.2 标准 | 当前实测 | 首版补齐条件 |
| --- | --- | --- |
| 多项修改可一次交接 | **部分满足**：一次 `continue` 可列出全部任务（11），但同页第 2 条起冲突（12） | H2 |
| 用户无需维护路径和任务状态 | **不满足**：本次交接文本需要人工写入项目路径和 CLI 路径；冲突后要人工取消重提 | H1、H2、H7 |

- 接手后，状态为 running，并带有 execution_ref（04）。
