# 内容、逐字稿、逐页稿与效果评价：待验证的产品方法

## 术语必须先对齐

用户的“逐字稿”可能指完整内容全文，也可能指现场口播稿。系统应从任务上下文识别；如果两者会造成实质不同交付，明确区分并针对该缺口提问，不静默选一种。本文采用以下候选定义：

| 产物 | 解决什么 | 包含 | 不能替代 |
|---|---|---|---|
| 内容论证稿 | 内容本身是否成立、为何这样讲 | 完整观点、理由、证据、限定、反对意见、论证顺序 | 目录、提示词或页面标题列表 |
| 口播逐字稿 | 人实际如何说，听众能否跟上 | 可说出口的句子、解释/举例、过渡、节奏、停顿、预计时长；与页关联 | 上屏全文；不能把关键证据只藏在备注 |
| 逐页上屏稿 | 每页让人看到什么并完成什么理解 | 标题、完整可见正文、图表内容/标签/注释、证据位置、页职责 | “本页讲清某某”的内部制作说明 |
| 设计/制作说明 | 内容以何种空间结构表达 | 阅读顺序、视觉层级、图式、素材、布局和密度约束 | 客户可见正文；不应混入 PPT |

现状：Page v2 已有 customer_visible/body_blocks、speaker_notes、visual_spec；ContentPlan 保存页目标与来源。以上“有存储字段”不证明有独立的口播生产、排练或语义映射流程。新模型是否新增独立稿件对象、如何引用 Page 以避免双份正文漂移，属于 D03/D06，尚未定 schema。

口播场景可先写完整论述再分镜，也可先组织页面职责再写口播；最终需要双向校对。独立阅读稿可以不生产口播逐字稿；公司介绍、教学、数据解读可以没有行动号召。不能用固定销售故事模板统治所有任务。

## 内容确定的过程

1. **读取与判断输入。** 分清正式要求、当前事实、历史参考、专家经验和模型推断。先提炼已知，再找会改变目标/主张/篇幅的缺口。
2. **有目的的专家访谈。** 展示已有理解和具体疑问，例如“材料证明当前问题在信息缺失，但建议要求扩大自动执行；哪种改变才是这次要讨论的范围？”每轮围绕当前分歧，答案更新决定或留下分歧。问题数量、回答字数都不是完成标准。
3. **建立受众变化目标。** 听众现在知道/相信/担心什么，希望其理解、判断或采取什么；哪些信息必须保留，哪些只是背景。用户目标已有依据就复用。
4. **搭建论证。** 主张 → 支持理由 → 可定位证据 → 推论边界 → 真实异议/替代 → 回应。指出无法从现有证据推出的结论，允许改变主张、补证或标注限制。
5. **组织叙事与篇幅。** 排序按听众需要解决的问题推进；每章/页有职责与承接。评估删页是否破坏理解，新增页是否有独立增量。先有内容预算，再协商页数。
6. **写作、阅读、反驳、实际改稿。** 对照目标和材料，从全文阅读检查跳步、重复、空洞和含混；具体指出问题并修改。主张变化回到 Planner，普通文字润色在已授权范围内完成。

当前 [content-methods](../../../skills/deck-master/references/content-methods.md) 已有机制、判断、选择、页间关系与完整正文方法，应保留并发展。不能宣称现版本完全没有内容方法；问题包括这些方法如何进入前期协作、产生什么中间产物、何时足够好以及由谁判断。

## 说服逻辑如何评价

“说服”不等于让人同意任何观点。应让目标受众能理解证据支持什么、条件是什么、为什么推荐某个选择，保留诚实异议。教学或说明型任务则评价能否正确解释/应用，而不是是否出现 CTA。

一条论证记录至少能回答：本页/本节的判断是什么；证据是否真的支持该判断；哪个推理步骤需要解释；听众最可能质疑什么；替代是否被公平描述；哪项限制会改变决策；此处之后为什么需要下一页。无需强制每页使用结论式标题，但需要有可辨认的沟通职责。

**合成示例，仅用于说明评审方法：** 给定材料“某次抽样 100 个请求中 38 个缺少设备版本”，不能写成“系统上线后将节省 38% 成本”。候选主张可改为“优先验证版本信息前置采集是否减少补问”；理由是缺版本现象明确，因果与收益尚未测量；异议是现场可能无法取得版本，需要采集可行性验证。这一判断可能组织为现象/原因假设、流程设计、验证方案三种页职责。页数取决于讲解时长和证据复杂度，不能先凑三页再填内容。

逐页稿示例：“抽样中 38/100 请求缺设备版本；拟将版本信息采集前移；尚需验证现场可得性与补问减少幅度。”口播稿应解释抽样范围、为何提出该方案及验证条件；上屏必须保留“拟/尚需验证”，不能只在备注降格。视觉可用现状—建议流程对照，不能用装饰性增长曲线暗示收益已证实。

## 页数、风格、视觉与排版怎么确认

| 决定 | 应展示的依据与选项 | 形成何种有效结果 | 何时必须重新讨论 |
|---|---|---|---|
| 页数 / 篇幅 | 用户上限、讲解时长、核心论证、页职责；附录与正文的取舍 | 精确页数或授权区间、必要内容、附录策略 | 新核心论据/受众变化；无法在约定篇幅保留必要信息 |
| 风格定位 | 使用场景、品牌/模板、语气、参考的适用点 | 正式/教学/叙事等表达意图与具体参考；已有规范可直接沿用 | 模板不适用、品牌/场景改变、用户否决 |
| 视觉语言 | 字体层级、配色用途、图/表/示意语言、图片角色 | 可落实到样页的设计规则 | 样页效果和原意明显不符 |
| 内容密度 | 现场讲解或独立阅读、展示条件、信息层级、关键图表复杂度 | 各页型密度范围及无法压缩的内容；没有全套统一字数阈值 | 缩字删论据才能放下，或读者无法找到关键关系 |
| 排版逻辑 | 本页关系是比较/过程/证据/架构/时间线等；阅读顺序与强调 | 内容关系到空间结构的明确映射 | 内容关系变化，原网格造成错误分组或误读 |
| 代表样页 | 真实且典型的正文：核心页、复杂机制/证据页、最密页等 | 确定何种表达可扩展、适用页型和生产范围 | 全套出现样页未覆盖的新页型或显著密度问题 |

需要协商时给具体方案和取舍，不逐一询问颜色字号等所有技术参数。样页试作可在限定探索授权下发生；试作结果再决定扩展，用户可明确委派。设计先介入篇幅和表达可行性，不能等全套文稿冻结后才发现装不下。

## 稿件生产的质量与过程评价

候选评分锚点：0=缺失/明显错误，1=需重建主线，2=需实质修改，3=局部修改可用，4=可直接用于约定目的。该量表尚未校准，**本包没有给当前产品打分，也未设定已通过的分数线**。每项评分必须附具体段落/页、依据和修改建议；关键事实或方向错误不能用其他高分平均掉。

| 对象 | 过程是否有效 | 结果怎么评 | 谁与何时评 / 必须保留的证据 |
|---|---|---|---|
| 访谈 / Brief | 读过材料；不重复已知；问题改变了决定；矛盾得到处置 | 用户认可目标、受众、边界，无代替用户杜撰立场 | 用户 + Planner，S1–S2；原始输入、问题、答复与决定变化 |
| 论证 / 内容全文 | 选择证据、处理异议、删留有原因，经历实际修订 | 正确、有增量、推理成立、主线清楚、适合受众 | 内容审查者，S2–S3；逐项主张证据和改稿差异 |
| 口播逐字稿 | 按说话方式改写；过渡完整；估时后实际试讲 | 能顺畅说出、听懂，关键限定未丢，时长合理 | 讲述者/目标听众试读，S3/S7；估时标 estimate，实测另记 |
| 逐页稿 | 每页承担明确职责，全文映射不漏关键内容 | 单页成立、跨页有推进、无重复空话，图表正文完整 | Writer 自编 + 独立审查或用户抽查；页职责、稿件映射、问题修复 |
| 视觉 / 版式 | 使用真实内容试作；解释图式和密度取舍 | 层级、可读性、关系表达、连贯风格，未误导数据 | Design/用户于样页，全稿检查于 S7；实际渲染与观察 |
| 文件工程 | 符合冻结稿/图，原生可编辑，回读与导出一致 | 无丢文/裁切/错图/隐私泄漏 | 自动检查 + 视觉审查；记录实际文件 hash、检查及局限 |
| 最终使用 | 用户不必重建主线，剩余修改可定位 | 达成约定理解/判断/行动目标 | 用户接受和目标受众复述/任务测试；不可由模型自签 |

评价可以分为：结构自动验证、Host 自编辑、独立内容审查、目标用户/听众验证、实际使用反馈。各自回答不同问题。独立模型可发现逻辑漏洞，但不证明用户满意；用户点了确认，也不证明所有事实和工程检查通过。

## 怎样验证新流程优于现状

设计比较协议再跑，不先宣布改善。候选协议：固定同一材料与任务，保留当前 main 基线输出与交互记录；新流程用匹配模型/工具版本和资源范围执行。真实生成非确定性，应记录每次结果而非只挑最好。对作者身份盲化、随机呈现内容与成品，独立评价后再请用户判断；模型/资料差异作为混杂因素记录。

不设未经验证的“说服力提升百分比”。观察目标受众能否复述主张、找出证据与限制、解释推荐理由；记录用户是否重写主线、实质删改页数/比例、方向错误发现时点、浪费的生成页/调用、有效提问与重复提问、返修轮次、时长及当前残留问题。效率是辅助指标，不能奖励跳过协作。

候选场景集：

| ID | 情景 | 核心判断 |
|---|---|---|
| V01 | 模糊一句话 + 原始资料 | 先读与定向，是否暴露关键分歧而非全套制作 |
| V02 | 正式要求 + 旧测试稿冲突 | 是否说明取舍并保持正式要求和建议分层 |
| V03 | 已确认大纲/设计/授权 | 是否复用决定，避免无效重访谈 |
| V04 | 讲解稿与独立阅读稿各一份 | 逐字稿需求、密度和评价是否随场景变化 |
| V05 | 固定页数/时间与内容冲突 | 是否提出真实删留方案，不偷偷缩字/删证据 |
| V06 | 证据弱/核心推论错误 | 能否改主张或补证，不能编造数字满足模板 |
| V07 | 先定设计/试一页 | 是否停在试作范围；最密页/新页型能否发现问题 |
| V08 | 样页后改受众/方向 | 哪些稿件、样页和授权失效，哪些可保留 |
| V09 | 只改局部/只审现有文件 | 是否避免整套重做与范围扩张 |
| V10 | 跨会话、撤回、取消、晚到回执 | 决定和费用可恢复，过期生产不能采用 |
| V11 | 已有模板、高密度技术页、数据图 | 能否保留必要细节、表达关系，不套统一卡片或字数 |
| V12 | professional policy / 三个交付入口 | 必要证据一致，self-review 与未评估不能冒充指定人类通过 |

每个最终公开 Skill 还要测试：明确点名调用、自然语言路由、主控连续调用、恢复后调用四条路径；不能只验证 SKILL.md 存在。先用少量合成案例校准评价员的一致性和分歧处理，再做真实 Host 与用户试用。案例数、重复数和门槛由评审建议后冻结，不把当前列出的 12 类称为已完成测试。
