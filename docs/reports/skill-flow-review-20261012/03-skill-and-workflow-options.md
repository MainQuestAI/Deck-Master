# Skill 体系与流程：候选方案，而非定案

## 先分清四层职责

| 层 | 负责 | 不能替代 |
|---|---|---|
| Skill | 明确用户何时调用、专业方法、必须读什么、如何形成和评估产物、何时交接 | 不能仅凭提示词假定状态安全；不能把方法名当执行证据 |
| Master 编排 | 识别输入/意图、读取当前状态、选择职责、维持上下文、解释下一步/等待原因 | 不应独占并隐藏全部专业方法，不替用户做未经委派的方向决定 |
| Runtime 合同 | 保存版本/出处/决定/任务/费用，统一判断允许动作、失效和恢复 | 无法仅靠字段齐全证明故事成立或文案优秀 |
| Studio / CLI / 聊天 Host | 展示同一工作状态与可审查稿件，接收选择和修改，提交真实回执 | UI 点击不是全部授权来源；CLI/Host 不能旁路同一运行约束 |

同一个 Agent 可以依次承担多个 Skill，Skill 数量不等于模型数量。需要独立审查时必须另有真实审查执行证据；换角色提示词不算独立。

## 体系选项 D01：不预先用数量定胜负

| 选项 | 结构 | 优势 | 必须验证的风险 |
|---|---|---|---|
| A | 一个公开 Master + 可路由、强制装载的内部职责模块 | 用户入口简单，同一状态清楚 | 用户不知道能单做策划/设计/讲稿；内部文件存在却未加载；主 Skill 再次过重 |
| B | Master + 少量可独立调用的专业 Skill + 共用 runtime/methods | 发现与指派职责更明确；保留连续编排 | 路由重叠、多个入口覆盖相同状态、重复规则；需安装与冷启动验证 |
| C | 恢复较细的阶段 Suite（参考旧体系，改用新核心） | 各阶段可见，职责容易对照旧表 | setup/init/brief/planner 等切得过碎；用户被迫做流程管理员；迁移复杂 |

**本轮讨论倾向 B，但尚未获用户批准。** 理由是用户已明确要求 Skill 定位与独立阶段协作；A 必须拿出可发现与可靠路由的证据才能成立，C 也不能靠旧名称恢复来证明效果。外部模型应提出裁剪/合并建议，不能只接受此倾向。

## 候选职责与入口表（名称全部待评审）

表列的是完整职责，不要求一行一个最终公开 Skill。明确“方法有用”和“值得独立入口”是两个评审判断。

| 候选名称 / 定位 | 当前落点 | 输入与触发 | 必须产出 / 方法重点 | 停止或退回 / 下一责任 |
|---|---|---|---|---|
| deck-master 总控 | 现有公开 Skill + continue | 新任务、续作、完整工作流、阶段不明 | 输入分类、当前阶段、范围和下一动作 | 有待决方向转 Brief/Planner；不自行补成用户决定 |
| deck-brief 理解与访谈 | source-reading/content-methods，缺前置阶段 | 原始材料、研究报告、模糊目标/冲突要求 | 材料用途、受众认知、目标、约束、关键问题和假设 | 有关键缺口请用户取舍；交 Planner；可与 Planner 合并 |
| deck-planner 内容与论证规划 | compose + ContentPlan | 已有背景、要确定怎么讲/讲哪些/几页 | 主张链、反问/异议、证据选择、章节、页面职责、篇幅方案 | K2；交 Writer，关键证据交 Sourcing |
| deck-sourcing 证据与复用 | sources、allowed assets、来源 links | 材料缺口、复用页/图、证据冲突 | reuse/adapt/generate/补证建议，来源边界和引用位置 | 关键证据不成立回 Planner；无库可继续读显式资料，不强制建库 |
| deck-writer 内容与讲述写作 | compose + Page body/speaker_notes | 方向已定，写内容论证稿/讲稿/逐页稿 | 完整论证、口语表达、页间衔接、语义映射与自编辑 | K3；主张变化回 Planner；可改名或与 Producer 内容职责合并 |
| deck-design 信息与视觉设计 | design_context/visual_spec、styles trial | 定视觉、密度、页型、参考模板；已有正文 | 设计简报、内容到图式映射、密度规则、代表样页说明 | K4/K5；内容装不下回 Writer/Planner，不静默删论据 |
| deck-producer 页面制作 | blueprint/SVG/任务协议 | 已有有效稿件/设计与限定生产范围 | 真实蓝图、SVG、可追溯页面、逐页校验 | 不改主张；范围/依据变了回上游；交 Builder |
| deck-builder 文件构建 | compiler/pipeline | 生成可编辑 PPTX/预览/交付格式 | 原生元素、文件和回读、构建记录 | 技术失败返制作；不重写正文；可作为 Producer 内部方法 |
| deck-quality 专业/技术检查 | Review 六维与自审 | 指定稿件、单页、整套、独立已有文件 | 具体问题、证据、严重度、应退回层级 | 不能替用户确认方向；可做独立文件入口，外部文件能力需实现验证 |
| deck-review 验收与交付 | exports/handoff/readiness | 项目可否交付、修订是否完成 | 合并各层证据，标当前版本、未解决项和交付范围 | K6；缺人类/独立条件不能自签；可与 Quality 合并但职责需区分 |
| 运维候选 deck-setup / deck-doctor / deck-upgrade | install/doctor/activate/rollback | 安装、异常、升级；不属于内容顺序步骤 | 环境诊断、安装/恢复证据 | 仅动作需要依赖时检查；是否一个管理入口待评审 |
| 项目初始化 / 反馈 | create/sources、annotations | 新项目目录或用户要求复盘 | 项目与材料索引、阶段记录；项目内经验 | init 可内部；长期记忆仅显式授权；不恢复强制全局 Workspace/Library |
| 连续推进模式 | Master continue | 用户授权推进明确范围 | 同一工作流自动执行记录 | autopilot 是模式还是独立入口 D02 待定；不得成为第二套状态机 |

每个最终公开 Skill 必须有：Use when、Do not use when、输入、专业方法、退出产物、质量判断、下一责任、停顿/授权规则、续作方式。详细方法可按需加载；命令/合同来自同一来源，避免重复不一致的 Allowed Commands。新增 SKILL.md 只有名字/跳转而无方法，不算完成。

## 按输入路由，允许中途进入

| 输入 | 起点与处理 | 不允许的跳跃 |
|---|---|---|
| 一句模糊目标 + 原始材料 | Master → Brief/Planner；先读后问，给初步理解与分歧 | 把自行扩写 brief 当用户确认后全套生图 |
| 完整研究报告 | 分清研究结论与本次受众任务，规划论证和取舍 | 报告目录直接变 PPT 目录 |
| 已确认方向/大纲 | 校验适用版本 → Writer；只问新缺口 | 强制从头访谈或重新投票已定方向 |
| 完整逐字稿 | 判断它是内容全文还是口播；提取页职责、证据、时长 | 为适配模板默默改立场/删关键限定 |
| 已有 PPT/模板 + 只改几页 | 读现有内容与视觉，限定页/层操作 | 擅自重规划整套、套用默认新风格 |
| 只要定风格或样页 | Design，读取足够代表性正文，限定试作 | 试作自动授权全套 |
| 只审文件/内容 | Quality/Review，只读评价和返修建议 | 自动改稿、重做或交付 |
| 继续 / 恢复 | 读项目状态、未解决问题、有效决定与撤回事实 | 仅靠聊天摘要或旧 approved 标记恢复生产 |

## 候选流程和停顿设计

阶段可并行准备和来回迭代；阶段数不等于对话轮数。资料读取、假设整理、备选草稿和已有授权内的机械动作可先做。用户明确方向或明确委派时，复用证据继续，不重复确认。

| 阶段 | 可审查产出 | Skill 主责 | 停顿点及用户实际看到什么 |
|---|---|---|---|
| S0 任务接入 | 输入类型、要完成的范围、资料用途 | Master / 初始化 | 目录或任务对象歧义才停，不要求先 setup 仪式 |
| S1 理解与访谈 | 目标、受众现有认知、约束、缺口与建议 | Brief | K1：影响主线的未知/冲突；展示理解和取舍后问针对性问题 |
| S2 论证与篇幅 | 中心判断、论据/异议、章节、每页职责、页数和时间方案 | Planner/Sourcing | K2：对齐内容方向与篇幅；展示真实论证和删留理由，不只目录 |
| S3 写作与编辑 | 内容全文、需要时的口播稿、逐页上屏稿及映射 | Writer | K3：对主张/叙事/表达的实质变化停；是否整稿逐字确认由任务约定 D03 决定 |
| S4 设计方案 | 视觉语言、密度、版式规则、参考适用性 | Design | K4：没有有效规范/选择时对齐；展示带真实内容的设计表达，避免空泛风格词 |
| S5 代表样页 | 覆盖核心/密集/机制等职责的实际样页 | Design/Producer | K5：确认/委派样页判断及扩展范围；样页数由风险决定，2–3 页仅建议 |
| S6 整套生产 | 逐页蓝图/SVG/PPT/回读 | Producer/Builder | 不逐页无意义追问；超范围、关键输入变化、调用未知、用户停止时停 |
| S7 全稿评价与返修 | 内容/讲述/视觉/工程各自证据与问题 | Quality + 上游 owner | 主线错误回 S2，内容表达回 S3，信息设计回 S4，转换错误回 S6 |
| S8 交付与复盘 | 当前文件、适用用途、已完成与剩余问题 | Review | K6：按本次交付约定；用户既有明确交付指令有效时不重复请求，外发他人仍须授权 |

每个停顿记录：原因、关联产出版本、推荐及备选、需要谁决定、已授权可继续的工作、恢复条件。取消/拒绝/新意见都要有路径，不能只给一个“批准”按钮。确认文字本身不证明理解正确；若关键误解未暴露，流程仍然失败。

## 尚未关闭的设计决定

- D01：A/B/C 体系与最终公开名称。评价可发现性和路由可靠性后决定。
- D02：自动推进是模式还是独立 Skill；应共用同一状态与门槛。
- D03：哪些任务需要口播逐字稿；全文、讲稿、逐页稿各自确认到什么粒度。
- D04：页数/时长/密度协商方式；样页覆盖规则与设计迭代边界。
- D05：专业质量评价标准、独立审阅条件、用户接受证据与默认交付口径。
- D06：产品职责确认后如何映射合同、迁移和安装；首轮 R1–R6 是否重排。

首轮方案提出 collaboration 版本对象与统一准入，属于 D06 候选。先用具体示例证明职责、产出、停顿和评价可用，再冻结字段，避免只建出一套复杂审批系统。
