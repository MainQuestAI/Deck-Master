## Required helper fixes

1. **H01 — settlement uses incompatible positional arguments, blocking every real settlement.** Helper lines 248–250 call `tasks.call_settle(store, task_id, allowance_id, ...)`. The inherited e007 public signature and Owner's explicit current interface confirmation both require keyword-only `task_id=` and `allowance_id=`. The independent helper-only probe against that exact signature raises `TypeError: ... takes 1 positional argument but 3 were given`, before the settlement body is called; `settlement.json` is absent. Root acknowledged this helper error. Fix the invocation rather than changing the public API. Re-review before emitting a real call; otherwise a genuinely consumed call cannot reach its SDK settlement through this helper.

2. **H02 — seal does not validate the dispatch marker's event, prompt/argument hash, or binding hash.** Lines 155–168 read the marker but consume only its timestamp. A marker for a different event, different literal arguments, and different binding was accepted and HMAC-sealed in the L1 probe. A misplaced/stale marker, or preparation accidentally changed between dispatch and callback, can therefore produce a falsely bound start clock/dispatch assertion even without attacking HMAC. Validate marker schema/event/argument hash/binding hash against the immutable preparation before sealing; verify sensible controller-clock order. Keep the original marker and callback on failure. This is accidental cross-run evidence mix protection, not a claim to resist a malicious coequal Host.

3. **H03 — actual_arguments silently changes frozen parameters.** Lines 82–85 copy only `transparent_background`, silently dropping any other frozen parameter; if absent they add a false default. The existing generation-input schema permits a general parameters object. The L1 probe passes frozen `model`, `seed`, and another parameter and observes all three disappear. Current tool metadata exposes none of those model/seed knobs, so the helper must reject unsupported frozen keys before dispatch rather than spend a call that the native comparison can only reject later. Require the precise supported frozen parameter contract (including explicitly frozen boolean transparency), or otherwise demonstrate exact equality with the actual submitted supported parameters. Never invent model/seed/default evidence. The SDK's later mismatch/downgrade is useful protection but does not prevent this avoidable call expenditure.

4. **H04 — mark-dispatch does not itself revalidate current original attachment bytes and literal arguments.** Preparation hashes owned raw blobs, but lines 140–148 discard the request returned by bound_state and reuse saved argument paths. A helper-only probe changes the actual original file after preparation while keeping its immutable Ref and binding and mark-dispatch still accepts. Root should rebuild actual_arguments from the current bound immutable request immediately before dispatch and compare exactly with preparation, thereby rechecking raw bytes/path/ordering and unsupported parameters. This L1 probe deliberately stubs image_binding and is not evidence that final SDK image_binding accepts corrupt bytes. Owner confirms later image_context checks actual literal paths/owned bytes; that check occurs after the actual call and should remain a second line of protection. Final snapshot integration must verify the actual behavior and the race boundary honestly.

5. **H05 — there is no native error/uncertain-completion settlement path.** Seal requires a successful PNG and settle requires a sealed observation. A real tool exception or completion of uncertain status has no usable helper command; a missing local seal must not be mistaken for an unspent allowance. Root explicitly requested this be repaired before using the controller: add an explicit unknown-settlement route requiring the actual native error/uncertainty callback and matching actual dispatch record, preserve the complete original error, and submit ordinary host_reported unknown with unknown dollars and no automatic retry. Do not manufacture a successful completion or mark no-output tool failure consumed with zero cost.
