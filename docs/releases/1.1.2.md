# 1.1.2 版本说明

状态：本说明随「升到 1.1.2」的发版 PR 一起合入，Python `deck-master`、Rust `deck`、`deck-tools` 和 WebUI 的包版本均改为 `1.1.2`。`v1.1.2` 标签和 GitHub Release 在该 PR 合入后另行创建，是否已发布以 [GitHub Releases](https://github.com/MainQuestAI/Deck-Master/releases) 页为准。本文不暗示 PyPI 上架。

谁该看：使用 Rust `deck`、本机 WebUI 或 Codex Skill 创作、审阅和修改方案的作者与维护者。安装与首跑见 [getting-started](../getting-started.md)，旧 Python 项目迁移见 [1.1.1 说明](1.1.1.md#5-升级与迁移)。

## 1. 摘要

本版覆盖 `v1.1.1`（`542e1bce`，2026-11-05）之后，到 `main` 的 `32c66bad`（[#306](https://github.com/MainQuestAI/Deck-Master/pull/306) 合入后）的改动。主要变化是：围绕商业任务进入创作，在 WebUI 修改任务、框架与页面结构，阅读历史版本；四个职责入口共用方法源，把页逻辑、构图、视觉资产、审阅和局部返修接到现有命令；补齐原图与编译预览对照，以及原生表格、曲线和素材处理的具体缺口。

这些是已合入的功能、方法与工程修复，不代表作品视觉验收通过。D13 未开展，T07 视觉人判仍开放；未验证项见第 5 节。

## 2. 作者入口、改稿与历史版本

- **入口与任务**：补充 verify-close、导出 URL 路径清洗的加粗、换行和本机路径边界用例（[#279](https://github.com/MainQuestAI/Deck-Master/pull/279)）；明确原生表格的发版说明与文档入口身份（[#280](https://github.com/MainQuestAI/Deck-Master/pull/280)）。创作入口先读任务，再按需展开业务框架（T02，[#282](https://github.com/MainQuestAI/Deck-Master/pull/282)）。
- **任务与主张可修改**：在总览编辑任务和主张框架（T04，[#283](https://github.com/MainQuestAI/Deck-Master/pull/283)）；共同作者的改写范围、专家反馈如何影响稿件写入方法文档（T03，[#284](https://github.com/MainQuestAI/Deck-Master/pull/284)）。后者是方法说明，不是新增专家服务。
- **页面结构可修改**：内容视图支持移动、删除页面（T05-A，[#285](https://github.com/MainQuestAI/Deck-Master/pull/285)），以及编辑页面区块、条目和表格（T05-B，[#287](https://github.com/MainQuestAI/Deck-Master/pull/287)）。409 冲突时保留结构草稿，不自动重放提交（T08，[#288](https://github.com/MainQuestAI/Deck-Master/pull/288)）。
- **查阅历史与差异**：提供只读 `GET /api/versions/{version}`（T06-A，[#281](https://github.com/MainQuestAI/Deck-Master/pull/281)），WebUI 可读历史版本并与当前稿对比（T06-B，[#286](https://github.com/MainQuestAI/Deck-Master/pull/286)）。

## 3. 四个职责入口与视觉制作方法

- **共用一份方法源**：`deck-master`、`deck-content`、`deck-design`、`deck-review` 四个职责入口共享 `references/` 与 `assets/`，调用 Rust `deck`；安装四入口需显式使用 `--skills-root`（[#289](https://github.com/MainQuestAI/Deck-Master/pull/289)）。补齐入口审查的可选说明（[#290](https://github.com/MainQuestAI/Deck-Master/pull/290)），并补充说明页／教学页的标题例外（D01，[#299](https://github.com/MainQuestAI/Deck-Master/pull/299)）。
- **先讲清页逻辑，再决定构图**：把页逻辑和构图句写入现有字段（[#291](https://github.com/MainQuestAI/Deck-Master/pull/291)）；视觉系统方法使用现有 Style 字段（D04，[#292](https://github.com/MainQuestAI/Deck-Master/pull/292)）。后续说明明确完整保存 style 时保留原画布与素材，不能拿示例覆盖已有内容（[#298](https://github.com/MainQuestAI/Deck-Master/pull/298)）。
- **按页选择视觉资产**：素材通过 `Asset.pages` 指定用途页，空列表表示公共素材（D05，[#295](https://github.com/MainQuestAI/Deck-Master/pull/295)）。`--page` 支持重复参数或逗号分隔，并核对指定页存在（[#298](https://github.com/MainQuestAI/Deck-Master/pull/298)）；页名去空白、去重，未知页在复制文件或调用转换工具前报错（[#305](https://github.com/MainQuestAI/Deck-Master/pull/305)）。
- **按对象还原并对照原图**：还原策略采用双门槛，原图依据变化时旧 SVG 派生失效（[#293](https://github.com/MainQuestAI/Deck-Master/pull/293)）；重建保留原图对象，并对照原图验收（[#304](https://github.com/MainQuestAI/Deck-Master/pull/304)）。查阅型表格的成功条件收紧为真实逐行查阅任务，不能只以压缩或转成卡片代替（[#303](https://github.com/MainQuestAI/Deck-Master/pull/303)）。这些方法仍需要实际作品判断。

## 4. 编译、审阅与局部返修

- **关系检查与编译修复**：接通 SVG 关系检查（D07，[#296](https://github.com/MainQuestAI/Deck-Master/pull/296)）。现有 emitter 修复原生表格逐边线条样式、表格文字字距，以及共线回折曲线的近似问题（D09，[#297](https://github.com/MainQuestAI/Deck-Master/pull/297)）；这些修复不等于整稿视觉质量达标。
- **定位问题、限定返修**：专业审阅方法区分三层 QA、缺陷分级和证据位置（D10，[#300](https://github.com/MainQuestAI/Deck-Master/pull/300)）；局部返修按问题分流并复审（D11，[#301](https://github.com/MainQuestAI/Deck-Master/pull/301)）。#298 与 #305 继续补齐方法说明、提示和相关行为测试，不增加自动认可作品的结论。
- **同页对照**：WebUI 对照同页原图与编译预览，两侧共用缩放和查看位置（D12，[#302](https://github.com/MainQuestAI/Deck-Master/pull/302)）；补充表格、行、列与 SVG 元素定位，并提示讲稿在正文层查看（[#305](https://github.com/MainQuestAI/Deck-Master/pull/305)）。有对照界面不等于已经完成浏览器采用或人工验收。
- **素材边界与测试收口**：空 `--page` 明确报错；测试收窄到实际涉及的行为段；转换期间页面被删除时，不留下本次新增的孤儿文件（[#306](https://github.com/MainQuestAI/Deck-Master/pull/306)）。

## 5. 已知未做与未验证

- **D13 未开展；T07（视觉人判）仍开放，本版不关闭。** 没有把 `visual_review` / `desktop_editing` 改成自动通过，也不声称视觉验收或 A1–A6 人判已通过。
- **真实 WPS / PowerPoint 桌面打开与编辑、officecli、完整真实安装验收、22 页样稿人判**：本版不声称已通过。LibreOffice 渲染不能替代 WPS，也不能证明桌面编辑通过。
- **真实 Host / ImageGen、浏览器 adopt、MA02 / MA03**：本版不声称已通过；方法文档、合成测试与界面接线不能替代这些执行与判断。
- **PPTX → deck 导入仍未实现**：当前 `deck import` 读取的是 `legacy-export.v1` 中性档案，不是 PPTX 文件。沿用 1.1.1 的未做项。
- **其它既有边界**：UNC 路径不在本机路径清洗内，Markdown 导出不做 PPTX 正文那套凭据检查；字体检测不证明每个字形能正确渲染。详见 [1.1.1 已知限制](1.1.1.md#6-已知限制与未验证) 与 [首跑指南](../getting-started.md#known-limitations)。历史维护者观察保留原时点，不作为 1.1.2 的验收结论。
