## Changes and supported entry points

1.1.0 is the first source line whose authoring path is the Rust core:

| Piece | Location | Entry |
| --- | --- | --- |
| Core, CLI, local HTTP | `rust/` | `deck` |
| File tools | `deck-tools/` | `python -m deck_tools …` (called by `deck`) |
| WebUI | `frontend/`, embedded in the binary | `deck serve <project>` |
| Codex Skill | `deck-skill/` | linked by `scripts/install.sh` |

`scripts/install.sh` builds the WebUI, installs `deck` (default
`~/.local/bin`), creates a Python 3.12 venv for `deck-tools`, and links
`deck-skill/` to `~/.codex/skills/deck`. It does not activate or roll back a
managed `deck-master` release. Rust 1.88 or later is required; Cargo enforces
`rust-version`.

Use the [first-run guide](../getting-started.md) for local installation and
`deck serve`. Command examples live in
[deck-skill/references/commands.md](../../deck-skill/references/commands.md).
The grouped change list is in [CHANGELOG](../../CHANGELOG.md).

The Python workbench `deck-master` in `src/deck_master/` and the four Skills
under `skills/` remain in the tree. AGENTS.md section 12 limits that line to
data-loss, duplicate consumption, open/export failure, and real security fixes.

## Upgrade and migration

### New install

```bash
./scripts/install.sh
deck new ./my-deck --title '方案标题'
deck serve ./my-deck
```

Options: `--prefix DIR`, `--skill-dir PATH`, `--dry-run`. A fresh install finds
deck-tools in the prefix venv and does not need `DECK_TOOLS_PYTHON`. Moving or
deleting the checkout leaves that editable venv unable to import deck-tools.

### Skill link already points elsewhere

The script links `deck-skill/` to `~/.codex/skills/deck`, or to `--skill-dir`.
If that path is already a symlink to another location, it prints
`已存在且指向其他位置` and exits 2. It does not replace the link. A path that
exists and is not a symlink to `deck-skill/` exits 2 with
`已存在且不是指向 deck-skill 的软链接`.

Remove that symlink and run `scripts/install.sh` again, or pass a different
`--skill-dir`. The 2026-11-04 macOS install took the remove-and-rerun path
([Maintainer acceptance](#maintainer-acceptance-2026-11-04)).

### Old Python projects

Do not initialize a new `.deck` directory inside an old project. Export a
neutral archive, then import into a new directory:

```bash
deck-master legacy-export <project> <out>
deck import <out> <new>
```

`<out>` must sit outside `<project>`. The old directory is unchanged. Imported
images and SVG are stored with `basis` `imported`; overview marks those pages
stale, and `deck export pptx` reports `input_changed`. The most recent PPTX is
cleaned before it becomes downloadable. If cleanup fails or its tool is
unavailable, editable content still imports; `last_export:false` and `unmapped`
name the gap. Format name: `legacy-export.v1`.

`visual_spec.intent` is not migrated. Old revisions are not migrated
([#274](https://github.com/MainQuestAI/Deck-Master/issues/274)).

v0.9.x run directories still follow
[migration-to-rebuilt-core.md](../migration-to-rebuilt-core.md); that path is
the previous Python rebuilt core, not `deck import`.

### Managed 1.0.0 wheel

The 1.0.0 managed installer (`deck-master install candidate` / `activate`) is
not the 1.1.0 install path. Rolling back a managed 1.0.0 prefix does not
install `deck`. Keep each line's project directories separate.

## Evidence limits and open observations

- Synthetic fixtures exercise engineering paths. They are not real customer
  production, independent model approval, professional human review, or
  cross-platform certification.
- UNC paths (`\\server\share`) are not in the local-path sanitizer
  (`deck-tools/src/deck_tools/sanitize.py`).
- `GET /api/export/md` writes Markdown from the in-memory deck
  (`rust/src/export.rs`) and does not run the PPTX credential check.
- `scripts/install.sh` runs on Linux CI (`ubuntu-latest`). The macOS install
  is under [Maintainer acceptance](#maintainer-acceptance-2026-11-04).
- The legacy test
  `test_small_json_cache_detects_corruption_and_returns_independent_objects`
  can fail on Linux because the cache signature includes ctime and the test
  rewrites the file within one clock tick. This is a test-timing issue in the
  old line and was not changed in this release.
- PPTX tool tests render through LibreOffice (`soffice`) when the `render`
  marker is selected. Desktop WPS and PowerPoint editing are not in that set.
  The earlier PR125 WPS gap remains: actual WPS editing was not verified
  because the device locked. See
  [known limitations](../getting-started.md#known-limitations).
- Fontconfig/LibreOffice Chinese glyph substitution remains as documented for
  1.0.0; this line does not add a new font certification.
- `codex app-server` ImageGen from the WebUI is still out of scope; the
  browser does not start image or SVG runs. Hosts use `deck run` on the CLI.
- SQLite projects on iCloud-style synced directories were not retested here.
