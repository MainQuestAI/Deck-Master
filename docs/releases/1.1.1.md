# 1.1.1 版本说明

状态：[#274](https://github.com/MainQuestAI/Deck-Master/issues/274) 的 6 项跟进已在 `main` 的 `40322142` 合入（[#276](https://github.com/MainQuestAI/Deck-Master/pull/276)，2026-11-05，北京时间）。本说明随「升到 1.1.1」的发版 PR 一起合入，该 PR 把 Python `deck-master`、Rust `deck`、`deck-tools` 和 WebUI 的包版本改为 `1.1.1`。`v1.1.1` 标签和 GitHub Release 在该 PR 合入后另行创建，是否已发布以 GitHub 的 Releases 页为准。本文不暗示 PyPI 上架。

## 1. 摘要

1.1.0（tag `v1.1.0` = `292fb60a`，2026-11-04）把主创作路径换成了 Rust CLI `deck`、独立 Python 包 `deck-tools`、`deck serve` 嵌入式 WebUI，以及 Codex Skill `deck-skill/`。1.1.1 跟进是验收清单 #274 里能在源码里落地的 6 项：安装提示、`doctor`、旧稿导出的 `unmapped`、`stale_*` 含义说明、npm 12 脚本放行，以及缺 `soffice` 时的停手文案。Rust 重构本身在 1.1.0；本文把重构全貌和技术优化一并写清，避免只看跟进项看不出主线。

## 3. 从 1.0 到 1.1：Rust 重构全貌

### 为什么重写

旧 Python 工作台能出稿，但协议、资格链、租约和配额越堆越多，和「作者改稿、Host 推理、工具只处理文件」这条主路径缠在一起。开发稿 v1.2（[docs/specs/rust-rebuild/README.md](../specs/rust-rebuild/README.md)）把核心与后端业务改到 Rust，生产工具拆成独立 `deck-tools`，不内置 LLM Provider；推理与生图由 Host（首个是 Codex）执行。保留 8 条对应真实故障的保护（版本只追加、按单元比基线保存、取消后迟到结果不自动采用、依据已变不自动采用、本地服务只绑回环并校 Host/Origin、导出清洗等），§2.1 列出的机制不再加回。[AGENTS.md](../../AGENTS.md) 是唯一开发规范，与开发稿冲突时以它为准。

### 现行结构（1.1.0 起）

| 部件 | 位置 | 入口 |
| --- | --- | --- |
| 核心、CLI、本地 HTTP | `rust/` | `deck`、`deck serve <project>` |
| 文件工具（编译、渲染、回读、清洗、doctor） | `deck-tools/` | 由 `deck` 子进程调用 |
| WebUI（React 18 + Vite，由 `build.rs` 嵌入） | `frontend/` | `deck serve` |
| Codex Skill | `deck-skill/` | `scripts/install.sh` 链到 `~/.codex/skills/deck` |
| 旧 Python 工作台 | `src/deck_master/`、`skills/` | `deck-master`（仅维护，见 AGENTS.md 第 12 节） |

作品落在 `<project>/.deck/`：`deck.db`（SQLite）+ `files/<sha256>.<ext>`（内容寻址）。CLI 与 `deck serve` 共用同一套用例，各自直连 SQLite，不设单写入服务。

合入 PR：S0 #251，S1 #252，S2 #256，S3 #258，S4 #259 / #250 / #257 / #260，S5 #261，S6 #262。跟进修复到 #272；发版说明整理见 #273。

## 4. 技术优化

以下每条都能在 `CHANGELOG.md`、1.1.0 说明或开发稿里对上，不逐条列提交。

### 存储与保存

- **现在**：作品在 `<project>/.deck/`：SQLite 存版本，文件按 sha256 内容寻址；当前作品是 id 最大的版本，相同文件重复加入不新拷。**相对旧线**：状态不再走 Python 工作台那条对象树主路径。**为什么**：版本只追加，可 `restore`；CLI 与 `deck serve` 共用同一库（开发稿 §3.2、CHANGELOG S1）。
- **现在**：`put --base N` 按单元（brief / framing / style / order / 每页作者字段）做基线、提交、当前三方比较；有冲突整次不写，退出码 5。**要防的故障**：覆盖别人已写入的单元。**为什么**：不同页可并行保存，同页冲突可见，重试同一提交不重复写版本（开发稿 §3.4）。

### run 与构建

- **现在**：取消后的迟到 `result` 只存不自动采用；依据已变同样不自动采用；同页后续不同文件进 unadopted，用 `run adopt` 手动采用（#264：第二次结果保留为候选）。**要防的故障**：取消后结果仍生效、把旧依据的图当成新稿（开发稿 §2.2 / §3.5）。
- **现在**：build 输入摘要含编译设置；只改设置也会报 `input_changed`（#267）。**之前的缺口**：设置变更可能进不了摘要。**为什么**：restore 会产生编号更大、内容更旧的版本，不能靠版本号判断导出是否过期。
- **现在**：同次 run 列表读取按页复用 basis 摘要，不再对每条历史 run 重算（#268）。**之前**：同一次轮询里重复计算。**为什么**：少做重复计算。

### 导出清洗与回读

- **凭据与路径**：清洗拒绝带凭据的 URL（含拆到 styled runs、单斜杠 `file:` / 正斜杠盘符嵌在公网链接里的形式）；普通公网路径（如 `/home/products`）按公网处理，不再当成本机路径（#265、#272）。
- **原生表格**：回读核可见性与非空标题；表格画出幻灯片外会报（#266、#272）。表格/图表仍是拼出来的形状与文字，不是 Office 电子表格式对象。
- **UNC**：`\\server\share` 仍不在本机路径清洗范围内（已知限制）。
- **Markdown 导出**：`GET /api/export/md` 不做 PPTX 那套凭据检查（已知限制）。

### 本地服务与安全

- **现在**：`deck serve` 只绑 `127.0.0.1`，非本机 Host/Origin 一律拒绝；浏览器存储失败不挡住取消。**要防的故障**：跨站请求篡改作品（开发稿 §2.2 / §3.7）。

### 其它修复（1.1.0 线上）

- 新页不再复用已删页 id（#263）。
- 候选比较用编译预览而非原始 SVG；生产依据变化会提示重新打开比较；放映在页删除时结束（#269、#272）。
- CI：`rust.yml` 管新线 PR 与 `main`；`rebuild.yml` 只管 `main` 上的旧线；默认矩阵收窄（#253、#254、#255）。CI 里 deck-tools 跑 `-m "not render"`，排除 67 条需要 `rsvg-convert` / `soffice` 的用例。

## 5. 升级与迁移

命令细节以 [getting-started](../getting-started.md) 和 [1.1.0 说明](1.1.0.md) 为准，这里只写路径差。

### 1.1.0 → 1.1.1

重新执行 `./scripts/install.sh`（可加 `--prefix` / `--skill-dir`）。已有 venv 会复用，`deck` 二进制会覆盖。若 `~/.codex/skills/deck`（或你传的 `--skill-dir`）已是指向别处的软链：脚本退出 2，不替换；只删该软链后再装，或换 `--skill-dir`。


### 旧 Python 项目 → 新线

不要在旧项目目录里初始化 `.deck/`。

```bash
deck-master legacy-export <project> <out>
deck import <out> <new>
```

`<out>` 必须在 `<project>` 外。旧目录哈希不变。导入的原图/SVG 的 `basis` 为 `imported`，总览会标依据已变；`export pptx` 会报 `input_changed`。tag `v1.1.0` 当时的导出还不把差异 intent / 旧 revision 写入 `unmapped`；当前 `legacy-export`（#276 之后）会列出。最近一次 PPTX 先清洗再入库；清洗失败或缺工具时内容仍导入，`last_export:false` 与 `unmapped` 说明缺口。

v0.9.x 运行目录仍走旧的 [migration-to-rebuilt-core.md](../migration-to-rebuilt-core.md)，那是迁到旧重建核心，不是 `deck import`。1.0.0 托管安装（`install candidate` / `activate`）不是 1.1 安装路径；回滚托管前缀不会装上 `deck`。

## 6. 已知限制与未验证

下列各项按来源照实写。**不要把本节读成「已在 1.1.1 上验证通过」。**

### 在 1.1.1 源码线上未验证或未实现

- **真机完整 `scripts/install.sh`（含 `npm ci` + `cargo install`）**：#276 做了语法检查、dry-run 与 `tests/install`；PR 自述未跑完整安装，装完回显也未在该环境观察到。
- **官方路径 `soffice` → `deck build` → `deck export pptx`**：1.1.0 维护者验收与 #276 均未跑通；验收时 svg/`soffice` 失败后曾绕去 `compile_job`（见 #274）。#276 只改了报错与 Skill 停手文案。
- **67 条 `render` 标记的 deck-tools 测试**：CI 固定 `-m "not render"`；合并前本机全量是 AGENTS.md 要求，不是本说明的已跑记录。
- **WPS / PowerPoint 桌面打开与编辑**：1.1.0 验收未做；工具测试走 LibreOffice。
- **#226 的 22 页客户样稿**：验收机上没有该稿，用了 15 / 20 页替代。
- **PPTX 导入为 deck**：能力不存在；#274 列为可选，#276 跳过。
- **浏览器里的候选比较 UI**：1.1.0 验收未核。
- **`codex app-server` 从 WebUI 调 ImageGen**：仍不在范围内；浏览器不启动 image/svg run，Host 走 CLI `deck run`。
- **SQLite 项目放在 iCloud 类同步目录**：1.1.0 准备未重测。

### 1.1.0 维护者验收（2026-11-04）怎么读

记录在 [1.1.0 说明 · Maintainer acceptance](1.1.0.md#maintainer-acceptance-2026-11-04)，证据链指向 #274。文中「Verified」是该次维护者核对写进仓库的条目（含安装软链行为、`deck doctor`、serve Host 200/403、15 页遗留导入、LibreOffice 像素差、officecli、两次 Codex 会话等），**其中部分结论来自 Codex 自述，本文不改写成独立认证或「已验证通过」**。同节「Not verified」已列出 WPS/PPT、22 页稿、候选比较 UI、官方 build/export 等缺口。

### 其它已知限制（1.1.0 起仍适用）

- UNC 路径（`\\server\share`）不在本机路径清洗内。
- `GET /api/export/md` 不做 PPTX 幻灯片正文那套凭据检查。
- 旧线测试 `test_small_json_cache_detects_corruption_and_returns_independent_objects` 在 Linux 上可能因 ctime 同 tick 误失败；是旧线测时序问题，本线未改。
- `doctor` 找到字体族 ≠ LibreOffice 能渲出每个字形；Fontconfig / 中文缺字问题见 getting-started。
- 合成 fixture 只练工程路径，不等于客户生产稿、专业人工审阅或跨平台认证。
