# E05｜输入材料

**性质：虚构教学材料。仅用于说明方法，不是客户项目事实。**


## 来路和性质
来自Gemini库存案例T1–T3。以下性能、工期、费用都是虚构场景给定的观测或估算，不是MySQL、Redis或NewSQL的普遍性能基准，也不是本库实测。
受众：CTO、架构师、业务和财务。黑五前7周，需5周内开发与全链路验证、留2周封网。目标请求峰值35000QPS，P99≤80ms，可用性≥99.99%，业务要求不超卖。
T1：过去热点请求12000QPS；该次部署在单热点约2500QPS以上出现显著锁等待，P99达1850ms、超时2.3%。材料称存在约420万元意向订单损失，未给反事实损失测量或利润口径。
T3：A热点库存拆20行，估计2周、8000QPS、无新增硬件，有尾货碎片问题；B全量迁移NewSQL，估计14周、6000QPS、160万元；C限流+Redis Lua预扣+MQ落库，估计4.5周、单组件60000+QPS/P99<12ms、扩容38万元，有复制切换及异步一致性问题；另申请6人月，未折算费用。

未提供：三条路线同负载端到端验证、持久确认协议、分区/切换/消息遗漏故障数据、不可重复的库存凭证、全部成本与收益模型。没有给出5%缓冲能覆盖所有故障的证明。
