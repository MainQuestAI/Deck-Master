# 从分析成果写成实际页面正文

问题树、论证卡和权衡表是写作材料，不是客户必须阅读的工作记录。完成的方法操作应转成自然、可用的正文。正文写入作品的 content；目的、布局、讲稿、待补和出处分别保存。

## 写作的四个动作
先说本页回答哪一个问题；挑出直接承担回答的材料；把材料与回答间不可省略的理由写出来；最后补上会改变理解或使用的条件。顺序可因教学、研究和操作任务调整，不要求每页出现同名栏目。

| 页面任务 | 应写到的程度 | 不能停留的形式 |
|---|---|---|
| 判断 | 具体判断＋可比对象/范围＋证据为何支持 | “趋势良好、需要重视” |
| 机制 | 谁在何时用什么信息做什么，状态怎样改变 | AI→数据→平台三块连接 |
| 对比 | 同口径的真实差异、各自后果、改选条件 | 推荐项全优，其余全差 |
| 实施 | 交付物如何改变工作，依赖和验证如何安排 | 甘特图横线＋加强协同 |
| 研究 | 观察如何得到，解释能到哪里，不能到哪里 | 文献逐篇摘要拼接 |
| 教学 | 一个完整判断/操作示范，边界和新情境反馈 | 定义＋名词清单＋灵活运用 |

## 一段写实示范
不写：“通过知识治理与AI赋能提升效率。”
改为：“先在请求入口记录型号和版本，再限定检索资料的适用范围。工程师能直接核对引用章节；需要总部接手的问题同时带上设备条件和已查资料。现场能取得设备条件时，可在接单前补齐；暂时无法取得的条件标为待补并随摘要交接。”

这段的专业性来自过程与作用，而非“参与者/触发/价值”标签齐全。没有材料证明当前已有上述能力时，写成拟议设计，不写成已上线。该段解释工作机制，没有承诺节时比例，不必追加收益测量段；若进一步主张减少处理时间，则需给出依据或标明待验假设及测量口径。

## 表格、流程与注释也是正文
矩阵应能让读者知道每一列比较什么、每一行的后果是什么；流程箭头说明触发和交接；必要条件不能只放notes。引用或证据ID若对读者无帮助可留内部追溯，但真实来源不可删除。

## 各类输出边界
只要策划时交主张与框架，不用空白页假装正文完成；已有方向只补正文时沿用该方向；只改讲稿时保留正文与事实；局部修改不重写范围外页面。

## 成稿自查
把“此处展示、通过三个维度、建议补充”之类制作注释移出正式正文，真正写出需要展示的内容。删除只是换词重复的副标题、SO WHAT和总结句。保留独特证据、推理、例外或操作信息；不通过抽走内容换取好排版。
