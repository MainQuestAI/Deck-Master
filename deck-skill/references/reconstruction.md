# 从原图还原可编辑页面

新作品默认走 native-reconstruction；本文件只用于只有 SVG 产物的旧作品。

重建以原图的布局、层级和空间关系为依据，正文取 content.json，文字绑定 atoms.json。保留构图句要表达的对象、方向、分支与分区职责，不在还原时重新决定业务含义。

重建依据是原图里的对象和关系，不是把 content.json 的段落、表格按正文块类型套进默认卡片、默认表或默认清单。蓝图已经画出的界面控件、人物动作、步骤节点、路径方向和回流，必须在 SVG 里以可辨认的对象或有边界的局部图留下；只保留说明文字、模块标题或带「→」的句子，不算还原。

## 同时满足可编辑与画面保真

主要文字、节点、连线、分区、表格和标签必须成为可编辑对象。插画、质感、人物、复杂曲线可以保留为有边界的图，但不能承载唯一正文。照片、标志等独立素材也保留清楚的边界、空间归属和层级。

禁止为了方便转 SVG，在生图提示词里先要求扁平色块；禁止把整页蓝图当背景；禁止为了 `pictures=0`，把流线或空间关系改成普通矩形或默认流程图。`pictures=0` 既不是目标，也不是失败；对象计数和图片数不能代表质量。应看主要信息能否编辑，以及原图的关系、阅读顺序与画面是否保留。

流程图、架构图、路径图只是在还原阶段判断空间锚点和标签避让的类别，不是规划菜单，也不能替代具体到本页的构图句。沿原图确定节点边界、连线端点和标签位置，保留方向、分支、回流与空间层级，不按类别名套默认模板。

## 界面原型

本页构图句或原图是手机、网页等界面原型时，内部必须出现构图句和正文点名的上屏内容与对应控件，并按原图分区排列，不留空白线框。只有框架和关键字不等于完成还原。

正文中的分区说明是对屏内内容的说明。例如「顶区：示例用户｜基础会员｜会员规则」可以放在原型外侧作对照标注，完整保留并绑定原来的文字 atom；原型内部仍要分别画出身份文字、等级和规则入口等可编辑控件，不能把分区说明句当作屏幕里的唯一内容。不要求把说明段落拆成多个 atom，也不改 atom 结构。

蓝图里已有的头像、图标宫格、商品图、内容图、状态栏等非纯文字对象，用 SVG 子集重画，或裁成有边界的局部 PNG/JPEG，按现有 `deck asset add <素材ID> <局部图> --page <页ID>` 登记后用 `image` 引用素材 ID。先登记局部图，再准备 SVG 任务取得随附素材；任务准备后才补图的，重新准备任务并读取新的 attachments.json。素材与引用限制见 [视觉资产](visual-assets.md) 和 [SVG 子集](svg-subset.md)。局部图保留空间归属，不能用整页蓝图作背景。身份、等级、积分数字、入口名称、按钮文案、表内正文等关键文字仍须成为可编辑对象，不让裁图承载唯一关键正文。生成或截取的界面须标明示意属性，不能冒充真实产品截图；示意属性与完整保留界面对象同时成立。

## 旅程与有方向的步骤

原图是带人物或场景的顾客旅程时，保留步骤的空间顺序，以及让读者看见「谁在做什么」的人物、动作与场景层。可以重画，也可以把人物和复杂插画裁成有边界的局部图；不能只收成一排同尺寸模块卡片，除非原图本身就是这样的卡片。

原图是横向或有方向的步骤、验证路径、履约流程时，沿原图留下节点边界、连线端点、方向、分支和回流。不能把多步路径收成一段带箭头的句子，或没有空间方向的两列清单；只有原图本身就是查阅清单，且阅读任务确实是逐行核对时，才沿用这种查阅表达。

查阅表本身不是问题。表作为主视觉的成功条件仍是阅读任务确实要逐行核对或按行查找，且构图句写明表是主视觉；`purpose` 或 `layout` 已经是时间线、交接、状态流或闭环时，不得把表当主视觉。完整判断沿用 [页面写作](page-writing.md)，不按标题、正文块类型或能否画成关系禁表。

## 何时直接修 SVG

错漏文字、局部排版和依据明确的连线可以沿用原图，依据正式正文和构图句直接修 SVG，再核对渲染。业务关系有歧义时先向内容作者厘清，不凭几何位置猜业务含义；主结构需要重排时先更新蓝图，再重建 SVG。

用 `deck run start svg --pages <页ID>` 准备任务。具体元素、文字绑定和构造样例见 [SVG 子集](svg-subset.md)。交回 `deck run result <run> <page> <SVG文件>` 后，实际打开预览，对照原图检查端点、方向、分支、层级、侧栏、标签避让与阅读顺序。文字回读只证明相应文字检查的结果，不能代替画面比对。

## 对照原图验收

Host 必须实际打开编译预览与原图，已有「原图／编译预览对照」功能时使用它。文字回读、字符串齐全、对象计数、图片数或机械 findings 通过，都不能作为重建通过；只记录「正文都在」不算完成比对。

沿原图逐项指出点名对象是否还在、空间关系是否保留，并写清缺了什么、位于哪里：

- 通用：点名的界面控件或步骤节点是否可辨认；方向、分支、回流、层级与阅读顺序是否保留；哪些对象被换成了说明文字、默认卡片或清单。
- 界面原型：身份、资产等上屏信息、分入口、内容区可视物、服务或操作入口，是否仍在屏幕结构里，而不只出现在分区说明句中。
- 顾客旅程：步骤的空间顺序，以及表达人物动作或场景的层是否还在。
- 路径／步骤：节点、连线端点、方向、分支和回流是否还在，连接是否到达原图对应对象。

只证明文字覆盖、未对照原图对象和关系时，重建未完成，交回按原图还原。此处是 Host 的实际看图判断，不新增自动视觉评分；机械回读中的 `visual_review`、`desktop_editing` 仍为 `not_evaluated`，不能改成自动通过。
