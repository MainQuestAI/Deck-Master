# 从原图还原可编辑页面

重建以原图的布局、层级和空间关系为依据，正文取 content.json，文字绑定 atoms.json。保留构图句要表达的对象、方向、分支与分区职责，不在还原时重新决定业务含义。

## 同时满足可编辑与画面保真

主要文字、节点、连线、分区、表格和标签必须成为可编辑对象。插画、质感、人物、复杂曲线可以保留为有边界的图，但不能承载唯一正文。照片、标志等独立素材也保留清楚的边界、空间归属和层级。

禁止为了方便转 SVG，在生图提示词里先要求扁平色块；禁止把整页蓝图当背景；禁止为了 `pictures=0`，把流线或空间关系改成普通矩形或默认流程图。`pictures=0` 既不是目标，也不是失败；对象计数和图片数不能代表质量。应看主要信息能否编辑，以及原图的关系、阅读顺序与画面是否保留。

流程图、架构图、路径图只是在还原阶段判断空间锚点和标签避让的类别，不是规划菜单，也不能替代具体到本页的构图句。沿原图确定节点边界、连线端点和标签位置，保留方向、分支、回流与空间层级，不按类别名套默认模板。

## 何时直接修 SVG

错漏文字、局部排版和依据明确的连线可以沿用原图，依据正式正文和构图句直接修 SVG，再核对渲染。业务关系有歧义时先向内容作者厘清，不凭几何位置猜业务含义；主结构需要重排时先更新蓝图，再重建 SVG。

用 `deck run start svg --pages <页ID>` 准备任务。具体元素、文字绑定和构造样例见 [SVG 子集](svg-subset.md)。交回 `deck run result <run> <page> <SVG文件>` 后，实际打开预览，对照原图检查端点、方向、分支、层级、侧栏、标签避让与阅读顺序。文字回读只证明相应文字检查的结果，不能代替画面比对。
