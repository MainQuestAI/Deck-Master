# 从原图逐页还原 native PPT

新作品按本方法把已采用的原图还原为可编辑页面。
内容规划、生图和原图采用仍沿用现有流程。
只有 SVG 产物的旧作品沿用 [还原策略](reconstruction.md)。

## 交付位置

当前阶段使用文件适配层，直调方式见 [命令](commands.md#native-还原文件工具)。
单页先渲染和对照，范围内各页完成后调用 assemble。
最终 PPTX 在 `<作品>/native/deck.pptx`。
这一阶段的 `deck export pptx` 不包含它，交付时照实说明文件位置。

## 一次处理一页

先打开这一页已采用的原图，读当前正文、目的与构图句。
确认要保留的对象、方向、分支和分区职责。
这一页的 plan 只描述这一页，不先造整套模板。
做完本页的并排图对照并写一行结论，再处理下一页。
默认由执行会话自己阅图判断，通过后继续已授权范围。

样页只做到约定页数，不因为工具能组装就扩成全稿。
指定页返修只处理受影响页，保留其他页面。
业务含义有歧义先交内容厘清，不按图形位置猜正文。
主结构需要重排时先更新蓝图，再重建。

## 先看空间，再选对象

先辨认画面的大区域、留白、轴线和阅读顺序。
沿原图记录各区域的起止位置与相互距离。
把图中的容器、节点、文字和连线分别看清。
不要把正文块的类型当作画面模板。
原图是旅程时保留旅程的动作与空间顺序。
原图是闭环时保留回路、入口与回流方向。
原图是查阅表时保留行列的对应与表头层级。
表格单元格内边距默认表头为 `[5,8,5,8]`、正文为 `[7,9,7,9]`（上、右、下、左，原图像素）；可用 margin 按原图调整，单元格优先于表头样式，表头样式优先于整表设置，详见命令说明。
原图是界面时保留屏内控件及分区关系。

先还原大轮廓，再校准局部尺寸。
先确定节点边界，再落连线端点。
先确定文字区域，再调整字号和换行。
先确定独立素材边界，再裁人物、照片或商品。

## 坐标来自原图

plan 的坐标单位是这一页原图的像素。
使用实际原图宽高，测量对象在图中的位置。
不要把另一页的坐标整段复制过来。
不能因为两页标题相似就用同一个布局。
通用画法可以复用，每页几何必须来自该页原图。

对象框应覆盖原图中对应对象的实际区域。
留白是构图的一部分，不自动填成卡片。
连线端点按节点边界定位，不能穿过文字。
标签沿原图安排，必要时微调以免遮挡。
透视、弧线、回流等异形用点序列还原轮廓。
不要把所有异形都换成普通矩形。

颜色、线宽、透明度与圆角按原图确定。
没有原图依据时不要引入新的装饰体系。
翻转按对象方向使用，不能用翻转改变业务关系。
输出幻灯片宽固定 13.333 in，高按原图宽高比换算；整套各页的 `canvas_px` 必须一致，否则组装报错。

## 正文来自 content

所有上屏文字都从当前正文取，不从原图重新识别后改写。
文字与表格单元格分别绑定对应 atom。
标题、副标题、数字、限定条件和脚注都要保留。
图中有字而正文没有时，先厘清它是否应进入正文。
不要在还原脚本里暗改词句或补业务事实。

主要文字用原生文本对象。
数字保留单位、正负号与适用范围。
表格内容用原生单元格，不贴表格截图。
流程节点的名称用原生文字，路径用原生形状与连线。
标签、条件和分支说明也必须能编辑。

换行是排版，不是删字的理由。
文字装不下时先比较原图区域与字号。
可在该区域内调字号、行距与对齐，不能丢掉必要条件。
不要为了过检查把同一句放到看不见的位置。
不要把缺失正文藏进讲稿来充数。
讲稿从页面 notes 传入，单页和整套都保留。

## 只用六类原语

文字用于标题、正文、数字、标签与脚注。
形状用于容器、节点、分区与自定义轮廓。
箭头用于有方向的连接，端点对应实际节点。
图标使用随包的 Tabler outline。
图片用于有边界的非正文素材。
表格写明各列宽度、各行高度与每个单元格。

徽标、分栏、横带、流程和回流都展开为这些原语。
不增加会从正文表结构自动套版的复合操作。
同样是三列内容，也可能对应不同的空间组织。
同样是步骤，也可能对应分支、环路或纵向交接。
以这一页原图为依据选画法。

## 图标先查图库

先用关键词在随包的 Tabler outline 索引里搜索。
选语义相符、轮廓接近的图标，再匹配原图尺寸和颜色。
同套作品沿用 Tabler outline，保持线条和视觉重量一致。
库中已有的图标不自行描一遍冒充图库复用。
不要把整库内容塞进提示词。
搜索和引用方法见 [命令](commands.md#native-还原文件工具)。

图标只是对象的一层，不代替节点名称。
图标旁的正文仍用原生文本。
原图中独立的品牌标志应使用授权原件。
不要用通用图标冒充实际品牌或产品标志。
来源与许可按 [视觉资产](visual-assets.md) 判断。

## 人物、商品与照片裁原图

原图中已经画出的独立人物、商品、照片可裁成局部图。
使用 crop，从本页已采用原图的实际区域取图。
裁片落在本页的 native assets 目录，再由 plan 引用。
裁图只处理本页，不扫描其他项目或材料目录。

边界尽量贴近素材，保留动作、方向和必要环境。
不要裁掉让读者理解角色或动作的部分。
不要把旁边的正文、按钮文字或数字一起裁进来。
裁片含正文时应重新选框，把正文单独还原为原生对象。
纯几何的边框、色块和路径优先用原生形状。

单张图片面积不能超过画布的 40%。
不能把整页原图当底图，再叠几个可编辑标题。
不能拆成几块大图来承载整页正文。
检查图片中是否混入正文需要实际看图，不能靠字段判断。
机械面积检查通过不代表图片用途正确。

## 界面与关系保留什么

界面原型要保留正文和原图点名的对象、控件与区域。
只有空框和少量关键词不算完整还原。
账号、状态、入口名称、按钮与表内正文必须能编辑。
分区说明可以放在原型外，屏内对象仍要完整。
示意界面按实际用途标明示意，不冒充上线截图。

人物旅程要看得见谁在什么位置做什么。
状态流要看得见条件、分支、终点与返回路径。
交接要看得见来源、去向与交接对象。
闭环要看得见回流，不只留一句带箭头的文字。
查阅表要看得见行列关系、对应值与必要限定。
图标、局部图与原生对象共同保留这些关系。

## 先检查，再渲染

调用 validate-plan 核对当前正文覆盖、画布范围与素材引用。
缺 atom 时补齐对应原生文字，不临时改正文绕过。
越界时回到原图坐标核对，不整体缩小凑合。
图标不存在时重新搜索，使用库里的真实引用。
图片过大时重新判断素材边界，不改面积限制。
工具失败就报告失败，不交占位产物。

调用 render 生成单页 PPTX、渲染 PNG 和并排图。
缺少工具时运行 deck doctor，按结果修复环境。
soffice 或 node 不可用时停下，报告结果；不手写 PPTX。
重新 render 后重新对照，不沿用旧的阅图结论。

## 每页看并排图

打开 source 与 render 的并排图，先比较整体构图。
再看大区域比例、边界、方向与阅读顺序。
再逐项核对标题、正文、数字、表格和标签。
再看图标、裁片与原生对象的对齐和层级。
最后看裁切、遮挡、换行、断线与误连。

发现局部偏差就改这一页 plan，再 render 再看。
只有文字回读通过不能代替画面比较。
只有图片数少、形状数多也不能证明还原质量。
主要信息能编辑与空间关系保真需要同时满足。

对照完成后写一行实际结论，说明检查对象及仍有的差异。
结论写进本页 status.json 的 note，其他值保留 render 输出。
不要用固定通过话术替代实际阅图。
没有看过并排图时不能填写已经通过。

## 组装与交回

范围内每页都有当前 plan 的并排图和非空结论后调用 assemble。
assemble 用同一批 plan 一次生成整套，不合并单页文件。
整套生成后会渲染一次，执行会话再检查页序和整体输出。
不另设相似度阈值或 QA 文件来替代阅图。

交回实际 PPTX 路径、完成范围和必要的剩余差异。
说明机制检查、真实工具执行与阅图判断各自的结果。
未执行的验证写明原因，不把退出码为零说成作品已获认可。
作品是否适合本次用途，由作者阅读实际产物判断。
