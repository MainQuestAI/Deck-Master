# Original Q2 four-flow 300s companion

`q2_later_300.py` is a prospective finite Host adapter. It executes no model,
image, renderer, admission review or business writing. Root must independently
review/admit the exact tool and observe actual future invocations. Engineering
fixtures, SDK acceptance and human/professional acceptance are distinct.

Only original `r03/r04/r11/r12`, their original projects, arms and repetitions
may continue. `raq2/cq2` retain their existing E1/600s cuts. Production uses the
original registered own A0/d61 Runtime and the canonical new
`/tmp/rc3-pv2/q2-300-later` ledger. It changes no old registration, installation,
helper, budget, cut, Skill, workflow or Runtime source. It only appends future
event/materialization facts to the original journal after Root admission.

## Control and invocation

Use each run's own absolute Python with **both `-I -B`**. CLI arguments are
`ACTION --control ABSOLUTE_FILE --control-sha256 SHA --flow r03|r04|r11|r12`,
plus an optional immutable `--payload` file with the exact fields in `FIELDS`.
There is no caller SDK/API, callback, provider, trusted context, arbitrary
message, project, pool, role-budget or operation override. `--engineering`
requires an explicitly synthetic control and forbids formal run/project paths;
it never means that the original installation was updated or formally admitted.

Root's control has exactly `format/status/observer_id/assurance/observed_at_utc/
implementation_review/scope`. Its format is `rc3-q2-later-300-control.v1`;
production is `ADMITTED`, `/root`, `host_attested`, with an exact ordinary Ref to
the independent implementation review. The scope has exactly these fields:

- `tool/common/scoped`: exact file Refs to this tool and frozen d0/442 siblings.
- `ledger_root`: the single canonical ledger above.
- `origins`: exactly the four original run names; each row binds the original
  `run`, journal `frontier`, actual `project_id/revision_id/request`.
- `six_cuts`: exactly r03/r04/r11/r12/raq2/cq2. Each binds original_complete and
  equal_budget_evaluated; the five SDK runs also bind existing first_sdk_complete.
  These are actual frozen outcomes, including missing/failed gates, not six PASS
  gates or new judgments. Cut bodies and nested Refs are opaque here.
- `protocol/resource_selection`: the exact original public frozen protocol and
  adopted resource-selection metadata.

`initialize` requires a fresh Root control and unchanged original frontier,
revision/Request, no unresolved SDK intents and no prior Q2 release/materialize.
It registers the fixed flow once. Copied runs/ledgers, changed controls, aliases
and reinitialization cannot reopen SDK128. Original public exposure-registry
bytes and top-level excluded identities are checked; nested private/oracle/key/
index targets are never followed. Old recursive load/validate is not invoked.

## Fixed lifecycle

`release` delegates the original d0 scripted event after a Root trigger binds
all six cut sets and its genuine source observations. Only the original 52B,
no-LF occurrence `改为5分钟，但保留关键证据与只读边界` is released.
`materialize` delegates original `Store.put_blob` in the original journal.
One logical event is materialized per original project. Repeating a confirmed
materialization returns the same checked project-local Ref without another SDK
attempt; interrupted/unknown materialization is never resent automatically.

For B, `request` uses actual `replace_request_id` and current CAS to start the
fixed content_only/content_full request, current actual Page IDs and null old
manifest. Its instruction is the project-local confirmed 52B Ref. `inputs`
queries actual inputs, replaces the unique `10 分钟` with `5 分钟` in brief,
sets the original exact reason/mode=auto, preserves every other task/source
fact, and returns the Runtime's true pending Tasks. It invents no time_seconds,
Task, decision, argument, timing allocation or page choice. A0 instead uses its
own legacy inputs/content_update path and gains no modern Request/receipt bridge.

`prepare/begin/claim/observe/objects/accept` use the original main **full-own Q2**
packet and native/SDK contracts. Every real public method/summary/claim call is
explicitly metered; pure Store reads and file hashes are not fabricated calls.
Full raw originals and native sidecars are frozen before parsing/acceptance.
Only exact native-authored proposal objects are materialized. No production,
files, image usage, Writer-authored independent review or host-authored business
result is accepted. No Q3/Q4 bounded view or mandatory packet-audit model calls
are introduced. `continue-content` is limited to B's content_only progression
before feedback; legacy production routing is unavailable.

Actual public lifecycle matters: content_only may legitimately complete/close
after reconciliation. Direct review dispatch to that closed Request remains a
real refusal. Like original r04/r12, `review-request` first starts a genuine
current Page/Plan-manifest-bound review_only Request. It preserves the same
project-local 52B instruction Ref; the new Request ID/revision are actual SDK
returns. `review-prepare` then uses the original protected NativeProvider.

After one actually accepted/delivered feedback with actual findings, `repair`
records at most three necessary layers and one cycle. `repair-request` grants
only those layers through the existing public lifecycle, retaining the same
52B source. A necessary speech-only repair uses existing speech_only. `repair-task`
dispatches only a declared layer through the actual public phase API; its SDK
intent is the existing `initial` enum, while its **metered native role remains
repair_writer**. Argument output stays proposal-only under the original SDK;
this adapter invents no direction decision/adoption. Verification needs actual
accepted necessary-layer results, a fresh current review_request and V<=1.
Its output never becomes another feedback/repair cycle. A0's actual capability
refusals remain refusals; no B bridge or migration is imported.

## Cost, provenance and failure

442's unchanged q2-300 profile supplies one pool
`q2-300:flow-NN:repetition:arm`: writer6/review2/SDK128/render0,
I3/R3/F1/V1/P0/PR0, image0. Every actual attempt/error/query/Request is charged.
Old costs and prefix/cut bytes are preserved, never copied as new native calls.
Materialization's original journal and later ledger reference **one** physical
identity `(project, journal, operation_key)`, charged once. Charge/intent/projection
interruptions conservatively remain unknown. No refund, retry or budget reset.
Actual native overruns remain recorded; they block scope consumption, including
selection of an earlier within-budget ordinal. Actual raw outputs remain recordable.

Original writer identities bind actual original journal/invocation/dispatch
Refs, including rejected/format attempts; later writers join that union. Review
executor and inherited identities cannot contain any author. The same union
must cover protected `author_execution_refs` and is transmitted as
`all_native_writer_execution_refs` through the original provider/collector.
A genuine same-project original-writer followup explicitly names its origin run
and costs one later turn; it is never relabeled a new fork-none invocation.

Both journals and the shared resource ledger are locked. Unresolved old union
later intents, changed frontiers/current revision, interrupted projections,
unknown/lost acknowledgments or overruns block new consumption. `status` only
reports actual local journal/resource facts and does not reconcile or grant retry.
Later snapshots live only in the new scope; old equal/qualified/E1 cannot be named.

Validation uses substantive real SDK source cases in a real isolated child of
ordinary pytest, plus new engineering installations of the original own wheels.
Synthetic native observations/reviews are explicitly marked. Logs retain all
argv, UTC, stdout/stderr, exits, failures and actual costs; evidence remains
ordinary public/engineering material and does not include private oracle targets.
