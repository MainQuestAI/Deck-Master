# M02 sequential SDK/native recorder

This module records one separately authorized, nonhuman capability experiment.
It is not GENTRY, E1 or an extra slot in the original twelve workflows. Both
committed fresh U-LIVE-01 and U-READ-01 experiments remain separate work. Neither
these model experiments nor M02 replace the two user-deferred human tasks.

`m02_recorder.py` adds no model/image caller, content author, Runtime patch or
receipt shortcut. Root alone invokes actual fresh agents and literal imagegen.
The registration pins the recorder, sibling d0 controller, bf image controller,
actual B installation, public grammar/supplements, source bytes, exclusions,
scopes and finite per-role budgets. The native budget belongs to this experiment;
it does not impose E1's 5/1/1/3 profile on the product. Actual overruns remain
counted and unconsumable. SDK errors remain unresolved until real reconciliation.

## Registration before the first output

`format=rc3-m02-registration.v1`; `status=ENGINEERING_ONLY_NOT_ADMITTED` allows
explicitly labelled engineering evidence. `ADMITTED` additionally requires exact
d0 R4 review, current public layer rules and actual PASS evidence for G04, GID,
GADAPTER, M02_NATIVE (recorder/native trust admission), IMAGE_NATIVE and M02_SCOPE.
These are real evidence references, not fields that this module grants itself.
No gate status in a template establishes admission or successful M02 production.

Required fields: `experiment_id`, `recorder_sha256`, `common`, `image_controller`,
`installation`, `protocol`, `grammar`, `admission_review`, `common_review` for
ADMITTED, `exposure_registry`, `technical_supplements`, `materials`,
`create_arguments`, `scopes`, admission `gates`, and the selected image profile
bindings described below.
References have absolute `path` and exact `sha256` (optional `bytes`). The
installation entry is the actual final B identity/inventory, not a relabelled
new source SHA. `common` must be the sibling d0 file; `common_review` pins its R4
limited review, not a repeat claim that this new recorder was reviewed there.

There are exactly four scopes: `common`, `live`, `read`, `live_notes_edit`.
Each has an exact UTF-8 synthetic `instruction` reference, `page_ids`, explicit
finite `native_limits` for initial_writer/repair_writer/feedback/verification/
production/production_review, `max_external_calls`, `max_candidates`, and
`notes_policy`. Live/read also specify `input_patch` (normally null).

Use a fixed common task with `presentation_mode=mixed`, containing both explicit
uses in its actual instruction. The actual Narrative stays fixed. Two real
variant requests and their distinct Plans express the live/read objectives;
live Plan speech policy is cues, read Plan policy is none. Live export uses
both notes, read export pure_reading; read Pages themselves have no notes.
Live and read Page IDs are distinct and stable within the shared whole run,
for example L01/L02 and R01/R02. The notes edit selects exactly one live Page,
layer speech only, no membership/order changes. Common and notes edit have zero
external image budget. Scope instructions are new explicit synthetic authority,
not an expanded Q1 P5 sample permission or a human Owner decision.

Optional real input patches must be registered and executed through inputs_update.
They retain the SDK's true input_revision/currentness barriers. In particular,
changing global task facts for read and selecting an old live revision may
require reconciliation; this recorder does not cancel tasks or rewrite task
facts to hide it. The fixed mixed-task/per-Plan route avoids that unnecessary
fact change and was checked through real public next/edit operations.

The shared image registration uses case=M02, whole_run_id=experiment_id,
repetition=1, arm=B for *both* variants. The budget document is pinned before
first output and covers exactly the original Page sets/combined ceiling. A
four-Page scope can preregister total four calls, one candidate/call per actual
Page, retry zero. Do not create another whole-run ID or ledger between variants.
The exact ledger may initialize later, before the first image. Actual Request
IDs enter independent bf batch profiles only after real freeze/begin, never as
future placeholders; every batch points to that same global budget/ledger.
This is a scoped experiment ceiling, not a product-wide quota.

`image_ledger_profile` defaults to `legacy-bf-v1`; omission retains the original
`global_image_budget` validation and bf ledger guard. Explicit
`scope-events-v1` instead requires `image_event_controller`,
`image_event_registration`, and `global_image_policy` refs and omits
`global_image_budget`. The new pinned helper validates one same-root event epoch,
the exact protocol/own B installation, original M02 parent, distinct exact
live/read Page sets, instructions, per-use caps and one candidate per allowed
call. Unknown or mixed profiles refuse. Existing actual SDK rights, per-phase
begun-attempt checks and all Narrative/version/notes/review business checks are
unchanged. See [IMAGE-EVENT-CONTROLLER.md](IMAGE-EVENT-CONTROLLER.md) for actual
Host dispatch/observation/settlement; this profile is not an image caller or a
new grant. A changed M02 recorder needs its actual new hash/registration; old
3c84 source and evidence remain historical.

## Public execution sequence

Use the actual B installation's absolute interpreter, `-I -B`, and short paths
for actual project/run directories. All JSON argument files below are exact
public API parameters chosen from actual responses, never invented Refs.
For illustration only:

```bash
M02_PY=/absolute/actual/B/venv/bin/python
M02_TOOL=/absolute/rc3-05/tools/rc3_campaign/m02_recorder.py
"$M02_PY" -I -B "$M02_TOOL" freeze --registration registration.json --out /short/mc
"$M02_PY" -I -B "$M02_TOOL" init --campaign /short/mc --out /short/mr --project /short/mp
"$M02_PY" -I -B "$M02_TOOL" instruction --run /short/mr --scope common --trigger common-trigger.json
"$M02_PY" -I -B "$M02_TOOL" public-operation --run /short/mr --operation service.create --arguments create.json
```

A trigger is Root's actual host_attested observation, with
`actual_trigger_satisfied=true` and immutable `source_observations` refs.
`instruction-evidence --run ... --scope ...` stores the exact released instruction
as public SDK evidence, explicitly synthetic/nonhuman. Create arguments equal
registered task facts plus the exact common instruction as brief and fixed source
paths; it does not import a semantic manuscript.

Common framing/argument use actual returned Tasks. An effective delegated
covering direction grant and `collaboration.record_decision` may be needed to
adopt the actual accepted Narrative with `content_production.adopt_proposal`.
All run through `public-operation --operation NAME --arguments exact.json`.
Direction grants can become stale on real adoption. After adoption,
`fix-narrative --run ...` records its actual own-project argument Ref, then make
the original two-use declaration against *current* dependencies with
`collaboration.grant` (constraints.variant_ids exactly [live,read]), using the
original preregistered common instruction. No fake direct_user/Owner approval.
The Runtime derives the actual group ID from that effective declaration.

For every real Task, prepare before spawning. `--role` must match its actual kind
and review stage. Packets include actual SDK metadata/methods/current objects,
contracts and exact public supplements. Controller-only registration files do
not go to Writers. Root records a genuine spawn/followup; no child delegation.

```bash
"$M02_PY" -I -B "$M02_TOOL" prepare --run /short/mr --stage live01 --task-id ACTUAL --role initial_writer
"$M02_PY" -I -B "$M02_TOOL" begin-native --run /short/mr --stage live01 --invocation root-spawn.json
"$M02_PY" -I -B "$M02_TOOL" claim-read --run /short/mr --stage live01 --ordinal N --executor /root/ACTUAL
"$M02_PY" -I -B "$M02_TOOL" observe --run /short/mr --stage live01 --ordinal N --result raw.json --result-sha256 SHA --observation root-completed.json --observation-sha256 SHA
"$M02_PY" -I -B "$M02_TOOL" materialize-native-objects --run /short/mr --stage live01 --ordinal N
"$M02_PY" -I -B "$M02_TOOL" accept --run /short/mr --stage live01 --ordinal N
```

Invocation/completion shapes are the pinned d0 actual-host-observation protocol:
Root actual canonical spawn identity/fork-none, exact Task/project, fresh time,
complete FINAL/completed status, full method-read record and exact raw bytes.
Sidecars use d0's immutable-first original collection and own-arm canonical
materialization. No output fixing or semantic envelope assembly is performed.
Continue only through `public-operation service.continue_project` and actual
returned phases. Raw originals and actual SDK snapshots remain separate.

Release live instruction/evidence, then `start-variant --variant live` with:

```json
{"input":{"intent":"full_deck","content_intent":null,"scope":"ACTUAL_BOUNDED_SCOPE_OBJECT","instruction_evidence":"ACTUAL_EVIDENCE_OBJECT","replace_request_id":"CURRENT_REQUEST","variant":{"group_id":"ACTUAL_DERIVED_GROUP","variant_id":"live","label":"live","requested_variant_ids":["live","read"]}},"base_revision":"ACTUAL_CURRENT","operation_id":"NEW_ID"}
```

This JSON is a template, not a valid argument file; replace entire labelled
objects with actual public contract objects. Produce full live Plan/Pages/notes,
then current independent preproduction review:
`review-prepare --role feedback --bootstrap ACTUAL --stage ID`, real fresh
reviewer begin/claim/full read/observe, `review-accept --bootstrap ACTUAL`.
If findings need repair, `deliver-feedback` once, `repair-begin --necessity FILE`
(actual finding IDs, necessary layers), native repair, then independent readonly
verification through `review-prepare --role verification` and review-accept.
Verification is not returned as another Writer feedback. No defect means no
fabricated repair. Actual central gate must pass.

Production remains actual public style/change/request-freeze/call-begin and
current returned blueprint/reconstruct/page_visual/final Tasks. Exposed direct
helpers include pipeline.preview_svg_page, stages.assemble, exports.show/download
and handoff.check_handoff. The recorder invokes no image tool. Each actual image
call uses the separately reviewed bf observer/batch and single shared global
ledger. Task call-begin checks scope/counters and exact frozen opaque parameters.

`export-version --arguments FILE` requires current full PPTX, trace, render
report, each Page's blueprint/SVG/SVG-preview/PPT-preview, current content and
visual/final gates, exact Plan/Page/Narrative mappings and actual full PPTX notes
readback. Arguments are `output_dir`, `purpose=review`, actual `revision`, new
`export_id`, and the registered `notes_policy`. It freezes internal export and
external copy trees. Content-only exports cannot unlock the next phase.

After that actual export, release read instruction/evidence and use
`start-variant --variant read` with the same original group/list, read metadata,
and `variant_transition={kind:next_variant,source:{revision_id:LIVE_REV,
export_id:LIVE_EXPORT}}`. Complete read's independent content/review/production/
notes/export chain. The common Narrative Ref stays identical; Plan/Page/output/
revision/export identities are recorded separately. The first files never change.

After both exports, release live_notes_edit instruction/evidence and use
`start-variant --variant live_notes_edit`: intent=edit, no `variant` declaration,
exact one-live-Page/speech scope, and
`variant_transition={kind:edit_variant,source:{revision_id:LIVE_REV,
export_id:LIVE_EXPORT}}`. The SDK selects the original live metadata under current
control. Wrong source, another group, third/repeated variant or missing full
source export is refused.

Notes writing uses public editing.edit_page, not a fabricated Task:

```bash
"$M02_PY" -I -B "$M02_TOOL" prepare-notes --run /short/mr --stage notes01 --operation-id NEW_ID --role initial_writer
"$M02_PY" -I -B "$M02_TOOL" begin-notes --run /short/mr --stage notes01 --invocation root-spawn.json
"$M02_PY" -I -B "$M02_TOOL" read-notes --run /short/mr --stage notes01 --ordinal N --executor /root/ACTUAL
"$M02_PY" -I -B "$M02_TOOL" observe-notes --run /short/mr --stage notes01 --ordinal N --result native-arguments.json --result-sha256 SHA --observation root-completed.json --observation-sha256 SHA
"$M02_PY" -I -B "$M02_TOOL" accept-notes --run /short/mr --stage notes01 --ordinal N
```

The native result itself contains exactly page/base_revision/page_hash/operation_id.
Binding metadata comes from prepare-notes; the model supplies the actual Page.
Only speaker_notes and speech_segments may differ. Root cannot compose a Page
wrapper around prose. Invocation/completion additionally bind dispatch_sha256;
the real method bytes come from read-notes without a Task claim. Full actual
completion/method-read/original-byte observations are still mandatory.

Notes edit consumes no image rights and preserves visual objects/old exports.
Runtime may invalidate PPTX freshness; this recorder reports that state and does
not call stale files fresh. Its current independent review/closure can use the
same readonly pathway. `selected-file --variant live|read --file ACTUAL_PPTX`
checks a frozen original hash through actual delivery_eligibility.describe and
handoff.check_handoff under current control. A stale/blocked judgement remains
blocked. It is not a human acceptance record or a third exported variant.

On an interrupted SDK operation, query actual Runtime operation/state first,
then `reconcile --record FILE`; intent logs alone grant neither success nor
permission to retry. All prior originals and unresolved failures stay preserved.

## Engineering evidence limits

Owner tests use explicitly synthetic observations. The installed-B probe also
uses honest SDK-result and content-only-milestone seams to isolate public
next/edit transitions. Those seams are absent from the recorder CLI and cannot
complete M02 export. These checks prove engineering boundaries, not actual
native trust, professional quality, full production, benchmark scores, or any
human task. Root must execute the admitted complete M02 chain separately.
