# M02 prospective Runtime successor (S11)

`m02_runtime_continuation.py` records a separately admitted supplemental epoch.
It does not continue the old 3ec admission, activate a candidate, grant direction
or images, or recertify E1/E2. Root alone observes actual actors and calls tools.
S12's same-root image transition remains separate and unimplemented here.

Use the actual admitted installation's absolute Python with `-I -B`. Ordinary
CI invokes `test_rc3_m02_runtime.py`, which executes the explicit substantive
carrier in a real isolated child. No production guard is patched.

## Write-once registration

`format=rc3-m02-runtime-successor.v1`, `status=ADMITTED` requires a distinct
managed installation, its independently verified inventory/toolchain/native
image registry, exact S07/S10 and companion reviews, and a **new** Root admission.
The Source card does not supply those future observations or an admission.
`ENGINEERING_ONLY_NOT_ADMITTED` instead refuses the formal project/run and can
verify an existing plain engineering wheel prefix without inventing managed
release metadata. This branch still checks interpreter/module origin, every
wheel member, current method epoch and absence of borrowed Runtime modules.

Registration fields are `companion_sha256`, exact sibling `common` and
`m02_recorder` Refs, `supplemental_validation_id`, `runtime_epoch`, `project`,
`experiment_id`, `group_id`, `fixed_narrative`, `installation`, `predecessor`,
`scopes`, `materials`, `grammar`, `protocol`, `exposure_registry`,
`technical_supplements`, `independent_reviews`, `auxiliary_executions`,
`initial_content`, `initial_pages`, `initial_outputs`, `protected_refs`,
`blocked_task`, `blocked_stage`, and `admission`. Refs have absolute `path`,
exact `sha256`, and optional `bytes`.

`predecessor` contains exact run/registration/frontier Refs and `event_count`.
Formal admission fixes the actual original M02 project, group, N and historical
229-event frontier. Old run/config/journal are read-only, not copied into a new
budget. The successor journal alone receives new events. Its historical view
retains original feedback/author lineage; packet preparation includes current
SDK objects and methods, rather than historical native raw outputs.

`scopes`, instructions, materials and public exclusions equal the predecessor.
Nested private/oracle/index/key references are opaque and never followed.
`auxiliary_executions` pins the two actual additional live production reviews,
including executor and evidence Ref. Accounting begins at helper14 + aux2 =
whole16/67, live production7/12 and live review5/8. Actual new invocation
observations, including overruns, remain counted; over-budget raw cannot be
consumed. Old actors/claims/raw are never re-used as new release executions.

`initial_content` is sources/N/Plan and Page entries excluding `ppt_preview`;
`initial_pages` preserves the complete original entries, and `initial_outputs`
preserves original failed output Refs. `protected_refs` must include every
initial N/Plan/Page and original PNG/SVG/preview/PPTX/report/trace metadata and
file, not merely a selection. These exact public dependencies are read through
the own SDK and rechecked; this is not a Store enumeration or nested Ref crawl.

The Root admission is `rc3-m02-runtime-admission.v1`, observer `/root`, same
status, nonempty actual `source_observations`, `administrative_only=true`,
`no_new_image_or_direction_authority=true`, and `registration_binding` equal
to the SHA256 of canonical registration JSON excluding `admission`. It pins
future exact evidence; it is not generated by this tool.

## Fixed commands and actual control

`initialize --registration FILE --out NEW` writes only the separate successor;
it does not create/copy the existing project. Subsequent commands use `--run`.
Every business/control command also requires `--bootstrap` (original d0 live
Root channel observation) and a fresh `--barrier`. The original fixed provider
is bound around the **whole** command, including SDK calls whose signatures do
not expose adapter context. No caller context, provider, selector or Store is
accepted.

Barrier format is `rc3-m02-exclusive-root-barrier.v1`, with observer `/root`,
host attestation, exact `command`, registration binding, current project ID and
base revision, successor event count, actual source observation Refs and exact
bootstrap Ref. It explicitly attests old write routes retired, all other
writers stopped, and exclusive control until command completion. The local
flock serializes this successor, while Root must actually serialize the old
route too. Public `task_cancel` has no CAS parameter; no CAS is invented here.
Changed frontier/control/content refuses. A consumed barrier cannot replay.

- `inspect-transition` records installation identity, only Task88deb3fff924
  status, collaboration/eligibility and exact bound dependencies.
- `cancel-blocked-readback-task` accepts only that exact running repair Task,
  original executor and scope. The barrier must additionally attest
  `producer_executor`, `producer_status=completed`, `producer_raw=null`, and
  zero `external_attempts`, `external_inflight`, `external_unknown`. Actual
  Task allowances/attempts must also be empty. Cancellation preserves content,
  outputs and original history; late SDK results keep ordinary settlement and
  adoption refusal. It never transfers a claim.
- `assemble-existing-live --operation-id NEW` requires actual cancellation,
  unchanged initial content/PNG/SVG/notes, current preproduction and page visual
  gates. It calls real `stages.assemble` with the current revision. Real tool
  failures/readback defects remain failures; no report or dummy repair is made.
- `continue-current`, `prepare`, `begin-native`, `claim-read`, `observe`,
  `materialize-native-objects`, `accept`, `review-prepare`, `review-accept`,
  `deliver-feedback`, and `repair-begin` retain original real Task, role,
  finding, independent protected receipt and complete-method/raw boundaries.
  Only successor-prepared, genuine new-release Tasks are claimable.
- `export-current-version --arguments FILE` retains the entire original
  `complete_version` contract and additionally requires an accepted successor
  final Task. SDK's omitted review stage means final. Export/show/every download
  are individually recorded; binary returns are preserved as immutable bytes.
  Export provenance names this runtime epoch. Content-only output cannot unlock
  the next use.
- `release-instruction`, `materialize-instruction`, `start-next-variant` retain
  real complete source exports, original group/N, original instructions and
  sequential read then selected-live notes transitions. No input-fact migration
  or new group is introduced. `prepare-notes`, `begin-notes`, `read-notes`,
  `observe-notes`, `accept-notes` reuse the original actual direct page-edit
  protocol, single Page/speech-only comparator and original caps.
- `status` is local. `query --operation-key EXACT` queries only a pending
  successor intent through fixed public readers, never the original mutation.
  Real durable current assembly can recover its actual output event; exact
  cancelled Task facts can recover cancellation. Known read-only queries may
  obtain fresh facts. Every query/error stays charged and complete. Unsupported
  durable reconciliation, not-found/error, drift or unknown remains blocked;
  there is no automatic replay, refund or caller settlement record.

No arbitrary operation, method/API/path selector, image call, runtime override,
forced Task, receipt injection, or old admission reuse is exposed. Future read
images, complete read production/export and notes execution still require their
actual prerequisites and separately admitted S12 where affected.

## Evidence limits

The engineering tests use explicitly synthetic history and Host completions;
they do not claim real model independence, native fees or business quality.
Own-wheel probes exercise actual SDK cancellation, compile/render/readback,
commit-lost-ack reconciliation, fresh Task/methods/result, full PPTX export and
same-group transition. Existing methods/Runtime source bytes are checked, not
reinstalled or relabelled. Ordinary missing tools, wrong geometry, missing final
review, early notes, unknowns and all initial mistakes are retained. Formal M02
continues to wait for final managed build, independent installed review and
prospective Root admission.
