## Linearization and failure behavior

The release decision re-reads the chain and all exact evidence under the same
`.controller.lock` used by frozen native CLI. The actual lock inode is checked
before and after append. An initial unlocked read is only preflight; waiting
for the lock never preserves permission after another writer advances history.
JSON parsing and reply projection must consume the actual bytes matching their
Refs; a transient different read cannot authorize an admission with another hash.

One write-once directory under `technical-controls/RC3-S13-native-preconfirmation`
contains the exact admission copy, projected message and typed provenance. Complete
fsynced bytes are exclusively published before one complete `scripted_event` JSON
is linked as journal record13. No old record is overwritten. The event data has
format `rc3-native-preconfirmation-control.v1`, a new distinct event ID, exact
message/trigger/admission Refs, and the intervention disclosure. Frozen `prepare`
already consumes only actually journal-released message Refs; no packet injection
or helper patch is used.

A failure before append can retain orphan control artifacts. They are not
released and frozen prepare does not deliver them. An interrupted partial write
cannot publish partial journal JSON. Failure after a complete append can lose the
acknowledgment: CLI says `refused_or_unknown`, and the one valid event may exist.
There is no automatic retry, deletion, rollback of old facts or recovery by
recreating the run. Existing artifacts or a changed frontier block replay; Root
must inspect the retained evidence. Only this attempt's unpublished temporary
write buffers are removed by the atomic publisher.

The event adds no writer call. Initial used2/cap5/remaining3, feedback1,
repair-cycle1/repair-writer3 remain. Further actual writers still consume the old
pool across actors. A later complete manuscript and cuts remain governed by the
unchanged old helper. Root must mark every affected continuation/cut as occurring
after this new controller intervention; helper-valid technical cuts do not grant
pre-intervention E1 comparison credit. Old waiting raws and missing cuts persist.
