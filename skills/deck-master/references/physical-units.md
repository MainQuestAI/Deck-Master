# SVG 逻辑画布与 PPTX 物理尺寸

这是制作、重建和成品审查共用的方法，不改变 compiler 的全局常数，也不授权修改已冻结样式。读取完整工作单的 canvas.width_px/height_px、slide_width_in/slide_height_in、fit 与逐对象语义/设计角色；后续调用使用该固定输入，不在外层包装偷偷追加不同字体要求。

## 先计算当前 contain 比例

设逻辑画布为 W×H，物理页为 wi×hi 英寸，编译器96ppi的目标为 Tw=wi×96、Th=hi×96。contain 的统一比例 `k=min(Tw/W, Th/H)`，居中偏移分别为 `(Tw-W*k)/2`、`(Th-H*k)/2`。必须用当前完整工单，不能拿截图像素或默认1600×900当实际编译尺寸。

文字的实际原生字号为 `SVG_font_px * k * 0.75 pt`；反求目标角色 pt 对应的 SVG px 为 `target_pt/(k*0.75)`。这不是一律18pt→24px。例：1600×900逻辑画布，13⅓×7.5in物理页，目标1280×720，k=0.8；18pt正文需30px，30pt标题需50px。24/40px在该页只得到14.4/24pt。比例有舍入时保留实际值与容差依据。

这条计算用于判断冻结设计能否落地；若冻结输入本身不可满足，正式提出更改并重冻，不覆盖 prompt、偷偷改 frozen style 或调 converter 的 `.88` 等常数。

## 核对实际 PPTX

打开真正导出/预览的 PPTX ZIP，读 `ppt/presentation.xml` 的 `p:sldSz@cx/cy`，用914400 EMU/in换算实际英寸。`type=screen4x3`只是模板元数据，不能代替 cx/cy 或用来推实际比例。记录实际文件 hash、页号、SVG/编译输入与尺寸。

按固定 Page atom/明确设计角色逐对象找到可见文字 shape/run，解析真实 run 有效字号（a:rPr、a:defRPr及其实际继承），以100为单位换算pt；记录期望 pt 与实际 pt。标题/正文/脚注要由显式语义/设计角色判定，不能以全局 min/max、粗体或字体大小猜角色。缺映射、不可解析继承或无法判定的对象记 `unverifiable`，不得判整页通过。XML有文字不证明可见；渲染后还需看实际墨迹。

## SVG 和原生 PPT 双层留白

留白的 px 须声明逻辑画布坐标还是渲染采样坐标，并记录采样尺寸/DPI与实际舍入（例如约120dpi可得到1601×900）。SVG文字边界与容器形状检查一层，真实 PPT/PDF渲染的文字墨迹到容器/邻接对象净空再查一层；XML anchor一致不保证文字墨迹相同。检查上下/左右 padding、换行、行距、表格每行、标签与箭头交叉。

对照固定角色与每个容器的要求记录最小实际净空和具体对象；不能只记全页最小字号或一张截图存在。若原生文字偏移导致净空不足，优先在该页未冻结的行距、换行、容器安排中留余量，并重编译/实际渲染复核。不得以扩大截图、改字或整体调 converter 常数掩盖。

同文字的错误表格归属、箭头反向仍是内容/关系错误；整体平移或等比缩放且关系保持则与反向错误分开。只有字符覆盖、XML坐标或工程编译通过不等于专业可读性通过。每次失败保留原文件和具体差异，工程/模型阅图/人类/桌面证据分别记录。
