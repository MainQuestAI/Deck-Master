# Source Reading｜资料阅读方法

对象：宿主 Agent。本方法规定如何把用户材料读进实际制作输入。工具层由 `deck_master.sources` 提供（`read_source`/`tail_constraint`），这里规定宿主如何使用与判断。

## 读取与登记

1. 直接读取用户现有路径，不要求先搬进知识库。每个材料文件先 `read_source` 取得 `SourceExtract`：`original_sha256` 是本次实测的文件字节 hash；`original_uri` 是用户给的原位置。
2. TXT/MD：逐行定位（`L1`/`L2`…），全文保留；摘要只作导航，不作已读依据。
3. JSON：按 JSON Pointer 定位（`/quarters/0/manual`），数字、0 值、单位、嵌套对象全部保留；`0`、空串、缺键语义不同，不得合并。
4. PDF：pdftotext 按页提取；无文本或图形承载含义的页，按页派发实际阅图；缺工具时该资料标 `needs_tool`，不返回空摘要成功。
5. DOCX：ZIP/XML 提取段落与表格；页码不可确定时用段/表定位，不伪造页码。
6. PPTX：python-pptx 读页序、文本、备注、图表；图片型页必须实际看图；旧 Deck 只作资料，不默认整页混编。
7. 图片与不可解析格式：`pending_visual` / `needs_tool` 状态如实登记，缺什么写什么，不得空成功。

## 尾部约束（AC-C01）

关键只读/不可回写约束通常放在材料末尾。`tail_constraint(extract)` 返回最后一条非空内容行；宿主必须把它纳入本次方案与图示判断——输出正文与设计关系要随约束改变，而不是只写"已读"。

## 失败与隐私

- 编码不可读、坏 JSON、缺解析工具：返回文件与原因，不返回空摘要成功。
- 未知原始 hash 不阻止读取已存提取文本或媒体；能测得的文件就测真实 hash，不能测得的未知保持 null，不用全零或 URI 哈希冒充。
- 文件与私密参考只用于宿主理解；进入外部图像工具 payload 的仅限已形成的对外正文、必要设计与允许资产。受限素材不外发；缺外发工具时停在该动作。
- 默认不自主访问网络；任务明确授权补查时记录可回查来源、日期与引用范围。
