# Deck Design

Read the shared [visual reference](../deck-master/references/visual-reference.md), [style calibration](../deck-master/references/style-calibration.md) and [blueprint/SVG method](../deck-master/references/blueprint-svg.md). Use the installed `deck-master` runtime for all project state, freeze, call settlement and adoption.

Start from `deck-master continue --project … --json` and `task status`. A design request consumes the complete fixed Page, its density requirements and the exact confirmed recipe. Initial design can use `style_input.v3` without an old image; feasibility makes zero calls, while a paid trial requires the runtime's preproduction and authorization gates. Never invent an original image. Preserve cell ownership, arrow direction, units, reading order and editable information. Missing data is a content gap; decorative numerical charts cannot replace it.

One-page trial means one page. A saved candidate is not adopted: show the actual candidate and difference, then use the user's explicit decision through the runtime. Expansion requires an adopted representative page and effective scoped authorization. Do not edit content or expand scope/budget to complete a design task. On timeout inspect the original operation, task and call ledger before any retry; retain original images and failed artifacts.
